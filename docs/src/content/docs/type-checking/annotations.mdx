Inference types most code without help, but it cannot know what a function is meant to accept, or
what a value read from a file contains. An annotation states that type, and ry then checks it
against the value and against every use, so a wrong call is reported at the call instead of deep
inside the function.

You can write an annotation as a `#:` comment directly above the assignment, or inline, in the code
itself. Both spellings mean the same, so pick the one you prefer: the tab you choose is
remembered on every page of this site.

<Tabs syncKey="annotation-style">
<TabItem label="Comments">

```r
#: fn(price: double, rate: double) -> double
apply_rate <- function(price, rate) price * rate

apply_rate(10, "x")
```

</TabItem>
<TabItem label="Inline">

```r
apply_rate <- function(price: double, rate: double) -> double price * rate

apply_rate(10, "x")
```

</TabItem>
</Tabs>

```text
type-mismatch

  x expected `double`, found `character`
```

The body is checked too, so a function declared `-> double` that returns a string is an error at the
return value. Only the comment spelling runs on every R tool; see
[inline annotations](/type-checking/inline-annotations) for what that means in practice.

## Values with no type

A value read from a file has no type until you give it one, and then every use is checked:

<Tabs syncKey="annotation-style">
<TabItem label="Comments">

```r
#: double
rate <- readRDS("rate.rds")
rate + "x"
```

</TabItem>
<TabItem label="Inline">

```r
rate: double <- readRDS("rate.rds")
rate + "x"
```

</TabItem>
</Tabs>

```text
type-mismatch

  x expected a numeric value (`integer` or `double`), found `character`
```

## Function annotations

The compact form above fits most functions. A long signature can be written one parameter per line
instead, in the style of roxygen. This block form is comment-only; inline, the same types sit on
the parameter list itself.

```r
#: @param count {integer}
#: @param label {character}
#: @return {integer}
```

[Functions](/type-checking/functions) covers optional parameters, `...`, and generics. The
[type system reference](/reference/type-system#typing-comment-syntax) has the full grammar,
including where a block may attach.

## Overriding inference

`@if-unknown` and `@trust` give a type without checking it against the value, for code ry cannot
type; [Unknown and Any](/type-checking/unknown#overriding-inference) shows both.
