import { Tabs, TabItem } from '@astrojs/starlight/components';

R models data with lists, S4 classes, R6 classes or Reference Classes, and ry can check none of them
very far. ry adds its own records, tuples and tagged unions instead. They have a fixed shape that the
checker knows exactly, and `match` reports the case you forgot:

<Tabs syncKey="annotation-style">
<TabItem label="Inline">

```r
alias Shape =
  | :Circle(radius: double)
  | :Rect(width: double, height: double)
  | :Empty

area <- function(s: Shape) -> double {
  match (s) {
    :Circle(radius = r) => pi * r^2
    :Rect(width = w, height = h) => w * h
  }
}
```

</TabItem>
<TabItem label="Comments">

```r
#: @alias Shape {
#:   | :Circle(radius: double)
#:   | :Rect(width: double, height: double)
#:   | :Empty
#: }

#: fn(s: Shape) -> double
area <- function(s) {
  match (s) {
    :Circle(radius = r) => pi * r^2
    :Rect(width = w, height = h) => w * h
  }
}
```

</TabItem>
</Tabs>

```text
non-exhaustive-match

  x this `match` does not handle `:Empty`: add an arm for it, or a catch-all `_ => ...` arm
```

`match` and the tag, record and tuple syntax exist only in ry, so they have a single spelling.
Only the annotations around them, including the definition of `Shape`, come in two styles.

These are ry values, not R lists. GNU R cannot parse code that uses them, so run it on ry's own
runtime:

```r
# points.R
point <- (x = 1, y = 2)
point$x + point$y
```

```text
$ ry run points.R
[1] 3
```

## Records and tuples

A record is written in parentheses with named fields, and a tuple with unnamed items. A one-item
form needs a trailing comma, so that `(x = 1)` and `(1)` keep the meaning they have in R:

```r
point <- (x = 1, y = 2)     # Record{x: double, y: double}
pair <- (1L, "a")           # Tuple{integer, character}
one <- (x = 1,)             # Record{x: double}
empty <- ()                 # Tuple{}
```

Fields are exact. `$` never matches a prefix, and a field that does not exist is an error:

<Tabs syncKey="annotation-style">
<TabItem label="Inline">

```r
origin: Record{x: double, y: double} <- (x = 0, y = 0)
moved <- origin$xx
```

</TabItem>
<TabItem label="Comments">

```r
#: Record{x: double, y: double}
origin <- (x = 0, y = 0)
moved <- origin$xx
```

</TabItem>
</Tabs>

```text
type-mismatch

  x field `xx` does not exist in `Record{x: double, y: double}`
```

A record has value semantics. `p$x <- 3` changes a copy that only `p` sees. The new value must fit
the field's type, and assigning to a field that the record does not have is an error, because a
record's fields are fixed.

## Tags

A tag is a name that starts with `:`, with an optional payload that hugs it: `:None`, `:Some(5L)`,
`:Rect(width = 2, height = 3)`. A union of tags lists the cases a value can be, and a value outside
the union is an error:

<Tabs syncKey="annotation-style">
<TabItem label="Inline">

```r
bad: :Ok(integer) | :Err(character) <- :Ok("five")
```

</TabItem>
<TabItem label="Comments">

```r
#: :Ok(integer) | :Err(character)
bad <- :Ok("five")
```

</TabItem>
</Tabs>

```text
type-mismatch

  x expected `integer`, found `character`
```

A union that ends in `..` is open: it accepts any other tag as well, so a `match` on it needs a
catch-all arm.

<Tabs syncKey="annotation-style">
<TabItem label="Inline">

```r
on_event <- function(event: :Click | :Key | ..) -> character {
  match (event) {
    :Click => "click"
    _ => "other"
  }
}
on_event(:Scroll)   # fine
```

</TabItem>
<TabItem label="Comments">

```r
#: fn(event: :Click | :Key | ..) -> character
on_event <- function(event) {
  match (event) {
    :Click => "click"
    _ => "other"
  }
}
on_event(:Scroll)   # fine
```

</TabItem>
</Tabs>

`match (value) { pattern => result }` tries each arm in order and runs the first that matches. Put
each arm on its own line, or separate arms with `;` or `,`. The `{` must be on the same line as the
`)`, which keeps R's own `match()` function working unchanged.

| Pattern | Matches |
| --- | --- |
| `_` | anything |
| `name` | anything, and binds it to `name` |
| `1L`, `"a"`, `TRUE`, `-1` | that literal |
| `:Some(p)`, `:Rect(width = w, ..)` | that tag, with a matching payload |
| `(p, q)` | a tuple of two items |
| `(x = p, ..)` | a record with an `x` field, and any others |
| `p \| q` | either pattern; both sides must bind the same names |

An arm may add a guard, `pattern if (condition) => result`. A guarded arm never counts toward
covering a case, because its condition can be false:

<Tabs syncKey="annotation-style">
<TabItem label="Inline">

```r
describe <- function(result: :Ok(integer) | :Err(character)) -> character {
  match (result) {
    :Ok(n) if (n > 100L) => "big"
    :Err(message) => message
  }
}
```

</TabItem>
<TabItem label="Comments">

```r
#: fn(result: :Ok(integer) | :Err(character)) -> character
describe <- function(result) {
  match (result) {
    :Ok(n) if (n > 100L) => "big"
    :Err(message) => message
  }
}
```

</TabItem>
</Tabs>

```text
non-exhaustive-match

  x this `match` does not handle `:Ok(_)`: add an arm for it, or a catch-all `_ => ...` arm
```

An arm that earlier arms already cover can never run, and ry warns about it:

```text
unreachable-pattern

  ! this arm is unreachable: the arms above it already match every value its pattern matches
    --[R/shapes.R:11:5]
 11 |     :Ok(_) => "never"
    |     ^^^^^^
```

ry checks coverage only when it knows the type of the matched value, and not while inline annotations
are turned off.

## Structural or nominal

Each of these types comes in two flavors, as [custom types](/type-checking/custom-types) explains:
`alias` names a *structural* type, which any value of the same shape fits, and `type` declares a
*nominal* one, which only its constructor `@Name(...)` creates. Choose nominal when values have the
same shape but must not mix, such as Celsius and Fahrenheit, or a user ID and an order ID, or when
every value should come from one constructor that checks it. The comment spellings are
`#: @alias Point {...}` and `#: @type Celsius {...}`:

<Tabs syncKey="annotation-style">
<TabItem label="Inline">

```r
type Celsius = Record{degrees: double}
type Fahrenheit = Record{degrees: double}
type Shape =
  | :Circle(radius: double)
  | :Square(side: double)

boiling <- function() -> Celsius @Celsius(degrees = 100,)

wrong: Fahrenheit <- boiling()
bare: Shape <- :Circle(radius = 1)
```

</TabItem>
<TabItem label="Comments">

```r
#: @type Celsius {Record{degrees: double}}

#: @type Fahrenheit {Record{degrees: double}}

#: @type Shape {
#:   | :Circle(radius: double)
#:   | :Square(side: double)
#: }

#: fn() -> Celsius
boiling <- function() {
  #: @new Celsius
  (degrees = 100,)
}

#: Fahrenheit
wrong <- boiling()
#: Shape
bare <- :Circle(radius = 1)
```

</TabItem>
</Tabs>

```text
type-mismatch

  x expected `Fahrenheit`, found `Celsius`

type-mismatch

  x expected `Shape`, found `:Circle(radius: double)`. The value has the right shape, but `Shape` is a nominal type, so only `@Shape(...)` or `#: @new Shape` creates one
```

The parentheses of `@Name(...)` belong to the value inside, so `@Celsius(degrees = 100,)` is a
one-field record, `@Pair(1L, "a")` a tuple, and `@Shape(:Circle(radius = 1))` a tag. Everything else
works as it does for the structural form: `$` reads a field, `match` checks every case of a nominal
union, a pattern binding keeps the nominal type, and a type can take parameters, as in
`type Tree<T> = :Leaf | :Node(left: Tree<T>, value: T, right: Tree<T>)`. At run time `@Name(x)` is
just `x`.

## Passing them to R

R functions and C code do not know these values, so passing one to an R function is an error:

```r
point <- (x = 1, y = 2)
sum(point)
```

```text
type-mismatch

  x `sum` is an R function, and this value is a ry record, not an R object. Convert it with `as.list()` first
```

A few R functions do accept them, such as `length()`, `print()`, `format()`, `identical()` and
`list()`, and so do the functions your own project defines. If the checker misses a case, the code
still stops when it runs, with the same fix in the message:

```text
Error in sum(point) :
  `point` is a ry record, not an R object; convert it with `as.list()`
Execution halted
```

Convert explicitly at the boundary: `as.list()` turns a record, tuple or tag into a list, and
`as.record()`, `as.tuple()` and `as.tag()` turn a list back.

## In the editor

- Hover on a tag, in a value or in a pattern, shows its payload type, and go-to-definition,
  references and rename follow a tag across the project. A tag spelled by the standard library, such
  as `:Ok`, is not renamed. Inside a pattern, completion offers the tags the matched value can still
  hold and the payload fields not yet named.
- Hover on a field name, in a literal or in a pattern, shows the field's type, and `$` completes only
  what the value really has. Inside a record literal, a tag's payload or an `@Name(...)` constructor,
  completion offers the fields the expected type still lacks, so
  `m: Record{amount: double, currency: character} <- (amount = 1, cu)` completes `currency`.
- Go-to-definition on a type name or a type parameter such as `T` jumps to its definition, and a type
  parameter renames within its definition or function.
- A type error points at the one field or item that is wrong, and a pattern that can never match
  points at the misspelled field or tag.
- Semantic highlighting colors type names, type parameters, tags, the `match` keyword and `=>`, in
  inline annotations, `#:` comments and `.Rtypes` stub files alike. An inlay hint is left out where
  the code already spells the type, as with a payload-free tag or an `@Name(...)` constructor.

## The standard library

The [standard library](/reference/standard-library/) is built on these values. Its functions return
`:Ok(value)` or `:Err(:Reason)` where R would return `NA` or warn, so `match` handles both cases:

```r
match (List.first(xs)) {
  :Ok(x) => x
  :Err(:ListWasEmpty) => 0L
}
```

It also adds `Dict` and `Set`, a dictionary and a set with value semantics, and `Result<T, E>`, the
type of those results, which every annotation can use.

## Instead of S4, R6 and Reference Classes

S4, R6 and Reference Classes keep working, but each class definition gets an `object-system`
warning that recommends records and tags. To forbid them in a project, set
`[check] object-systems = false` in [`ry.toml`](/reference/configuration#object-systems).
