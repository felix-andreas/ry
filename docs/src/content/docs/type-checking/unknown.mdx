R has constructs no static checker can follow, such as data frame columns and S4 and R6 objects.
Their values are `Unknown`, which is compatible with everything. ry would rather skip a check than
report something false, so one unmodeled construct never causes a cascade of errors.

The cost is that a clean run does not say how much was checked.
[Strict mode](/type-checking/strict-mode) reports the places a value became `Unknown`, with the
exceptions listed under its [known gaps](/type-checking/strict-mode#known-gaps).

## Giving a value a type

An annotation gives an `Unknown` value a type, so every later use is checked against it:

<Tabs syncKey="annotation-style">
<TabItem label="Comments">

```r
#: double
amount <- df$amount
```

</TabItem>
<TabItem label="Inline">

```r
amount: double <- df$amount
```

</TabItem>
</Tabs>

## Overriding inference

A plain annotation is checked against the value. Two forms give a type without that check, and
inline they go between a binding's `:` and its type, as in `amount: @if-unknown double <- df$amount`.

`#: @if-unknown TYPE` types an `Unknown` value, such as a data frame column, and becomes an error
once ry can infer the type, so it never goes stale:

```r
#: @if-unknown double
amount <- df$amount

#: @if-unknown double
n <- 1.5
```

```text
type-mismatch

  x `@if-unknown` applies only where the type is unknown, and this is already `double`. Drop the annotation, or use `#:` to check the type or `@trust` to override it
```

A value declared `Any`, such as the result of `readRDS()`, takes a plain annotation instead.
`#: @trust TYPE` overrides a type ry did infer, for the cases where you know better.

## `Any`

`Any` is also compatible with everything, but it is a deliberate choice rather than a gap. A value
declared `Any`, file reads such as `readRDS()`, `eval()`, and calls to S3 generics that dispatch
through `UseMethod()` are `Any`, and strict mode does not report them.

## Data frames

`data.frame()` returns a `data.frame`, but a base data frame's columns are not typed, so
`df$amount` is `Unknown`. An annotation such as `df: data.frame` checks that a data frame arrives,
but not which columns it has. ry's built-in [`DataFrame`](/type-checking/dataframes) is the typed
alternative, with every column, query and join checked. For analysis code this is the gap that
matters most, and a column read such as `df$amount` is usually the first place strict mode reports.
