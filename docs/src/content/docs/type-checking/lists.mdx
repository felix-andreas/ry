An R vector bends to fit: `c(1, "a")` quietly becomes a character vector, `c(1, 2) + c(1, 2, 3, 4)`
recycles, and any element may be `NA`. ry's `List` does none of that. You write one as `[1.5, 2, 3]`,
its type is `List<F64>`, and the checker holds it to one item type with no missing values, no names
and no recycling:

<Tabs syncKey="annotation-style">
<TabItem label="Inline">

```r
average <- function(xs: List<F64>) -> F64 List.sum(xs) / Num.to_f64(List.len(xs))

average([1.5, 2, 3])
average(c(1, 2, 3))
```

</TabItem>
<TabItem label="Comments">

```r
#: fn(xs: List<F64>) -> F64
average <- function(xs) List.sum(xs) / Num.to_f64(List.len(xs))

average([1.5, 2, 3])
average(c(1, 2, 3))
```

</TabItem>
</Tabs>

```text ry check typing
type-mismatch

  x expected `List<F64>`, found `double[]`. Convert an R vector with `List.from_r()`
```

The `[...]` literal is ry syntax, so it has one spelling, and the type is written `List<F64>` in both
annotation styles. A list's item type comes from its first item: `[1, 2, 3]` is a `List<I64>`,
`["a", "b"]` is a `List<Str>`, and `[(x = 1, y = 2)]` is a list of records. The
[standard library](/reference/std/list/) works on lists with functions such as `List.map`,
`List.walk` and `List.sum`.

## The rules

Every item has the same type, and items are never converted into each other:

```r
prices <- [12.5, "free", 20]
```

```text ry check typing
type-mismatch

  x this item is `Str`, but the list's first item is `F64`. A `List`'s items share one type and are never converted into each other
```

An item is a number, a `Bool`, a `Str`, or another ry value: a record, tuple, tag, `Dict`, `Set` or
list. So `[[1, 2], [3]]` is a `List<List<I64>>`.

A list holds no missing values. Model a value that may be missing with a tag:

```r
readings <- [1.5, NA, 3]
```

```text ry check typing
type-mismatch

  x a `List` holds no missing values. Mark an item that may be missing with a tag instead, as in `[:Some(1), :None]`
```

Operators work item by item on two lists of the same length, or on a list and a single value. Both
sides need the same number type, so an `I64` list does not mix with a fraction:

```r
counts <- [1, 2, 3]
scaled <- counts * 1.5
```

```text ry check typing
type-mismatch

  x this literal does not fit `I64`, which cannot hold its value exactly
```

Arithmetic gives a list of the same item type, a comparison gives a `List<Bool>`, and `&`, `|` and
`!` need `Bool` items. When the program runs, lists of different lengths are an error rather than
recycled:

```r ry run runtime=ry strict
[1, 2, 3] + [10, 20, 30]
#> [11, 22, 33]
```

## Indexing

`xs[[i]]` is one item, typed as the item type. `xs[i]` is a list again, selected by positions or by a
`Bool` mask such as `xs[xs > 1]`. A position outside the list is an error when the code runs, never
an `NA`.

## Lists and R code

A `List<F64>`, `List<Bool>` or `List<Str>` is stored as the R vector it looks like, so it passes
wherever R expects a `double`, `logical` or `character` vector, and `sum(prices)` works on a list of
prices. Other lists cross the boundary through an explicit conversion:

```r ry run runtime=ry strict
xs <- List.from_r(c(1, 2, 3))
List.map(xs, function(x) x * 2)
#> [2, 4, 6]
List.to_r([3i64, 1i64])
#> [1] 3 1
```

`List.from_r()` refuses a vector with an `NA` or a class, and drops names. The typing contract is
the reference section [Lists](/reference/type-system/#lists).
