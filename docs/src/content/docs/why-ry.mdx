R reports most mistakes only when a line runs: a misspelled name, a string where a number belongs,
a `NULL` nobody handled. That was tolerable while people wrote and read every line. Now agents
change R code bases that are years old, and code an agent writes needs to be checked by something
other than a person reading it. R has no type checker, so ry adds one, and it works today on the R
code you already have.

ry is one tool for R: it checks, formats, loads and runs your code, configured by one `ry.toml`.
Its type system sits on top of R, so plain R stays valid. It also adds what R lacks: records,
tagged unions, a typed table called `DataFrame` with a Polars-style API, and a standard library.
Everything ry runs, plain R plus these additions, is what we call R++. Strict mode then keeps only
code whose types are known, which we call R--.

## Speed

On ry's own runtime, loops and vector code run several times faster than on GNU R, with the same
results:

| program | GNU R, untyped | ry, untyped | ry, typed and strict | ry vs GNU R |
| --- | ---: | ---: | ---: | ---: |
| closures | 0.818 s | 0.395 s | 0.397 s | 2.1x |
| drawdown | 0.314 s | 0.024 s | 0.023 s | 13.1x |
| fib | 0.080 s | 0.094 s | 0.109 s | 0.9x |
| log_rank | 0.101 s | 0.073 s | 0.062 s | 1.4x |
| loop_sum | 0.265 s | 0.042 s | 0.040 s | 6.3x |
| vasicek | 0.042 s | 0.041 s | 0.039 s | 1.0x |
| vector_arith | 0.176 s | 0.140 s | 0.135 s | 1.3x |

Code dominated by small function calls (`fib`) is still about 10% slower, and `vasicek` is at
parity. Types do not make code faster yet: a static `double` still admits an integer or a logical
through promotion, so the compiled code keeps its runtime checks, and the differences between the
two ry columns are measurement noise. The runtime is still incomplete (see [Status](#status)), and
[How it was measured](#how-it-was-measured) describes the benchmark.

## From plain R to fully typed code in four steps

In the diagram above, your code moves from the blue circle toward the purple one, one step at a
time. Each step is
optional, and you can stop after any of them, so you can adopt ry on a large code base without a
rewrite. Steps 1 and 2 work with GNU R as it is. Steps 3 and 4 use what ry adds, and ry's own data
types run only on ry's runtime, which is still incomplete (see [Status](#status)).

### 1. Check the code you have

Run `ry check` in a project, with no configuration and nothing to annotate. It reads the source
without running it, so it reports mistakes that R reports only when the line runs:

```r
# R/pricing.R
net_price <- function(price, rate) {
  price * (1 - ratee)
}
```

```text
unresolved

  ! I could not resolve `ratee` in this package, its imports, or builtins. Did you mean `rate`?
   --[R/pricing.R:2:16]
 1 | net_price <- function(price, rate) {
 2 |   price * (1 - ratee)
   |                ^^^^^
 3 | }
```

The same analysis drives [your editor](/guides/editors). `ry fmt` formats the project, and
`ry run`, started inside a package, [reloads what you edit](/guides/loading-packages) before each
command, so you never call `load_all()` again.

### 2. Type your code

Set `typing = true` under `[check]` in `ry.toml`, and ry reports type errors. It infers types from
how values are used, and a `#:` comment states the type where you want it fixed:

```r
#: fn(price: double, rate: double) -> double
net_price <- function(price, rate) {
  price * (1 - rate)
}

net_price(100, "0.2")
```

```text
type-mismatch

  x expected `double`, found `character`
   --[R/pricing.R:6:16]
 5 |
 6 | net_price(100, "0.2")
   |                ^^^^^
```

The file is still plain R, so GNU R, `Rscript`, RStudio and every other R tool run it unchanged. If
you want files that every R tool can run without ry, this is where you stop.

### 3. Switch to inline types

Inline annotations write the same types in the code itself, and the checker reports the same
`type-mismatch` for `net_price(100, "0.2")`. They also check at run time, which matters for a value
whose type only shows up when the script runs:

```r
net_price <- function(price: double, rate: double) -> double {
  price * (1 - rate)
}

rate <- eval(parse(text = '"0.2"'))
net_price(100, rate)
```

On ry's runtime, the call fails at the boundary and names the argument:

```text
$ ry run pricing.R
Error in net_price(100, rate) :
  argument `rate` must be `double`, not `character`
Execution halted
```

`ry R pricing.R` runs the file on GNU R with the annotations erased, and there it fails later, inside
the body: `Error in 1 - rate : non-numeric argument to binary operator`. Plain `Rscript` cannot
parse the annotations, so a file with inline types needs ry.

### 4. Go fully typed

A field read from an R6 object, or from a list built at run time, has a type the checker cannot
see. ry's own data types have one. [Records, tuples and tagged unions](/type-checking/records-and-tags)
come with a `match` that knows every case, [`DataFrame`](/type-checking/dataframes) is a table whose
columns the checker follows through every query, and the
[standard library](/reference/standard-library) returns `Result`, `List` and `Dict` values instead
of `NA` or a warning:

```r
alias Payment =
  | :Paid(amount: double)
  | :Refunded(amount: double)
  | :Pending

balance <- function(payment: Payment) -> double {
  match (payment) {
    :Paid(amount = a) => a
    :Refunded(amount = a) => -a
  }
}
```

```text
non-exhaustive-match

  x this `match` does not handle `:Pending`: add an arm for it, or a catch-all `_ => ...` arm
   --[R/payments.R:4:3]
 3 | balance <- function(payment: Payment) -> double {
 4 |   match (payment) {
   |   ^^^^^^^^^^^^^^^
```

[Strict mode](/type-checking/strict-mode) (`strict = true`, kept beside `typing = true`) finishes the move: a value ry cannot
type, or a parameter nothing constrains, is an error, and ry's run commands (`ry run`, `ry R`, `ry load` and the console) refuse to run code that has
one.
`object-systems = false` additionally rejects new S4, R6 and Reference Classes:

```text
strict

  x strict mode: parameter `x` has no type. How the function uses it does not determine one, so any value is accepted unchecked. Annotate it, as in `x: TYPE`

object-system

  x R6 classes are turned off in this project (`[check] object-systems = false`), so `R6Class` cannot define an R6 class. Use a record or a tagged union instead
```

## What it leaves out

Every rule in the type system has to be cheap enough to run on each keystroke, so some things are
left out on purpose:

- **Several signatures for one of your functions.** That would turn every call into a search. A
  parameter can accept either of two types instead, written `integer | character`.
- **Inheritance.** One type extending another makes inference slow and its results hard to predict.
  [Custom types](/type-checking/custom-types) keep values apart without it.

Some things it cannot model yet. S4 and R6 objects and data frame columns get a type that is
compatible with everything, so they never cause a false error, but they are not checked either.
Strict mode shows most of the places where that happens, and [limitations](/type-checking/limitations) lists the rest.

## Status

ry is in beta. The checker, language server, formatter and loader are ready for daily use, and
diagnostic codes, `ry.toml` keys and the JSON output are stable, so CI built on them keeps working.
The type system is still growing, so a new release can report findings an older one did not, which
is why CI should pin the version.

ry's own runtime is under construction. It still reads base R from your GNU R installation, and a
script that uses something it lacks stops with an error that names it. Records, tagged unions, `DataFrame` and
the standard library run only on it, so for production work today, run plain R and typed R on GNU R
with `ry R`.

## How it was measured

ry's runtime (`ry run`) interprets R and compiles hot code to machine code. Each
program exists twice in `tools/bench/why/`: as plain R, and with inline annotations checked in
[strict mode](/type-checking/strict-mode). Each time is the best of three runs after one warm-up
run, measured inside the script, so it leaves out startup and, for the typed column, the static
check. The best run is reported rather than the median because other load on a machine only ever
slows a run down. Measured on an Intel Xeon at 2.10GHz with 4 cores, Linux 6.18, against GNU R
4.3.3 with its bytecode compiler on. `just bench-why` builds ry and regenerates the table on your
machine.
