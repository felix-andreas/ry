R reports most mistakes only when a line runs: a misspelled name, a string where a number belongs, a
`NULL` nobody handled. Agents now change R code that no person reads line by line, so ry checks it
before it runs, and its own runtime runs it faster.

Code that spends its time in R itself gains the most, while vectorized builtins already run in C on
GNU R. [Benchmarks](/benchmarks) has the code and the method.

## From plain R to fully typed code

</figure>

Each step moves your code further right in the diagram, and you can stop after any of them. Steps 1
and 2 keep plain R that GNU R runs, while steps 3 and 4 need ry.

### 1. Check the code you have

`ry check` needs no configuration and no annotations.

```r
net_price <- function(price, rate) {
  price * (1 - ratee)
}
```

```text ry check
unresolved
  ! I could not resolve `ratee` in this package, its imports, or builtins. Did you mean `rate`?
```

### 2. Type your code

With `typing = true` under `[check]` in `ry.toml`, a `#:` comment fixes a type, and the file stays
plain R.

```r
#: fn(price: double, rate: double) -> double
net_price <- function(price, rate) {
  price * (1 - rate)
}

net_price(100, "0.2")
```

```text ry check typing
type-mismatch
  x expected `double`, found `character`
```

### 3. Switch to inline types

Inline types are also checked at run time, for values whose type shows only then.

```r
net_price <- function(price: double, rate: double) -> double {
  price * (1 - rate)
}

rate <- eval(parse(text = '"0.2"'))
net_price(100, rate)
```

```text ry run runtime=ry
Error in net_price(100, rate) :
  argument `rate` must be `double`, not `character`
```

### 4. Go fully typed

[Records and tagged unions](/type-checking/records-and-tags), [`DataFrame`](/guides/dataframes#types)
and the [standard library](/reference/standard-library) give the checker types that R6 objects and
lists built at run time lack. [Strict mode](/type-checking/strict-mode) then rejects any value it
cannot type.

```r
log_line <- function(message) cat(message, "\n")
```

```text ry check typing strict
strict
  x strict mode: parameter `message` has no type. How the function uses it does not determine one, so any value is accepted unchecked. Annotate it, as in `message: TYPE`
```

## What it leaves out

- **Several signatures for one function**, because every call would become a search. Write
  `integer | character` instead.
- **Inheritance**, because it makes inference slow and hard to predict.
  [Custom types](/type-checking/custom-types) keep values apart without it.

S4 and R6 objects and data frame columns are not checked yet.
[Limitations](/type-checking/unknown#limitations) lists the gaps.

## Status

ry is in beta. The checker, language server, formatter and loader are ready for daily use, and
diagnostic codes, `ry.toml` keys and the JSON output are stable.

ry's runtime is incomplete, and records, tagged unions, `DataFrame` and the standard library run
only on it. For production work, run plain and typed R on GNU R with `ry R`.
