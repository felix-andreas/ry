Functions over R lists, typed `list[T]`, and over [Arrays](/type-checking/arrays/). Each function
also takes an `Array<T>` as its collection (the `list`, `first` or `lists` argument) and then
returns an Array where it would return a list, so `List.map([1, 2, 3], \(x) x * 2)` is the
`Array<double>` `[2, 4, 6]`. An item argument does not count, so `List.append(list([1]), [2])` is
the list `list([1], [2])`, and `List.single` and `List.repeat` always return lists. A function
whose result items come from a callback, such as `List.map`, requires them to be Array items (the
[`item` constraint](/reference/type-system/#constraints)), so `List.map([1, 2], \(x) list(x))` is
a type error.

</TabItem>
<TabItem label="Comments">

```r
#: fn(start: integer, end: integer) -> list[integer]

```

</TabItem>
</Tabs>

The integers from `start` up to and including `end`, or an empty list when `end` is smaller.
Unlike R's `:`, it never counts down.

Both `List.range` and `List.repeat` stop with an error when the list would hold more than
2,147,483,647 elements, the longest vector an R integer index reaches.

```r ry run runtime=ry dput
List.range(2L, 5L)
#> list(2L, 3L, 4L, 5L)
List.range(3L, 1L)
#> list()
```
