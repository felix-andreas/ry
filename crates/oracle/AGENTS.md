# oracle

Read this before you change the differential test harness against GNU R. Cross-cutting traps live in `.agents/memory/MEMORY.md`.

## Traps

- **The oracle stops a case at its first top-level error**, so compare behavior under `options(error = ...)` against `Rscript` directly.
- **GNU R's answer to `NaN op NA` is not portable.** `real_binary` is the same source in 4.3.3 and 4.6, but the C compiler may commute `+` and `*`, so on the AST interpreter (a closure's first, uncompiled call) the 4.6.2 build gives NA for `NaN + NA_integer_` where compiled code and the 4.3.3 build give NaN. `NA_real_` does not avoid it. An oracle case about NaN and NA order compiles its closures with `compiler::cmpfun` before the first call (`crates/oracle/cases/builtins__nan_na_order.R`).
- **A forced oracle against a GNU R other than the one in `crates/oracle/cases/gnu-r.txt` checks less.** ry then runs that release's base R, so the run cannot catch a release-gated gap, and a library that ry installed says it was built under 4.6.2, so every `library()` warns under an older GNU R.
- **Run `oracle compare`, `oracle record` and `oracle packages` with `R_LIBS` naming only `.corpus/library`, and with an absolute `ORACLE_RY`.** GNU R's side inherits `R_LIBS`, so `.corpus/ry-library` ahead of it makes GNU R load ry-built shared objects and fail with "undefined symbol: PREXPR".
- **A corpus library must hold every package itself.** GNU R skips a dependency its own `.Library` holds, and the reference R ships about 50 non-priority packages there (testthat among them), which ry's runtime cannot see; without the copy step in `tools/corpus/install.R`, most top-package suites fail under ry for want of testthat.
- **A corpus package that crashes under GNU R 4.6 too is usually snapshot C code calling a pointer-returning function older R headers declared and R 4.6's do not by default** (`ATTRIB`, `ENCLOS`, `CLOENV`, `Rf_findVar`, `Rf_findVarInFrame`; some have a prototype only under `ENABLE_LEGACY_NONAPI`, some none at all): gcc 13 only warns, and the implicit `int` return truncates the pointer. `Built: R 4.6.2` does not rule it out, because Posit lacks binaries for many packages and `install.R` compiles their snapshot sources. `install.R` reinstalls every package whose shared object imports such a function from the newest CRAN source; functions whose legacy prototype returns `int` or `void` (`OBJECT`, `SET_ATTRIB`) are harmless and skipped. A newest source that needs a newer dependency than the snapshot (spatstat.random) stays broken and is named in `logs/install.log`.
- **Every path into the cargo target directory goes through `oracle::target_directory`.** The nested build follows `CARGO_TARGET_DIR`, so a hardcoded `../../target` finds a stale or missing `ry` and `libR.so` in a checkout that sets it.
- **`ry_matches_recorded_outcomes` passes when base R is not built**, saying so only on standard error, which cargo hides for a passing test. `ORACLE_ENGINE` turns that skip into a failure, so use it when the run must prove something.
