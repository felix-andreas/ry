# interp

Read this before you change the R interpreter. Cross-cutting traps live in `.agents/memory/MEMORY.md`.

## Traps

- **A fast path that reads vector storage directly must refuse a vector with `flag_bits::ARRAY`**, or it skips the strict checks in `arrays.rs`. `duplicate` drops the flag (re-flag with `arrays::finish`), and `finish_result` copies a shared constant.
- **gp bit 12 is `TYPED_DEFINITION` on a formals list or body and `CHECKED_PROMISE` on a promise.** `annotations::leave` runs at every closure exit, error or not, or a pending annotation check outlives its frame.
- **Start-up state the environment can change is re-derived in `interp::session::start_from_image`**, since the image is written once in an emptied environment (`image::LOADING_VARIABLES`, `image::save_state`). Run `just start-image` after editing runtime R sources (`development/architecture.md`, "The start-up image").
- **Start-up and code images are keyed by build**, so builds sharing a base R tree coexist and a build's first start writes its own. `RY_IMAGE_LOG=1` names each skipped image, and `bench.py` fails a timed process that reports one.
- **`read_renviron` (`interp::session`) appends GNU R's user and site libraries to an unset `R_LIBS_USER`/`R_LIBS_SITE`**, skipping any that holds `base`, which would shadow ry's base packages (`reference/cli.md`, "How ry finds R").
- **`Sys.getenv`, `Sys.setenv` and `Sys.unsetenv` read `environ` once per call; never keep a private copy.** Writes go through libc so C code sees them (`.agents/memory/decisions/builtins.md`, "Environment variable calls read `environ` once").
- **Read a closure's body through `bytecode::closure_body`, never `function.cdr()`**: a body that ran twice is replaced by its compiled `BCODESXP` (`.agents/memory/decisions/jit-ssa.md`, "Closures over one body expression share its compiled code").
- **`NULL` is a valid closure body** (`function(e) NULL`), so a table keyed by a body or any other R value never marks a free slot with `NULL`: a live entry for a `NULL` body would look free, be skipped by `clear_dead`, and hand freed code to the next such closure. The shared-body table (`Bodies` in `bytecode.rs`) marks a free entry by its code instead (oracle case `bytecode__null_body_shared_code_freed`).
- **A tier-0 fast path makes no calls, and the generic handlers and `jump` stay `#[inline(never)]`** (`bytecode.rs`). Any call makes the handler save registers on every instruction. Use `Heap::try_alloc_scalar`, `become` the generic handler, and check with `objdump -d` that the handler starts without `push`. The call and return handlers do make calls, and there a rare branch still costs the common one: with the by-name caller's tests in `call_fast` and the pending-environment discard in `return_fast`, a call from slots ran about 20 instructions longer although neither branch was taken. Each rarer variant is therefore compiled apart (`call_fast::<BY_NAME>`, `return_fast::<DISCARD>`) and reached by `become` from the common handler (`call_generic_by_name`, `return_discarding`); measure a change to either with `just bench-mechanisms --filter call:` on the rows it should not touch.
- **A quickened opcode is visible only to tier 0's dispatch**: every other reader of code words goes through `op_of`, never a comparison with `op_word`.
- **A native port of a package function sits behind a hash-guarded prologue and declines whatever its R body could observe that the port does not model.** A new one is a zero-argument `.Internal` marked `BuiltinDef::prologue`, with an oracle case against the R body (`.agents/memory/decisions/builtins.md`, "Package code that dominates a workload runs natively: rlang's trace_back").
- **A prologue may port only the head of a body**: it binds what the body has bound at that point and runs the body's remaining statements, copied verbatim into the prologue so they compile (`validObject` in `methods_core.R`). `new()` copies the prototype shallowly and `R_do_new_object` deeply, because C code may write into a slot without checking (`.agents/memory/decisions/builtins.md`, "`validObject` runs validity methods without its slot loop, and `new()` copies the prototype shallowly").
- **A condition prologue keeps every frame of the R chain it replaces.** Oracle cases pin the frames `tryCatch` leaves (`sys.calls()`, `sys.function()` and each frame's bindings: `conditions__try_catch_fast_path`, `conditions__rlang_trace_back`), so `tryCatch`, `tryCatchList`, `tryCatchOne` and `doTryCatch` all stay closure calls. The prologues save the R statements around the calls and pass values that already exist as forced promises (`eval::apply_closure`, `base_fast_paths.rs`).
- **An S3 method name resolves in one frame read unless its symbol has `gp::BOUND_ELSEWHERE`** (`lookup_in_scope`, `dispatch.rs`). The sticky bit is set when any attached frame other than base binds the symbol, so without it only the methods table and base can hold the method. Under `enable_invariants()` each fast resolution is checked against the full scope walk, except through an active binding, whose every read is a new value (`fuzz_s3_method_lookups_agree_with_a_full_walk`).
- **A methods-package fast path is exact or invisible** (`methods_core.rs`): it reads arguments only through `quiet_value` and bails before any effect R code could observe. `RY_PRINT_FAST_PATH_HASHES=1` prints the `FAST_PATHS` hashes after a GNU R upgrade.
- **The methods package's R code relies on native quirks** (`methods.rs`): `R_set_slot` modifies in place, `.allowPrimitiveMethods(FALSE)` must turn primitive dispatch off or selection recurses, and an argument is `"missing"` only when its own binding is missing.
- **S4 methods are rewritten at install time (a `.local` wrapper in the lazy-load database)**, so a fix to what `setMethod` runs needs the package reinstalled (`oracle install <pkg>`). `length<-` returns the object itself when the length is unchanged, because `conformMethod` compares with `identical`.
- **`missing()` counts a defaulted formal as missing only in its own function**, as GNU R's `R_isMissing` does (`eval::is_missing`); methods' `registerNames` depends on it.
- **`ry run` and the console parse the whole input but lower each top-level expression just before it runs**, because `options(keep.source = TRUE)` affects the expressions after it (`interp::session`).
- **A slot frame's variable is in its slot or in a binding cell, never both** (`.agents/memory/decisions/interp.md`, "A slot frame's environment binds a variable only when a lookup asks for it"; `development/design/slot-frames.md`). Get a frame's environment only through `eval::frame_env`, `eval::frame_sys_parent` or `Call::env`; what they return may bind nothing yet, so read a frame's variables through the heap's lookups (which ask the frame for a missing name) or `eval::slot_binding`, never by walking `Frame` bindings of an environment flagged `gp::SLOT_FRAME`.
- **Recheck the frame before writing a slot.** Code that updates a slot frame's variable in its slot (`replace_variable`, `assign_slot_element`, `ElementCalls` in `envir.rs`) and first runs anything that can ask for the frame (forcing a promise, a function lookup, a callee) must test the frame's environment again afterwards (`*state.header != nil()`, `interp().frames[frame].env`), because the variable may have moved to a cell and a slot write would be lost. A builtin's direct entry (`eval::call_direct`) must behave the same under a profile as without one, or measuring changes which path runs.
- **An argument forwarded through `...` is the caller's own promise**, where GNU R wraps it in a new promise whose value then counts two references. So a write to a variable bound to a promise must also treat a shared promise as sharing its value (`eval::complex_assign`), or `..1` reads the callee's change. Every tier treats a value read through a promise as the caller's: tier 0 copies it on the first element assignment (`through_promise` in `bytecode.rs`), and compiled code gives such a load, and any value a caller passes an inlined call, the `ENCLOSING` status (`jit::analysis::status`, `bytecode::load_variable`, `jit_probe`), so its first element store copies.
- **An argument reference is reused once its call returns**, so code that keeps an argument past the call, or hands a frame's arguments on as promises, detaches it first (`eval::materialize_references`, `detach_reference`). `Interp::pending_closures` stays ordered by frame: insert through `eval::slot_closure` only.
- **`R_PreserveObject` holds without counting a reference**, so a test that an object dies with its frame (`refcount() == 1` on a promise or closure the frame holds) must also ask the header's preserved flag (`Heap::is_preserved`, `Heap::frame_alone_holds`). Native code that preserved a promise it read from a running call forces it after the call returned; `native_code_forces_a_kept_promise_after_its_slot_frame_returned` in `crates/libr/tests/test_fuzz_native.rs` pins it.
- **`sys.call()` and `sys.calls()` copy only a frame's call cells** (`envir::call_with_srcref`): `do.call` puts values into the call, and data.table's `cedta()` runs `sys.calls()` on every `[`. `test_call_stack.rs` counts allocations.
- **A text output connection's target vector is shared with its binding**, so `push_text_line` copies when `maybe_shared` and `textConnectionValue` returns a copy (`connections.rs`).
- **`perl = TRUE` patterns go through `crates/interp/src/pcre.rs`, never the `pcre2` crate's `Regex`**, which revalidates the subject on every match and makes a global `gsub` quadratic.
- **A behavior GNU R changed between releases is gated on the emulated release** (`interp::system::r_at_least`, or `r_at_least_release` for a patch release), because ry runs whichever base R its home holds. NEWS omits most message changes, so find the release in the r-source tags (`raw.githubusercontent.com/wch/r-source/tags/R-4-5-0/src/main/...`).
- **The base-closure fast paths install only on GNU R 4.6.2's code**, because each prologue is guarded by a hash of the R body it replaces. A home that holds another release's base R leaves most of them out, so a container with GNU R 4.3.3 as its reference never runs them against GNU R: check them with a GNU R 4.6.2 as `ORACLE_R` and a library that release installed as `R_LIBS`.
- **An OpenBLAS result can depend on its buffer's address modulo 16**, so every BLAS and LAPACK buffer in `linalg.rs` goes through `Placed`. Reproduce with `OPENBLAS_CORETYPE=Zen` (`.agents/memory/decisions/builtins.md`, "Base R's linear algebra").
- **BLAS and LAPACK are found by soname, then through GNU R's `etc/Makeconf`, then as ry's reference copies** (`library_candidates`, `linalg.rs`), which `open_reference_blas` opens `RTLD_LOCAL` before the first package `dlopen` so a package's `NEEDED libRblas.so` resolves without interposing.
- **Console socket requests run on the interpreter thread only** (`interp::console_server`): readers queue, `poll_interrupt` drains, and anything that evaluates R is refused as busy while a command runs. `browser()` drives the same `debugger::Adapter`.
- **An `interp` test runs its body inside `interp::testing::with_interpreter`**, which takes the lock on the process-global interpreter. A symbol's name is `symbol.car().bytes()`, not `Sexp::bytes()` on the symbol.
- **A session that sources a user profile never loads the start-up image**, so a test about start-up points `HOME` and the working directory away from any `.Rprofile` (`test_start_image.rs`).
- **Tell a prologue difference from a kernel difference by stripping the prologue** (`body(f) <- body(f)[[3]]`) and running ry again. Writing a prologue's oracle case is often how a kernel bug surfaces.
- **Fill a fresh list or character vector through its slice, then count once** (`slice_mut::<Sexp>()`, then `crate::heap().count_written_elements(result)`). `values::set_elt` per element pays a refcount store and a write barrier each, which made `as.character`, `matrix` and `strsplit`-style builders several times slower than GNU R.
- **A test that links `frames` belongs in `crates/frames/tests`.** In `interp/tests` it links Polars into the test binary, which makes it 1.2 GB and doubles the build after an edit.
- **Do not merge interp's test binaries into one.** The interpreter is one per process, so merged tests would share its state and run one at a time behind its lock.
