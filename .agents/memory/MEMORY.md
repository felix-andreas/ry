# Memory

Cross-session knowledge base for the agents building ry, in three horizons. **Short-term** holds the current focus, so prune an item once it is resolved. **Mid-term** holds active priorities and debt. **Long-term** holds durable, non-obvious traps and their rationale. Every entry is context-free and timeless, and points at code or docs instead of restating them.

`.agents/orchestrator.md` is the brief for the orchestrating session only, and every other agent ignores it. The companion files are `backlog.md` (open work, plus a one-line shipped ledger at the bottom), `decisions.md` (settled decisions and why), `test-user-reports.md` (closed simulated-user findings), and `worklog.md` (chronological, appended by a routine). The specs live in the docs site: `reference/type-system.mdx` is the typing contract, the four `tutorial/` pages introduce it, and `development/{index,architecture,structure,testing,authoring-stubs}.md` cover the internals. Unsettled design work goes to `docs/…/development/design/` (out of the sidebar, listed on its index page), never here.

## Short-term

- **The typed runtime is designed and next to build** (`development/design/typed-runtime.md`, `decisions.md` "Typed values are native, immutable, acyclic and freed by reference counts" and "Typed code compiles ahead of time"). The build starts with native `List`, `Str` and `Dict` and ahead-of-time compilation of the typed benchmark programs, with the typed calling convention behind one narrow seam to the untyped call path.
- **Docs pages follow the writing rules in `AGENTS.md`, and a page that reads like a telegram is as much a regression as dense prose.** Read a page aloud when you edit it, and keep a reason inside its sentence rather than splitting it off. Before rewriting a page, run an adversarial reader subagent with the owner's objections as the rubric (too abstract, information the reader does not need, a term used before it is introduced, copy about the tool instead of what the reader gets).
- **A new em-dash in a diagnostic or a comment is a regression.** Two survive on purpose as test data (`literate.rs`, `test_cli.rs`), and `worklog.md` keeps its original wording.
- **Validate a docs link against the ids in the built HTML** (`docs/dist/**/index.html` after `cd docs && bun run build`), never against a hand-rolled slug, because two headings that differ only in punctuation slug to the same id and the second silently becomes `-1`.
- **User pages are snippets with real output, not prose** (user feedback: the earlier docs read as walls of text, "cringe", with no clear concept). `getting-started.mdx` is a four-row step table, then one example per step and the benchmark table; each tutorial page opens with its goal and ends with "You can now" and a Next link. Typed examples have up to three tabs, Untyped, Comments and Inline (user direction): Untyped first, then Comments on `tutorial/types.mdx` and Inline on the rest; tabs sync by label, so the order is per page. An example drops Untyped when its plain R would not be R (ry-only syntax) or its subject is an annotation itself (signatures, definitions, the reference pages), and a tab whose output differs holds its own output block (`development/index.md`). Tagged unions in examples go one variant per line with a leading `|` (user preference), which `ry fmt` keeps. R lists are "fixed-shape" and "any length", so "record" and "tuple" name only ry's own types.


## Mid-term

- **Scope (user directive): ry becomes a full, backwards-compatible reimplementation of R, extended with ry's typing.** `AGENTS.md` ("Goals" and "Process") holds the mandate, the benchmark dependency set, and the process rules. The top priority is designing the R C API layer (`SEXP`, memory protection, `.Call`), because most benchmark dependencies ship compiled code against it, so it constrains the architecture more than the JIT does. Inline annotations, the comment-agreement warning and strict mode's untyped-parameter rule have shipped (`decisions.md`, "How inline annotations are built"), and so has lazy package loading (`ry load` on ry's own runtime by default, the `ry run` console on ry's runtime, the `ry R` console and plain-R `load_all()` on GNU R; `decisions.md`, "the package-development loader"; gaps in `backlog.md`, "Open: the package loader"). Then come the runtime, the typed table type that must outperform data.table, and a JIT on the level of Bun. Progress is measured on three synthetic code bases (finance, data science, biostatistics) of about 300,000 lines in about 500 files each.
- **Positioning (user direction; final framing is the agents' call, settled in `decisions.md` "positioning"):** the website and docs sell ry's use case plainly. One toolchain for R, plus a type system, plus runtime features beyond GNU R ("R++"); strict mode allows only those ("R--"), possibly drawn as a Venn diagram. The pitch shows a plain-R snippet, then a benchmark of GNU R against ry's JIT against ry with typed runtime features. ry may add runtime features such as stricter arrays for speed, provided they convert to normal R structures. The GNU R runtime keeps working with `#:` comments. The migration story has four steps, and the Tutorial has one page per step: (1) check the code you have, (2) type your code (both on GNU R or ry's runtime), (3) switch to the ry runtime (inline types plus ry's own features), (4) go fully typed. R++ features (custom types and records, tagged unions, `match`, `DataFrame`, the standard library) get their own section, clearly separate from classic R support. Target audience: legacy R code bases moving into the agentic age, where agent-written systems need the verification a type system provides.
- **Naming of ry's own types and APIs (user direction):** new-world types are UpperCamelCase (`DataFrame`, `Result`, `Dict`, `Set`, `List`, `Str`), which sets them apart from R's lowercase types. The table API is Polars-style, with qualified names such as `DataFrame.filter` used with `|>`. data.table syntax stays for compatibility with existing code only.
- **Inline annotations run end to end** (`decisions.md`, "inline annotations at run time"): ry's runtime checks parameter and return types at function boundaries, GNU R runs the erasure, and `ry run` and `ry R` print the annotation warnings and enforce strict mode first. `ry load` enforces strict mode on the package's `R/` files on both runtimes (`preflight::check_package`, through `cli::analyze_project`, the same project analysis `ry check` runs). Gaps are in `backlog.md`, "Open: the runtime".
- **Runtime status: the interpreter and the C API both exist, and base R is ry's own build of R 4.6.2.** `crates/interp` (evaluator, tier-0 bytecode, conditions, S3 and S4 dispatch, base internals in Rust) sits on `crates/heap` and links into `crates/libr` (`libR.so`, headers in `include/`), which covers the measured C API surface, ALTREP, connections, serialization, Rmath and the numerical routines, with BLAS and LAPACK header-only against the system libraries. `crates/rcmd` builds and installs packages with `R CMD INSTALL` semantics against ry's R home, and the interpreter plugs into libr through the `libr::eval::Evaluator` hook. `ry run script.R` runs a script on it (`ry R script.R` on GNU R), and the oracle's second engine is `ProcessEngine::ry`. The default packages' native routines are Rust (`builtin_libraries.rs`), filled in per package. Base R is built from GNU R's pinned source release by `just base-r` and embedded in `ry` (`decisions.md`, "ry ships its own base R"); `R_HOME` naming any GNU R 4.3 or later replaces it, and the runtime then emulates that version, with changed behavior gated by `interp::system::r_at_least`, or `r_at_least_release` for a change made in a patch release (`decisions.md`, "The runtime emulates the GNU R version it loads base R from"). The help system works as on GNU R, including the dynamic help server (`interp::help_server`, `decisions.md` "R's dynamic help server runs on the interpreter thread"). `decisions.md` ("the interpreter and base R", "the runtime's object model, collector and native boundary", "the full C API surface and package installation") has the settled shape; `backlog.md` ("Open: the runtime") the gaps.
- **Base R kernels are measured against GNU R with `just bench-base`** (`tools/bench/base`, `development/testing.md`). Sorting, subsetting, `match` and `%in%` on strings, `merge`, `rowSums`, `cumsum` and `as.character(double)` beat GNU R; the slower kernels are listed in `backlog.md`, "Open: base R kernels against GNU R". GNU R's and ry's `as.character(double)` both return a deferred vector, so time it forced (`nchar(as.character(x))`). Long double accumulation lives only in `crates/interp/src/long_double.rs`, and a kernel that makes millions of strings interns repeated pieces through a per-call `values::StringMemo` (`decisions.md`, "Base R kernels").
- **R's graphics engine runs on ry's runtime** (`crates/interp/src/graphics_engine.rs`, the C API in `crates/libr/src/graphics.rs`; `decisions.md`, "One graphics engine for base graphics, grid and device packages"). Base graphics, grid and device packages such as ragg all draw through one engine to `DevDesc` callbacks, and the built-in devices are `DevDesc`s too. The `grid__*` oracle cases (grid units and grobs, the display list, ragg and lattice pixel checksums) match GNU R exactly and need ragg and lattice in `.corpus/library`. ragg's, gtable's, xts's and PerformanceAnalytics' test suites pass under ry. The built-in devices support patterns, clipping paths, masks, groups and fill rules (pdf, svg, bitmaps), PostScript refuses them as GNU R's does, and knitr/rmarkdown vignettes with plots render (`graphics__knitr_figures`, `graphics__build_vignettes`), and rasters, `saturate` and padded patterns match GNU R (`graphics__raster_and_compositing`). The plot gallery (`crates/oracle/gallery`, 149 figures, `oracle gallery`; `decisions.md`, "Base graphics is checked against GNU R by a plot gallery") renders on both engines and the agg, png, pdf and svg devices; all 596 renders pass, and on agg no figure has a pixel off by more than antialiasing at any seed from 0 to 24 (140 of the 149 are identical). A console with VS Code attached sends each changed plot as svg to an "R Plot" panel (`decisions.md`, "The editor's plot panel is fed from the engine's display list"). Base graphics and grid render faster than GNU R; ggplot2, lattice and PerformanceAnalytics are 1.2 to 1.9 times slower because of interpreter call cost. Gaps: `backlog.md`, "Graphics gaps".
- **The standard library is measured against GNU R with `just bench-stdlib`** (`tools/bench/stdlib`, `development/testing.md`): one row per `List`, `Str`, `Dict` and `Result` function against its fastest base R, purrr, stringr or stringi equivalent, with checksums. `tools/bench/stdlib/results.md` holds the last full run. Callback functions (`List.map`, `keep_if`, `find_*`, the `Result` functions, `Dict.walk`, `Dict.insert`) beat R; the rows still slower and their causes are in `backlog.md`, "Open: standard library rows slower than GNU R", led by per-element `Str` calls against stringi's vectorized C and one-shot traversals that run their callback from tier 0.
- **Peak memory follows GNU R's on its collection schedule.** The heap has one limit on all its bytes, moved with GNU R's `AdjustHeapSize` fractions and `R_GC_MEM_GROW`, and vectors of 1 MB or more (and libR's own blocks of that size) are anonymous mappings unmapped when they die (`decisions.md`, "Collections run on GNU R's schedule"). The CI report's rep, subset and data.table loops peak within 1% of GNU R's; `runtime_peak_memory_stays_near_gnu_r` (`crates/ry/tests/test_perf.rs`, release, `--ignored`) fails past 1.10x. Open: builder peaks still above GNU R's and the one-old-generation cost of `R_GC_MEM_GROW=0` (`backlog.md`, "Open: collector throughput on the benchmark suites").
- **Collector throughput is no longer the bottleneck for package code.** Minor collections scan only new roots and `Frame::remove` is O(1) (`decisions.md`, "Root scanning is proportional"), so `RY_GC_STRESS=startup` runs in about 7 s in a debug build and `just gc-torture` passes every oracle case in about ten minutes on four cores. Against GNU R 4.3.3 (profiling build, one thread) data.table's fwrite (0.09 s vs 0.13 s) and keyed join (0.014 s vs 0.039 s) are faster and fread is level (0.064 s vs 0.060 s), while its group sum (0.057 s vs 0.037 s) and order (0.073 s vs 0.048 s) and jsonlite `toJSON` on 20k lists (2.23 s vs 1.50 s) are slower. Callgrind of `toJSON` puts collection at 1% and allocation at about 8% self cost, so what remains is interpreter work (S4 dispatch, argument matching, lookups), not the collector. Not yet measured: the collector's share of the three 300K benchmark suites against GNU R's (`backlog.md`, "Open: collector throughput on the benchmark suites"); `oracle bench` now prints each runtime's `gc.time()` and `RY_GC_LOG` records every pause.
- **The JIT compiles hot bodies and loops, with direct calls and native scalar functions** (`crates/jit`, `decisions.md` "the JIT tier" and "Native scalar functions", `r-runtime.md` section 5 "What tier 1 does today"). Scalar loops run tens of times faster than tier 0, and a recursive scalar function such as `fib` runs as frameless machine code (over 100x GNU R). `RY_JIT_LOG=1` names each compiled body, each native function, and the instructions left to tier 0. `just bench-why --write` regenerates `tools/bench/why/results.json`, which every benchmark table renders. Open regression: against an earlier published run, `drawdown` fell from about 10x GNU R to 4.5x, `loop_sum` from 6.4x to 4.5x and `log_rank` from 1.4x to 0.9x, while `fib` and the Array loops held; the earlier run was on a different machine, so bisect with `just bench-why --filter drawdown` before trusting the cause. A typed closure runs as a native function from its first call over scalars, plain vectors, records, tags and `match` (`decisions.md`, "Typed closures run as native functions over records, tags and match"), so typed `orders` and `expr_tree` run 13x and 80x GNU R; typed code that builds vectors or strings still runs at untyped speed (`backlog.md`, "Typed natives, the rest of the end shape"). Open regression: `x <- f(x, ...)` compiles to `CallRebinding`, inlined only when `x` is proven plain. Records, tuples and tags are the faster choice in compiled code (`decisions.md`, "Records, tuples and tags compile natively"): `Construct` is a JIT op, guarded `match` compiles in place, and an integer and a double joined after a `match` stay unboxed as `Ty::Num` (`decisions.md`, "An integer and a double joined stay unboxed"). All three benchmark code bases use records, tags and tuples in their typed program (finance `ledger`, data-science `readings`, biostatistics `followup`); the typed folds run in 0.05-0.10 s against 0.65-0.91 s untyped and 0.40-0.70 s in GNU R. Debt: machine code and `Compiled` boxes of invalidated bodies are never freed.
- **Untyped interpreter speed toward GNU R (JIT off):** period.apply takes 1.4 to 1.5 s against GNU R's 0.89 s, and most of the extra time goes to L1 instruction misses spread over the whole call path. A closure call costs 0.75 µs against GNU R's 0.35 µs, which is why graphics packages render at 1.2 to 1.9x GNU R's time. Next: closure-call overhead and code layout, measured on `oracle gallery`, then the `frame_cell` lookups in the finance `ledger` template and the S4 metadata-cache-miss path. PGO measured slower and is not used (`decisions.md`, "PGO is not used for the release build"; details in `backlog.md`, "Matrix and time series").
- **`DataFrame` (the typed table type) runs in ry's runtime with a Polars-style API.** `crates/table` holds the Polars engine, the query IR and the lazy planner (`lazy.rs`: `Plan`, `Step`, the optimizer, `explain`); `crates/interp/src/dataframe.rs` defines `col`/`Expr.*` and the verbs (`DataFrame.select`, `with_columns`, `filter`, `group_by` + `GroupBy.agg`, `sort`, `join`, `join_asof`, `head`, `LazyFrame.*`, `collect`, `explain`), and `crates/interp/src/frame.rs` the value itself (class `"DataFrame"`, readers, writers, conversions, and `x[i, j, by]` kept as data.table compatibility). The checker refines each verb call from the syntax of its arguments (`refine_dataframe_call` in `check.rs`), so the schema flows through `DataFrame{...}` (Array columns such as `[1.5, 2]` store as plain vectors, and `df$x` reads back a plain vector, see `decisions.md`), `LazyFrame{...}`, `GroupBy{keys; rest}`; the IDE completes and hovers column strings (`dataframe_columns_for` in `ide.rs`, which resolves a named frame type through `representation`). `DataFrame.read_csv`/`LazyFrame.scan_csv` with a literal project path take the sniffed file's columns (`read_csv_type`), and strict mode reports a query that names columns of a frame whose columns are unknown (`decisions.md`, "Strict mode reports a DataFrame query over unknown columns"). Completion inside `col("")` at the end of a 1,650-line pipeline script in a 30k-line project: release build about 30 ms for the first request after opening, 2 ms settled, and 2 ms p50 (14 ms p95) right after typing in the string; a debug build is about 25 times slower. Expression operands are checked against the engine's typing (`check_expression_operand` in `check.rs`, `decisions.md` "DataFrame expression operands"). User guide for moving off data.table: `reference/from-data-table.md`, with the opt-in `[lint] data-table` lint pointing at it. Decisions: `decisions.md` ("The built-in frame", "Frames as runtime values", "The DataFrame API is Polars'"); user view: `reference/dataframes.mdx`; gaps: `backlog.md` ("Open: DataFrame"). `tools/bench/table/ry.R` runs the db-benchmark questions through the verbs under `ry run` beside `datatable.R`: at 1e7 rows on 4 cores it beats data.table on every question, 5.2 s in total against 27.3 s, at 5e7 rows the group-by questions take 9.3 s against 30.8 s at a 6.1 GB peak against 6.6 GB, and at 1e8 rows 22.4 s against 69.2 s at a 13.4 GB peak against data.table's 13.7 GB (best of two, same checksums, release build, peak memory in the last row; CSV reads stream into the final column buffers, `decisions.md` "CSV files are read in released slices"; `just bench-table` regenerates the tables in `development/design/r-runtime.md`, section 7); only the `:=` loops still use data.table syntax, and data.table for the run lives in a scratch library passed as `RY_BENCH_RLIB`. data.table's helpers (`fread`/`fwrite`, `setkey`/`setorder`, `unique`, `rbindlist`, `melt`/`dcast`, `shift`, `fifelse`, `nafill`, `rleid`, `tstrsplit` and friends) live in `crates/table/src/ops.rs` and `io.rs`, typed by the checker; `ops_benchmark` beats `tools/bench/table/ops.R` on each at 1e7 rows except `setkey` (about 10% behind) and `dcast` (parity), measured from Rust. R calls to these names run data.table's own C, which at 1e7 rows runs as fast as on GNU R or faster under ry because the hot C API accessors skip the error boundary and the collector stays out of their way (`decisions.md`, "data.table's C runs at or below GNU R's time"); routing them to the engine was measured and rejected (`decisions.md`, "data.table's helpers run data.table's own C"; numbers in `reference/dataframes.mdx`). The verbs also cover windows and ranks (`Expr.over`, `Expr.rank`), `DataFrame.pivot`, cross joins and Date columns (`decisions.md`, "Dates, windows, ranks, cross joins and pivots in the table engine"). The benchmark code bases' data.table modules (`tables`, `market_data`, `trials` templates) carry DataFrame variants in `#@ typed` blocks, and `just bench-frames` times them end to end against data.table (`development/design/r-runtime.md`, "Real code: the benchmark modules"): 11.6 s typed against 17.8 s for data.table on ry and 20.4 s on GNU R at 1e7 rows. `ry migrate data-table` (`crates/ide/src/migrate.rs`) rewrites the forms `reference/from-data-table.md` documents. Factors are ry's own dense codes plus one level table (`decisions.md`, "Factors are ry's own codes plus one level table, outside Polars"). `just bench-migrate` fuzzes `ry migrate data-table --write` over the three generated code bases and the oracle's data.table cases (parse, strict checks, checksums); at 300k lines only finance has data.table code to rewrite (826 rewrites in 398 files), and its 821 table module instances give the same checksums after migration. A full three-domain run takes over 50 minutes on four cores, so pass `--domain` while iterating, and rebuild release `ry` first, since a stale binary misses stub types such as `condition`. Next: the 1e8 joins, which neither engine fits in 15 GB yet (`backlog.md`, "Open: DataFrame", top item, with the measured causes).
- **data.table code runs on ry's engine unchanged.** `crates/interp/src/data_table.rs` answers `[` on a plain data.table when the result is guaranteed identical to data.table's and declines to data.table otherwise (`decisions.md`, "data.table queries run on ry's engine"; user view in `reference/dataframes.mdx`). `crates/oracle/cases/datatable__*.R` pin it against GNU R; `options(ry.datatable.trace = TRUE)` shows which engine answered. Widening what it accepts is in `backlog.md` ("Open: the data.table bridge").
- **The editor runs and debugs R on ry's runtime.** The debugger is `interp::debugger`, served as a Debug Adapter Protocol server by `ry debug-adapter`; the VS Code extension (`editors/code`) adds code lenses, send-to-console and F5 (`decisions.md`, the debugger entry; user view in `reference/cli.md`, "debug-adapter"). Journeys are `crates/ry/tests/scenarios/debug-*.scenario`.
- **Records, tuples, tags and `match` exist end to end**: parser, formatter, checker with exhaustiveness (`crates/semantics/src/exhaustiveness.rs`), IDE, and interpreter (`crates/interp/src/records.rs`). A `type` over any of them makes it nominal (decision record "Nominal and structural types cover both product and sum types"), and every shape-reading check projects through the definition. The typing contract is the reference section "Records, tuples and tags"; rationale and open questions stay in `development/design/records-and-tags.md`. The R functions that accept one are listed once in `crates/syntax/src/native_values.rs`, which both the checker's `type-mismatch` on `sum(point)` and the runtime's boundary error read. Not done in the checker: a missing number or string case is reported only as `_`. Not done in the runtime: a payload-free tag the AST evaluator builds allocates per evaluation (compiled code shares one constant), `$<-` always copies instead of reusing an unshared value, the libr side (`TYPEOF` 27, opaque accessors) has no C-level test, and `crates/oracle/cases/syntax__ry_lookalikes_stay_r.expected` was written by hand and needs re-recording under GNU R.
- **Corpus packages' own tests run under ry through `oracle packages`** (`development/corpus-and-oracle.md`, `decisions.md` "package tests through the oracle"). The rate is the share of packages GNU R passes that ry passes too: 140 of 144 (97.2%) with the corpus library GNU R installed (`.corpus/library`), and 155 of 164 (94.5%) with the packages ry installed itself (`.corpus/ry-library`, `oracle packages --installed`). The oracle cases: 247 of 247 match GNU R on `--engine ry` with the corpus library on `R_LIBS` (`ry-jit` last measured at 201 of 203). Run `oracle compare` and `oracle record` with `R_LIBS` naming only `.corpus/library`: GNU R's side inherits `R_LIBS`, so putting `.corpus/ry-library` first makes GNU R load ry-built shared objects and fail ("undefined symbol: PREXPR"). 236 of the 238 corpus packages (the closure plus svglite and magick, which must be built from source on ry) install from source with `oracle install` and load: Rblpapi needs Bloomberg's proprietary blpapi3, and magick needs Magick++. The headers declare the API of the R version ry presents (`decisions.md`, "The C headers declare the API of the presented R version"). Remaining classes: numeric precision (Bessel's `besselI`, nlme's `anova` F value), 12 of data.table's 11,767 `test.data.table()` tests, four tinytest failures in RcppSimdJson, and package-specific gaps listed in `backlog.md` ("Corpus package tests: what still fails"). Run `oracle packages` with an absolute `ORACLE_RY`, and check a script by hand with `ry run`, which runs ry's runtime (`ry R` runs GNU R). `gctorture(TRUE)` turns on the heap's collection stress. `.corpus/tests/summary.md` lists each package's first failure.
- **ry's standard library exists** (`List`, `Str`, `Num`, `Bool`, `Result`, `Dict`, `Set`, with constants such as `Bool.true` bound as values; namespace `std`, in scope by bare name unless `[check] prelude = false`; user contract `reference/standard-library.mdx` plus the API pages `reference/std/` generated from `types/std.Rtypes` by `just docs-std`, never edited by hand; rationale in `decisions.md` "ry's standard library"). Types and doc comments live in `types/std.Rtypes`, the runtime in `crates/interp/src/standard_library.rs`, and `crates/interp/tests/test_standard_library.rs` keeps the two in sync. Updates of the form `x <- Dict.insert(x, ...)` and `state$x <- Dict.insert(state$x, ...)` reuse a uniquely held value in place, and `gp::COMPILED_FRAME` guards uncounted bytecode registers (`decisions.md`, "Standard library updates reuse a uniquely held value" and "In-place updates through nested targets"); `d <- helper(d, k)` moves a dictionary or set into the helper's parameter when a static check shows nothing reads the caller's variable meanwhile, with an undo journal for errors (`decisions.md`, "Moving a collection into a helper's parameter"); library leaves such as `Dict.get` resolve at compile time and compile to JIT intrinsics (`decisions.md`, "Library leaves resolve at compile time"); and `#'` lines above a stub declaration become hover docs. It runs only on ry's runtime by decision; gaps are in `backlog.md`, "Open: ry's standard library". Examples in `std.Rtypes` run in the docs test, so regenerate an example's output by running it, never by hand.
- **The runtime design draft is `development/design/r-runtime.md`**, with the measured C API usage of the benchmark closure in `tools/research/data/` (regenerate with `tools/research/r_api_usage.py`). Its main conclusions: ship an ABI-compatible `libR` covering the whole R 4.6 public header set (the closure uses 792 API names plus 150 BLAS and LAPACK routines, and covering half of its 121 compiled packages takes the 495 most used names), and present as R 4.6, including `R_SVN_REVISION` of at least 89194, so packages take their modern-API branches instead of non-API fallbacks. In practice ry presents the version of the base package its R home links (`decisions.md`, "The presented R version comes from the base package the runtime runs"), which is 4.6 only with an R 4.6 library. `development/design/prior-art.md` records which ideas from Roc, Bend, goose and Vx the runtime adopts.
- **The corpus, oracle and benchmark generator exist** (`development/corpus-and-oracle.md`): `tools/corpus/install.R` builds the GNU R library of the benchmark closure, the `oracle` crate runs files under GNU R and a second engine (`oracle compare --engine ry`, or `ORACLE_ENGINE=ry` for the test), and `tools/bench/generate.py` writes the three synthetic packages from R templates. `oracle bench` (`just bench-compare`) runs the generated packages' tests under both runtimes test by test. At the full benchmark size (`--lines 300000 --files 500`, about 308,000 lines each), ry matches GNU R on 100% of finbench's 10,452 tests, dsbench's 10,562 and biobench's 9,757. With the JIT on (the default), suite times are 1.30x, 1.35x and 1.21x GNU R's (312 s against 240 s, 157 s against 116 s, 168 s against 139 s); the JIT's own cost on the suites' cold code is now within about 2% of `RY_JIT=off` (finbench 199.8 s against 195.9 s, dsbench 94.9 s against 89.6 s in suite time but 128 s against 131 s in process wall, single runs whose noise is about ±4%): profitability gates keep it from compiling bodies that would mostly hand back to tier 0 or end at once, and tier 0 records type feedback only for warm bodies (`decisions.md`, from "Bodies that would mostly hand back to tier 0 compile only for loops"). Each suite compiles about 60 bodies in 0.65 s of Cranelift time and 1 MiB of code. Every generated test passes under GNU R (the clustering template runs k-means with `nstart = 25L`, since fewer starts land in local optima at some grid points, and the logistic AUC bound is 0.7, the grid's minimum being 0.78), and process wall times are about 0.97x, 0.78x and 0.75x, because GNU R spends minutes in testthat's per-file `gc()` (Long-term, "Runtime traps"). The interpreter's call path and lookups are recorded in `decisions.md`, "the interpreter's call path, lookups and allocation". Next for this area: close the per-test gap (`backlog.md`, "Open: the benchmark packages under ry's runtime") and check the generated code with `ry check` for false reports. ### Runtime traps

- **S4 methods are rewritten when a package is installed, so a fix to what `setMethod` runs needs the package reinstalled.** A method with fewer formals than its generic becomes a `.local` wrapper inside the package's lazy-load database, and a wrong wrapper built by an older ry survives until `oracle install <pkg>` (Matrix is the usual one). `conformMethod` compares signatures with `identical`, so `length<-` must return the object itself when the length is unchanged.
- **An Array is an R vector with `flag_bits::ARRAY` set** (`decisions.md`, "An Array is a flagged R vector"). Any new fast path that reads vector storage directly (bytecode, JIT, a builtin shortcut) must refuse a flagged vector, or it skips the strict checks in `crates/interp/src/arrays.rs`. Small operator results may be shared constants, so `arrays::finish_result` copies before flagging. A `duplicate` drops the flag, so Array code that copies must re-flag with `arrays::finish`.
- **The interpreter is process-global, so an `interp` integration test binary holds exactly one `#[test]`**; a second test in parallel threads crashes. A symbol's name bytes are `symbol.car().bytes()`; `Sexp::bytes()` on the symbol itself reads garbage.
- **Growability lives in the heap's resizable flag, and `LEVELS` reports it as GNU R's gp bit `0x20`** (`gp::GROWABLE`, `crates/libr/src/attributes.rs`). Packages built against GNU R before 4.6, data.table among them, test `LEVELS(x) & 0x20` directly instead of calling `IS_GROWABLE`, so without it `data.table()` and `setDT` fail with "attempt to resize a non-resizable vector".
- **An ALTREP object's header holds no length**: read it with `libr::altrep::length`, never `Sexp::length`, which returns garbage for ALTREP and caused a multi-gigabyte allocation in `crates/libr/src/frame_altrep.rs`.
- **`libR.so` has its own global allocator** (mimalloc in `crates/libr/src/libr.rs`), because the binary's allocator does not reach a separate shared object, and glibc malloc there cost page faults and a memset on every large vector. It must use the `local_dynamic_tls` feature: the default TLS model fails `dlopen` with "cannot allocate memory in static TLS block". It must also use the `v2` allocator: the default v3 crashes in `mi_thread_init` (a null thread heap) on the second thread that allocates after the first one exits, which is what every libr test binary does.
- **Do not run `cargo fmt` on a whole crate**: `rustfmt.toml` sets nightly-only import options and the code is not stable-rustfmt clean, so stable `cargo fmt -p interp` rewrites dozens of unrelated files.
- **testthat calls `gc()` after every test file that registered a teardown** (`teardown_run`), so a 500-file suite runs hundreds of full collections. A full collection with a 300,000-line package forced takes about 600 ms on GNU R and about 100 ms on ry, which is why per-test suite time and process wall time give very different ratios.
- **BLAS and LAPACK are found by soname first, then where GNU R's `etc/Makeconf` says they are, then as R's own `libRblas`/`libRlapack`** (`library_candidates` in `crates/interp/src/linalg.rs`, `decisions.md` "BLAS and LAPACK come from the system, then from GNU R's Makeconf"). NixOS has no global library path, so the Makeconf `-L` directories are what make linear algebra work there. Opening LAPACK loads BLAS first, so a LAPACK whose BLAS is not on the search path resolves it by soname. The Makeconf reader is `crates/rcmd/src/makeconf.rs`, which `interp` includes by path.
- **Polars computes `NaN` where R says `NA`** (`cor` over a constant group, for one), so every IR lowering that can produce `NaN` must decide which R means. `crates/table/tests/test_table.rs` checks results against data.table.

- **A Rust function that allocates while it holds a handle nothing else roots must root it first** (`heap.root`, or the `keep` list of `Heap::allocate`). Collection stress is the only thing that shows it, so run `crates/libr/tests/test_fuzz_native.rs` with a large `FUZZ_ITERS` after touching allocation paths.
- **Native code must never be called from Rust except through a C trampoline in `native.c`**, and a callback native code hands to the API (`R_UnwindProtect` and friends) must run from C, so a `longjmp` or a C++ exception never crosses a Rust frame. An exported API function runs its body through `boundary::enter`.
- **A data symbol exported from `native.c` is marked `RY_EXPORT_DATA`**, not `RY_EXPORT`; `build.rs` reads both markers into the version script, and a function-pointer variable is named by the `(*name)` inside its declarator.
- **The corpus tests (`test_corpus_binaries`, `test_corpus_calls`, `RY_SOURCE_PACKAGES` in `test_install`) need `.corpus/library`** from `tools/corpus/install.R` and skip without it. Re-record `tests/data/corpus_calls/cases.rds` under `LC_ALL=C.UTF-8`, or string routines record C-locale results.
- **The pinned nightly cargo gives every build unit its own `target/<profile>/build/<pkg>/<hash>/out/` directory and has no `deps/`**, so the fresh `libR.so` from `cargo test` is in libr's newest build output, not beside the test executable; the copy in `target/<profile>` is only refreshed by `cargo build`. `crates/libr/tests/harness.rs` (`library_path`) picks the newest one, and the `ry-lang` docs and scenario tests run `cargo build -p libr` first, because `ry` loads the copy beside itself and refuses a stale one.
- **Cross-building the macOS runtime from Linux needs clang with ld64.lld, not zig.** zig's Mach-O linker ignores `-exported_symbols_list` and exports every symbol (about a million), which hides export bugs. Use a macOS SDK (`SDKROOT`) and a `CC`/linker wrapper running `clang --target=arm64-apple-macos11 -isysroot $SDKROOT -fuse-ld=lld`; the Windows CLI checks with `zig cc -target x86_64-windows-gnu` as `CC` once cc-rs's `--target=` flag is stripped.
- **Type-check macOS and Windows from Linux without an SDK** before touching platform code, because the release job is otherwise the first build there: `rustup target add aarch64-apple-darwin x86_64-pc-windows-gnullvm`, then `cargo clippy --workspace --all-targets --target <t> -- -D warnings` with `CC_<t>`/`CXX_<t>` (underscored triple) pointing at a wrapper that runs `clang --target=<clang triple> "$@"` for probes (cc-rs detects the compiler family with `-E` and `-?`) and `clang --target=... -c -x c /dev/null -o <out>` for each `-c` compile, `AR_<t>=llvm-ar-18`, and `WINDRES=llvm-windres-18` for gnullvm. Nothing links, so empty objects suffice. libc's Linux-only items (`pipe2`, `sched_*affinity`, `cpu_set_t`) and its deprecated Apple `iconv` bindings are the usual macOS traps.
- **`parallel`'s fork routines are Unix-only** (`crates/interp/src/fork.rs`, registered in `UNIX_ROUTINES` in `builtin_libraries.rs`), as in GNU R, whose Windows `parallel` R code never calls them. `mcaffinity()` returns `NULL` off Linux, as GNU R's does without `sched_setaffinity`.
- **On macOS, `dyn.load` opens a rebound copy of GNU R's package binaries** (`decisions.md`, "macOS packages bind to ry's libR"), cached under `~/Library/Caches/ry/rebound/`. Links around the copy mirror the original's directory and as many ancestors as its `@loader_path` paths climb.
- **GNU R's public C API is pinned by `crates/libr/tests/headers/r_api_names.txt`**: every name GNU R's headers declare and `R.dll` exports must be declared by ry's headers and exported by `libR` (`decisions.md`, "GNU R's public C API is a checked list").
- **A C function native code calls must be marked `RY_EXPORT` in `native.c`**, because rustc's version script hides C symbols in a cdylib and `build.rs` exports only the marked ones.
- **A default package's native routine raises errors with `unwind::error`**, which reports the
  calling closure as GNU R's `error()` does (`Error in rgb(2, 0, 0)`). Only the `.External2`
  routines report their own call, through `NativeCall::error`.
- **Translate a C `do { ... } while (a > b)` that can meet NaN as `if !(a > b) { break }`**, never `if a <= b { break }`: a NaN comparison is false, so the C loop ends and the inverted one spins forever (`rmath.rs`).
- **Code translated from GNU R may only live in a GPL crate, with a provenance header** (`decisions.md`, "licensing"; `reference/licensing.md`). The header names each R source file and keeps its copyright lines, and `THIRD_PARTY_NOTICES` reads it, so run `just notices` after adding one. A UPL crate (`syntax`, `semantics`, `format`, `ide`, `heap`, `table`, `sniff`, `rdb`, `rcmd`, `repl`, `oracle`) must never depend on `interp` or anything linking it. The headers in `crates/libr/include` are LGPL-2.1-or-later and must not copy R's GPL-only `Rinterface.h` or `Rembedded.h`. Vendored test packages carry their own licence (brio is MIT).
- **The methods package's R code relies on native quirks** (`crates/interp/src/methods.rs`): `slot<-` (`R_set_slot`) modifies its argument in place, because the default `initialize` calls it as a plain function on a fresh copy and drops the result; `.findInheritedMethods` turns primitive dispatch off through `.allowPrimitiveMethods(FALSE)` (`allow_primitive_methods`), or selection recurses; a signature argument that fails to evaluate is reported against the call `h(simpleError(msg, call))`, as in GNU R. Dispatch only treats a generic's argument as `"missing"` when its own binding is missing, not when it was passed on from a caller where it is missing.
- **GNU R's own default-package shared libraries can never load on ry's heap**, because they are built against R's internal headers and inline the object layout (`LENGTH`, `PROTECT` through `R_PPStack`). Their routines are Rust in `crates/interp/src/builtin_libraries.rs` and the per-package modules; never try to make `methods.so` or `stats.so` load.
- **Read a closure's body through `bytecode::closure_body`, never `function.cdr()`**, because a body that ran twice (or once, with a loop) is replaced by its compiled `BCODESXP`.
- **A binding created outside a function frame must go through `Heap::define`** (and removals through `remove_binding`, enclosure changes through `set_enclosure`), because those move the binding epoch the bytecode's inline caches trust. An environment that is a closure frame carries `gp::FUNCTION_FRAME` and never moves it.
- **gp bit 12 means `TYPED_DEFINITION` on a formals pairlist or body and `CHECKED_PROMISE` on a promise** (`heap::object::gp`). Both belong to the inline-annotation checks (`crates/interp/src/annotations.rs`); `annotations::leave` must run at every closure exit, error or not, or a stale pending check outlives its frame.
- **Source references follow `keep.source` per top-level expression** (`interp::lower`, `interp::session`). `ry run` and the console parse the whole input but lower each expression just before it runs, because `options(keep.source = TRUE)` in a script affects the expressions after it, as in GNU R. `Interp.srcref` is GNU R's `R_Srcref` and `Frame.srcref` the caller's value at the call; `{` sets it per statement (`Op::SetSrcref` in compiled code, emitted only when the brace carries srcrefs, so code without kept source pays nothing), and `run_closure` sets it to the closure's own `srcref`.
- **ry's parse errors inside a `#:` comment are not R syntax errors** (`ParseError::in_annotation`). The runtime's parser and the console's completeness test skip them, or a malformed comment stops a script GNU R would run.
- **`missing()` counts a defaulted formal as missing only in its own function**: following an argument back to a caller (`h(where)` with `where` defaulted) yields `FALSE`, as GNU R's `R_isMissing` does (`eval::is_missing`). The methods package's `registerNames` depends on it.

- **`cargo build -p ry-lang` alone leaves `libR.so` stale**, and the interpreter is linked into it, so a runtime fix seems to have no effect. Build `-p ry-lang -p libr` together. Building `-p libr` alone also changes feature unification and rebuilds polars, which can fill the session disk.
- **Native code builds calls with `LCONS`, so their argument cells are `LANGSXP`, not `LISTSXP`.** `libr::eval::normalize_argument_cells` retypes them before the interpreter walks a call.
- **A `cbind`/`rbind` S3 method gets only the `...` arguments, never `deparse.level`**, and a vector without a tag is named from its `...` promise's expression (`subset.rs`, `argument_expressions`).
- **The oracle stops a case at its first top-level error**, so it cannot show a script continuing under `options(error = ...)`; compare such behavior against `Rscript` directly.
- **Every non-missing argument gets a promise, constants included** (`eval::promise_args`), because native code such as lazyeval and ellipsis reads a promise's environment to tell whether it was forced.
- **Environment listing order is derived, not stored** (`heap::env::Frame::listed_cells`): newest binding first, a closure's formals last, hashed frames by the buckets of GNU R's chained table, which the frame keeps incrementally because the order depends on removals too.

- **Every JIT helper that can allocate must release its handles (`scoped` in `crates/jit/src/runtime.rs`)**, because every interpreter constructor roots its result and compiled loops have no backward jump where tier 0 would release them. A helper that skipped it kept each boxed scalar alive until the call returned (1.6 GB for 10M iterations). Compiled code stores a helper's result in the register window before it allocates again, which is what makes the release safe.
- **Compiled code must write variables back before anything that can read the environment** and forget them after anything that can write it, including the first read of a formal whose default is an expression (`crates/jit/src/analysis.rs`, `defaulted`) and any warning, which can run a calling handler (the `HANDOFF` slow paths and `Effect::PureUnlessObserved`). The `ry-jit` oracle engine (`RY_JIT=force`) and `crates/jit/tests/test_tiers.rs` are what catch a missed case; run both after changing the JIT or tier 0's instruction set.

### Performance traps

- **A per-item query must never scan a per-file or per-project list.** Compute once per file in a memoized query and probe per item. `item_spans` is the single source of top-level item identity, so never re-derive the classification. Such a quadratic has two factors (items times names looked up), so vary both axes when measuring, because either axis alone looks linear.
- **A per-item read that joins over a project-wide list needs a cap**, not just memoization (`CONDITIONAL_SLOT_JOIN_CAP`, widening to `Unknown`).
- **A check reads per-name firewalls, never a project-wide map** (`package_name`, `interface_group`, `frame_binder`). `crates/semantics/tests/test_incremental.rs` pins it by counting query executions.
- **Never call `Checker::infer` twice on one expression.** It has no memo, so a double walk made operator chains cost 2^depth and reported each finding 2^depth times. The fixtures dedup, so they cannot see it. Thread the `Ty` you already have.
- **`GlobalEnv` facts are borrowed per-file values** (`&'db`). Returning them owned makes every item pay for the whole project.
- **Hot tracked queries returning maps or vectors use `returns(ref)`**, because `returns(clone)` deep-clones per call.
- **A type is a hash-consed DAG, so walk it with a memo**, never as a tree (`substitute_rigid` went from 278M to 2M calls).
- **A query that reads a syntax tree must keep a small memoized result and be warmed in `diagnostics::derive_from_syntax`**, and its syntax half must not depend on naming. `ry check` derives every tree fact across all cores in its first pass, so a tree reader left out walks other files' trees on the checking threads later. Split a finding that also needs naming or project declarations into a memoized syntax half and a cheap join (`decisions.md`, "Syntax trees are evicted, and only small syntax facts are memoized").
- **The server's inputs are `Durability::MEDIUM`, except open documents and `ProjectFiles`, which are `LOW`.** A new place that creates, reloads or rewrites a `SourceFile` must name a durability, because a setter without one keeps the field's current durability, and a `MEDIUM` write makes every memo in the project deep-verify. Salsa never backdates a memo whose durability drops, so the project-wide maps must be `LOW` before any file's first edit (they read the `LOW` `ProjectFiles`), or that edit re-executes every item check. One `LOW` input that most memos read (the stubs once were) silently turns every keystroke into a full-project deep verification. A project-wide map reads per-file memos, never per-item ones (architecture page, "Keeping project-wide work cheap"). `ry debug analysis-stats` and `examples/keystroke_probe.rs` mirror these durabilities, so their timings match the server's; a probe that enters an input at the default `LOW` measures a full deep verification instead. Lowering an opened file to `LOW` therefore re-runs once every fold that reads it, so a fold that only editor requests read must be re-derived in idle time (`Worker::editor_folds_stale`), or the first request after an open pays for it.
- **Salsa clears a handle's cancellation flag whenever a top-level query returns** (`DbGuard::drop` in salsa's `attach.rs`). A flip that lands at the end of a query is lost, so background work that must stop for a queued job polls `CancelHandle::has_queued_jobs` between units of work instead of relying on the token alone (`Worker::in_parallel` in `crates/ry/src/server.rs`).
- **A composite type past `TYPE_SIZE_CEILING` records as `Unknown`** in `Checker::record`. `types::type_size` counts paths, not distinct nodes, because a consumer walking a type pays the tree it denotes. Without the ceiling, a record whose fields all return that record grew tenfold per level and one file never finished.
- **A write inside a call-argument block binds at top level**, so `test_that("x", { out <- f() })` publishes `out` package-wide, which is why a package's tests can dominate its cost. Whether R binds outward depends on the callee: `try`, `suppressWarnings` and `invisible` do, while `local` and `test_that` do not.
- **`sys.call()` and `sys.calls()` copy only a frame's call cells** (`envir::call_with_srcref`, GNU R's `shallow_duplicate`), never the whole call. `do.call` puts the argument values themselves into the call, so a deep copy costs the size of the arguments, and data.table's `cedta()` runs `sys.calls()` on every `[`. Copy-on-modify of the shared arguments rests on the copy's cells adding to their refcounts. `crates/interp/tests/test_call_stack.rs` counts allocations to pin it.
- **Measurement traps.** Alternate the two binaries run by run, because sequential blocks showed a fake 2x win. Measure the analysis path with `--output json`, because the human reporter is itself quadratic in findings. Compare corpus outputs as unique sorted records, not line counts (baselines: data.table 4077, dplyr 675, ggplot2 1091, shiny 1038). Every in-container timing is effectively a two-core number or worse.
- **Budgets:** keystroke-to-diagnostics p50 at or under 30 ms and p95 at or under 100 ms at 300K LoC, pinned by `crates/semantics/tests/test_perf.rs` (`just perf`, which needs the fetched corpus). For reference, 794K lines across 69 CRAN packages check cold in about 14 s at about 1.3 KiB resident per line, with a keystroke p50 of about 12 ms.

### Semantics traps

- **`GlobalEnv` has no default method bodies, on purpose.** The SCC fixpoint's view is a second implementor, and a defaulted method silently gives it a wrong answer (this once collapsed every recursive function using `Date + 1` to `Unknown`). Test such facts with a recursive and non-recursive fixture pair.
- **Dispatch and the numeric constraint must read the same class scope** (stubs plus project), so a package's own `+.Money` makes `Money` arithmetic.
- **A read recorded by name instead of by expression id is invisible to the slot model**, which is why `%op%` reads go through `mark_slot_read`.
- **One structural map rewrites types: `types::map_child_types`** (reads use `for_each_child_type` and `Parameter::types`). A second hand-written walk once skipped a parameter's default and leaked an inference variable across the item boundary, so new `TyKind`, `FunctionType` or `Parameter` members go there and nowhere else.
- **Every type the checker prints must parse back** (`test_roundtrip.rs`), so a new constraint, `TyKind` or rendering includes its grammar side. A function member of a union renders parenthesized.
- **Every mismatch report goes through `Checker::type_mismatch`**, which narrows record and function mismatches to the failing field or position and narrows the range with the message.
- **A finding underlines the smallest expression its message is about.** Thread narrower ranges (`name_range` on fields and call arguments), keep the whole type as the verdict, and use the leaves only to place it.
- **Every finding inside an item is reported**, and only the export is cut to `Unknown` when the item fails.
- **A `#:` annotation declares parameter types, never the parameter list.** The export is always the formals, and `check_declared_function` owns the reconciliation, so a call is never blamed for an annotation's mistake.
- **Do not `table.resolve` a type you display as written**, because resolve expands aliases.
- **One `TypeRenderer` spans everything that shares variable names** (a signature, both sides of a mismatch).
- **Immediate reads resolve against the nearest earlier writer in the file, while deferred reads (closures) differ by kind.** A package closure sees the project-wide winner and a script closure sees the settled file frame. Getting this backwards breaks forward references from function bodies.
- **Typing is off unless `ry.toml` says `[check]` `typing = true`.** A throwaway project for checking a docs claim needs that line, or every type rule silently passes.
- **A called name is looked up as a function** (`Checker::function_lookup`, reference "Called names"): non-function bindings are skipped, and the binding the call reached is recorded in `ItemCheck.callee_targets`, which hover, goto, references and rename must follow instead of the plain slot resolution. A type parameter counts as untyped, or `test_roundtrip` finds unwritable schemes.
- **Implicit reads for `unused` stay inside naming's slot reads**, never in `captured_slots`, which the checker uses for typing (`naming.rs`: `tail_assignments`, `escaped_frames`, `mark_formals_read`, the name-string readers). A function whose frame escapes through a bare `environment()` skips the lint wholesale; `environment()` handed to an accessor in `EXPLICIT_NAME_ACCESSORS` does not escape. `duplicate` drops a pair when top-level code between the two definitions eagerly reads the name or is a `setGeneric` over the existing function (`diagnostics::earlier_value_read`); deferred reads in function bodies do not count.
- **Test files are `DocumentKind::Test`, helper and setup files `TestHelper`** (`semantics::test_document_kind`). Only helpers fill the shared test namespace, and no test binding reaches the package namespace. Removing the old pooling of every test file exposed checker false positives that it used to mask, chiefly rlang's own `expr(foo(...))` being checked as evaluated code inside rlang, where `expr` is a project function rather than a quoting stub.
- **`"x" <- 1` binds `x`** through the name-target arm, not `replacement_base`, which reads the base first.
- **A fixture cannot exercise anything keyed on `PackageMetadata`**, so those cases belong in `crates/ry/tests/test_cli.rs`. Read what a bless recorded before believing it covers the scenario.

### Parser and annotation traps

- **Recovery stops at the statement boundary when the next line assigns** (`starts_new_statement`). `=` does not count, because inside a list it is a named argument. The check scans backwards, because the newline was consumed with the previous element.
- **One mistake, one finding.** A lexer `ERROR_TOKEN` is already diagnosed and suppresses its statement's boundary report, and the `#:` grammar reports once per region (`error_unclosed` lets one unclosed opener through). Never report a consequence beside its cause, and blame the incomplete construct rather than where the search stopped.
- **An unterminated quote ends at its first line break**, so typing a quote does not take the rest of the file out of analysis.
- **`#:` block-form rules are about lines, and a stitched line's marker may sit inside a nested node**, so count lines over all of the block's tokens. A `<T>` binder list is a prefix of the next type, not an item. A refused region is an `ERROR` node, and a block containing one carries no typing payload.
- **A ry rule on a construct that parsed in full reports through `Parser::error_rule`** (a tuple item with a name, a repeated record field, a bad pattern shape). It sets `Unexpected::Nothing`, so the runtime keeps ry's message instead of GNU R's "unexpected <token>" form and a console reports the error instead of waiting for more input. Plain `error_at` there would blame whatever token follows, or the end of the input.
- **A diagnostic code names whose grammar broke**: `syntax-error` for R and `annotation` for `#:` (`SyntaxError::in_annotation`).
- **Formatter:** trailing comments attach inside expression nodes, so placement decisions are token-level (`last_token_before`). Line math uses `significant_range`, and the formatter refuses only on R-grammar errors.
- **Formatter speed:** any per-node query that scans the node's subtree makes deep files quadratic; `last_token_before` walks back from the offset instead (cost: tree depth). `ry fmt` on 309k lines takes about 0.5 s on four cores; what remains is cursor traversal (an `Arc` bump per `SyntaxNode`) and allocation. Sweep a corpus through every invariant with `RY_FORMAT_DIR=<dir> cargo test-release -p format --test test_fuzz format_directory -- --ignored`.
- **Golden error suite** (`crates/syntax/tests/errors`): a new parser error path adds its case in the same change.
- **Inline type grammar defers its trivia** (`Parser::deferred_trivia`): a new `ann_*` path must emit through `bump`, `start` or `checkpoint`, which flush it, never through the builder directly, or trivia lands on the wrong side of a node.
- **An annotated binding is recognized only at a statement start** (`Parser::statement`), because R reads `name:TYPE <- v` as `` `:<-` ``; everywhere else `x:y` stays a range. Tree-sitter judges the erased text (`erase_inline_annotations`), so an annotated fixture needs no allowlist entry.
- **Both annotation spellings lower into one `Annotation`** (`lower_annotation`, `lower_inline_annotation`, `merge_annotations`). A new annotation feature goes into that shared lowering, never into a checker path that knows the spelling.
- **Inline type definitions pair with a `#:` definition directly above them** (`syntax::paired_comment_definition`, which erasure also uses to drop the inline copy), so read definitions through `file_type_definitions`, never by walking the tree for one spelling. An inline union continues onto a line that starts with `|` (`Parser::inline_line_continues_with_pipe`), which is safe because no R statement starts with `|`. `NamedDefinition::inline` only picks the spelling hover shows.
- **The parser's acceptance gate is hard:** zero unadjudicated divergences against tree-sitter, with R as the referee.

### IDE and server

- **Cursor position model:** the smallest end-inclusive expression wins, with a `NameRef` winning a tie, so the declaration scan stays a fallback for every binding kind. Which token declares an item has one answer, `semantics::item_name_range`, and `:=` is never a definition.
- **The server** is one async-lsp frontend thread plus one worker owning the database. Edits flip salsa's cancellation token, and later jobs use a fresh storage handle. Host assembly (config gating, typing modes, suppressions, lints) is shared with the CLI in `crates/ry/src/diagnostics.rs`.
- **Coherence failures panic** (document sync), and IDE lookups never panic.
- **The console socket's requests run on the interpreter thread only** (`interp::console_server`): reader threads just queue and set `SERVICE_REQUESTED`, which `poll_interrupt` drains. While a command runs, only debugger requests are answered; anything that evaluates R must be refused as busy, or it interleaves with the user's command. `browser()` at a terminal drives the same `debugger::Adapter` through a text transport (`console_server::Browse`), so stepping rules live in the adapter only (`decisions.md`).
- **CLI reporting is miette's** (`crates/ry/src/cli.rs`). Its header column counts bytes, so `read_span` re-counts characters. A range over several lines clamps to the first, and sources are borrowed (`NamedText`), never `NamedSource`.
- **A quick fix is a field on the diagnostic** (`Diagnostic.fix`), never a re-derivation in `ide`; the server reads fixes from the diagnostics it publishes after suppressions. Whole-file features (outline, folds, tokens, fixes, selection) have their own fixture suite, `crates/ide/tests/structure`. Gaps: `backlog.md`, "Open: editor parity".
- **Completion ranking by expected type only demotes, and only on declared types** (`decisions.md`, "Completion pushes down names whose declared type cannot fit"). Read the callee's declared scheme across every overload, never the call's instance, or the argument being typed decides its own slot.
- **`list` and `c` have stubs only for signature help and their value type**; the checker types their calls itself before any stub lookup. data.table's `.()` reads as `list()` for signature help when `.` is unbound and the call sits in a `[` argument (`is_query_list`).
- **The IDE fixtures print the token a range covers**, not a byte offset, so a stub addition never forces a re-bless. If one fails after a corpus change, the range is genuinely wrong.

### Package loader

- **A plan is backend-neutral, and only the R side knows a runtime.** `runtime.R` is shared; `gnur.R` (plus `r.rs`'s RDS transport) and `ry.R` (plus `ry_runtime.rs`'s internals) are the two backends' hooks. Never put R-specific logic in the diff (`loader::diff`).
- **On ry's runtime a lazy binding is a promise over a per-file source handle** (`FileSource` in `ry_runtime.rs`: the file's `Parse` or text, preserved in the `HANDLES` thread-local while a plan or deferred S4 unit needs it). With `keep.source` off it lowers the definition's node directly; with it on (or a debugger attached) it builds the file's `srcfile` once, on the first force from that file, and reparses only the definition, padded to its column, through `lower_node_at_line`, so srcrefs carry the file's real lines and columns (`decisions.md`, "Lazy definitions keep source references").
- **Every load of a strict package checks it, on both runtimes** (`Plan::strict`, `load::strict_value` for GNU R, the `ry_loader_set_check` callback for ry's runtime). The first plan of a `ry load` session skips the callback, because the concurrent verdict covers it; a refused plan is never committed, so the console watches the package and retries after the next edit.
- **Every reload rule must keep `test_reload_fuzz.rs` green**, which compares a reload against a fresh load in a model. Hand-reasoned rules missed swapped writers, `f <- memoise(f)` wrapping twice, and a fixpoint that stopped before the changed-name set settled.
- **A native fast path for a methods-package function must be exact or invisible** (`crates/interp/src/methods_core.rs`). It reads arguments only through `quiet_value` (forcing must run no code and cannot fail), bails before any effect when R code could observe it (validity functions, `as()` caching coerce methods in `coerce`'s `.MTable`, user `initialize` methods, a data part that is not set through the standard replacement method cached in `coerce<-`'s table), and evaluates the calls that may signal (`initialize(value, ...)`, `list(...)`, `validObject(.Object)`) in the R function's own frame so condition calls and `sys.calls()` match GNU R. `FAST_PATHS` pins each function's hash; `RY_PRINT_METHODS_HASHES=1` prints them after a GNU R upgrade. The default `initialize` method exists as many separate closures: the generic's `default`, `.__T__initialize:methods$ANY`, `.MTable`/`.AllMTable$ANY`, and a copy per class that inherited dispatch cached in `.AllMTable` (the saved methods namespace already holds some, such as `MethodDefinition`). Installing scans every table entry and patches each closure whose hash matches. Look a generic up in `.genericTable` as `getGeneric()` does, not through the namespace binding, which may be an unforced lazy-load promise.
- **R traps the GNU R backend hit:** `environment<-` strips a closure's bytecode (cache the whole environment instead); `getOption("keep.source.pkgs")` is `FALSE` by default, so it must not shadow `keep.source`; `.Internal(...)` arguments are evaluated, so a language argument needs `quote()` (`.ry_internal`); `ls()` sorts, so hot paths use `names(env)`; the attached package environment keeps names the namespace dropped unless every sync removes stale ones (S4 `.__C__` metadata).
- **A body edit must stop at `file_binds`.** A reload re-derives the edited file's `file_load_index`, `file_items` and `file_binds`; equal binds backdate `package_bindings`, and `diff` skips the laziness-flip scan when the bindings `Arc` is unchanged (`decisions.md`, "A reload re-derives one file"). `test_incremental.rs` counts the executions. The first edit of a file costs about 20 ms more than later ones, because lowering its durability deep-verifies every memo once.
- **Cold `ry run` and `ry load` overlap analysis with base R** through `Loader::prepare`, which the host starts on a thread (`ry_loader_prepare` in libR for ry's runtime, `load::prepare` for GNU R) before R starts. Strict mode reaches ry's runtime as an atomic (`ry_runtime::STRICT`), not through the session lock, so starting R never waits for the prepare. A second cold start reads the package's index from the load-index cache and parses items only when forced, and S4 definitions are held back until first use (`decisions.md`, "A load holds back S4 definitions and caches its index across processes"). What remains on the 326,000-line bench package is mostly base R. The first S4 use restores the held-back definitions from the S4 metadata cache, a lazy-load database whose classes and generics enter the `methods` tables as shared promises (`decisions.md`, "The S4 cache is a lazy-load database"); a cache miss, or a unit that reads package constants, still runs them through the `methods` package's R code (`setMethod` and `setClass` dominate it; `new()`, `validObject()`, `is()` and `extends()` run natively). On the synthetic finance code base (`tools/bench/generate.py --domain finance`, imports trimmed to R6 where only R6 is installed), holding back `show` methods too brings `ry run` start-up from about 2 s to about 0.6 s (GNU R `ry R`: 2.1 to 2.8 s), and first S4 use then costs about 200 ms on a cache hit (mostly `cacheMetaData`) and 1.5 s on a miss. Its 199 `R6::R6Class` generators now bind lazily in any file (`decisions.md`, "Lazy R6 generators"), which brings the load on an index-cache hit from about 0.4 s to about 0.29 s and `ry load` wall time to about 0.47 s; 849 top-level statements still run. On a seeded S4-heavy package (`just bench-s4-first-use target/s4heavy lubridate,data.table,xts`: 2,892 S4 definitions including 25 unions, 15 of them of basic classes only, and 11 `setAs`; generator in `tools/loader-bench/`) the whole unit is held back, so the load takes about 0.33 to 0.41 s (process start 110 to 150 ms, imports 210 to 270 ms, 364 remaining top-level statements about 70 ms) against about 6.5 s eager (GNU R `load_all` 6.3 to 7.1 s). First `new()` costs 57 to 63 ms on a metadata-cache hit (warm wall time 0.55 to 0.59 s), but a miss still runs every definition (about 6 s, 1.3x GNU R's per-call cost) and saves the database (about 0.4 s), so `setClass`/`setMethod` interpreter speed is the remaining lever on a miss. On a hit the floor is process start plus imports, which run GNU R's own R code (`registerS3methods` runs natively, `decisions.md`, "start-up and imports run GNU R's code"); the next lever is `cacheMetaData`'s `.checkGroupSigLength` (`backlog.md`). `rm()` of many names from a large frame is O(frame) per name (`Frame::remove` in `crates/heap/src/env.rs` shifts the vector and every index slot); the S4 restore path avoids it, but a batch removal would fix it at the root.
- **Console typeahead reaches fd-0 readers** because the console reads typed-ahead bytes itself only up to the first line break (`take_typed_line` in `repl/src/console.rs`), leaving the rest in the tty for `readLines(file("stdin"))` or a `system()` child. Ctrl-C is seen through an R `interrupt` calling handler plus a chained SIGINT handler, since GNU R swaps its own handler in during `Sys.sleep` and `system()`. Known gap: lines pasted at a prompt in one chunk with the command that reads them go to the console, because the line editor already consumed them.
- **Measure loaders with the same `keep.source`.** `ry run` and `ry R` keep source references on, while `Rscript` runs others without them; that alone is 10 to 20% of a cold load. `tools/loader-bench` is the harness.

### Testing

- **An oracle is trusted only once an injected bug turns it red.** Determinism, idempotence and round-trip are self-consistency checks that a uniformly wrong answer satisfies, and three batteries here stayed green over real mutants.
- **Give a differential oracle inputs that always exist.** The tree-sitter acceptance test never ran while it pointed only at the gitignored corpus, and the test runner hid its skip note.
- **A foreign renderer's expectations are never bulk-blessed.** Adjudicate each case against the typing reference.
- **The fuzz batteries' cost is re-parsing the stub corpus per fresh database**, not the iteration count.
- **A gate must fail on its own exit status.** `cmd | grep …; echo OK` always passes, and a background job's output file can be read mid-write.
- **A simulator failure is a server bug until shown otherwise, but check the client model first.** Two false-positive classes came from the simulator, not the server: a reopened document must continue its version from the last one (VS Code does), and the first-wave-is-a-subset check only holds when no config or disk change landed since the sync.
- **`syntax::testing::enable_invariants()` makes every splice reparse also parse from scratch.** The simulator turns it on; a harness that drives incremental code should too.
- **A REPL pty test must expect text the echoed command cannot contain** (`Error: boom`, not `boom`; a `cat` of joined words). Matching the echo returns before the command runs, so the next line races its evaluation and the test asserts nothing about the output.

### REPL and environment

- **The REPL never feeds R input through the console to set state.** Startup work goes through `RApi::eval` between `setup_Rmainloop()` and `run_Rmainloop()`. `development/design/repl.md` has the details, including the Windows recipe (`GA_initapp` lives in `Rgraphapp.dll`) and the pty harness requirements (answer the cursor-position query, serialize the sessions). The pty suite is verified on Windows against R 4.5.2 and on Unix.
- **A path that reaches R or a tool R starts must not carry Windows' `\\?\` prefix**, which `fs::canonicalize` adds and R rejects (it also forbids the `/` that `file.path()` appends). `loader::find_package_root` strips it, so every package root ry hands R is plain; strip it the same way anywhere else a canonical path goes to R. On Windows `getwd()` answers with `/` and `basename`/`dirname` split at both separators, as in GNU R; base R's own code (`tools:::.build_packages`) depends on both. Windows base R calls `.Internal(system())` with seven arguments and no shell (GNU R's `sys-win32.c`), Unix base R with three and `sh -c`; `do_system` picks the contract by argument count, so `crates/interp/tests/test_system.rs` exercises the Windows form on Linux. Embedded R sources must reach GNU R with LF endings: its parser rejects `\r`, so `.gitattributes` forces LF checkouts and `repl::libr::Api::eval` normalizes CRLF.
- **`R.dll` and `ry.exe` are built for gnullvm and linked with lld** (`decisions.md`, "Windows runtime"): GNU ld relocates `SECREL32` TLS offsets, so every `thread_local` access in a relocated DLL crashes, and windows-gnu links msvcrt, not the UCRT packages use. `r-runtime.md` section 11 has the Linux cross-build recipe (host clang and lld over MSYS2's clang64 sysroot packages, which are `.pkg.tar.zst` archives; `pip install zstandard` unpacks them where no `zstd` CLI exists). Run `wine64 ry.exe run file.R` (wine64 is in `/usr/lib/wine`, not on PATH) with `R_HOME=Z:<a Windows R home>`. A Windows R home unpacked with `innoextract` works without executing its DLLs, given zero-byte placeholders at `library/<pkg>/libs/x64/<pkg>.dll` for the default packages. winedbg chokes on the DWARF; `WINEDEBUG=+seh,+loaddll` and `llvm-objdump --disassemble-symbols` locate a crash. `ry.exe` and `R.dll` must come from the same tree (runtime identity). Rtools-ABI test packages: MSYS2 ucrt64 GCC 14.2 headers and static libstdc++ with `clang --target=x86_64-w64-mingw32 -fuse-ld=lld`, linked `-lR -lpthread`.
- **A windows-gnu cross-link needs a synthesized `synchronization` import library**, which the flake's windows `preBuild` makes with `zig dlltool`. A crane deps-only build cannot catch a breakage here, because the dummy sources never reference reedline.
- **R installs in agent containers** (`apt-get install -y --no-install-recommends r-base-core`, or the CRAN apt repo for a current R). `fs` needs `libuv1-dev`, and the tidyverse needs `libcurl4-openssl-dev libharfbuzz-dev libfribidi-dev libfreetype-dev libpng-dev libjpeg-dev`. Free disk first (`target/debug/incremental`).
- **Export manifests** (`types/*.exports`) come from a live session (`Rscript scripts/export-manifests.R`) on an R at least as new as the recorded one, because a hand-written or older-R manifest turns real exports into false `unresolved` findings. Meta-packages expand through `stubs::META_PACKAGE_MEMBERS`.
- **Stubs** are declaration-only `.Rtypes` files in `types/`, using the `#:` grammar with the loader in `semantics/src/stubs.rs`. They are a set-once salsa input, and project `stubs/*.Rtypes` files override them. An overload set ends with an `Any` fallback.
- **Landing-page and README samples are captured from the running tools**, never hand-edited, and the landing markup renders through `set:html` because Astro strips whitespace-only content. The landing samples are tests (`test_docs`); the README's two diagnostics are plain text from `ry check` piped to a file (ASCII, no colour), which nothing checks, so re-capture them when a message or blame range changes.

### Conventions

- **Verify with CI's toolchain:** run `rustup update stable` first, and check for a formatting diff rather than an exit code piped through `head`. The nightly-only `rustfmt.toml` keys warn on stable.
- **Exclude exactly `zed_ry`** (`--workspace --exclude zed_ry`), because cargo only warns on a misspelled `--exclude` and builds the crate anyway.
- **`[check] typing` defaults off**, so CLI probes need `[check]\ntyping = true` in `ry.toml`, while `[check] unused` defaults on. To read an expression's inferred type, annotate its binding with a type it cannot have and read the `found` half of the mismatch.
- **`reference/formatting-rules.md` is generated** from `crates/format/tests/formatter.template.md` (`RY_BLESS=1 cargo test -p format --test test_format_docs`), so a site-wide link rewrite must include the template.
- **Scratch output goes to absolute paths.** `cd dir && job &` backgrounds the whole compound, so later commands run in the repo and `git add -A` then commits their output. Read `git status` before `git add -A`.
- **The `fuzz/` lockfile is gitignored**, and a fresh resolution can pick a `salsa-macro-rules` that does not match the pinned `salsa`. Seed it from the workspace lock.
- **Docs content:** state every rule with its reason, motivate a design with its technical reason, explain a thing once where it is introduced, tabulate it once in Reference, and link elsewhere. Never use a capability before the page introduces it. The fixed terms are finding, diagnostic code, annotation, check (the command), code analysis (the capability), the language server, and project.
- **Verify every docs claim against the binary**, even for a prose-only edit. A contradiction between two sections of one spec is invisible to every gate (the reference once said `!` takes only `logical` while the checker coerces numbers), so read a page end to end when you touch it.
- **Docs output blocks are tests** (`crates/ry/tests/test_docs.rs`, `development/testing.md` "Docs examples"). A fence info of `text ry check typing` pairs the output with the code or tab group before it, and unmarked blocks are untested. A tab group with no output block must give the same findings in both tabs. Keep marker words free of `/`, quotes and braces, because Expressive Code reads those in the fence meta as highlight markers.
- **Docs are served as Markdown too** (user direction, for agents): `/<page>.md`, `/llms.txt`, `/llms-full.txt`, built from the raw MDX by `docs/src/lib/markdown.ts` rather than the `starlight-llms-txt` plugin, which converts rendered HTML and has no per-page files. Sidebar order comes from `virtual:starlight/user-config`, so the sidebar in `astro.config.ts` stays the one source of order. The docs build needs `bun --bun run astro build`, because the container's Node is older than Astro 7 requires.
- **Docs site structure:** Introduction (overview, installation, at a glance, benchmarks), Tutorial (four pages, one per migration step), Reference and Development (`docs/astro.config.ts`; owner direction). A new user topic joins a tutorial page as a section, and detail goes to Reference; every moved page keeps its old URL as an Astro redirect. The sidebar keeps its scroll position across page loads through `docs/src/components/Sidebar.astro`, because the theme scrolls `.sidebar-content`, which Starlight's own persister does not watch. Breadcrumbs come from the sidebar (`docs/src/components/PageTitle.astro`).
- **Benchmark numbers have one source:** `tools/bench/why/results.json` (best time and largest peak RSS per program and engine, from `os.wait4`), written by `just bench-why --write`, which also rewrites the `<!-- bench-why -->` table in `README.md` and `editors/code/README.md` (GitHub and the Marketplace render those as they are). `docs/src/lib/benchmarks.ts` renders it (and the programs beside it) for the Benchmark components, the landing page and the pages' Markdown, so never copy a number into prose. Every table on the site is a CPU tab and a Memory tab (`benchmarkViews`, `syncKey="benchmark-metric"`); the READMEs, which cannot show tabs, get one combined table from `run.py`'s `readme_table`. The typed programs' strict `ry.toml` is force-added, because the root `.gitignore` ignores every `ry.toml`.
- **UI:** no `border-l` accent rail on rounded elements.
