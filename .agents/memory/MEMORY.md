# Memory

Cross-session knowledge base for the agents building ry, in three horizons. **Short-term** holds the current focus, so prune an item once it is resolved. **Mid-term** holds active priorities and debt. **Long-term** holds durable, non-obvious traps and their rationale. Every entry is context-free and timeless, and points at code or docs instead of restating them.

`.agents/orchestrator.md` is the brief for the orchestrating session only, and every other agent ignores it. The companion files are `backlog.md` (open work, plus a one-line shipped ledger at the bottom), `decisions.md` (settled decisions and why), `test-user-reports.md` (closed simulated-user findings), and `worklog.md` (chronological, appended by a routine). The specs live in the docs site: `reference/type-system.mdx` is the typing contract, `type-checking/` introduces it one short page per idea, and `contributing/{architecture,structure,testing,development,authoring-stubs}.md` cover the internals. Unsettled design work goes to `docs/…/contributing/design/` (out of the sidebar, listed on its index page), never here.

## Short-term

- **Docs pages follow the writing rules in `AGENTS.md`, and a page that reads like a telegram is as much a regression as dense prose.** Read a page aloud when you edit it, and keep a reason inside its sentence rather than splitting it off. Before rewriting a page, run an adversarial reader subagent with the owner's objections as the rubric (too abstract, information the reader does not need, a term used before it is introduced, copy about the tool instead of what the reader gets).
- **A new em-dash in a diagnostic or a comment is a regression.** Two survive on purpose as test data (`literate.rs`, `test_cli.rs`), and `worklog.md` keeps its original wording.
- **Validate a docs link against the ids in the built HTML** (`docs/dist/**/index.html` after `cd docs && bun run build`), never against a hand-rolled slug, because two headings that differ only in punctuation slug to the same id and the second silently becomes `-1`.
- **User pages open with why the reader should care and the task they do most, as a verified snippet** (the reload loop, `ry run` inside a package, leads `guides/console.md`, `guides/loading-packages.md` and `getting-started.md`). Step-2 pages list the Comments tab first and step-3/4 pages the Inline tab first; tabs sync by label, so the order is per page. Tagged unions in examples go one variant per line with a leading `|` (user preference), which `ry fmt` keeps. In `vectors-and-lists.mdx`, R lists are "fixed-shape" and "any length", so "record" and "tuple" name only ry's own types.

## Mid-term

- **Scope (user directive): ry becomes a full, backwards-compatible reimplementation of R, extended with ry's typing.** `AGENTS.md` ("Goals" and "Process") holds the mandate, the benchmark dependency set, and the process rules. The top priority is designing the R C API layer (`SEXP`, memory protection, `.Call`), because most benchmark dependencies ship compiled code against it, so it constrains the architecture more than the JIT does. Inline annotations, the comment-agreement warning and strict mode's untyped-parameter rule have shipped (`decisions.md`, "How inline annotations are built"), and so has lazy package loading (`ry load` on ry's own runtime by default, the `ry run` console on ry's runtime, the `ry R` console and plain-R `load_all()` on GNU R; `decisions.md`, "the package-development loader"; gaps in `backlog.md`, "Open: the package loader"). Then come the runtime, the typed table type that must outperform data.table, and a JIT on the level of Bun. Progress is measured on three synthetic code bases (finance, data science, biostatistics) of about 300,000 lines in about 500 files each.
- **Positioning (user direction; final framing is the agents' call, settled in `decisions.md` "positioning"):** the website and docs sell ry's use case plainly. One toolchain for R, plus a type system, plus runtime features beyond GNU R ("R++"); strict mode allows only those ("R--"), possibly drawn as a Venn diagram. The pitch shows a plain-R snippet, then a benchmark of GNU R against ry's JIT against ry with typed runtime features. ry may add runtime features such as stricter arrays for speed, provided they convert to normal R structures. The GNU R runtime keeps working with `#:` comments. The migration story has four steps, and the docs structure follows them: (1) it works on your code today, (2) type your code, (3) inline types, (4) R++ types. R++ features (custom types and records, tagged unions, `match`, `DataFrame`, the standard library) get their own section, clearly separate from classic R support. Target audience: legacy R code bases moving into the agentic age, where agent-written systems need the verification a type system provides.
- **Naming of ry's own types and APIs (user direction):** new-world types are UpperCamelCase (`DataFrame`, `Result`, `Dict`, `Set`, `List`, `Str`), which sets them apart from R's lowercase types. The table API is Polars-style, with qualified names such as `DataFrame.filter` used with `|>`. data.table syntax stays for compatibility with existing code only.
- **Inline annotations run end to end** (`decisions.md`, "inline annotations at run time"): ry's runtime checks parameter and return types at function boundaries, GNU R runs the erasure, and `ry run` and `ry R` print the annotation warnings and enforce strict mode first. `ry load` enforces strict mode on the package's `R/` files on both runtimes (`preflight::check_package`, through `cli::analyze_project`, the same project analysis `ry check` runs). Gaps are in `backlog.md`, "Open: the runtime".
- **Runtime status: the interpreter and the C API both exist; base R still comes from the user's GNU R.** `crates/interp` (evaluator, tier-0 bytecode, conditions, S3 and S4 dispatch, base internals in Rust) sits on `crates/heap` and links into `crates/libr` (`libR.so`, headers in `include/`), which covers the measured C API surface, ALTREP, connections, serialization, Rmath and the numerical routines, with BLAS and LAPACK header-only against the system libraries. `crates/rcmd` builds and installs packages with `R CMD INSTALL` semantics against ry's R home, and the interpreter plugs into libr through the `libr::eval::Evaluator` hook. `ry run script.R` runs a script on it (`ry R script.R` on GNU R), and the oracle's second engine is `ProcessEngine::ry`. The default packages' native routines are Rust (`builtin_libraries.rs`), filled in per package. Base R comes from any GNU R 4.3 or later, and the runtime emulates that version, with changed behavior gated by `interp::system::r_at_least` (`decisions.md`, "The runtime emulates the GNU R version it loads base R from"). `decisions.md` ("the interpreter and base R", "the runtime's object model, collector and native boundary", "the full C API surface and package installation") has the settled shape; `backlog.md` ("Open: the runtime") the gaps.
- **R's graphics engine runs on ry's runtime** (`crates/interp/src/graphics_engine.rs`, the C API in `crates/libr/src/graphics.rs`; `decisions.md`, "One graphics engine for base graphics, grid and device packages"). Base graphics, grid and device packages such as ragg all draw through one engine to `DevDesc` callbacks, and the built-in devices are `DevDesc`s too. The `grid__*` oracle cases (grid units and grobs, the display list, ragg and lattice pixel checksums) match GNU R exactly and need ragg and lattice in `.corpus/library`. ragg's, gtable's, xts's and PerformanceAnalytics' test suites pass under ry. Gaps: `backlog.md`, "Graphics gaps".
- **The JIT compiles hot bodies and loops, with direct calls; compiled-to-compiled calls are next** (`crates/jit`, `decisions.md` "the JIT tier", `r-runtime.md` section 5 "What tier 1 does today"). `python3 tools/bench/jit/run.py` compares GNU R's bytecode compiler, ry tier 0 and the JIT: scalar loops (`loop_sum`, `integer_loop`, `drawdown`) run tens of times faster than tier 0 and well ahead of GNU R, while vector-bound and call-heavy code (`vector_arith`, `fib`, `lapply`) is at parity with GNU R or slightly behind, and the JIT is never measurably slower than tier 0. `RY_JIT_LOG=1` names each compiled body and the instructions it leaves to tier 0, which is the first thing to read when a compiled loop is slow. `just bench-why` regenerates the user-facing table in `why-ry.mdx` ("Speed"); typed runs as fast as untyped, because static types do not yet remove guards, except the typed `array_*` programs, which run 50 to 200 times slower because `Array` element access (`x[[i]]` goes through `DispatchSubject`) stays in tier 0. Open regression: since in-place rebinding, `x <- f(x, ...)` compiles to `CallRebinding`, which the JIT inlines only when `x` is already proven plain, so a loop like `s <- add(s, i)` never leaves tier 0 (why-ry `closures` went from 2.1x to 0.9x GNU R). Next: compiled-to-compiled calls (fib), then static types as early profiles. Debt: machine code and `Compiled` boxes of invalidated bodies are never freed.
- **`DataFrame` (the typed table type) runs in ry's runtime with a Polars-style API.** `crates/table` holds the Polars engine, the query IR and the lazy planner (`lazy.rs`: `Plan`, `Step`, the optimizer, `explain`); `crates/interp/src/dataframe.rs` defines `col`/`Expr.*` and the verbs (`DataFrame.select`, `with_columns`, `filter`, `group_by` + `GroupBy.agg`, `sort`, `join`, `join_asof`, `head`, `LazyFrame.*`, `collect`, `explain`), and `crates/interp/src/frame.rs` the value itself (class `"DataFrame"`, readers, writers, conversions, and `x[i, j, by]` kept as data.table compatibility). The checker refines each verb call from the syntax of its arguments (`refine_dataframe_call` in `check.rs`), so the schema flows through `DataFrame{...}` (Array columns such as `[1.5, 2]` store as plain vectors, and `df$x` reads back a plain vector, see `decisions.md`), `LazyFrame{...}`, `GroupBy{keys; rest}`; the IDE completes and hovers column strings (`dataframe_columns_for` in `ide.rs`). Decisions: `decisions.md` ("The built-in frame", "Frames as runtime values", "The DataFrame API is Polars'"); user view: `guides/dataframes.md`; gaps: `backlog.md` ("Open: DataFrame"). `tools/bench/table/ry.R` runs the db-benchmark questions through the verbs under `ry run` beside `datatable.R`: at 1e7 rows on 4 cores it beats data.table on every question, 5.2 s in total against 26.2 s (best of two, same checksums, release build; table in `contributing/design/r-runtime.md`, section 7); only the `:=` loops still use data.table syntax, and data.table for the run lives in a scratch library passed as `RY_BENCH_RLIB`. data.table's helpers (`fread`/`fwrite`, `setkey`/`setorder`, `unique`, `rbindlist`, `melt`/`dcast`, `shift`, `fifelse`, `nafill`, `rleid`, `tstrsplit` and friends) live in `crates/table/src/ops.rs` and `io.rs`, typed by the checker; `ops_benchmark` beats `tools/bench/table/ops.R` on each at 1e7 rows except `setkey` (about 10% behind) and `dcast` (parity), measured from Rust. R calls to these names run data.table's own C, which at 1e7 rows runs as fast as on GNU R or faster under ry because the hot C API accessors skip the error boundary and the collector stays out of their way (`decisions.md`, "data.table's C runs at or below GNU R's time"); routing them to the engine was measured and rejected (`decisions.md`, "data.table's helpers run data.table's own C"; numbers in `guides/dataframes.md`).
- **data.table code runs on ry's engine unchanged.** `crates/interp/src/data_table.rs` answers `[` on a plain data.table when the result is guaranteed identical to data.table's and declines to data.table otherwise (`decisions.md`, "data.table queries run on ry's engine"; user view in `guides/dataframes.md`). `crates/oracle/cases/datatable__*.R` pin it against GNU R; `options(ry.datatable.trace = TRUE)` shows which engine answered. Widening what it accepts is in `backlog.md` ("Open: the data.table bridge").
- **Records, tuples, tags and `match` exist end to end**: parser, formatter, checker with exhaustiveness (`crates/semantics/src/exhaustiveness.rs`), IDE, and interpreter (`crates/interp/src/records.rs`). A `type` over any of them makes it nominal (decision record "Nominal and structural types cover both product and sum types"), and every shape-reading check projects through the definition. The typing contract is the reference section "Records, tuples and tags"; rationale and open questions stay in `contributing/design/records-and-tags.md`. The R functions that accept one are listed once in `crates/syntax/src/native_values.rs`, which both the checker's `type-mismatch` on `sum(point)` and the runtime's boundary error read. Not done in the checker: a missing number or string case is reported only as `_`. Not done in the runtime: payload-free tags still allocate per evaluation instead of sharing one constant, `$<-` always copies instead of reusing an unshared value, the libr side (`TYPEOF` 27, opaque accessors) has no C-level test, and `crates/oracle/cases/syntax__ry_lookalikes_stay_r.expected` was written by hand and needs re-recording under GNU R.
- **Corpus packages' own tests run under ry through `oracle packages`** (`contributing/corpus-and-oracle.md`, `decisions.md` "package tests through the oracle"). The rate is the share of packages GNU R passes that ry passes too: 97 of 146 (66.4%). 236 of the 238 corpus packages (the closure plus svglite and magick, which must be built from source on ry) install from source with `oracle install` and load: Rblpapi needs Bloomberg's proprietary blpapi3, and magick needs Magick++. ## Long-term

- **HIR lists are `Span`s into the module's side arrays, and every HIR kind is `Copy`** (`crates/semantics/src/hir.rs`). Read a list as `module[span]`, visit children with `Module::for_each_child`, and copy a kind out (`*module.kind(id)`) instead of cloning lists to release a borrow before a `&mut self` call. Literal text is a `Text` span into the module (`module[text]`), never a `Symbol`: the interner never frees, so interning literals leaks every spelling typed in the editor. Lowering keeps the old `ExprId` order (call arguments before the callee), which fixtures and every per-expression map rely on.
- **The toolchain is a dated nightly pinned in `rust-toolchain.toml` (user directive),** so std's allocator API and other nightly features with a clear payoff are usable before they stabilize. Move the date on purpose, together with the fixes the new nightly needs; `flake.nix` reads the same file. Nightly rustfmt applies `rustfmt.toml`'s unstable import settings, so every file has a single `use { ... }` tree. Policy: `decisions.md`, "Data-oriented design and explicit allocators".
- **Positioning:** one toolchain for R, a type system on top of R, R++ for everything ry runs (R plus its additions) and R-- for strict mode, sold through a four-step migration that the docs sidebar mirrors (`decisions.md`, "positioning"). The landing page sells features first (tabbed toolchain, then tabbed runtime) and the migration last, with almost no prose. Keep the landing page, `why-ry.mdx` and the sidebar on the same step names.

### Runtime traps

- **An Array is an R vector with `flag_bits::ARRAY` set** (`decisions.md`, "An Array is a flagged R vector"). Any new fast path that reads vector storage directly (bytecode, JIT, a builtin shortcut) must refuse a flagged vector, or it skips the strict checks in `crates/interp/src/arrays.rs`. Small operator results may be shared constants, so `arrays::finish_result` copies before flagging. A `duplicate` drops the flag, so Array code that copies must re-flag with `arrays::finish`.
- **The interpreter is process-global, so an `interp` integration test binary holds exactly one `#[test]`**; a second test in parallel threads crashes. A symbol's name bytes are `symbol.car().bytes()`; `Sexp::bytes()` on the symbol itself reads garbage.
- **Growability lives in the heap's resizable flag, and `LEVELS` reports it as GNU R's gp bit `0x20`** (`gp::GROWABLE`, `crates/libr/src/attributes.rs`). Packages built against GNU R before 4.6, data.table among them, test `LEVELS(x) & 0x20` directly instead of calling `IS_GROWABLE`, so without it `data.table()` and `setDT` fail with "attempt to resize a non-resizable vector".
- **An ALTREP object's header holds no length**: read it with `libr::altrep::length`, never `Sexp::length`, which returns garbage for ALTREP and caused a multi-gigabyte allocation in `crates/libr/src/frame_altrep.rs`.
- **`libR.so` has its own global allocator** (mimalloc in `crates/libr/src/libr.rs`), because the binary's allocator does not reach a separate shared object, and glibc malloc there cost page faults and a memset on every large vector. It must use the `local_dynamic_tls` feature: the default TLS model fails `dlopen` with "cannot allocate memory in static TLS block". It must also use the `v2` allocator: the default v3 crashes in `mi_thread_init` (a null thread heap) on the second thread that allocates after the first one exits, which is what every libr test binary does.
- **Do not run `cargo fmt` on a whole crate**: `rustfmt.toml` sets nightly-only import options and the code is not stable-rustfmt clean, so stable `cargo fmt -p interp` rewrites dozens of unrelated files.
- **testthat calls `gc()` after every test file that registered a teardown** (`teardown_run`), so a 500-file suite runs hundreds of full collections. A full collection with a 300,000-line package forced takes about 600 ms on GNU R and about 100 ms on ry, which is why per-test suite time and process wall time give very different ratios.
- **Polars computes `NaN` where R says `NA`** (`cor` over a constant group, for one), so every IR lowering that can produce `NaN` must decide which R means. `crates/table/tests/test_table.rs` checks results against data.table.

- **A Rust function that allocates while it holds a handle nothing else roots must root it first** (`heap.root`, or the `keep` list of `Heap::allocate`). Collection stress is the only thing that shows it, so run `crates/libr/tests/test_fuzz_native.rs` with a large `FUZZ_ITERS` after touching allocation paths.
- **Native code must never be called from Rust except through a C trampoline in `native.c`**, and a callback native code hands to the API (`R_UnwindProtect` and friends) must run from C, so a `longjmp` or a C++ exception never crosses a Rust frame. An exported API function runs its body through `boundary::enter`.
- **A data symbol exported from `native.c` is marked `RY_EXPORT_DATA`**, not `RY_EXPORT`; `build.rs` reads both markers into the version script, and a function-pointer variable is named by the `(*name)` inside its declarator.
- **The corpus tests (`test_corpus_binaries`, `test_corpus_calls`, `RY_SOURCE_PACKAGES` in `test_install`) need `.corpus/library`** from `tools/corpus/install.R` and skip without it. Re-record `tests/data/corpus_calls/cases.rds` under `LC_ALL=C.UTF-8`, or string routines record C-locale results.
- **The pinned nightly cargo gives every build unit its own `target/<profile>/build/<pkg>/<hash>/out/` directory and has no `deps/`**, so the fresh `libR.so` from `cargo test` is in libr's newest build output, not beside the test executable; the copy in `target/<profile>` is only refreshed by `cargo build`. `crates/libr/tests/harness.rs` (`library_path`) picks the newest one, and the `ry-lang` docs and scenario tests run `cargo build -p libr` first, because `ry` loads the copy beside itself and refuses a stale one.
- **Cross-building the macOS runtime from Linux needs clang with ld64.lld, not zig.** zig's Mach-O linker ignores `-exported_symbols_list` and exports every symbol (about a million), which hides export bugs. Use a macOS SDK (`SDKROOT`) and a `CC`/linker wrapper running `clang --target=arm64-apple-macos11 -isysroot $SDKROOT -fuse-ld=lld`; the Windows CLI checks with `zig cc -target x86_64-windows-gnu` as `CC` once cc-rs's `--target=` flag is stripped.
- **On macOS, `dyn.load` opens a rebound copy of GNU R's package binaries** (`decisions.md`, "macOS packages bind to ry's libR"), cached under `~/Library/Caches/ry/rebound/`. Links around the copy mirror the original's directory and as many ancestors as its `@loader_path` paths climb.
- **A C function native code calls must be marked `RY_EXPORT` in `native.c`**, because rustc's version script hides C symbols in a cdylib and `build.rs` exports only the marked ones.
- **A default package's native routine raises errors with `unwind::error`**, which reports the
  calling closure as GNU R's `error()` does (`Error in rgb(2, 0, 0)`). Only the `.External2`
  routines report their own call, through `NativeCall::error`.
- **Translate a C `do { ... } while (a > b)` that can meet NaN as `if !(a > b) { break }`**, never `if a <= b { break }`: a NaN comparison is false, so the C loop ends and the inverted one spins forever (`rmath.rs`).
- **Never copy GNU R's GPL code into the repository** (`decisions.md`, "runtime licensing"). Headers and implementation are written independently; vendored test packages carry their own license (brio is MIT).
- **The methods package's R code relies on native quirks** (`crates/interp/src/methods.rs`): `slot<-` (`R_set_slot`) modifies its argument in place, because the default `initialize` calls it as a plain function on a fresh copy and drops the result; `.findInheritedMethods` turns primitive dispatch off through `.allowPrimitiveMethods(FALSE)` (`allow_primitive_methods`), or selection recurses; a signature argument that fails to evaluate is reported against the call `h(simpleError(msg, call))`, as in GNU R. Dispatch only treats a generic's argument as `"missing"` when its own binding is missing, not when it was passed on from a caller where it is missing.
- **GNU R's own default-package shared libraries can never load on ry's heap**, because they are built against R's internal headers and inline the object layout (`LENGTH`, `PROTECT` through `R_PPStack`). Their routines are Rust in `crates/interp/src/builtin_libraries.rs` and the per-package modules; never try to make `methods.so` or `stats.so` load.
- **Read a closure's body through `bytecode::closure_body`, never `function.cdr()`**, because a body that ran twice (or once, with a loop) is replaced by its compiled `BCODESXP`.
- **A binding created outside a function frame must go through `Heap::define`** (and removals through `remove_binding`, enclosure changes through `set_enclosure`), because those move the binding epoch the bytecode's inline caches trust. An environment that is a closure frame carries `gp::FUNCTION_FRAME` and never moves it.
- **gp bit 12 means `TYPED_DEFINITION` on a formals pairlist or body and `CHECKED_PROMISE` on a promise** (`heap::object::gp`). Both belong to the inline-annotation checks (`crates/interp/src/annotations.rs`); `annotations::leave` must run at every closure exit, error or not, or a stale pending check outlives its frame.
- **Source references follow `keep.source` per top-level expression** (`interp::lower`, `interp::session`). `ry run` and the console parse the whole input but lower each expression just before it runs, because `options(keep.source = TRUE)` in a script affects the expressions after it, as in GNU R. `Interp.srcref` is GNU R's `R_Srcref` and `Frame.srcref` the caller's value at the call; `{` sets it per statement (`Op::SetSrcref` in compiled code, emitted only when the brace carries srcrefs, so code without kept source pays nothing), and `run_closure` sets it to the closure's own `srcref`.
- **ry's parse errors inside a `#:` comment are not R syntax errors** (`ParseError::in_annotation`). The runtime's parser and the console's completeness test skip them, or a malformed comment stops a script GNU R would run.
- **`missing()` counts a defaulted formal as missing only in its own function**: following an argument back to a caller (`h(where)` with `where` defaulted) yields `FALSE`, as GNU R's `R_isMissing` does (`eval::is_missing`). The methods package's `registerNames` depends on it.

- **`cargo build -p ry-lang` alone leaves `libR.so` stale**, and the interpreter is linked into it, so a runtime fix seems to have no effect. Build `-p ry-lang -p libr` together.
- **Native code builds calls with `LCONS`, so their argument cells are `LANGSXP`, not `LISTSXP`.** `libr::eval::normalize_argument_cells` retypes them before the interpreter walks a call.
- **A `cbind`/`rbind` S3 method gets only the `...` arguments, never `deparse.level`**, and a vector without a tag is named from its `...` promise's expression (`subset.rs`, `argument_expressions`).
- **The oracle stops a case at its first top-level error**, so it cannot show a script continuing under `options(error = ...)`; compare such behavior against `Rscript` directly.
- **Every non-missing argument gets a promise, constants included** (`eval::promise_args`), because native code such as lazyeval and ellipsis reads a promise's environment to tell whether it was forced.
- **Environment listing order is derived, not stored** (`heap::env::Frame::listed_cells`): newest binding first, a closure's formals last, hashed frames by PJW bucket. GNU R's hash-table growth rule is not reproduced, so a hashed frame with many bindings can list differently.

- **Every JIT helper that can allocate must release its handles (`scoped` in `crates/jit/src/runtime.rs`)**, because every interpreter constructor roots its result and compiled loops have no backward jump where tier 0 would release them. A helper that skipped it kept each boxed scalar alive until the call returned (1.6 GB for 10M iterations). Compiled code stores a helper's result in the register window before it allocates again, which is what makes the release safe.
- **Compiled code must write variables back before anything that can read the environment** and forget them after anything that can write it, including the first read of a formal whose default is an expression (`crates/jit/src/analysis.rs`, `defaulted`) and any warning, which can run a calling handler (the `HANDOFF` slow paths and `Effect::PureUnlessObserved`). The `ry-jit` oracle engine (`RY_JIT=force`) and `crates/jit/tests/test_tiers.rs` are what catch a missed case; run both after changing the JIT or tier 0's instruction set.

### Performance traps

- **A per-item query must never scan a per-file or per-project list.** Compute once per file in a memoized query and probe per item. `item_spans` is the single source of top-level item identity, so never re-derive the classification. Such a quadratic has two factors (items times names looked up), so vary both axes when measuring, because either axis alone looks linear.
- **A per-item read that joins over a project-wide list needs a cap**, not just memoization (`CONDITIONAL_SLOT_JOIN_CAP`, widening to `Unknown`).
- **A check reads per-name firewalls, never a project-wide map** (`package_name`, `interface_group`, `frame_binder`). `crates/semantics/tests/test_incremental.rs` pins it by counting query executions.
- **Never call `Checker::infer` twice on one expression.** It has no memo, so a double walk made operator chains cost 2^depth and reported each finding 2^depth times. The fixtures dedup, so they cannot see it. Thread the `Ty` you already have.
- **`GlobalEnv` facts are borrowed per-file values** (`&'db`). Returning them owned makes every item pay for the whole project.
- **Hot tracked queries returning maps or vectors use `returns(ref)`**, because `returns(clone)` deep-clones per call.
- **A type is a hash-consed DAG, so walk it with a memo**, never as a tree (`substitute_rigid` went from 278M to 2M calls).
- **A query that reads a syntax tree must keep a small memoized result and be warmed in `diagnostics::derive_from_syntax`**, and its syntax half must not depend on naming. `ry check` derives every tree fact across all cores in its first pass, so a tree reader left out walks other files' trees on the checking threads later. Split a finding that also needs naming or project declarations into a memoized syntax half and a cheap join (`decisions.md`, "Syntax trees are evicted, and only small syntax facts are memoized").
- **The server's inputs are `Durability::MEDIUM`, except open documents and `ProjectFiles`, which are `LOW`.** A new place that creates, reloads or rewrites a `SourceFile` must name a durability, because a setter without one keeps the field's current durability, and a `MEDIUM` write makes every memo in the project deep-verify. Salsa never backdates a memo whose durability drops, so the project-wide maps must be `LOW` before any file's first edit (they read the `LOW` `ProjectFiles`), or that edit re-executes every item check. One `LOW` input that most memos read (the stubs once were) silently turns every keystroke into a full-project deep verification. A project-wide map reads per-file memos, never per-item ones (architecture page, "Keeping project-wide work cheap"). `ry debug analysis-stats` and `examples/keystroke_probe.rs` mirror these durabilities, so their timings match the server's; a probe that enters an input at the default `LOW` measures a full deep verification instead. Lowering an opened file to `LOW` therefore re-runs once every fold that reads it, so a fold that only editor requests read must be re-derived in idle time (`Worker::editor_folds_stale`), or the first request after an open pays for it.
- **Salsa clears a handle's cancellation flag whenever a top-level query returns** (`DbGuard::drop` in salsa's `attach.rs`). A flip that lands at the end of a query is lost, so background work that must stop for a queued job polls `CancelHandle::has_queued_jobs` between units of work instead of relying on the token alone (`Worker::in_parallel` in `crates/ry/src/server.rs`).
- **A composite type past `TYPE_SIZE_CEILING` records as `Unknown`** in `Checker::record`. `types::type_size` counts paths, not distinct nodes, because a consumer walking a type pays the tree it denotes. Without the ceiling, a record whose fields all return that record grew tenfold per level and one file never finished.
- **A write inside a call-argument block binds at top level**, so `test_that("x", { out <- f() })` publishes `out` package-wide, which is why a package's tests can dominate its cost. Whether R binds outward depends on the callee: `try`, `suppressWarnings` and `invisible` do, while `local` and `test_that` do not.
- **Measurement traps.** Alternate the two binaries run by run, because sequential blocks showed a fake 2x win. Measure the analysis path with `--output json`, because the human reporter is itself quadratic in findings. Compare corpus outputs as unique sorted records, not line counts (baselines: data.table 4077, dplyr 675, ggplot2 1091, shiny 1038). Every in-container timing is effectively a two-core number or worse.
- **Budgets:** keystroke-to-diagnostics p50 at or under 30 ms and p95 at or under 100 ms at 300K LoC, pinned by `crates/semantics/tests/test_perf.rs` (`just perf`, which needs the fetched corpus). For reference, 794K lines across 69 CRAN packages check cold in about 14 s at about 1.3 KiB resident per line, with a keystroke p50 of about 12 ms.

### Semantics traps

- **`GlobalEnv` has no default method bodies, on purpose.** The SCC fixpoint's view is a second implementor, and a defaulted method silently gives it a wrong answer (this once collapsed every recursive function using `Date + 1` to `Unknown`). Test such facts with a recursive and non-recursive fixture pair.
- **Dispatch and the numeric constraint must read the same class scope** (stubs plus project), so a package's own `+.Money` makes `Money` arithmetic.
- **A read recorded by name instead of by expression id is invisible to the slot model**, which is why `%op%` reads go through `mark_slot_read`.
- **One structural map rewrites types: `types::map_child_types`** (reads use `for_each_child_type` and `Parameter::types`). A second hand-written walk once skipped a parameter's default and leaked an inference variable across the item boundary, so new `TyKind`, `FunctionType` or `Parameter` members go there and nowhere else.
- **Every type the checker prints must parse back** (`test_roundtrip.rs`), so a new constraint, `TyKind` or rendering includes its grammar side. A function member of a union renders parenthesized.
- **Every mismatch report goes through `Checker::type_mismatch`**, which narrows record and function mismatches to the failing field or position and narrows the range with the message.
- **A finding underlines the smallest expression its message is about.** Thread narrower ranges (`name_range` on fields and call arguments), keep the whole type as the verdict, and use the leaves only to place it.
- **Every finding inside an item is reported**, and only the export is cut to `Unknown` when the item fails.
- **A `#:` annotation declares parameter types, never the parameter list.** The export is always the formals, and `check_declared_function` owns the reconciliation, so a call is never blamed for an annotation's mistake.
- **Do not `table.resolve` a type you display as written**, because resolve expands aliases.
- **One `TypeRenderer` spans everything that shares variable names** (a signature, both sides of a mismatch).
- **Immediate reads resolve against the nearest earlier writer in the file, while deferred reads (closures) differ by kind.** A package closure sees the project-wide winner and a script closure sees the settled file frame. Getting this backwards breaks forward references from function bodies.
- **Typing is off unless `ry.toml` says `[check]` `typing = true`.** A throwaway project for checking a docs claim needs that line, or every type rule silently passes.
- **A called name is looked up as a function** (`Checker::function_lookup`, reference "Called names"): non-function bindings are skipped, and the binding the call reached is recorded in `ItemCheck.callee_targets`, which hover, goto, references and rename must follow instead of the plain slot resolution. A type parameter counts as untyped, or `test_roundtrip` finds unwritable schemes.
- **Test files are `DocumentKind::Test`, helper and setup files `TestHelper`** (`semantics::test_document_kind`). Only helpers fill the shared test namespace, and no test binding reaches the package namespace. Removing the old pooling of every test file exposed checker false positives that it used to mask, chiefly rlang's own `expr(foo(...))` being checked as evaluated code inside rlang, where `expr` is a project function rather than a quoting stub.
- **`"x" <- 1` binds `x`** through the name-target arm, not `replacement_base`, which reads the base first.
- **A fixture cannot exercise anything keyed on `PackageMetadata`**, so those cases belong in `crates/ry/tests/test_cli.rs`. Read what a bless recorded before believing it covers the scenario.

### Parser and annotation traps

- **Recovery stops at the statement boundary when the next line assigns** (`starts_new_statement`). `=` does not count, because inside a list it is a named argument. The check scans backwards, because the newline was consumed with the previous element.
- **One mistake, one finding.** A lexer `ERROR_TOKEN` is already diagnosed and suppresses its statement's boundary report, and the `#:` grammar reports once per region (`error_unclosed` lets one unclosed opener through). Never report a consequence beside its cause, and blame the incomplete construct rather than where the search stopped.
- **An unterminated quote ends at its first line break**, so typing a quote does not take the rest of the file out of analysis.
- **`#:` block-form rules are about lines, and a stitched line's marker may sit inside a nested node**, so count lines over all of the block's tokens. A `<T>` binder list is a prefix of the next type, not an item. A refused region is an `ERROR` node, and a block containing one carries no typing payload.
- **A diagnostic code names whose grammar broke**: `syntax-error` for R and `annotation` for `#:` (`SyntaxError::in_annotation`).
- **Formatter:** trailing comments attach inside expression nodes, so placement decisions are token-level (`last_token_before`). Line math uses `significant_range`, and the formatter refuses only on R-grammar errors.
- **Golden error suite** (`crates/syntax/tests/errors`): a new parser error path adds its case in the same change.
- **Inline type grammar defers its trivia** (`Parser::deferred_trivia`): a new `ann_*` path must emit through `bump`, `start` or `checkpoint`, which flush it, never through the builder directly, or trivia lands on the wrong side of a node.
- **An annotated binding is recognized only at a statement start** (`Parser::statement`), because R reads `name:TYPE <- v` as `` `:<-` ``; everywhere else `x:y` stays a range. Tree-sitter judges the erased text (`erase_inline_annotations`), so an annotated fixture needs no allowlist entry.
- **Both annotation spellings lower into one `Annotation`** (`lower_annotation`, `lower_inline_annotation`, `merge_annotations`). A new annotation feature goes into that shared lowering, never into a checker path that knows the spelling.
- **Inline type definitions pair with a `#:` definition directly above them** (`syntax::paired_comment_definition`, which erasure also uses to drop the inline copy), so read definitions through `file_type_definitions`, never by walking the tree for one spelling. An inline union continues onto a line that starts with `|` (`Parser::inline_line_continues_with_pipe`), which is safe because no R statement starts with `|`. `NamedDefinition::inline` only picks the spelling hover shows.
- **The parser's acceptance gate is hard:** zero unadjudicated divergences against tree-sitter, with R as the referee.

### IDE and server

- **Cursor position model:** the smallest end-inclusive expression wins, with a `NameRef` winning a tie, so the declaration scan stays a fallback for every binding kind. Which token declares an item has one answer, `semantics::item_name_range`, and `:=` is never a definition.
- **The server** is one async-lsp frontend thread plus one worker owning the database. Edits flip salsa's cancellation token, and later jobs use a fresh storage handle. Host assembly (config gating, typing modes, suppressions, lints) is shared with the CLI in `crates/ry/src/diagnostics.rs`.
- **Coherence failures panic** (document sync), and IDE lookups never panic.
- **CLI reporting is miette's** (`crates/ry/src/cli.rs`). Its header column counts bytes, so `read_span` re-counts characters. A range over several lines clamps to the first, and sources are borrowed (`NamedText`), never `NamedSource`.
- **A quick fix is a field on the diagnostic** (`Diagnostic.fix`), never a re-derivation in `ide`; the server reads fixes from the diagnostics it publishes after suppressions. Whole-file features (outline, folds, tokens, fixes, selection) have their own fixture suite, `crates/ide/tests/structure`. Gaps: `backlog.md`, "Open: editor parity".
- **The IDE fixtures print the token a range covers**, not a byte offset, so a stub addition never forces a re-bless. If one fails after a corpus change, the range is genuinely wrong.

### Package loader

- **A plan is backend-neutral, and only the R side knows a runtime.** `runtime.R` is shared; `gnur.R` (plus `r.rs`'s RDS transport) and `ry.R` (plus `ry_runtime.rs`'s internals) are the two backends' hooks. Never put R-specific logic in the diff (`loader::diff`).
- **On ry's runtime a lazy binding is a promise over the analysis's own syntax tree** (an external pointer to the file's `Parse`, freed by a weak-reference finalizer), lowered with `interp::lower::lower_node` on first force. Source text never reaches R and nothing parses twice; the cost is that the interpreter keeps no source references.
- **Every reload rule must keep `test_reload_fuzz.rs` green**, which compares a reload against a fresh load in a model. Hand-reasoned rules missed swapped writers, `f <- memoise(f)` wrapping twice, and a fixpoint that stopped before the changed-name set settled.
- **R traps the GNU R backend hit:** `environment<-` strips a closure's bytecode (cache the whole environment instead); `getOption("keep.source.pkgs")` is `FALSE` by default, so it must not shadow `keep.source`; `.Internal(...)` arguments are evaluated, so a language argument needs `quote()` (`.ry_internal`); `ls()` sorts, so hot paths use `names(env)`; the attached package environment keeps names the namespace dropped unless every sync removes stale ones (S4 `.__C__` metadata).
- **A body edit must stop at `file_binds`.** A reload re-derives the edited file's `file_load_index`, `file_items` and `file_binds`; equal binds backdate `package_bindings`, and `diff` skips the laziness-flip scan when the bindings `Arc` is unchanged (`decisions.md`, "A reload re-derives one file"). `test_incremental.rs` counts the executions. The first edit of a file costs about 20 ms more than later ones, because lowering its durability deep-verifies every memo once.
- **Cold `ry run` and `ry load` overlap analysis with base R** through `Loader::prepare`, which the host starts on a thread (`ry_loader_prepare` in libR for ry's runtime, `load::prepare` for GNU R) before R starts. Strict mode reaches ry's runtime as an atomic (`ry_runtime::STRICT`), not through the session lock, so starting R never waits for the prepare. On the 326,000-line bench package, what is left is about 140 ms of base R, 280 ms of parsing and per-file facts on 4 cores, and 300 ms of running eager code, mostly `setClass` and `setMethod` through the `methods` package's R code, which runs about 1.5x slower than on GNU R.
- **Console typeahead reaches fd-0 readers** because the console reads typed-ahead bytes itself only up to the first line break (`take_typed_line` in `repl/src/console.rs`), leaving the rest in the tty for `readLines(file("stdin"))` or a `system()` child. Ctrl-C is seen through an R `interrupt` calling handler plus a chained SIGINT handler, since GNU R swaps its own handler in during `Sys.sleep` and `system()`. Known gap: lines pasted at a prompt in one chunk with the command that reads them go to the console, because the line editor already consumed them.
- **Measure loaders with the same `keep.source`.** `ry run` and `ry R` keep source references on, while `Rscript` runs others without them; that alone is 10 to 20% of a cold load. `tools/loader-bench` is the harness.

### Testing

- **An oracle is trusted only once an injected bug turns it red.** Determinism, idempotence and round-trip are self-consistency checks that a uniformly wrong answer satisfies, and three batteries here stayed green over real mutants.
- **Give a differential oracle inputs that always exist.** The tree-sitter acceptance test never ran while it pointed only at the gitignored corpus, and the test runner hid its skip note.
- **A foreign renderer's expectations are never bulk-blessed.** Adjudicate each case against the typing reference.
- **The fuzz batteries' cost is re-parsing the stub corpus per fresh database**, not the iteration count.
- **A gate must fail on its own exit status.** `cmd | grep …; echo OK` always passes, and a background job's output file can be read mid-write.
- **A simulator failure is a server bug until shown otherwise, but check the client model first.** Two false-positive classes came from the simulator, not the server: a reopened document must continue its version from the last one (VS Code does), and the first-wave-is-a-subset check only holds when no config or disk change landed since the sync.
- **`syntax::testing::enable_invariants()` makes every splice reparse also parse from scratch.** The simulator turns it on; a harness that drives incremental code should too.
- **A REPL pty test must expect text the echoed command cannot contain** (`Error: boom`, not `boom`; a `cat` of joined words). Matching the echo returns before the command runs, so the next line races its evaluation and the test asserts nothing about the output.

### REPL and environment

- **The REPL never feeds R input through the console to set state.** Startup work goes through `RApi::eval` between `setup_Rmainloop()` and `run_Rmainloop()`. `contributing/design/repl.md` has the details, including the Windows recipe (`GA_initapp` lives in `Rgraphapp.dll`) and the pty harness requirements (answer the cursor-position query, serialize the sessions). The pty suite is verified on Windows against R 4.5.2 and on Unix.
- **`R.dll` and `ry.exe` are built for gnullvm and linked with lld** (`decisions.md`, "Windows runtime"): GNU ld relocates `SECREL32` TLS offsets, so every `thread_local` access in a relocated DLL crashes, and windows-gnu links msvcrt, not the UCRT packages use. `r-runtime.md` section 11 has the Linux cross-build recipe (host clang and lld over MSYS2's clang64 sysroot packages, which are `.pkg.tar.zst` archives; `pip install zstandard` unpacks them where no `zstd` CLI exists). Run `wine64 ry.exe run file.R` (wine64 is in `/usr/lib/wine`, not on PATH) with `R_HOME=Z:<a Windows R home>`. A Windows R home unpacked with `innoextract` works without executing its DLLs, given zero-byte placeholders at `library/<pkg>/libs/x64/<pkg>.dll` for the default packages. winedbg chokes on the DWARF; `WINEDEBUG=+seh,+loaddll` and `llvm-objdump --disassemble-symbols` locate a crash. `ry.exe` and `R.dll` must come from the same tree (runtime identity). Rtools-ABI test packages: MSYS2 ucrt64 GCC 14.2 headers and static libstdc++ with `clang --target=x86_64-w64-mingw32 -fuse-ld=lld`, linked `-lR -lpthread`.
- **A windows-gnu cross-link needs a synthesized `synchronization` import library**, which the flake's windows `preBuild` makes with `zig dlltool`. A crane deps-only build cannot catch a breakage here, because the dummy sources never reference reedline.
- **R installs in agent containers** (`apt-get install -y --no-install-recommends r-base-core`, or the CRAN apt repo for a current R). `fs` needs `libuv1-dev`, and the tidyverse needs `libcurl4-openssl-dev libharfbuzz-dev libfribidi-dev libfreetype-dev libpng-dev libjpeg-dev`. Free disk first (`target/debug/incremental`).
- **Export manifests** (`types/*.exports`) come from a live session (`Rscript scripts/export-manifests.R`) on an R at least as new as the recorded one, because a hand-written or older-R manifest turns real exports into false `unresolved` findings. Meta-packages expand through `stubs::META_PACKAGE_MEMBERS`.
- **Stubs** are declaration-only `.Rtypes` files in `types/`, using the `#:` grammar with the loader in `semantics/src/stubs.rs`. They are a set-once salsa input, and project `stubs/*.Rtypes` files override them. An overload set ends with an `Any` fallback.
- **Landing-page and README samples are captured from the running tools**, never hand-edited, and the landing markup renders through `set:html` because Astro strips whitespace-only content. The landing samples are tests (`test_docs`); a changed message or blame range means re-capturing the README image with `scripts/render-diagnostic-svg.rs`.

### Conventions

- **Verify with CI's toolchain:** run `rustup update stable` first, and check for a formatting diff rather than an exit code piped through `head`. The nightly-only `rustfmt.toml` keys warn on stable.
- **Exclude exactly `zed_ry`** (`--workspace --exclude zed_ry`), because cargo only warns on a misspelled `--exclude` and builds the crate anyway.
- **`[check] typing` defaults off**, so CLI probes need `[check]\ntyping = true` in `ry.toml`, while `[check] unused` defaults on. To read an expression's inferred type, annotate its binding with a type it cannot have and read the `found` half of the mismatch.
- **`reference/formatting-rules.md` is generated** from `crates/format/tests/formatter.template.md` (`RY_BLESS=1 cargo test -p format --test test_format_docs`), so a site-wide link rewrite must include the template.
- **Scratch output goes to absolute paths.** `cd dir && job &` backgrounds the whole compound, so later commands run in the repo and `git add -A` then commits their output. Read `git status` before `git add -A`.
- **The `fuzz/` lockfile is gitignored**, and a fresh resolution can pick a `salsa-macro-rules` that does not match the pinned `salsa`. Seed it from the workspace lock.
- **Docs content:** state every rule with its reason, motivate a design with its technical reason, explain a thing once where it is introduced, tabulate it once in Reference, and link elsewhere. Never use a capability before the page introduces it. The fixed terms are finding, diagnostic code, annotation, check (the command), code analysis (the capability), the language server, and project.
- **Verify every docs claim against the binary**, even for a prose-only edit. A contradiction between two sections of one spec is invisible to every gate (the reference once said `!` takes only `logical` while the checker coerces numbers), so read a page end to end when you touch it.
- **Docs output blocks are tests** (`crates/ry/tests/test_docs.rs`, `contributing/testing.md` "Docs examples"). A fence info of `text ry check typing` pairs the output with the code or tab group before it, and unmarked blocks are untested. A tab group with no output block must give the same findings in both tabs. Keep marker words free of `/`, quotes and braces, because Expressive Code reads those in the fence meta as highlight markers.
- **Docs are served as Markdown too** (user direction, for agents): `/<page>.md`, `/llms.txt`, `/llms-full.txt`, built from the raw MDX by `docs/src/lib/markdown.ts` rather than the `starlight-llms-txt` plugin, which converts rendered HTML and has no per-page files. Sidebar order comes from `virtual:starlight/user-config`, so the sidebar in `astro.config.ts` stays the one source of order. The docs build needs `bun --bun run astro build`, because the container's Node is older than Astro 7 requires.
- **Docs site structure:** four sidebar groups by purpose (Introduction, Type checking, Reference, Contributing), and no how-to guides (owner decision). The installation page is deliberately absent from the sidebar. Breadcrumbs come from the sidebar (`docs/src/components/PageTitle.astro`).
- **UI:** no `border-l` accent rail on rounded elements.
