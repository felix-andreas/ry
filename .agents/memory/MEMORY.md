# Memory

Cross-session knowledge base for the agents building Roughly. Three horizons:

- **Short-term** — current focus and loose ends. Prune aggressively; delete each item once it is resolved or obvious from the tree.
- **Mid-term** — active priorities, open bugs, and technical debt. Lives across sessions until done.
- **Long-term** — durable, non-obvious design decisions and their rationale. Only things a future agent would otherwise rediscover. Keep terse and point at code or the docs.

Companion documents in this folder (kept separate only because they are larger in scope): `worklog.md` (one line per autonomous work cycle — the *only* deliberately chronological file here; an every-3-hours routine appends to it), `backlog.md` (the prioritized work punch-list — **open work only**), `test-user-reports.md` (simulated-user findings that are closed; a finding moves out of the backlog and into it when it is fixed, so the punch-list stays the work that is left while the reports survive), and `decisions.md` (the settled architecture decision log). Authoritative user- and contributor-facing specs live in the docs site (`docs/src/content/docs/`): `reference/type-system.md` (the typing contract), `type-checking/tutorial.md`, `contributing/{architecture,structure,testing,authoring-stubs}.md` — point at them, don't duplicate. **Unsettled design work is docs too, under `contributing/design/`** — an index page plus the drafts (`open-questions.md` for undecided type-system questions, `data-masking.md` for the NSE sketchpad, `inline-type-syntax.md` for the compiled-dialect proposal whose own recommendation is not to build it, `repl.md` for the runtime-loaded-R console). Those pages are deliberately absent from the sidebar and reachable only from their index, because they are proposals rather than contracts; a draft either graduates into the reference pages or stays as the record of why it was declined. A new design document goes there, not here. Do not spawn new knowledge files for small things; inline them into a horizon below. Every entry must be **context-free and timeless** (clear to a reader with zero project history — no milestone/phase/gate names, commit hashes, or "this session") and **high-signal** (terse; point at code/docs).

## Short-term

- **Adoption reviews are the current source of truth for what to fix next.** Three independent black-box reviews (docs and `--help` only, no source access) simulated an analysis-script user, a CRAN package author, and a numerical-computing user on real multi-file projects. They converged on the same walls, which now head `backlog.md` with a minimal repro each. Two lessons worth keeping: the reviews found *quadratic* behaviour the whole in-house instrument suite had missed, because every witness measured many files rather than one file with many top-level items — a shape real repositories have (generated bindings, a 4,000-line `utils.R`) and the corpus did not; and the highest-value fixes were not new features but *reporting* honesty — a per-item cap on findings, per-call argument caps, and a verdict that changed with the command line all made a clean run mean nothing.
- **An expression is inferred by whoever needs its type, and `Checker::infer` has no memo — so a second call is a second full subtree walk.** `infer_binary` inferred both operands in the operator-dispatch probe and then again in the numeric/comparison fallback, which made a nested chain cost 2^operators: measured 58 / 514 / 1975 / 8708 ms at 16 / 20 / 22 / 24 `+`s, against a flat 20 ms once the operands are threaded through. Two consequences worth remembering. It is not only slow: each re-walk re-reports, so one mistake inside a chain came out 2^depth times in the CLI — while the fixture path showed a single finding, because `item_check` sorts by range and dedups, so **a fixture cannot see a report multiplication at all**. And `&&`/`||`/`:`/`%>%`/`|>` were flat throughout, which is what isolated the cause to the double walk rather than to tree depth. When adding a path that needs an operand's type, thread the `Ty` you already have; never call `infer` again for it.
- **A per-item performance trap to watch for.** Any per-item query that walks or re-classifies the whole file is quadratic in top-level items, and the file-count-based witnesses will not see it. `item_annotation_syntax` did exactly that (13.9s on 2,000 statements). The pattern to use instead: compute once per file in a memoized query, probe per item — the per-item query still cuts off downstream work, because an untouched item's derived value compares equal. `item_spans` is the single source of top-level item identity and ranges; never re-derive the classification, and never scan it per item.

- **REPL Windows support is VERIFIED on real Windows + R 4.5.2** — the pty e2e suite (7 tests, now enabled over ConPTY) runs green, plus `roughly run` exit codes, `system()`, `~`, and `.Platform$GUI`. The original `STATUS_ACCESS_VIOLATION` root cause: `GA_initapp` lives in `Rgraphapp.dll`, not `R.dll`, and skipping it crashes `readconsolecfg`. Recipe details and the follow-on fixes (CRLF feed normalization, `home` from `getRUser()`, the UTF-8 code-page manifest, wrapper-script path vars on Unix) live in `contributing/design/repl.md`. The Unix side of these changes is compile/clippy-checked against x86_64-unknown-linux-gnu only — the next Unix session with R should re-run the pty suite.
- **Manifests are the cheap lever on the tolerance hole, and R is installable here to make them.** A
  namespace with an `.exports` manifest has a knowable export set, so attaching it never triggers the
  blanket unresolved tolerance — no typed declarations needed, every name just types `Unknown`. That
  is how the tidyverse and friends stopped switching the check off project-wide. Two traps: the
  generator must run on an R at least as new as the one each existing manifest records (it now refuses
  and says so — regenerating on an older R silently drops names like `%||%` and turns every use into a
  false `unresolved`), and a *meta*-package like `tidyverse` attaches its members rather than
  exporting them, so activation has to expand to them (`stubs::META_PACKAGE_MEMBERS`; the generator
  prints what a live session attaches, so the list is checkable). Installing the tidyverse from source
  needs system headers first: `libcurl4-openssl-dev libharfbuzz-dev libfribidi-dev libfreetype-dev
  libpng-dev libjpeg-dev` (curl, textshaping and ragg fail without them, taking the meta-package with
  them).
- **The Unix REPL is e2e-verified against real R** — the full pty suite (7 tests) runs green (see `contributing/design/repl.md` for the two harness requirements: answer the editor's cursor-position query; serialize sessions). **R installs in agent containers**: plain `apt-get install -y --no-install-recommends r-base-core` is enough for a distro R (Ubuntu ships 4.3.3), or add the CRAN apt repository (`cloud.r-project.org/bin/linux/ubuntu`, key `marutter_pubkey.asc`) for current R; `install.packages` compiles data.table/dplyr/testthat/ggplot2 from source in minutes. **Two build-dependency traps:** `fs` (a testthat dependency) needs `apt-get install libuv1-dev`, and every stub corpus addition must have its `.exports` manifest generated from a live session (`Rscript scripts/export-manifests.R`) — a manifest written from memory turns a real export into a false `unresolved`. Watch disk: the R toolchain + target/ can exhaust the session allowance — delete `target/debug/incremental` first.
- **The REPL must never feed R input through the console just to set state.** `read_console` returning a statement costs a main-loop round trip, and one taken before the editor's first prompt leaves the terminal in the state R found it in — the next read desynchronises, and two pty tests time out. Anything that has to run at startup goes through `RApi::eval` (`R_ParseEvalString`) in the window between `setup_Rmainloop()` and `run_Rmainloop()`: the startup profiles have been sourced, so a profile's own choice is visible and can be deferred to, and no prompt has run so nothing can be perturbed. The console feed is for user input and for the pre-loaded script, nothing else.
- **Parser recovery must stop at the statement boundary, and "did we cross a line?" is the wrong test.** An unclosed `(`/`[` used to adopt every following statement as one more argument — a confident "missing `,`" per line, scaling with the file, and each adopted line lost its own definitions. But a list running onto the next line is ordinary R and a *fragment* there (`beta)`) really is a forgotten separator, so two fixtures pin that report; the signal that separates them is whether the next line **assigns** (`starts_new_statement`). Three traps found the hard way. `=` must NOT count as assigning: inside an argument or parameter list `name = value` is a *named argument*, so counting it broke the commonest forgotten comma of all — the multi-line `list(a = 1\n b = 2)` — into top-level statements, which then drew lint and `unused` findings out of source that had not parsed. The newline is consumed while parsing the element *before* the loop head, so the check must scan backwards — a peek-at-the-loop-head version looked right and never fired. And breaking out of the list is not enough on its own, because the statement loop then sees a stray token where it wants a newline, reports again, and recovers over the next line anyway (`statement_left_group_open` suppresses both).
- **One mistake, one finding: the `#:` type grammar reports once per region.** It cannot resynchronize the way the statement loop can — a region is one expression with no boundary inside it to restart at — so it used to report every token it could not use (nine findings for one mistyped optional parameter, five of them on the same column). `error_at` drops annotation-grammar reports after the first. The refinement that is easy to miss: an **unclosed opener** is discovered at the *end* of the construct it names, so first-wins alone drops the outermost truth for an inner consequence — `error_unclosed` lets exactly one of those through per region.
- **Two whole types side by side are not an explanation, and there is now ONE place that decides.** A function value rejected at a parameter names the failing position (`explain_function_mismatch`); a record names the failing field and, when nested, the path (`explain_record_mismatch`). Both pair by the rule `compatible` uses, so an explanation can never disagree with the verdict — and for records that means optionality is deliberately NOT compared, because `compatible` does not either. Every site that reports two types goes through `Checker::type_mismatch`, which narrows to the field when both sides resolve to records and returns the whole `TypeError` so the RANGE narrows with the message; add new mismatch reports there rather than building `TypeErrorKind::Mismatch` directly, or the narrowing will be present at one site and missing at another. Whole types are still right when the failure is not about one position (a record against a non-record or against `list[T]`, an arity or rest-parameter disagreement). **A type carries no source ranges, so the caret is recovered by walking the field path back against the expression that BUILT the record** — a `list(...)` whose tagged arguments are its fields — which is why the value's `ExprId` rides on `CallArgument`. The part blamed follows the message: the value for a bad field type, the field's NAME for an undeclared one, the innermost list for a missing one. A record that did not come from a literal (a variable) has no field expression, and the whole value stays the blame.
- **`"x" <- 1` binds `x`, and the obvious place to fix that is the wrong one.** R accepts a string where a name belongs (verified: it prints `1`), and it used to bind nothing, so a later read was a false `unresolved`. The tempting fix is `replacement_base` — and it is wrong, because that path *reads* the base before writing it (`names(v) <- x` reads `v`) and marks the write unreportable, neither of which is true of a plain definition. The string literal belongs in the name-target arm by or-pattern; the lowering makes that exact, since `string_value` has already stripped quotes and resolved escapes, so the payload IS the name R binds. Backticks never needed it — `` `y` <- 1 `` lowers to a `NameRef`.
- **A gate pipeline that ends in `echo` cannot fail, and a background job's output file can be read mid-write.** Both bit at once: `cargo test … | grep -E "FAILED|failures:" ; echo TESTS_OK` exits 0 whatever happened, and grepping the task's output file before it finished writing showed a clean prefix — so a real pty failure was reported as a green gate. Read the **completed** output, and make the gate's own exit status the signal (`set -o pipefail`, or assert on `test result: ok` counts) rather than the absence of a grep hit in a partial file. Absence of evidence in a file still being written is not evidence.
- **The REPL pty suite is timing-sensitive and flakes under concurrent load**, distinct from the desynchronisation bug a wrong startup mechanism causes. Signature: a single test fails and the whole suite's wall clock balloons (41 s against a normal 4–6 s for nine tests) while something else saturates the machine. Re-run serially before believing it; three clean runs at 4–6 s is the confirmation. A genuine desync instead shows up reproducibly and pushes the suite to ~90 s.
- **A filed finding is a hypothesis with an expiry date; re-run it before ranking work off it.** An adoption-review entry ranked "`setGeneric` does not define its name, so every call to a project's own S4 generic reports `unresolved`" as the top fix. It had already been fixed (`set_generic_target`), and a second claim in the same entry ("R6 has no stub at all") was mischaracterised — R6 ships an export manifest and resolves once the project declares or attaches it. Two of four claims stale in one bullet. **Always run a control in the same file** (an obviously undefined name) so "no finding" cannot be misread as "the check is off"; that is what distinguished fixed-behaviour from inactive-check here.
- **A fixture cannot exercise anything that keys on `PackageMetadata`.** The attached-package tolerance, `imports_every_name`, and the rest of the metadata layer read a salsa input only a real project sets, so a single-file fixture silently takes the *other* branch — a pair of fixtures written for the tolerance blessed as ordinary `unresolved` warnings while their comments claimed to be testing strict mode. Anything metadata-dependent belongs in the CLI suite (`crates/ry/tests/test_cli.rs`), which builds real project directories. **Bless output is not proof the case reproduces the scenario; read what it blessed.**
- **`GlobalEnv` has no default method bodies, and that is load-bearing.** Two implementors answer it: the ordinary salsa-backed resolver and the *cyclic group's* view used during an SCC fixpoint. A defaulted method lets the second silently inherit a wrong answer — which happened: `arithmetic_classes` defaulted to empty, so `Date + 1` inside any recursive function failed the numeric constraint and the whole scheme collapsed to `Unknown` while its non-recursive twin typed fine, with no diagnostic anywhere. Adding a fact to that trait must stay a compile error at every implementor. The recursive/non-recursive **pair** is the fixture shape that catches it: either alone looks plausible.
- **A class's operator method makes it arithmetic, and "the project's own sources" has to mean the project's.** Operator dispatch resolves `+.Class`/`Arith.Class`/`Ops.Class` through the *global scope* (stubs plus the project), but the numeric constraint's admissibility check consulted the **stub library alone** — so a package defining `+.Money` had its `+` dispatched and its class refused by `function(x) x + 1L`, a false positive on code R runs. The set now comes from both (`GlobalEnv::arithmetic_classes`, memoized per corpus and per project, plus a script's own top level) and rides on `InferenceTable` beside `definitions`. **The generalizable trap: two places decide whether a class participates in arithmetic — dispatch and the constraint — and they must read the same scope.** A class declaring no arithmetic method is still refused, which is also what R does.
- **A `%op%` read must reach the SLOT, not only the by-name set.** The operator is a token, not a `NameRef`, so its read is recorded by name in `quiet_operator_reads` — right for the cross-item check on a package's own operator, and silently useless for a **local** one: the definition had no read resolving to it and reported as a dead store while the calls sat on the next line. Real packages write exactly that shape, aliasing a namespaced operator into a function (`` `%+replace%` <- ggplot2::`%+replace%` ``, `%NA_OR%` in shiny, `%fin%` in data.table's `merge`). `mark_slot_read` is the slot half of a read, factored out for the operator path to call; `resolve_read` stays the only place that maps an expression id, and the unused check is *not* blanket-quiet for operators — an unused local one still reports. **The lesson generalizes: any read recorded by name rather than by expression id is invisible to the slot model.** Check both when adding one.
- **Do not report a consequence next to its cause.** A function whose parameter list never closed does not also get "expected a function body"; that is the same mistake said twice, and the unclosed opener is the version worth reading (`statement_left_group_open` gates it). And an error blamed on "wherever the search stopped" lands off the code — a header running to end of file put a **zero-width** caret on the blank line past the last statement, underlining nothing; blame the construct that is incomplete (the `function` keyword) instead.

Three things must land before the move is safe — see `backlog.md` §test & fuzz architecture review and §fuzzing economics.

This is the documented iteration loop, so a typo'd or renamed case id reads as "my fix works" during exactly the work that renames case ids. Until the harness asserts the filter matched something, confirm the case actually ran before believing a focused green.

Raising `FUZZ_ITERS` on a semantics arm buys stub re-parsing, not coverage.

## Mid-term

- **User direction (standing): drive autonomously toward best-possible shape; empty `backlog.md` §Open; work continuously.** `backlog.md` holds the open work (semantics opportunistic items, editor polish, structure/perf levers, website) and the one-line shipped ledger.
- **The language is `ry`** (renamed from Roughly). Crate `crates/ry`, published as `ry-lang`; binary and lib `ry`; config `ry.toml`; suppression `# ry: allow(...)`; variables `RY_*`; docs at ry-lang.org. **Former spellings still work and must keep working** — `roughly.toml`, `# roughly: allow(...)`, `ROUGHLY_*`, and the extension's `roughly.*` settings all fall back, because each lives where a rename would break silently (the suppression comment worst of all, since it sits in users' own files). `legacy/` is deliberately un-renamed. `backlog.md` §"rename to `ry`: what is left" holds the surfaces that are the user's call.
- **The type system admits only what is fast to check, which means Hindley-Milner (user directive).** Declaration files (`.Rtypes`) carry the one sanctioned exception, today ad-hoc overloading; a user's `#:` annotation is pure HM and declares exactly one signature. Traits/typeclasses are **declined, not deferred** — they are the textbook-correct way to get ad-hoc polymorphism into HM, which is precisely why they are not the bar here. General subtyping is out for the same reason; a declared coercion at a named boundary is the HM-compatible shape any variance work must take. Full record in `decisions.md`; evaluate every proposed type-system feature against it before designing.
- **Open type-system design questions** live in `contributing/design/open-questions.md`: tags/discriminated-union `match` (post-beta, user direction), S3 dispatch, data.frame/matrix modeling, variadic `...` body semantics, NAMESPACE/import model. (Traits are closed — see above.)
- **`GlobalEnv`'s facts are BORROWED per-file values, and returning them owned is a quadratic.** `type_definitions` and `arithmetic_classes` are consulted once per item checked, so handing back an owned copy makes every item pay for the whole project's table: at 2,000 items, typecheck went 18 → 100 ms purely as `@type` declarations went 0 → 2,400. Both are now memoized per-file tracked queries returning `&'db`, and `InferenceTable` holds `Option<&'db …>` because both are pure lookups. Adding a fact to that trait means adding a per-file query, not a per-item merge.
- **The legacy fixture corpus is NOT run by the new code, and it is much larger than the new one.** `legacy/analysis-legacy` holds 2,830 fixture cases against the new stack's 1,192, but `legacy/fixtures` is a harness-only crate and `analysis-legacy/tests/test_fixtures.rs` drives those cases against the *frozen oracle* — no test under `crates/` reads those directories. So they are green on every gate run and prove nothing about the shipping crates. The corpus was reimplemented, not ported: case-name overlap is 15 of 138 for ide and 1 across the whole typecheck suite. (Name overlap understates behavioural overlap — do not read it as 2,830 missing cases.) It is the largest untapped fixture source in the repo, and the one directory partially mined found two real bugs, so mine before anyone proposes deleting `analysis-legacy`.
- **`cd scratch && job &` does NOT move the commands after it, and `git add -A` will commit what they wrote.** The `&` backgrounds the whole `cd`-and-run compound, so every `;`-separated command after it runs in the *original* working directory — which is the repository. A profiling session redirecting output that way put twenty stack dumps in the repo root, and a later `git add -A` committed them. Two habits: write scratch output to an absolute path rather than relying on a `cd`, and read `git status` before `git add -A` rather than after.
- **The frozen stack's ~2,830 fixture cases are runnable as INPUTS, never as expectations.** Its renderers differ in kind — binding-resolution trees for naming, `fn(x: ?1) -> ?1` where the shipping crates print `<T> fn(x: T) -> T` — so any bulk-bless encodes today's behavior as the contract instead of checking it. The 1,967 distinct sources are mined into `crates/syntax/tests/corpus-legacy/` and run in the syntax, format and semantics invariant batteries, where no expectation is needed. Two traps found doing it: that stack's `type_syntax` suite stores **bare annotation bodies** with no `#:` marker (287 of 303 cases read as `expected a statement, found @` until one is prepended — a format difference, not a parser gap), and its sources are fragments whose declaring context lives in sibling files of the same case, so an automated semantic pass reports unknown types on `@new Person` and similar. Adjudicating expectations needs per-case context.
- **A quadratic with two independent factors is invisible until you vary both.** `frame_definition` scanned a file's item list per name lookup, so cost was (items) × (distinct names looked up). Holding either at 200 and growing the other to 20,000 was perfectly linear (245 ms and 576 ms); growing both together was 4,305 ms, five times the sum of the two edges. **Measuring one axis at a time proves nothing here** — the interaction is the bug. Fixed with a memoized per-file name→items index (`file_binders`), but the trap generalizes to any per-item query that scans a per-file or per-project list, so vary both axes when checking one.
- **A whole-project table consulted from a per-item query needs a bound, not just memoization.** `conditional_slot_scheme` was memoized at every level and still cost 7 s of a 7.8 s run, because the *join* ran one item check per writer of the name and a per-item read reached it: cost is (items reading the name) × (writers of it), and neither factor is bounded by a file. Memoizing the table does nothing for that shape — the fix is a cap plus widening to `Unknown`, which is also the honest answer, since a union of dozens of unrelated types is not a fact any check can act on. Look for the same shape wherever a per-item query joins over a project-wide list.
- **A write inside a call-argument block binds at the item's TOP LEVEL, and for a package that publishes it project-wide.** A bare `{...}` is not a scope, so `test_that("x", { out <- f() })` makes `out` a package-namespace conditional slot; a cross-file deferred read of a common name then joins over every conditional writer of it in the project. That is the whole reason a package's own test suite can cost 17× what its `R/` costs — the shape is invisible in a script project and invisible to any per-file witness. **Whether R actually binds outward depends on the callee, so check before "fixing" it**: `suppressWarnings`/`invisible`/`system.time`/`try`/`withCallingHandlers` DO bind (a promise is forced in the caller's frame), while `local` and `test_that`'s `eval(substitute(b), new.env())` do not. A blanket rule manufactures false `unresolved` on `try({cfg <- read()}); use(cfg)`.
- **Measure both sides of a performance A/B through the same output mode, and know which path each mode exercises.** `ry check` with human output, `--output json`, and `ry debug analysis-stats` cost wildly different amounts on the same project because the human reporter is itself quadratic in findings × file length: at 8,000 findings in one file the instrument says 452 ms, JSON takes 550 ms, and human output takes 10,527 ms. So a "fix" measured with JSON against a baseline measured with human output shows an enormous win that is mostly the output mode — a review filed exactly that comparison here. Use JSON to measure the analysis path, and remember the instrument sees neither the reporter nor anything the CLI does around it.
- **A corpus regression check must compare UNIQUE sorted records, not line counts.** The long-standing "baselines" of data.table 4078 / ggplot2 1315 / shiny 1044 each contained duplicate records — ggplot2's 1315 was 1091 unique findings plus 224 exact copies, 17% of its output, one finding repeated up to 32 times. So every check that compared raw counts was comparing partly-duplicated output, and a change that removed duplicates would have read as a regression. Current unique baselines: data.table 4077, dplyr 675, ggplot2 1091, shiny 1038.
- **Two independent architecture reviews are the current queue for debt work**, both filed in `backlog.md` with measurements rather than code-reading: §"abstraction & duplication review" (three disagreeing copies of "is this a package file", a rename that accepts `...`, a dead-code batch hidden behind `let _ =`, a duplicated rule table, a `use`-qualification sweep) and §"test & fuzz architecture review" (CI runs no fixtures or fuzz, the fuzz pass spends ~95% re-parsing stubs, the formatter battery cannot notice deleted code, the protocol edge panics on non-boundary offsets, `FIXTURE_FILTER` false-greens). Both were told not to introduce abstraction, and both name items deliberately **not** worth fixing — respect those.
- Audit habit: treat "landed" claims in old notes with suspicion; the verified state is `backlog.md` + the fixture suites.

## Long-term

### Testing

- **An invariant that says "the answer is well-formed" cannot see a wrong answer, and the only way to
  know an oracle bites is to inject the bug it exists to catch.** Three oracles here looked adequate
  and were not: formatter preservation compared token *kinds*, so respelling identifiers preserved
  every kind while renaming the user's variables; the parse invariants bounded the error count only
  from *above*, so dropping errors turned broken files silently clean; the IDE battery checked ranges
  for in-bounds-ness, so a rename with every edit shifted one byte passed and corrupted the file.
  Each mutation left the shipping battery fully green. The method to reuse: copy `crates/` to a
  scratch workspace, mutate one function, run the **unmodified** harness against it, and only trust a
  new assertion once the mutant is red and the pristine tree is 0-violation. Determinism, idempotence,
  round-trip and containment are all self-consistency checks — a uniformly wrong answer satisfies
  every one of them.
- **Every type the checker prints must be a type a user can write back, and one test enforces it.**
  `#: TYPE` asserts compatibility with `TYPE`, so re-declaring an inferred scheme above its own
  definition must add no finding (`crates/semantics/tests/test_roundtrip.rs`). Every other suite reads
  a rendering as a *string*, so a type that prints beautifully and parses back as something else is
  invisible to all of them — which is how an unquoted record field name containing a comma came to
  re-parse as a different type, and how `scalar numeric` came to be rendered but unwritable. When
  adding a `Constraint`, a `TyKind`, or any new rendering, the grammar side is part of the change.
- **Give a differential oracle inputs that always exist.** The tree-sitter acceptance test was written
  correctly and never ran, because it pointed only at a gitignored corpus nothing fetches, and it
  skipped with an `eprintln!` the test runner hides. Anything gated on an optional directory is
  decoration until an in-tree input set is wired to it.

### Documentation

- **The docs site is organised by purpose, not by component**, in five sidebar groups: Introduction
  (getting-started, why-roughly, features), Type checking (tutorial, concepts, domain-modeling, stubs,
  limitations), Guides (adopting, continuous-integration, r-console), Reference (configuration, cli,
  diagnostic-codes, formatting-rules, type-system), Contributing. The installation page is deliberately
  absent from the sidebar — getting-started closes with the extension links and a one-line install, and
  the page itself only covers awkward cases. Introduction pages live at the site root; every other page
  nests under its group.
- **Write plain English. No jargon, no idiom, no empty phrases.** Not "table stakes", not "bread and
  butter", not "under the hood", not "it turns out", not "let's dive in". Headings name their subject
  ("Syntax errors", "Formatting", "Rename") rather than editorialising about it ("Syntax errors that
  say what you forgot"). Every sentence must carry information a reader did not have; if a sentence
  only sets up the next one, delete it. This is a hard rule across the whole site, and reviewers check
  it.
- **The register is neutral and precise: plain declarative sentences (user directive).** The README's
  "Why ry" and "Type system" sections are the style reference. No punchy fragments or sales lines
  ("no options to argue about", "built for exactly this job", "One more thing"), no rhetorical
  build-up ("Read that error carefully, because it is the whole idea"), and no promoting an
  incidental fact into a selling point. State a limit as a fact rather than as candour about a limit
  — "the honest way to find out" is just "how you find out". **Motivate a design decision with the
  technical reason**, not with its virtue: R is highly dynamic, ry targets soundness and speed on
  large codebases, so inference is Hindley–Milner, and class hierarchies plus user-side overloading
  are excluded because a system admitting them can spend unbounded time on one expression. Where a
  construct cannot be described statically it is `Unknown`, so a gap is a skipped check rather than a
  wrong answer.
- **Never rely on a capability the page has not introduced yet.** The Features page builds
  navigation → syntax errors → formatting → rename → the type checker, so an example that needs
  inference cannot appear before the reveal. An example is evidence for the section it sits in.
- **The rule that keeps pages from bleeding into each other**: explain a thing once, in prose, where it
  is introduced; tabulate it once, in Reference; never half-explain it in a third place. The previous
  layout documented suppression in three pages and configuration in three more. When a page needs a
  fact it does not own, it links.
- **Terminology is fixed, no synonyms**: finding (not issue/problem), diagnostic code (not rule/lint
  code), annotation (not type hint), *check* for the command and *code analysis* for the capability
  (never "linting" for either), the language server (not "the LSP"), nominal type, project (not
  workspace).
- **Breadcrumbs come from the sidebar, not the URL** — `docs/src/components/PageTitle.astro` walks
  `starlightRoute.sidebar` for the entry marked current. It exists because both Starlight and
  starlight-theme-black render a hardcoded two-level `Docs > title`. Declaring `components.PageTitle` in
  `astro.config.ts` makes the theme skip its own override and log a warning; that warning is expected.
- **`reference/formatting-rules.md` is generated**, not authored — `crates/format/tests/test_format_docs.rs`
  runs every example in `crates/format/tests/formatter.template.md` through the formatter and writes the
  page. Edit the template and rebless with `RY_BLESS=1`; editing the page directly is always wrong,
  and a site-wide link rewrite must include the template or the generated page silently keeps stale links.
- **Docs claims are verified against the binary, never against other docs.** A prior pass shipped a
  fabricated JSON example and formatter behaviour the tool does not have; the rewrite caught a
  fabricated `--output json` sample still in the install page. Run examples before writing them down.
  A pass that only intended to change *prose* still found five false claims, so re-run the examples
  even when the edit is stylistic. The kinds that drift: **quoted diagnostic text** truncated or
  paraphrased (the `@type`/`@alias` block message, the misplaced-config-key warning), **rendered
  types missing their binder** (a hover written `fn(x: T) -> …` when the tool prints
  `<T> fn(x: T) -> …`), **flag behaviour described from intent** (`--min-severity error` was said to
  still print warnings; it suppresses them entirely), and **a capability claimed in several pages at
  once** (strict mode "makes every tolerated read visible" — it does not; see `backlog.md`). Driving
  the LSP server over stdio from a throwaway script is the way to check hover and completion.

### Architecture

- **The product stack** is a hand-written lexer/parser emitting lossless rowan trees (`crates/syntax`; `#:` annotations are first-class grammar) under a salsa-based analysis core (`crates/semantics`: file input → parse → item tree with insertion-stable identity → per-item green subtrees → per-item HIR/naming → HM inference → interned types → diagnostics), with `crates/ide` as pure reads, `crates/format` on syntax only, and `crates/roughly` as the LSP server + CLI. The contract is `architecture.md` (read it before touching the engine or scheduling) and `structure.md` (file layout). Position independence: per-item derived values carry item-relative ranges; `semantics::item_node` is the ONLY re-anchoring edge.
- **Cyclic package interfaces resolve through one canonical fixpoint**, never through whichever query arrived first: `interface_sccs` (static item→winner reference graph, iterative Tarjan, canonical project order) feeds `scc_schemes` (Jacobi rounds from all-Unknown; convergence by table equality; the round cap pins ALL members), and `item_check` adopts the canonical scheme as the single exported truth. Member checks inside the fixpoint run `check_item_with_annotation` directly — never through `item_check` — so no salsa cycle forms; salsa cycle recovery stays only as a backstop for edges the static graph cannot see. Converging recursion types precisely; the remainder is attributed under strict mode (decisions.md).
- **The server** runs one async-lsp frontend thread + one worker owning the db. Latest-edit-wins rides salsa's cancellation token: edits flip the token; every subsequent job starts on a fresh storage-handle clone (`refresh_cancellation`). The two-wave publish gates on a real query split (`parse_stage_diagnostics` never computes naming/typing). Host assembly (config gating, typing modes, suppressions, lints) is shared between server and CLI in `crates/roughly/src/diagnostics.rs` so the surfaces cannot drift.
- **Correctness rests on the new stack's own fixture suites** — they are the semantics contract (the identity-parity program against the frozen legacy oracle is complete and retired by user decision; `legacy/differential` is benchmark-only). Fuzzing is pipeline-wide from each stage's first commit (decisions.md).

### Quality bar (the acceptance contract future work is held to)

- **Performance:** keystroke-to-diagnostics p50 ≤ 30 ms / p95 ≤ 100 ms at 300k LoC (always read latency numbers against the raw-parse floor the instrument prints; machine load swings them ~1.4×); budgets pinned by `stats_witness`; instruments in `legacy/differential/tests/test_stats.rs`. Corpus scale for reference: ~965K lines / 81 packages in 19.0 s / 1.0 GiB, against the frozen legacy stack's 30.3 s / 2.0 GiB, with parallel and sequential findings identical. **Every in-container timing is effectively a ≤2-core number** — the dev container's 4 vCPUs deliver ~1.8× of native compute at 4 threads, so read the parallel-cold-pass entry in `backlog.md` before drawing any parallelism conclusion from a measurement taken here.
- **Soundness:** the type relation is pure (probe-then-rollback, order-independent given program order); nominal variance is single and correct; resolve errors are never swallowed; recursion is guarded everywhere; UTF-16 position handling is correct including non-BMP; IDE features never panic on stale ranges.

### Invariants and traps (new stack — a well-meaning refactor silently breaks these)

- **A type member skipped by ONE rebuilding walk crosses the item boundary as a live inference variable.** Five walks rewrote types by re-listing the composites by hand (resolution, rigid substitution, generalization, residual erasure, variable erasure), and two of them mapped a parameter's `ty` while leaving its `default` untouched — so an exported scheme for `f <- function(x, n = x)` carried an index into the *defining* item's table. A reader resolves that index in its own table: past the end it panics, and inside it silently names an unrelated variable of the reader's own, which is the worse half. Every real package in the corpus leaked, several crashed `ry check`. All rewriting walks now go through the single structural map `crate::types::map_child_types` (reads: `for_each_child_type`, `Parameter::types`), and `close_scheme` asserts the closed body carries no variable. **Adding a member to `TyKind`/`FunctionType`/`Parameter` means adding it there and nowhere else** — a second hand-written walk over `Ty` reopens exactly this bug.
- **A type is a DAG, so walk it with a memo, never as a tree.** Interning means one subtree is reached by every path that mentions it, so a record whose fields all return that record is revisited once per field per level — exponential in depth, with no cap able to help, because the cap bounds depth and the cost is in paths. `substitute_rigid` memoises per node for one top-level call (sound: the substitution is fixed for that call, so a node's answer cannot depend on how it was reached); it went from 278M calls to under 2M on one R file. Any new recursive walk over `Ty` needs the same treatment.
- **Two measurement traps that have each produced a confident wrong answer here.** First: a probe counter printing to stderr **through a pipe** loses its output when `timeout` kills the process, so "no output" reads identically to "never called" — redirect to a file, and make the probe fire once on entry so absence and silence are distinguishable. Second: **never A/B two binaries in separate blocks.** Sequential blocks on this machine produced an apparent 2x win that interleaving showed to be zero, and a cold first run produced an apparent 12% win that was 2%. Alternate the binaries run-by-run and discard nothing.
- **Salsa:** hot tracked queries returning maps/vecs use `returns(ref)` — `returns(clone)` deep-clones per call (measured ~8s of corpus render). Input setters need the `salsa::Setter` trait in scope. Never run the stats instruments batched in one process — resident/peak RSS numbers pollute each other; the protocol is one process per instrument.
- **CLI reporting is miette's, and it has two sharp edges.** Every user-facing message the CLI prints
  — findings, companion notes, configuration failures — is one `Report` drawn by one
  `GraphicalReportHandler` (`crates/ry/src/cli.rs`; the decision record explains why). Trap one:
  miette counts the snippet header's column in **bytes**, so the borrowed-source `read_span` re-counts
  it in characters — remove that and the human header silently disagrees with the JSON record for the
  same finding. Trap two: miette draws every line a range covers, so a range over three lines is
  clamped to its first line with the reach stated in the label. Snippet sources are borrowed
  (`NamedText`), never `miette::NamedSource`, which owns its text and would copy the whole file into
  every finding reported against it. Trap three: the theme is a custom one (unbroken gutter, caret
  underline, no closing rule) — the closing rule is *filtered out of the rendered string* because
  miette hardcodes it from characters the cause-chain arrows share, so it cannot be themed away.
- **Formatter (rowan attachment differs from tree-sitter's):** trailing comments attach INSIDE expression nodes — every closer-placement / after-comment decision must be TOKEN-level (`last_token_before`), never element-level; line math uses `significant_range` (some nodes swallow trailing trivia); `]]` closes with two `]` tokens and the FIRST is the placement anchor; `# fmt: skip` recognizes three comment attachments. The formatter refuses only on R-grammar errors — annotation-grammar errors carry `SyntaxError.in_annotation` and the block renders verbatim; never re-derive that split from positions. Raw strings (`r"(...)"`) reproduce byte-for-byte.
- **An unterminated quote must not eat the file.** A string or backtick name may legally span lines, so the lexer can only discover the failure at EOF — and a token that ran that far took every statement below it out of analysis, which is the state a file is in while a quote is being typed. Unterminated tokens end at their first line break instead. The error *renderer* clamps its caret to the first line either way, so the syntax error fixtures cannot see this: pin it where the recovery is observable, on the bindings the following statements still produce.
- **Parser error doctrine:** a lexer `ERROR_TOKEN` is already precisely diagnosed — the parser consumes it silently as a placeholder atom (`primary()`), and a statement that contained one suppresses its own boundary report (`statement_had_lexer_error`); one mistake must never fan out into a report storm (the fuzz harness pins errors ≤ linear in tokens, plus non-empty messages and in-bounds ranges). The golden error suite (`crates/syntax/tests/errors`, by area) covers every distinct message template; when adding a parser error path, add its case in the same change.
- **Fixtures:** consecutive `#:` lines STITCH into one annotation region, and mixing `@type` with a compact form invalidates the whole block — separate regions need a blank line. The `group__case` id is the test identity; ids must be unique per suite.
- **IDE position model:** cursor → smallest end-INCLUSIVE non-empty HIR expression with NameRef tie-win; `position_in_item` tries strict containment then item-end-touch. **End-inclusive ranking means an expression ENDING at the cursor outranks a declaration STARTING there**, so the declaration scan has to remain a fallback for every binding kind (and a name that resolves nowhere must fall through to it rather than refuse) — otherwise a declaration is unreachable from its own first character wherever two siblings abut, and goto-definition stops being reciprocal with references. **Which token declares an item is naming's answer, never a syntax scan** (`declared_name_range`): the first `NAME` node reads `name <- value` and every other shape wrong, and a right assignment (`compute(1) -> total`) declares its name last. Directive-name readers must join only TOUCHING tokens (`@if-unknown`), or every name gains a trailing space and matches nothing.
- **Corpus instruments:** the only cross-stack instrument left is the benchmark (`legacy/differential/tests/test_stats.rs`); the comparison arms went with the identity-parity retirement. The acceptance gate for the parser IS hard (zero unadjudicated divergences vs tree-sitter, R as referee).
- **Windows-gnu cross-link needs a synthesized `synchronization` import lib:** reedline → crossterm → winapi links `-lsynchronization` (the `WaitOnAddress` API set); cargo-zigbuild sets `WINAPI_NO_BUNDLED_LIBRARIES=1` (winapi's bundled import libs break zig's lld) and zig's bundled mingw-w64 ships no `synchronization.def`, so the flake's windows `preBuild` generates the import lib with `zig dlltool` and adds it via `RUSTFLAGS -L` (see `flake.nix`). A crane deps-only build won't catch a breakage here — the dummy sources never reference reedline, so the winapi `-l` flags reach only the real final link.

### Typing — durable implementation rationale (the spec is `reference/type-system.md`; this is the *why*)

- **HM with union-find variables and an undo-log environment:** all writes funnel through the undo-log so branches, loop passes, and function bodies roll back without cloning the environment; loops iterate to a fixed point (cap 3, widen-to-Unknown, diagnostics only on the stable pass). `<T>` annotation binders are rigid skolems: they refuse to bind while their scope checks, then generalize back out.
- **Unions normalize in exactly one place** (`types` union construction: flatten, dedupe keeping first, `NULL` last, `Any`/`Unknown` absorb, singleton unwraps). Never build a `Union` literally. Unification is the invariant floor (set equality + the single nullable member-wise case); all directional member-wise logic lives in compatibility. No union constraint is ever imposed on an inference variable (HM-speed guardrail).
- **Exported schemes close at the export edge** (`erase_residual_vars`): substitute bound vars, erase unbound to Unknown, follow var bindings only — a raw inference var escaping into a foreign table is a crash class the fuzzer caught.
- **The capture model mirrors R's environments:** naming pre-mints frame assignment targets so closures resolve later-written names (an unassignable slot does not shadow — lookup falls outward), and the checker re-checks a body ONCE when a captured-write join grows after being read.
- **Cross-item name resolution splits on the READ kind, not the document kind.** A file is sourced top-down whether it is a script or a package, so an *immediate* read resolves against the nearest earlier writer in its own file before the project-wide map — that ordered scan used to exist for scripts only, which made a top-level `record$age <- …` invisible to the next statement in a package while the identical script was correct (the project-wide map holds definition items, and a replacement write is a statement item). A *deferred* read — from inside a closure — is where the kinds diverge, because what has finished running differs: in a package the function runs after every file is sourced, so the project-wide winner owns the answer and the file scan must stand aside or a later file's override is lost; in a script the closure runs once that file's frame settled, so it scans the whole file including its own binding (self-recursion). Get this backwards and forward references from function bodies break.
- **Flow state for a name the item does not bind still lives in the environment.** Scopes are per-item, so a top-level variable read by a later statement is a *non-local*, with no slot to refine — which silently disabled guard narrowing at file top level. The checker mints a slot for such a name (ids allocated above every id naming issued) and seeds it with the observed type; the environment carries the refinement from there, so there is no second place flow state can hide. The item boundary is the hard limit: a refinement cannot outlive its statement, because `item_check` is per-item and memoized, which is why the early-return guard idiom narrows inside a function body or one braced block but not across bare top-level statements.
- **A `#:` annotation declares parameter TYPES, never the parameter list.** R matches call arguments against the `function(...)` header, so the signature a definition exports must always be the formals — names, order, optionality, `...` position — with declared types filled in name-aware and undeclared formals left as fresh variables for the export edge to close. Exporting the annotation as written instead is the trap: every arity disagreement then gets resolved in the annotation's favour and charged to the *call sites*, which turns one mistyped `@param` into a finding on every correct call, and makes annotating only some parameters (the ordinary way to start) worse than not annotating at all. `check_declared_function` owns the reconciliation and every report that comes out of it; a call must never be blamed for an annotation's mistake.
- **Do not `table.resolve` a type you want to display as written.** Resolve expands aliases by design ("an alias is a transparent shorthand"), so resolving a declared signature turns `fn(x: UserId) -> UserId` into `fn(x: integer) -> integer`. Resolve the inference variables you introduced, individually, and leave the annotation's own types alone.
- **A constraint has nowhere to go in a rendered monotype**, so a diagnostic must never lean on one being visible. It belongs to the variable and can only appear in a binder prefix (`<T: numeric>`), while a finding renders a monotype — `fn(s: T) -> T` therefore prints the same whether `T` takes anything or only numbers, and against an expected `fn(character) -> U` it describes a call that should have fit. Any message about a constrained position has to *say what the position needs* instead of showing its type; `explain_function_mismatch` is where function values do that, naming the parameter or the return that failed. Two whole signatures are only honest for a shape disagreement (arity, optionality, rest parameter).
- **Call arguments are inferred exactly once, before any signature matching** (`CallArgument`), so an overload probe can re-match without re-running expression inference. That rules out the textbook fix for callback diagnostics — pushing the expected parameter type into a lambda body before inferring it — because the body would be re-inferred per candidate. Naming the failing position works within the constraint; changing it is its own slice with a real performance cost.
- **A function member of a union must render parenthesized.** `->` extends over a whole union, so without them `(fn(A) -> B) | NULL` and `fn(A) -> (B | NULL)` print the same string while being different types, and a type copied out of a finding into an annotation changes meaning. This is the *only* place the rendered grammar is ambiguous — every other nesting is closed by a bracket, comma, or paren — so the rule is one arm in the union renderer, not a precedence framework.
- **`#:` block-form rules are about LINES, and an `ANNOTATION_MARKER` is not reliably a direct child of the block.** A stitched line's marker lands inside whatever node was still open across the break, so line boundaries must be counted over *all* the block's tokens, not `children_with_tokens()`. Two more traps in the same function: a `<T, U>` binder list is a *prefix* of the type after it, not an item of its own — counting it as one refuses every stub declaration carrying a binder, which silently empties the whole stdlib corpus — and a line yielding a second item is parser-recovery debris, not a second annotation, so it means "this line did not parse", never "the forms clash".
- **A parser region the annotation grammar refused is marked with an `ERROR` node, and a block containing one carries no typing payload.** That is the same rule shape violations already had; without it a refused `<T>` binder leaves its names unbound and each one reports as an unknown type on top of the refusal. Recovery reads the type as though the refused binder were absent, so the rest of the block still parses and the refusal stays the only finding.
- **A diagnostic code names whose grammar broke, not which stage noticed.** `syntax-error` is R the parser could not read; `annotation` is a wrong `#:` comment (`SyntaxError::in_annotation` carries the split). Keying it on the stage is the trap: it filed a deliberate annotation-language limit under `syntax-error` while its siblings reported as `annotation` purely because lowering, not parsing, caught them.
- **A finding underlines the smallest expression its message is about** (the contract is `reference/type-system.md` §Where a finding points). The trap is that a check naturally has the *enclosing* range in hand, so the default is a caret over text containing both types the message contrasts — unreadable. When a range must be narrower than the node being checked, thread it: `ExpressionKind::Field` carries `name_range` and `CallArgument` carries `name_range` for exactly this, because a token's range is not derivable from its parent's without re-parsing. For a construct with several value-producing leaves (`if`/`else` arms, a block tail), keep the *whole* type as the verdict and use the leaves only to place the finding — checking leaves individually instead would drop the implicit `NULL` an `else`-less `if` contributes and silently lose real errors.
- **One `TypeRenderer` instance must span everything that shares names** (a whole signature, both sides of an expected/found pair) — a fresh renderer restarts the `T`/`U`/`V` numbering and collapses distinct variables.
- **Every finding inside an item is reported; only the item's *export* is cut.** A failed item exports `Unknown` so downstream items do not check against an untrustworthy shape, but the findings inside it are all reported: a failing expression records `Unknown`, which is compatible with everything, so later checks read a poisoned value as an absent fact instead of cascading off it. The report dedups per site and kind, because speculative paths (overload probing, guard edges) can record the same failure twice. Truncating to the first finding — which this once did — makes a green run meaningless, since most code lives inside function bodies; three independent adoption reviews called it a blocker.

### Error handling

- **Coherence failures panic.** Document-sync/analysis-sync failures in the LSP path are unrecoverable — `panic!`, never best-effort logging over corrupted state. But IDE feature lookups must never panic: a not-yet-bound local falls back to `Unknown`.

### Conventions / traps

- **Verify with CI's toolchain, not the container default.** CI uses the *latest* stable; a stale container toolchain has an older clippy (misses newer lints) and a rustfmt that wraps differently — `rustup update stable` first. Check for a formatting *diff*, not just `cargo fmt`'s exit code (piping through `head` masks the exit via SIGPIPE). The `rustfmt.toml` `imports_granularity`/`group_imports = One` rules are nightly-only and skipped (with warnings) on stable.
- CI gates exclude `zed_ry` alone (wasm toolchain) — verify with `--workspace --exclude zed_ry`. The `rofy` exclusion is gone with the crate; a command still carrying `--exclude rofy` is stale. **Spell the crate name exactly**: cargo does not fail on a wrong `--exclude`, it prints one `warning: excluded package(s) … not found in workspace` and builds the crate anyway, so a stale `zed_roughly` in a copy-pasted command silently exercises the wasm crate instead of skipping it.
- Standard-library stubs are **declaration-only `.Rtypes` files** in the top-level `types/` directory — each line `name : <type-expr>` reusing the `#:` annotation grammar (no second type parser; loader in `semantics/src/stubs.rs`). Project overrides in `<project>/stubs/*.Rtypes` fold on top (project wins). The assembled library is a **set-once singleton input** — never route stub files through document sync. Repeating a name in one source declares an ordered overload set (end every set with an `Any` fallback — the unresolved-argument path selects the last candidate); `@type NAME` declares an opaque stub nominal.
- `[check] typing` defaults **off** — CLI probes need `[check]\ntyping = true` in a `roughly.toml`, or probe through the fixture harness. `[check] unused` defaults ON (user directive).
- `docs/…/formatter.md` is **generated** from `crates/format/tests/formatter.template.md` via `cargo test -p format --test test_format_docs` (`RY_BLESS=1` rewrites); never edit the output file.
- **Legacy-only traps live with the frozen stack** (consult only when touching it): tree-sitter node/field ids are grammar-version-pinned integer constants; tree-sitter parses `#:` annotations as opaque comments; its fixture runner resolves a relative stub `base_path` against the test CWD. Do not extend legacy; data files may be duplicated across stacks, code never.
- **UI design guideline:** no `border-l` left-accent rail on rounded elements (generic-AI look) — use a full ring, fill, underline, or weight change instead.
