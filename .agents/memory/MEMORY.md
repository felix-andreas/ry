# Memory

Cross-session knowledge base for the agents building ry. Three horizons:

- **Short-term** holds the current focus and the loose ends. Prune it aggressively, and delete each item once it is resolved or obvious from the tree.
- **Mid-term** holds active priorities, open bugs, and technical debt. These items live across sessions until they are done.
- **Long-term** holds durable, non-obvious design decisions and their rationale. Record only what a future agent would otherwise rediscover. Keep each entry terse, and point at the code or the docs.

Four companion documents live in this folder, kept separate only because they are larger in scope. `worklog.md` holds one line per autonomous work cycle. It is the *only* deliberately chronological file here, and a three-hourly routine appends to it. `backlog.md` is the prioritized work punch-list, and it holds **open work only**. `test-user-reports.md` holds the simulated-user findings that are closed. A finding moves out of the backlog and into it when it is fixed, so the punch-list stays the work that is left while the reports survive. `decisions.md` is the settled architecture decision log.

The authoritative user-facing and contributor-facing specs live in the docs site, under `docs/src/content/docs/`. They are `reference/type-system.md`, which is the typing contract, `type-checking/tutorial.md`, and the four pages under `contributing/`, which are `architecture.md`, `structure.md`, `testing.md`, and `authoring-stubs.md`. Point at them rather than duplicating them.

**Unsettled design work is docs too, under `contributing/design/`.** That folder holds an index page plus the drafts. `open-questions.md` holds the undecided type-system questions, `data-masking.md` is the non-standard-evaluation sketchpad, `inline-type-syntax.md` is the compiled-dialect proposal whose own recommendation is not to build it, and `repl.md` covers the runtime-loaded-R console. Those pages are deliberately absent from the sidebar and reachable only from their index, because they are proposals rather than contracts. A draft either graduates into the reference pages or stays as the record of why it was declined. A new design document goes there rather than here.

Do not spawn a new knowledge file for something small. Inline it into a horizon below instead. Every entry must be **context-free and timeless**, meaning clear to a reader with zero project history, so name no milestone, phase, or gate, cite no commit hash, and never write "this session". Every entry must also be **high-signal**, so keep it terse and point at the code or the docs.

## Short-term

- **Every docs page is converted to the writing rules, and the adversarial reader is what makes the conversion worth anything.** Convert a page by spawning a reader subagent against it first, then applying the findings. The reader is given the project owner's own objections as the rubric, because they name faults a style checklist misses: wording that is too abstract, information a reader does not need at all, a term used without introduction, a section twice as long as the rule it states, the inference engine described as though it were the type system, and copy that describes the tool instead of what the reader gets. Run the reader before editing, not after, and do not edit the page while it is reading. It has paid for itself twice: 35 false claims on the user-facing pages, and 14 more on the two large contributing pages, including a flagship example that was a type error.
- **The writing rules are applied everywhere they belong, so a new violation is a regression rather than a leftover.** Every docs page, every user-facing diagnostic message, every code comment under `crates/`, and every file in `.agents/memory/` is converted. `worklog.md` is the one exception, and its header says why: its past entries are a record of what happened, so they keep their original wording. Two em-dashes survive in the tree on purpose, both test data: a literate document pinning that a non-ASCII character blanks to as many spaces as it occupies bytes, and R source pinning that a reported column counts characters. Grepping the shipping crates for the em-dash character finds exactly those two, and the legacy crates are frozen and out of scope. Rewrite a comment rather than repunctuating it, because most of the old ones joined two ideas that wanted to be two sentences.
- **Validate a docs link against the ids in the built HTML, never against a hand-rolled slug function.** A hand-rolled slug reported a broken anchor as fine. Build the site with `cd docs && npm run build`, then read `id="..."` out of `docs/dist/**/index.html`.
- **Adoption reviews are the current source of truth for what to fix next.** Three independent black-box reviews simulated an analysis-script user, a CRAN package author, and a numerical-computing user on real multi-file projects. Each reviewer had the docs and `--help` only, with no source access. They converged on the same walls, which now head `backlog.md` with a minimal repro each. Two lessons are worth keeping. The reviews found *quadratic* behaviour the whole in-house instrument suite had missed, because every witness measured many files rather than one file with many top-level items. Real repositories have that shape, in generated bindings and in a 4,000-line `utils.R`, and the corpus did not. The highest-value fixes were also not new features but *reporting* honesty. A per-item cap on findings, a per-call argument cap, and a verdict that changed with the command line each made a clean run mean nothing.
- **An expression is inferred by whoever needs its type, and `Checker::infer` has no memo, so a second call is a second full subtree walk.** `infer_binary` inferred both operands in the operator-dispatch probe and then again in the numeric and comparison fallback. That made a nested chain cost 2^operators, measured at 58, 514, 1975, and 8708 ms for 16, 20, 22, and 24 `+`s, against a flat 20 ms once the operands are threaded through. Two consequences are worth remembering. It is not only slow, because each re-walk re-reports, so one mistake inside a chain came out 2^depth times in the CLI. The fixture path showed a single finding, because `item_check` sorts by range and dedups, so **a fixture cannot see a report multiplication at all**. And `&&`, `||`, `:`, `%>%`, and `|>` were flat throughout, which is what isolated the cause to the double walk rather than to tree depth. When adding a path that needs an operand's type, thread the `Ty` you already have, and never call `infer` again for it.
- **A per-item performance trap to watch for.** Any per-item query that walks or re-classifies the whole file is quadratic in top-level items, and the file-count-based witnesses will not see it. `item_annotation_syntax` did exactly that, at 13.9 s on 2,000 statements. Use this pattern instead: compute once per file in a memoized query, then probe per item. The per-item query still cuts off downstream work, because an untouched item's derived value compares equal. `item_spans` is the single source of top-level item identity and ranges, so never re-derive the classification and never scan it per item.
- **REPL Windows support is verified on real Windows against R 4.5.2.** The pty end-to-end suite, seven tests now enabled over ConPTY, runs green, and so do `ry run` exit codes, `system()`, `~` expansion, and `.Platform$GUI`. The original `STATUS_ACCESS_VIOLATION` had one root cause: `GA_initapp` lives in `Rgraphapp.dll` rather than in `R.dll`, and skipping it crashes `readconsolecfg`. The recipe and the follow-on fixes live in `contributing/design/repl.md`. Those fixes are CRLF feed normalization, `home` from `getRUser()`, the UTF-8 code-page manifest, and the wrapper-script path variables on Unix. The Unix side of these changes is checked by compilation and clippy against x86_64-unknown-linux-gnu only, so the next Unix session with R should re-run the pty suite.
- **Manifests are the cheap lever on the tolerance hole, and R is installable here to make them.** A namespace with an `.exports` manifest has a knowable export set, so attaching it never triggers the blanket unresolved tolerance. It needs no typed declaration, because every name simply types `Unknown`. That is how the tidyverse and its neighbours stopped switching the check off project-wide. Two traps come with it. The generator must run on an R at least as new as the one each existing manifest records, and it now refuses and says so, because regenerating on an older R silently drops a name such as `%||%` and turns every use of it into a false `unresolved`. A *meta*-package such as `tidyverse` attaches its members rather than exporting them, so activation has to expand to them through `stubs::META_PACKAGE_MEMBERS`, and the generator prints what a live session attaches, so the list is checkable. Installing the tidyverse from source needs system headers first: `libcurl4-openssl-dev libharfbuzz-dev libfribidi-dev libfreetype-dev libpng-dev libjpeg-dev`. Without them curl, textshaping, and ragg fail, taking the meta-package with them.
- **The Unix REPL is verified end to end against real R.** The full pty suite of seven tests runs green. `contributing/design/repl.md` records the two harness requirements: answer the editor's cursor-position query, and serialize the sessions. **R installs in an agent container.** A plain `apt-get install -y --no-install-recommends r-base-core` is enough for a distribution R, and Ubuntu ships 4.3.3. Add the CRAN apt repository at `cloud.r-project.org/bin/linux/ubuntu`, with the key `marutter_pubkey.asc`, for a current R. `install.packages` compiles data.table, dplyr, testthat, and ggplot2 from source in minutes. **Two build-dependency traps.** `fs`, a testthat dependency, needs `apt-get install libuv1-dev`. Every stub corpus addition must have its `.exports` manifest generated from a live session with `Rscript scripts/export-manifests.R`, because a manifest written from memory turns a real export into a false `unresolved`. Watch the disk too. The R toolchain plus `target/` can exhaust the session allowance, so delete `target/debug/incremental` first.
- **The REPL must never feed R input through the console just to set state.** `read_console` returning a statement costs a main-loop round trip, and one taken before the editor's first prompt leaves the terminal in the state R found it in. The next read then desynchronizes, and two pty tests time out. Anything that has to run at startup goes through `RApi::eval`, which is `R_ParseEvalString`, in the window between `setup_Rmainloop()` and `run_Rmainloop()`. The startup profiles have been sourced by then, so a profile's own choice is visible and can be deferred to, and no prompt has run, so nothing can be perturbed. The console feed is for user input and for the pre-loaded script, and for nothing else.
- **Parser recovery must stop at the statement boundary, and "did we cross a line?" is the wrong test.** An unclosed `(` or `[` used to adopt every following statement as one more argument. That produced a confident "missing `,`" per line, scaling with the file, and each adopted line lost its own definitions. A list running onto the next line is ordinary R, and a *fragment* there such as `beta)` really is a forgotten separator, so two fixtures pin that report. The signal that separates them is whether the next line **assigns**, which `starts_new_statement` decides. Three traps were found the hard way. `=` must NOT count as assigning, because inside an argument or parameter list `name = value` is a *named argument*. Counting it broke the commonest forgotten comma of all, the multi-line `list(a = 1\n b = 2)`, into top-level statements, which then drew lint and `unused` findings out of source that had not parsed. The newline is consumed while parsing the element *before* the loop head, so the check must scan backwards, and a peek-at-the-loop-head version looked right and never fired. Breaking out of the list is not enough on its own, because the statement loop then sees a stray token where it wants a newline, reports again, and recovers over the next line anyway. `statement_left_group_open` suppresses both.
- **One mistake gets one finding, because the `#:` type grammar reports once per region.** It cannot resynchronize the way the statement loop can, because a region is one expression with no boundary inside it to restart at. It used to report every token it could not use, which was nine findings for one mistyped optional parameter, five of them on the same column. `error_at` drops an annotation-grammar report after the first. One refinement is easy to miss. An **unclosed opener** is discovered at the *end* of the construct it names, so first-wins alone drops the outermost truth for an inner consequence. `error_unclosed` lets exactly one of those through per region.
- **Two whole types side by side are not an explanation, and there is now ONE place that decides.** A function value rejected at a parameter names the failing position, through `explain_function_mismatch`. A record names the failing field, and the path when the failure is nested, through `explain_record_mismatch`. Both pair by the rule `compatible` uses, so an explanation can never disagree with the verdict. For a record that means optionality is deliberately NOT compared, because `compatible` does not compare it either. Every site that reports two types goes through `Checker::type_mismatch`, which narrows to the field when both sides resolve to records and returns the whole `TypeError`, so the RANGE narrows with the message. Add a new mismatch report there rather than building `TypeErrorKind::Mismatch` directly, or the narrowing will be present at one site and missing at another. Whole types are still right when the failure is not about one position, such as a record against a non-record or against `list[T]`, or an arity or rest-parameter disagreement. **A type carries no source ranges, so the caret is recovered by walking the field path back against the expression that BUILT the record.** That expression is a `list(...)` whose tagged arguments are its fields, which is why the value's `ExprId` rides on `CallArgument`. The part blamed follows the message: the value for a bad field type, the field's NAME for an undeclared one, and the innermost list for a missing one. A record that did not come from a literal, such as a variable, has no field expression, and the whole value stays the blame.
- **`"x" <- 1` binds `x`, and the obvious place to fix that is the wrong one.** R accepts a string where a name belongs, which is verified, because it prints `1`. The construct used to bind nothing, so a later read was a false `unresolved`. The tempting fix is `replacement_base`, and it is wrong, because that path *reads* the base before writing it, as `names(v) <- x` reads `v`, and marks the write unreportable. Neither of those is true of a plain definition. The string literal belongs in the name-target arm, through an or-pattern. The lowering makes that exact, because `string_value` has already stripped the quotes and resolved the escapes, so the payload IS the name R binds. Backticks never needed it, because `` `y` <- 1 `` lowers to a `NameRef`.
- **A gate pipeline that ends in `echo` cannot fail, and a background job's output file can be read mid-write.** Both bit at once. `cargo test … | grep -E "FAILED|failures:" ; echo TESTS_OK` exits 0 whatever happened, and grepping the task's output file before it finished writing showed a clean prefix. A real pty failure was therefore reported as a green gate. Read the **completed** output, and make the gate's own exit status the signal, through `set -o pipefail` or by asserting on the `test result: ok` counts, rather than the absence of a grep hit in a partial file. Absence of evidence in a file still being written is not evidence.
- **The REPL pty suite is timing-sensitive and flakes under concurrent load.** This is distinct from the desynchronization bug a wrong startup mechanism causes. The signature is that a single test fails and the whole suite's wall clock balloons, to 41 s against a normal 4 to 6 s for nine tests, while something else saturates the machine. Re-run it serially before believing it, and three clean runs at 4 to 6 s is the confirmation. A genuine desynchronization shows up reproducibly instead, and pushes the suite to about 90 s.
- **A filed finding is a hypothesis with an expiry date, so re-run it before ranking work off it.** An adoption-review entry ranked "`setGeneric` does not define its name, so every call to a project's own S4 generic reports `unresolved`" as the top fix. It had already been fixed, in `set_generic_target`. A second claim in the same entry, that R6 has no stub at all, was mischaracterized, because R6 ships an export manifest and resolves once the project declares or attaches it. Two of four claims were stale in one bullet. **Always run a control in the same file**, such as an obviously undefined name, so "no finding" cannot be misread as "the check is off". That is what distinguished fixed behaviour from an inactive check here.
- **A fixture cannot exercise anything that keys on `PackageMetadata`.** The attached-package tolerance, `imports_every_name`, and the rest of the metadata layer read a salsa input only a real project sets, so a single-file fixture silently takes the *other* branch. A pair of fixtures written for the tolerance blessed as ordinary `unresolved` warnings while their comments claimed to be testing strict mode. Anything metadata-dependent belongs in the CLI suite, `crates/ry/tests/test_cli.rs`, which builds real project directories. **Bless output is not proof the case reproduces the scenario, so read what it blessed.**
- **`GlobalEnv` has no default method bodies, and that is load-bearing.** Two implementors answer it: the ordinary salsa-backed resolver, and the *cyclic group's* view used during an SCC fixpoint. A defaulted method lets the second silently inherit a wrong answer, which happened. `arithmetic_classes` defaulted to empty, so `Date + 1` inside any recursive function failed the numeric constraint and the whole scheme collapsed to `Unknown`, while its non-recursive twin typed fine, with no diagnostic anywhere. Adding a fact to that trait must stay a compile error at every implementor. The recursive and non-recursive **pair** is the fixture shape that catches it, because either one alone looks plausible.
- **A class's operator method makes it arithmetic, and "the project's own sources" has to mean the project's.** Operator dispatch resolves `+.Class`, `Arith.Class`, and `Ops.Class` through the *global scope*, which is the stubs plus the project. The numeric constraint's admissibility check consulted the **stub library alone**, so a package defining `+.Money` had its `+` dispatched and its class refused by `function(x) x + 1L`. That is a false positive on code R runs. The set now comes from both, through `GlobalEnv::arithmetic_classes`, memoized per corpus and per project, plus a script's own top level, and it rides on `InferenceTable` beside `definitions`. **The trap generalizes: two places decide whether a class participates in arithmetic, which are dispatch and the constraint, and they must read the same scope.** A class declaring no arithmetic method is still refused, which is also what R does.
- **A `%op%` read must reach the SLOT, not only the by-name set.** The operator is a token rather than a `NameRef`, so its read is recorded by name in `quiet_operator_reads`. That is right for the cross-item check on a package's own operator, and silently useless for a **local** one, whose definition had no read resolving to it and reported as a dead store while the calls sat on the next line. Real packages write exactly that shape, aliasing a namespaced operator into a function, as `` `%+replace%` <- ggplot2::`%+replace%` `` does, and as `%NA_OR%` in shiny and `%fin%` in data.table's `merge` do. `mark_slot_read` is the slot half of a read, factored out for the operator path to call. `resolve_read` stays the only place that maps an expression id, and the unused check is *not* blanket-quiet for an operator, because an unused local one still reports. **The lesson generalizes: any read recorded by name rather than by expression id is invisible to the slot model.** Check both when adding one.
- **Do not report a consequence next to its cause.** A function whose parameter list never closed does not also get "expected a function body", because that is the same mistake said twice, and the unclosed opener is the version worth reading. `statement_left_group_open` gates it. An error blamed on wherever the search stopped also lands off the code. A header running to end of file put a **zero-width** caret on the blank line past the last statement, underlining nothing. Blame the construct that is incomplete, which is the `function` keyword, instead.
- **The operating model is full ownership with no check-in gates, by user direction.** The AGENTS.md ownership mandate is the record. Pull the highest-value item from `backlog.md` section Open, semantics first, and land it as a complete slice: contract-first docs, implementation, fixtures, and the full gates, which are the workspace tests, clippy at `-D warnings`, and fmt. Commit and push per green slice, and keep memory and the backlog current in the same slice. Three constraints stand. Work directly on `main`, by user directive. Open no new pull request. **Keep the legacy crates in the tree, by user directive**, because the final deletion sweep is deferred until the user asks for it, whatever the gate says.
- **The local gate is the only thing running the fixture suites and the fuzz batteries. CI runs neither, and its second job runs nothing at all.** `Cargo.toml` sets `default-members = ["crates/ry"]`, so a bare `--all-targets` **without** `--workspace` resolves to the default member. The blocking job therefore runs 171 product-crate tests out of the workspace's 707, which leaves 75.8% never run, and nothing from `syntax`, `semantics`, `format`, or `ide`. The `extended` job is worse. `--all-targets -- --list --ignored` reports **0 tests and 0 benchmarks**, so it is a full `lto = true` release build followed by an empty test run on every push. The widened commands are staged in `.github/pending-ci.yml` for a human to `git mv` into `.github/workflows/`, because that token lacks the GitHub `workflow` scope. **Never read a green CI badge as "the fixtures pass"**, and run `--workspace --exclude zed_ry` locally per slice. Three things must land before the move is safe, and `backlog.md` records them in the test and fuzz architecture review and in the fuzzing economics section.
- **The fuzz batteries are dominated by re-parsing the shipped stubs rather than by the iteration count.** A fresh database with stubs costs about 113 ms a round, against about 1.4 ms without them, because `stub_library` takes about 114 ms to parse and intern 601 names and is memoized after that. `StubLibrary<'db>` is interned per database, so it genuinely cannot be shared across databases. The levers are how many fresh databases an input builds, and how many offsets the ide arm sweeps. Raising `FUZZ_ITERS` on a semantics arm buys stub re-parsing rather than coverage.
- **The current state.** The backlog's open sections hold one user-requested item, which is a `--jobs` flag, plus the items blocked on external action. Those are the extension release for hover fences, the CI hardware for deep fuzzing and llvm-cov, and the human `git mv` of `pending-ci.yml`. It also holds two standing habits: grow the typing and ide fixture coverage, and honour the "when touched" notes on the overload candidates. The coverage-guided fuzz targets cover parse, format, and semantics, with the lint layer folded in. The verb level of the non-standard-evaluation ladder has shipped. The conditional data.table and dplyr stub namespaces, the bracket result-shape classifier, typed-subject masking, formal-aware `@masked`, and the native-pipe desugar compose end to end, and the decision records describe them. `contributing/design/data-masking.md` holds the remaining step, which is the column vocabulary and the membership checks, gated on the data frame row-type design. The details live in the backlog ledger.
- The landing-page hero animation is user-owned, so do not touch it. NOTES.md is human-maintained, so never edit it.
- **A stub-corpus addition no longer re-blesses the IDE fixtures.** They used to pin an absolute byte offset into `base.Rtypes`, so adding any declaration shifted them and forced a re-bless that proved nothing. The renderer now prints the token the range covers instead. If a corpus addition ever makes those cases fail again, the range is genuinely wrong, so do not bless it away.
- **Landing-page code samples are captured from the running tools rather than written by hand.** The language-server, check, and formatter showcases in `docs/src/pages/index.astro` hold generated markup in the frontmatter, under `ideCode`, `analysisCode`, `analysisOutput`, and `formatterCode`. The hovers, completions, references, rename edits, and inlay hints come from driving `ry server` over LSP. The diagnostics and the diffs come from `ry check` and `ry fmt --diff`. The columns, the underline widths, and the gutter widths are the ones the tools report, so **re-capture rather than hand-edit**, because an edited sample silently becomes a fake screenshot of a real product. Astro strips whitespace-only element content, so that markup must be rendered through `set:html`. **Nothing verifies any of this, and it has already shipped wrong twice.** Once the reporter changed, and once a parser change falsified the headline missing-comma sample in `features.md`, which is the example chosen to show the parser off. Treat "changed a message or a blame range" as implying a manual re-capture of the pages listed in the docs-sample item in `backlog.md`, and name in the commit which ones were re-run. The README's `.github/diagnostic.svg` is in that set. `scripts/render-diagnostic-svg.rs` generates it from a real pty run, and because it is an image, a stale one is invisible.

## Mid-term

- **The standing user direction is to drive autonomously toward the best possible shape, empty the Open section of `backlog.md`, and work continuously.** `backlog.md` holds the open work, which is the opportunistic semantics items, editor polish, the structure and performance levers, and the website. It also holds the one-line shipped ledger.
- **The language is `ry`**, renamed from Roughly. The crate is `crates/ry`, published as `ry-lang`. The binary and the library are both `ry`. The configuration file is `ry.toml`, the suppression comment is `# ry: allow(...)`, the environment variables are `RY_*`, and the docs are at ry-lang.org. **The former spellings still work and must keep working.** `roughly.toml`, `# roughly: allow(...)`, `ROUGHLY_*`, and the extension's `roughly.*` settings all fall back, because each one lives where a rename would break silently. The suppression comment is the worst of them, because it sits in a user's own files. `legacy/` is deliberately not renamed. The section of `backlog.md` titled "rename to `ry`: what is left" holds the surfaces that are the user's call.
- **The type system admits only what is fast to check, which means Hindley-Milner. This is a user directive.** A declaration file, meaning a `.Rtypes` file, carries the one sanctioned exception, which today is ad-hoc overloading. A user's `#:` annotation is pure Hindley-Milner and declares exactly one signature. Traits and typeclasses are **declined rather than deferred**. They are the textbook-correct way to get ad-hoc polymorphism into Hindley-Milner, which is precisely why they are not the bar here. General subtyping is out for the same reason, and a declared coercion at a named boundary is the Hindley-Milner-compatible shape any variance work must take. `decisions.md` holds the full record, so evaluate every proposed type-system feature against it before designing.
- **The open type-system design questions** live in `contributing/design/open-questions.md`. They are the tags and discriminated-union `match`, which the user placed after the beta, S3 dispatch, data frame and matrix modeling, the semantics of `...` inside a body, and the NAMESPACE and import model. Traits are closed, as the entry above says.
- **`GlobalEnv`'s facts are BORROWED per-file values, and returning them owned is a quadratic.** `type_definitions` and `arithmetic_classes` are consulted once per item checked, so handing back an owned copy makes every item pay for the whole project's table. At 2,000 items, typecheck went from 18 ms to 100 ms purely as the `@type` declarations went from 0 to 2,400. Both are now memoized per-file tracked queries returning `&'db`, and `InferenceTable` holds an `Option<&'db …>`, because both are pure lookups. Adding a fact to that trait means adding a per-file query rather than a per-item merge.
- **The legacy fixture corpus is NOT run by the new code, and it is much larger than the new one.** `legacy/analysis-legacy` holds 2,830 fixture cases against the new stack's 1,192. `legacy/fixtures` is a harness-only crate, and `analysis-legacy/tests/test_fixtures.rs` drives those cases against the *frozen oracle*, so no test under `crates/` reads those directories. They are therefore green on every gate run and prove nothing about the shipping crates. The corpus was reimplemented rather than ported, and the case-name overlap is 15 of 138 for ide and 1 across the whole typecheck suite. Name overlap understates behavioural overlap, so do not read it as 2,830 missing cases. It is the largest untapped fixture source in the repository, and the one directory that was partially mined found two real bugs, so mine it before anyone proposes deleting `analysis-legacy`.
- **`cd scratch && job &` does NOT move the commands after it, and `git add -A` will commit what they wrote.** The `&` backgrounds the whole compound that does the `cd` and the run, so every `;`-separated command after it runs in the *original* working directory, which is the repository. A profiling session that redirected output that way put twenty stack dumps in the repository root, and a later `git add -A` committed them. Two habits follow. Write scratch output to an absolute path rather than relying on a `cd`. Read `git status` before `git add -A` rather than after.
- **The frozen stack's 2,830 fixture cases are runnable as INPUTS, and never as expectations.** Its renderers differ in kind. It renders binding-resolution trees for naming, and it prints `fn(x: ?1) -> ?1` where the shipping crates print `<T> fn(x: T) -> T`. Any bulk bless therefore encodes today's behaviour as the contract instead of checking it. The 1,967 distinct sources are mined into `crates/syntax/tests/corpus-legacy/` and run in the syntax, format, and semantics invariant batteries, where no expectation is needed. Two traps were found doing it. That stack's `type_syntax` suite stores **a bare annotation body** with no `#:` marker, so 287 of 303 cases read as `expected a statement, found @` until one is prepended, which is a format difference rather than a parser gap. Its sources are also fragments whose declaring context lives in a sibling file of the same case, so an automated semantic pass reports an unknown type on `@new Person` and on similar lines. Adjudicating an expectation needs per-case context.
- **A quadratic with two independent factors is invisible until you vary both.** `frame_definition` scanned a file's item list per name lookup, so the cost was the item count times the count of distinct names looked up. Holding either at 200 and growing the other to 20,000 was perfectly linear, at 245 ms and 576 ms. Growing both together was 4,305 ms, five times the sum of the two edges. **Measuring one axis at a time proves nothing here**, because the interaction is the bug. The fix was a memoized per-file index from a name to its items, `file_binders`. The trap generalizes to any per-item query that scans a per-file or per-project list, so vary both axes when checking one.
- **A whole-project table consulted from a per-item query needs a bound, not just memoization.** `conditional_slot_scheme` was memoized at every level and still cost 7 s of a 7.8 s run, because the *join* ran one item check per writer of the name and a per-item read reached it. The cost is the count of items reading the name times the count of writers of it, and neither factor is bounded by a file. Memoizing the table does nothing for that shape. The fix is a cap plus widening to `Unknown`, which is also the honest answer, because a union of dozens of unrelated types is not a fact any check can act on. Look for the same shape wherever a per-item query joins over a project-wide list.
- **A write inside a call-argument block binds at the item's TOP LEVEL, and for a package that publishes it project-wide.** A bare `{...}` is not a scope, so `test_that("x", { out <- f() })` makes `out` a package-namespace conditional slot. A cross-file deferred read of a common name then joins over every conditional writer of it in the project. That is the whole reason a package's own test suite can cost 17 times what its `R/` costs. The shape is invisible in a script project, and invisible to any per-file witness. **Whether R actually binds outward depends on the callee, so check before "fixing" it.** `suppressWarnings`, `invisible`, `system.time`, `try`, and `withCallingHandlers` DO bind, because a promise is forced in the caller's frame. `local` and `test_that`'s `eval(substitute(b), new.env())` do not. A blanket rule manufactures a false `unresolved` on `try({cfg <- read()}); use(cfg)`.
- **Measure both sides of a performance comparison through the same output mode, and know which path each mode exercises.** `ry check` with human output, `--output json`, and `ry debug analysis-stats` cost wildly different amounts on the same project, because the human reporter is itself quadratic in findings times file length. At 8,000 findings in one file the instrument says 452 ms, JSON takes 550 ms, and human output takes 10,527 ms. A "fix" measured with JSON against a baseline measured with human output therefore shows an enormous win that is mostly the output mode, and a review filed exactly that comparison here. Use JSON to measure the analysis path, and remember that the instrument sees neither the reporter nor anything the CLI does around it.
- **A corpus regression check must compare UNIQUE sorted records rather than line counts.** The long-standing baselines of 4078 for data.table, 1315 for ggplot2, and 1044 for shiny each contained duplicate records. ggplot2's 1315 was 1091 unique findings plus 224 exact copies, which is 17% of its output, with one finding repeated up to 32 times. Every check that compared raw counts was therefore comparing partly duplicated output, and a change that removed duplicates would have read as a regression. The current unique baselines are 4077 for data.table, 675 for dplyr, 1091 for ggplot2, and 1038 for shiny.
- **Two independent architecture reviews are the current queue for debt work.** Both are filed in `backlog.md` with measurements rather than code-reading. The abstraction and duplication review names three disagreeing copies of "is this a package file", a rename that accepts `...`, a batch of dead code hidden behind `let _ =`, a duplicated rule table, and a `use`-qualification sweep. The test and fuzz architecture review names that CI runs no fixtures or fuzz, that the fuzz pass spends about 95% of its time re-parsing stubs, that the formatter battery cannot notice deleted code, and that the protocol edge panics on a non-boundary offset. Both reviews were told not to introduce abstraction, and both name items deliberately **not** worth fixing, so respect those.
- Treat a "landed" claim in an old note with suspicion. The verified state is `backlog.md` plus the fixture suites.

## Long-term

### Documentation

- **The docs site is organized by purpose rather than by component**, in five sidebar groups.
  Introduction holds getting-started, why-ry, and features. Type checking holds tutorial, concepts,
  domain-modeling, stubs, and limitations. Guides holds adopting, continuous-integration, and
  r-console. Reference holds configuration, cli, diagnostic-codes, formatting-rules, and
  type-system. Contributing is the fifth. The installation page is deliberately absent from the
  sidebar, because getting-started closes with the extension links and a one-line install, and the
  page itself only covers the awkward cases. An introduction page lives at the site root, and every
  other page nests under its group.
- **Write plain English. No jargon, no idiom, no empty phrases.** Not "table stakes", not "bread and
  butter", not "under the hood", not "it turns out", not "let's dive in". Headings name their subject
  ("Syntax errors", "Formatting", "Rename") rather than editorialising about it ("Syntax errors that
  say what you forgot"). Every sentence must carry information a reader did not have; if a sentence
  only sets up the next one, delete it. This is a hard rule across the whole site, and reviewers check
  it.
- **The register is neutral and precise: plain declarative sentences (user directive).** The README's
  "Why ry" and "Type system" sections are the style reference. No punchy fragments or sales lines
  ("no options to argue about", "built for exactly this job", "One more thing"), no rhetorical
  build-up ("Read that error carefully, because it is the whole idea"), and no promoting an
  incidental fact into a selling point. State a limit as a fact rather than as candour about a
  limit. "The honest way to find out" is just "how you find out".
  **Motivate a design decision with the
  technical reason**, not with its virtue: R is highly dynamic, ry targets soundness and speed on
  large codebases, so inference is Hindley–Milner, and class hierarchies plus user-side overloading
  are excluded because a system admitting them can spend unbounded time on one expression. Where a
  construct cannot be described statically it is `Unknown`, so a gap is a skipped check rather than a
  wrong answer.
- **Never rely on a capability the page has not introduced yet.** The Features page builds
  navigation → syntax errors → formatting → rename → the type checker, so an example that needs
  inference cannot appear before the reveal. An example is evidence for the section it sits in.
- **The rule that keeps pages from bleeding into each other**: explain a thing once, in prose, where it
  is introduced; tabulate it once, in Reference; never half-explain it in a third place. The previous
  layout documented suppression in three pages and configuration in three more. When a page needs a
  fact it does not own, it links.
- **Terminology is fixed, no synonyms**: finding (not issue/problem), diagnostic code (not rule/lint
  code), annotation (not type hint), *check* for the command and *code analysis* for the capability
  (never "linting" for either), the language server (not "the LSP"), nominal type, project (not
  workspace).
- **Breadcrumbs come from the sidebar rather than from the URL.** `docs/src/components/PageTitle.astro` walks
  `starlightRoute.sidebar` for the entry marked current. It exists because both Starlight and
  starlight-theme-black render a hardcoded two-level `Docs > title`. Declaring `components.PageTitle` in
  `astro.config.ts` makes the theme skip its own override and log a warning; that warning is expected.
- **`reference/formatting-rules.md` is generated rather than authored.** `crates/format/tests/test_format_docs.rs`
  runs every example in `crates/format/tests/formatter.template.md` through the formatter and writes the
  page. Edit the template and rebless with `RY_BLESS=1`; editing the page directly is always wrong,
  and a site-wide link rewrite must include the template or the generated page silently keeps stale links.
- **A docs claim is verified against the binary, never against other docs.** A prior pass shipped a
  fabricated JSON example and formatter behaviour the tool does not have, and the rewrite caught a
  fabricated `--output json` sample still in the install page. Run examples before writing them down.
  A pass that only intended to change *prose* still found five false claims, so re-run the examples
  even when the edit is stylistic. The kinds that drift: **quoted diagnostic text** truncated or
  paraphrased (the `@type`/`@alias` block message, the misplaced-config-key warning), **rendered
  types missing their binder** (a hover written `fn(x: T) -> …` when the tool prints
  `<T> fn(x: T) -> …`), **flag behaviour described from intent** (`--min-severity error` was said to
  still print warnings; it suppresses them entirely), and **a capability claimed in several pages at
  once**, such as strict mode making every tolerated read visible, which it does not, as
  `backlog.md` records. Driving the LSP server over stdio from a throwaway script is the way to
  check hover and completion.
- **A reference page can drift from the implementation in a way no test catches, and rewriting the prose is what finds it.** The typing reference stated that `!` accepts only `logical` operands and that any other operand is a type error. The checker coerces `integer` and `double` exactly as a condition does, so `!0` is `logical` and `function(x) !x` infers `fn(x: logical) -> logical`. The page contradicted its own conditions section two hundred lines earlier. No fixture failed, because the fixtures agreed with the code and nobody had compared the two prose passages. The lesson generalizes: a contradiction between two sections of one spec is invisible to every automated gate, so read a page end to end when you touch it, and run the claim.
- **Verifying a claim needs `[check] typing = true` in the probe project's `ry.toml`.** Type checking is off by default, so a probe without it reports only `unused` findings, and a wrong annotation looks like a passing check. The fastest way to read an expression's inferred type is to annotate the binding with a type it cannot have and read the `found` half of the mismatch.

### Testing

- **An invariant that says "the answer is well-formed" cannot see a wrong answer, and the only way to
  know an oracle bites is to inject the bug it exists to catch.** Three oracles here looked adequate
  and were not: formatter preservation compared token *kinds*, so respelling identifiers preserved
  every kind while renaming the user's variables. The parse invariants bounded the error count only
  from *above*, so dropping errors turned a broken file silently clean. The IDE battery checked that
  a range was in bounds, so a rename with every edit shifted one byte passed and corrupted the
  file.
  Each mutation left the shipping battery fully green. The method to reuse: copy `crates/` to a
  scratch workspace, mutate one function, run the **unmodified** harness against it, and only trust a
  new assertion once the mutant is red and the pristine tree is 0-violation. Determinism, idempotence,
  round-trip, and containment are all self-consistency checks, and a uniformly wrong answer
  satisfies every one of them.
- **Every type the checker prints must be a type a user can write back, and one test enforces it.**
  `#: TYPE` asserts compatibility with `TYPE`, so re-declaring an inferred scheme above its own
  definition must add no finding (`crates/semantics/tests/test_roundtrip.rs`). Every other suite reads
  a rendering as a *string*, so a type that prints beautifully and parses back as something else is
  invisible to all of them. That is how an unquoted record field name containing a comma came to
  re-parse as a different type, and how `scalar numeric` came to be rendered but unwritable. When
  adding a `Constraint`, a `TyKind`, or any new rendering, the grammar side is part of the change.
- **Give a differential oracle inputs that always exist.** The tree-sitter acceptance test was written
  correctly and never ran, because it pointed only at a gitignored corpus nothing fetches, and it
  skipped with an `eprintln!` the test runner hides. Anything gated on an optional directory is
  decoration until an in-tree input set is wired to it.

### Architecture

- **The product stack** is a hand-written lexer/parser emitting lossless rowan trees (`crates/syntax`; `#:` annotations are first-class grammar) under a salsa-based analysis core (`crates/semantics`: file input → parse → item tree with insertion-stable identity → per-item green subtrees → per-item HIR/naming → HM inference → interned types → diagnostics), with `crates/ide` as pure reads, `crates/format` on syntax only, and `crates/ry` as the LSP server and the CLI. The contract is `architecture.md` (read it before touching the engine or scheduling) and `structure.md` (file layout). Position independence: per-item derived values carry item-relative ranges; `semantics::item_node` is the ONLY re-anchoring edge.
- **Cyclic package interfaces resolve through one canonical fixpoint**, never through whichever query arrived first: `interface_sccs` (static item→winner reference graph, iterative Tarjan, canonical project order) feeds `scc_schemes`, which runs Jacobi rounds from an all-Unknown start, converges by table equality, and pins ALL members at the round cap. `item_check` then adopts the canonical scheme as the single exported truth. A member check inside the fixpoint runs `check_item_with_annotation` directly, and never through `item_check`, so no salsa cycle forms. Salsa cycle recovery stays only as a backstop for an edge the static graph cannot see. Converging recursion types precisely, and the remainder is attributed under strict mode, which `decisions.md` records.
- **The server** runs one async-lsp frontend thread + one worker owning the db. Latest-edit-wins rides salsa's cancellation token: edits flip the token; every subsequent job starts on a fresh storage-handle clone (`refresh_cancellation`). The two-wave publish gates on a real query split (`parse_stage_diagnostics` never computes naming/typing). Host assembly (config gating, typing modes, suppressions, lints) is shared between the server and the CLI in `crates/ry/src/diagnostics.rs` so the surfaces cannot drift.
- **Correctness rests on the new stack's own fixture suites.** They are the semantics contract. The identity-parity program against the frozen legacy oracle is complete and retired, by user decision, and `legacy/differential` is benchmark-only now. Fuzzing is pipeline-wide from each stage's first commit, and `decisions.md` records that.

### The quality bar

This is the acceptance contract future work is held to.

- **Performance.** Keystroke-to-diagnostics latency must hold a p50 at or under 30 ms and a p95 at or under 100 ms, at 300k lines of code. Always read a latency number against the raw-parse floor the instrument prints, because machine load swings it by about 1.4 times. `stats_witness` pins the budgets, and the instruments live in `legacy/differential/tests/test_stats.rs`. For scale, the corpus is about 965K lines across 81 packages, checked in 19.0 s using 1.0 GiB, against the frozen legacy stack's 30.3 s and 2.0 GiB, with the parallel and the sequential findings identical. **Every in-container timing is effectively a two-core number or worse.** The dev container's 4 vCPUs deliver about 1.8 times native compute at 4 threads, so read the parallel-cold-pass entry in `backlog.md` before drawing any conclusion about parallelism from a measurement taken here.
- **Soundness.** The type relation is pure, through probe-then-rollback, and order-independent given program order. Nominal variance is single and correct. A resolve error is never swallowed. Recursion is guarded everywhere. UTF-16 position handling is correct, including for a non-BMP character. An IDE feature never panics on a stale range.

### Invariants and traps

A well-meaning refactor silently breaks each of these.

- **Every walk that rebuilds a type goes through `types::map_child_types`.** Five walks (resolution, rigid substitution, generalization, residual erasure, variable erasure) once re-listed the composite kinds by hand, and two of them mapped a parameter's `ty` but forgot its `default`. The exported scheme of `f <- function(x, n = x)` then carried an inference variable from the *defining* item's table. A reader looks that index up in its own table: past the end it panics, and inside it silently names an unrelated variable, which is the worse outcome. Every real package in the corpus leaked, and several crashed `ry check`. Reads go through `for_each_child_type` and `Parameter::types`, and `close_scheme` asserts that a closed body carries no variable. So when you add a member to `TyKind`, `FunctionType`, or `Parameter`, add it in those helpers and nowhere else. A second hand-written walk over `Ty` reopens this bug.
- **A type is a DAG, so walk it with a memo, never as a tree.** Interning means one subtree is reached by every path that mentions it, so a record whose fields all return that record is revisited once per field per level. That is exponential in depth, and no cap can help, because a cap bounds depth while the cost is in paths. `substitute_rigid` memoizes per node for one top-level call. That is sound, because the substitution is fixed for that call, so a node's answer cannot depend on how it was reached. It went from 278M calls to under 2M on one R file. Any new recursive walk over `Ty` needs the same treatment.
- **A composite type past `TYPE_SIZE_CEILING` is recorded as `Unknown`.** `types::type_size` counts a type as a *tree*, meaning paths rather than distinct nodes, and saturates at 100,000. `Checker::record` gives any composite past the ceiling `Unknown` instead. Tree size is the number that matters, because a consumer walking a type pays the tree it denotes while sharing keeps the stored graph small. A distinct-node count is blind to exactly the case the ceiling exists for. `record` is the right site because every expression's inferred type passes through it. Bounding the capture-join site instead was tried and changed nothing, because it fires nine times on the file that motivated this. Without the ceiling, a record whose fields all return that record grew through 877, 8823, 104655 and 1046623 nodes, and one 1,563-line R file never finished. With it, that file takes 56 ms.
- **Two measurement traps that have each produced a confident wrong answer here.** First: a probe counter printing to stderr **through a pipe** loses its output when `timeout` kills the process, so "no output" reads identically to "never called". Redirect to a file instead, and make the probe fire once on entry, so absence and silence are distinguishable. Second, **never compare two binaries in separate blocks.** Sequential blocks on this machine produced an apparent 2x win that interleaving showed to be zero, and a cold first run produced an apparent 12% win that was 2%. Alternate the binaries run-by-run and discard nothing.
- **Salsa.** A hot tracked query returning a map or a vector uses `returns(ref)`, because `returns(clone)` deep-clones per call, which measured about 8 s of a corpus render. An input setter needs the `salsa::Setter` trait in scope. Never run the stats instruments batched in one process, because the resident and peak memory numbers pollute each other. The protocol is one process per instrument.
- **CLI reporting is miette's, and it has three sharp edges.** Every user-facing message the CLI
  prints is one `Report` drawn by one
  `GraphicalReportHandler`, in `crates/ry/src/cli.rs`, and the decision record explains why. That
  covers the findings, the companion notes, and the configuration failures. The first trap is that
  miette counts the snippet header's column in **bytes**, so the borrowed-source `read_span`
  re-counts it in characters. Remove that and the human header silently disagrees with the JSON
  record for the same finding. The second trap is that miette draws every line a range covers, so a
  range over three lines is clamped to its first line, with the reach stated in the label. Snippet sources are borrowed
  (`NamedText`), never `miette::NamedSource`, which owns its text and would copy the whole file into
  every finding reported against it. The third trap is the theme, which is a custom one with an
  unbroken gutter, a caret underline, and no closing rule. The closing rule is *filtered out of the
  rendered string*, because miette hardcodes it from characters the cause-chain arrows share, so it
  cannot be themed away.
- **The formatter's rowan attachment differs from tree-sitter's.** A trailing comment attaches INSIDE an expression node, so every decision about placing a closer, or about what follows a comment, must be TOKEN-level, through `last_token_before`, and never element-level. Line math uses `significant_range`, because some nodes swallow trailing trivia. `]]` closes with two `]` tokens, and the FIRST is the placement anchor. `# fmt: skip` recognizes three comment attachments. The formatter refuses only on an R-grammar error. An annotation-grammar error carries `SyntaxError.in_annotation`, and the block renders verbatim. Never re-derive that split from positions. Raw strings (`r"(...)"`) reproduce byte-for-byte.
- **An unterminated quote must not eat the file.** R lets a string or a backtick name span lines, so the lexer only discovers a missing close quote at the end of the file. A token that ran that far took every statement below it out of analysis, and a file is in exactly that state while someone is typing a quote. Unterminated tokens therefore end at their first line break. The error renderer clamps its caret to the first line either way, so the syntax error fixtures cannot see this. Pin it where the recovery is observable: on the bindings the following statements still produce.
- **The parser's error doctrine.** A lexer `ERROR_TOKEN` is already precisely diagnosed, so the parser consumes it silently as a placeholder atom, in `primary()`, and a statement that contained one suppresses its own boundary report, through `statement_had_lexer_error`. one mistake must never fan out into a report storm (the fuzz harness pins errors ≤ linear in tokens, plus non-empty messages and in-bounds ranges). The golden error suite (`crates/syntax/tests/errors`, by area) covers every distinct message template; when adding a parser error path, add its case in the same change.
- **Fixtures.** Consecutive `#:` lines STITCH into one annotation region, and mixing `@type` with a compact form invalidates the whole block, so two separate regions need a blank line between them. The `group__case` id is the test identity, and an id must be unique per suite.
- **The IDE position model.** A cursor maps to the smallest end-INCLUSIVE non-empty HIR expression, with a `NameRef` winning a tie. `position_in_item` tries strict containment first, then an item-end touch. Because ranking is end-inclusive, an expression that ENDS at the cursor outranks a declaration that STARTS there. The declaration scan therefore has to stay a fallback for every binding kind, and a name that resolves nowhere must fall through to it rather than refuse. Otherwise a declaration is unreachable from its own first character wherever two siblings abut, and goto-definition stops mirroring references. Which token declares an item is naming's answer (`declared_name_range`), never a syntax scan: the first `NAME` node is right for `name <- value` and wrong for every other shape, and a right assignment (`compute(1) -> total`) declares its name last. Directive-name readers must join only TOUCHING tokens (`@if-unknown`), or every name gains a trailing space and matches nothing.
- **The corpus instruments.** The only cross-stack instrument left is the benchmark, in `legacy/differential/tests/test_stats.rs`, because the comparison arms went with the identity-parity retirement. The acceptance gate for the parser IS hard: zero unadjudicated divergences against tree-sitter, with R as the referee.
- **A windows-gnu cross-link needs a synthesized `synchronization` import library.** reedline depends on crossterm, which depends on winapi, which links `-lsynchronization`, the `WaitOnAddress` API set. cargo-zigbuild sets `WINAPI_NO_BUNDLED_LIBRARIES=1`, because winapi's bundled import libraries break zig's lld, and zig's bundled mingw-w64 ships no `synchronization.def`, so the flake's windows `preBuild` generates the import lib with `zig dlltool` and adds it through `RUSTFLAGS -L`, which `flake.nix` shows. A crane deps-only build will not catch a breakage here, because the dummy sources never reference reedline, so the winapi `-l` flags reach only the real final link.

### Typing

`reference/type-system.md` is the spec. This section holds the durable implementation rationale, which is the *why*.

- **HM with union-find variables and an undo-log environment:** all writes funnel through the undo-log so branches, loop passes, and function bodies roll back without cloning the environment; loops iterate to a fixed point (cap 3, widen-to-Unknown, diagnostics only on the stable pass). `<T>` annotation binders are rigid skolems: they refuse to bind while their scope checks, then generalize back out.
- **Unions normalize in exactly one place** (`types` union construction: flatten, dedupe keeping first, `NULL` last, `Any`/`Unknown` absorb, singleton unwraps). Never build a `Union` literally. Unification is the invariant floor (set equality + the single nullable member-wise case); all directional member-wise logic lives in compatibility. No union constraint is ever imposed on an inference variable (HM-speed guardrail).
- **An exported scheme closes at the export edge**, in `erase_residual_vars`. It substitutes a bound variable, erases an unbound one to Unknown, and follows variable bindings only. A raw inference variable escaping into a foreign table is a crash class the fuzzer caught.
- **The capture model mirrors R's environments.** Naming pre-mints the frame's assignment targets, so a closure resolves a name written later. An unassignable slot does not shadow, because lookup falls outward. The checker re-checks a body ONCE when a captured-write join grows after being read.
- **Cross-item name resolution splits on the READ kind, not the document kind.** A file is sourced top-down whether it is a script or a package, so an *immediate* read resolves against the nearest earlier writer in its own file before the project-wide map. That ordered scan used to exist for a script only, which made a top-level `record$age <- …` invisible to the next statement in a package while the identical script was correct. The project-wide map holds definition items, and a replacement write is a statement item. A *deferred* read, from inside a closure, is where the kinds diverge, because what has finished running differs. In a package the function runs after every file is sourced, so the project-wide winner owns the answer and the file scan must stand aside or a later file's override is lost; in a script the closure runs once that file's frame settled, so it scans the whole file including its own binding (self-recursion). Get this backwards and forward references from function bodies break.
- **Flow state for a name the item does not bind still lives in the environment.** Scopes are per-item, so a top-level variable read by a later statement is a *non-local*, with no slot to refine. That silently disabled guard narrowing at file top level. The checker mints a slot for such a name, with ids allocated above every id naming issued, and seeds it with the observed type. The environment carries the refinement from there, so there is no second place flow state can hide. The item boundary is the hard limit, and a refinement cannot outlive its statement, because `item_check` is per-item and memoized, which is why the early-return guard idiom narrows inside a function body or one braced block but not across bare top-level statements.
- **A `#:` annotation declares parameter TYPES, never the parameter list.** R matches call arguments against the `function(...)` header, so the signature a definition exports must always be the formals, with their names, their order, their optionality, and the `...` position. The declared types fill in name-aware, and an undeclared formal is left as a fresh variable for the export edge to close. Exporting the annotation as written instead is the trap. every arity disagreement then gets resolved in the annotation's favour and charged to the *call sites*, which turns one mistyped `@param` into a finding on every correct call, and makes annotating only some parameters (the ordinary way to start) worse than not annotating at all. `check_declared_function` owns the reconciliation and every report that comes out of it; a call must never be blamed for an annotation's mistake.
- **Do not `table.resolve` a type you want to display as written.** Resolve expands aliases by design ("an alias is a transparent shorthand"), so resolving a declared signature turns `fn(x: UserId) -> UserId` into `fn(x: integer) -> integer`. Resolve the inference variables you introduced, individually, and leave the annotation's own types alone.
- **A constraint has nowhere to go in a rendered monotype**, so a diagnostic must never lean on one being visible. It belongs to the variable and can only appear in a binder prefix (`<T: numeric>`), while a finding renders a monotype. `fn(s: T) -> T` therefore prints the same whether `T` takes anything or only numbers, and against an expected `fn(character) -> U` it describes a call that should have fit. Any message about a constrained position has to *say what the position needs* instead of showing its type. `explain_function_mismatch` is where a function value does that, naming the parameter or the return that failed. Two whole signatures are only honest for a shape disagreement (arity, optionality, rest parameter).
- **Call arguments are inferred exactly once, before any signature matching** (`CallArgument`), so an overload probe can re-match without re-running expression inference. That rules out the textbook fix for a callback diagnostic, which is pushing the expected parameter type into a lambda body before inferring it, because the body would then be re-inferred per candidate. Naming the failing position works within the constraint. Changing it is its own slice, with a real performance cost.
- **A function member of a union must render parenthesized.** `->` extends over a whole union, so without them `(fn(A) -> B) | NULL` and `fn(A) -> (B | NULL)` print the same string while being different types, and a type copied out of a finding into an annotation changes meaning. This is the *only* place the rendered grammar is ambiguous, because every other nesting is closed by a bracket, a comma, or a parenthesis. The rule is therefore one arm in the union renderer rather than a precedence framework.
- **`#:` block-form rules are about LINES, and an `ANNOTATION_MARKER` is not reliably a direct child of the block.** A stitched line's marker lands inside whatever node was still open across the break, so line boundaries must be counted over *all* the block's tokens, not `children_with_tokens()`. Two more traps live in the same function. A `<T, U>` binder list is a *prefix* of the type after it rather than an item of its own, and counting it as an item refuses every stub declaration carrying a binder, which silently empties the whole standard-library corpus. A line yielding a second item is parser-recovery debris rather than a second annotation, so it means "this line did not parse" and never "the forms clash".
- **A parser region the annotation grammar refused is marked with an `ERROR` node, and a block containing one carries no typing payload.** That is the same rule shape violations already had; without it a refused `<T>` binder leaves its names unbound and each one reports as an unknown type on top of the refusal. Recovery reads the type as though the refused binder were absent, so the rest of the block still parses and the refusal stays the only finding.
- **A diagnostic code names whose grammar broke, not which stage noticed.** `syntax-error` is R the parser could not read, and `annotation` is a wrong `#:` comment. `SyntaxError::in_annotation` carries the split. Keying it on the stage is the trap. it filed a deliberate annotation-language limit under `syntax-error` while its siblings reported as `annotation` purely because lowering, not parsing, caught them.
- **A finding underlines the smallest expression its message is about** (the contract is `reference/type-system.md` §Where a finding points). The trap is that a check naturally has the *enclosing* range in hand, so the default is a caret over text containing both types the message contrasts, which is unreadable. When a range must be narrower than the node being checked, thread it. `ExpressionKind::Field` carries `name_range` and `CallArgument` carries `name_range` for exactly this, because a token's range is not derivable from its parent's without re-parsing. For a construct with several value-producing leaves, such as the arms of an `if` and `else` or a block tail, keep the *whole* type as the verdict and use the leaves only to place the finding. Checking the leaves individually instead would drop the implicit `NULL` an `if` without an `else` contributes, and silently lose real errors.
- **One `TypeRenderer` instance must span everything that shares names**, which is a whole signature, and both sides of an expected-and-found pair. A fresh renderer restarts the `T`, `U`, `V` numbering and collapses distinct variables.
- **Every finding inside an item is reported; only the item's *export* is cut.** A failed item exports `Unknown` so downstream items do not check against an untrustworthy shape, but every finding inside it is reported. A failing expression records `Unknown`, which is compatible with everything, so a later check reads a poisoned value as an absent fact instead of cascading off it. The report dedups per site and kind, because a speculative path, such as an overload probe or a guard edge, can record the same failure twice. Truncating to the first finding, which this once did, makes a green run meaningless, since most code lives inside function bodies; three independent adoption reviews called it a blocker.

### Error handling

- **A coherence failure panics.** A document-sync or analysis-sync failure in the LSP path is unrecoverable, so call `panic!` rather than logging best-effort over corrupted state. An IDE feature lookup must never panic, and a not-yet-bound local falls back to `Unknown`.

### Conventions and traps

- **Verify with CI's toolchain rather than the container default.** CI uses the *latest* stable. A stale container toolchain has an older clippy, which misses a newer lint, and a rustfmt that wraps differently, so run `rustup update stable` first. Check for a formatting *diff* rather than just `cargo fmt`'s exit code, because piping through `head` masks the exit status through SIGPIPE. The `rustfmt.toml` `imports_granularity`/`group_imports = One` rules are nightly-only and skipped (with warnings) on stable.
- The CI gates exclude `zed_ry` alone, because it needs a wasm toolchain, so verify with `--workspace --exclude zed_ry`. The `rofy` exclusion went with the crate, so a command still carrying `--exclude rofy` is stale. **Spell the crate name exactly**: cargo does not fail on a wrong `--exclude`, it prints one `warning: excluded package(s) … not found in workspace` and builds the crate anyway, so a stale `zed_roughly` in a copy-pasted command silently exercises the wasm crate instead of skipping it.
- The standard-library stubs are **declaration-only `.Rtypes` files** in the top-level `types/` directory. Each line is `name : <type-expr>` and reuses the `#:` annotation grammar, so there is no second type parser, and the loader lives in `semantics/src/stubs.rs`. A project override in `<project>/stubs/*.Rtypes` folds on top, and the project wins. The assembled library is a **set-once singleton input**, so never route a stub file through document sync. Repeating a name in one source declares an ordered overload set. End every set with an `Any` fallback, because the unresolved-argument path selects the last candidate. `@type NAME` declares an opaque stub nominal.
- `[check] typing` defaults **off**, so a CLI probe needs `[check]\ntyping = true` in its `ry.toml`, or it must probe through the fixture harness instead. `[check] unused` defaults ON, by user directive.
- `docs/…/formatter.md` is **generated** from `crates/format/tests/formatter.template.md` via `cargo test -p format --test test_format_docs` (`RY_BLESS=1` rewrites); never edit the output file.
- **Legacy-only traps live with the frozen stack** (consult only when touching it): tree-sitter node/field ids are grammar-version-pinned integer constants; tree-sitter parses `#:` annotations as opaque comments; its fixture runner resolves a relative stub `base_path` against the test CWD. Do not extend legacy; data files may be duplicated across stacks, code never.
- **A UI design guideline.** Do not put a `border-l` left-accent rail on a rounded element, because it reads as generic AI output. Use a full ring, a fill, an underline, or a weight change instead.
