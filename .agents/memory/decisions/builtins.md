# Decisions: Builtins and base R

Base R's builtins and native kernels, numerics, regular expressions, connections, the default packages, and package code that runs natively.

## One connection table, in the interpreter

**Status:** built.

- `interp::connections` owns the `#[repr(C)] Rconn`, the table, the devices, the sinks and every connection internal (GNU R 4.3.3's arities). Two tables meant R-opened connections were invisible to `R_GetConnection` and package custom connections (curl, processx) unreadable from R.
- A package's C method is called through `Hooks::connection_method` (libr's `native.c` trampolines), ry methods that C calls enter through `Hooks::enter_from_native` so an R error becomes the `longjmp` C expects, and the default `vfprintf` arrives as `Hooks::connection_vfprintf`. libr keeps only `R_new_custom_connection`, `R_GetConnection`, `R_ReadConnection`, `R_WriteConnection` and `ry_connection_count`. Hook defaults error, so the interpreter builds and tests without libR.
- The interpreter's root source traces what the table holds (a text output connection's variable and environment), replacing preserve and release. libr's `boundary::warn` defers onto the interpreter's warning list, the one warning store.
- `closeAllConnections` is a base closure in GNU R, so ry registers no internal for it.

## Base R's linear algebra

**Status:** built.

- `crates/interp/src/linalg.rs` calls the system BLAS and LAPACK through `dlopen` (the workspace builds without them; a missing library is an R error), with GNU R's arguments, workspace queries and gfortran's hidden character lengths; on the same libraries the results are GNU R's bit for bit (`crates/interp/tests/test_linalg.rs`). LAPACK-backed functions always call the host libraries.
- **`dqrdc2`, the `dqrsl` family and `dtrco` are Rust**, since no system library ships R's LINPACK variant. They call BLAS level 1 (`dnrm2`, `ddot`, `daxpy`, `dscal`, `dasum`) because those decide the bits: reference `dnrm2` is scaled, not a plain square root.
- **One table of base's native routines**, `native::BASE_ROUTINES`; `getRegisteredRoutines` derives from it and every `.Call`/`.C`/`.Fortran` asks `native::call_base_routine` first, so `qr()` works without libR. A routine is base's only when its `NativeSymbolInfo`'s `dll` is `base`. GNU R's `R_init_base` calls `R_forceSymbols(dll, TRUE)`, so `.Fortran("dqrdc2", PACKAGE = "base")` errors, `is.loaded("dqrdc2")` is `FALSE` and `forceSymbols = TRUE`; ry matches all three.
- **Matrix products are ry's own kernels.** `%*%`, `crossprod` and `tcrossprod` sum in reference `dgemm`/`dgemv`/`dsyrk`/`zgemm` order (columns as axpys), which is also GNU R's NaN fallback order, so one kernel serves both and the NaN screen is gone. The result is GNU R's on its bundled reference BLAS on every machine; the host BLAS (CI's OpenBLAS with FMA moved bits by 1 to 2 ULP) is not used by default. Complex products use Fortran's plain multiply on finite operands and C99's otherwise. A faster kernel must keep each entry's sum sequential in the inner index: block over rows and columns only, no FMA (`backlog.md`).
  - A source-built GNU R links its reference `libRblas`; Debian's `r-base` may resolve `libblas.so.3` to OpenBLAS, which ry does not reproduce by default. A source-built R 4.6.2 reports `sessionInfo()$BLAS` as `libRblas.so`; a GNU R whose `default`/`blas` products differ from a plain double loop has an optimized BLAS.
  - `options(ry.blas = "host")` (or `RY_BLAS=host`; the option wins) uses the host BLAS with GNU R's routine choice from `array.c` (`dgemv` for vector shapes, `dsyrk` plus a mirrored triangle for one-argument `crossprod`/`tcrossprod`, `dgemm`, `zgemm`) and its NaN screen per `options(matprod=)` (`mayHaveNaNOrInf` for `default`, a plain sum for `default.simd`, none for `blas`; a tripped screen falls to the reference kernel). `"internal"` ignores it; the default is `"reference"`. All 66 product shapes and modes of a probe equal GNU R on reference BLAS under `"host"` (`test_linalg.rs` reruns them), but last-bit equality with an OpenBLAS GNU R is unverified: only the call mapping was checked.
  - `tcrossprod(x, y)` with a vector `y` takes it as a row when `nrow(x) == 1`, as `do_matprod` does.
  - `options(matprod = "internal")` sums each entry in x87 long double and rounds once (`long_double_product`), complex parts separately. `default` and `default.simd` keep the reference-order kernel, which equals GNU R's NaN/Inf fallback loop, so the screen changes no result.
- **Related long double ports.** `cumprod` (`long_double::running_products`), complex `sum`/`prod`/`mean`, two-argument `cor` (`sqrtl`); one-argument `cor` takes the double `sqrt` of the rounded variance. `fft`/`mvfft` port `fft.c`'s `fft_factor`/`fftmx` (`fft.rs`).
- **Quirks kept**: `La_solve` norms the factored copy when `a` was not double; `La_dgecon` uses `n` as leading dimension, which ry refuses for `m < n` rather than read past the matrix.
- **Buffers sit at GNU R's addresses modulo 16.** OpenBLAS's SSE2 level-1 kernels (Zen, Sandybridge, Nehalem and older) peel a first element that is not 16-aligned, which regroups partial sums. ry's vector data is always 0 modulo 16 (`VECTOR_DATA_OFFSET` 32, 16-aligned slots); Haswell, SkylakeX and Cooperlake kernels have no peel, so a mismatch shows only on the older kernels. GNU R's vector data starts 48 bytes into the node (measured with `.Internal(inspect())`, read from `memory.c`): 128 data bytes or less come from small-vector pages at 8 modulo 16, larger from `malloc` at 0; `R_alloc` follows the same rule. `Placed` and `PlacedInput` in `linalg.rs` hand each buffer at the address GNU R's has in the same call, tagged `Allocation::Vector` or `Allocation::Scratch` per GNU R's `Lapack.c`, `array.c` and `.Fortran`; a vector at the wrong address is copied and written back on drop, and only buffers of 128 bytes or less ever move. `La_svd_cmplx`'s real workspace takes GNU R's size, because the size decides the address. Moving vector data in the heap was rejected: `VECTOR_DATA_OFFSET` is baked into the JIT and the image, and it costs memory. Opteron and Bulldozer-family kernels are untested. Package code calling BLAS stays exposed (`backlog.md`, "BLAS buffer addresses in package code"). Test with `RY_TEST_REFERENCE_LIBRARIES=1`, GNU R on `PATH` and `OPENBLAS_CORETYPE`.

## The default packages' utils, tools, grDevices and graphics routines

**Status:** built.

The routines live in `crates/interp/src/utils.rs`, `tools.rs` and `crates/graphics/src/routines.rs`, wired in `builtin_libraries::implementation`, derived from GNU R's documentation and observed output (oracle cases `io__*`, `colours__*`, `graphics__*`, `utils__sizes_hashtabs_and_tools`), never its C source.

- **One graphics engine.** Base graphics and grid call the engine (`crates/graphics/src/engine.rs`), which calls devices through a `DevDesc`'s C callbacks. `GEDevDesc`, `DevDesc`, `GEContext` and `GESystemDesc` are `#[repr(C)]` copies of R_GE_version 17 because grid and ragg touch fields directly; built-in devices are `DevDesc`s with Rust callbacks (`crates/graphics/src/render.rs`), so ragg and `pdf()` take one path.
  - The display list is struct-of-arrays in `EngineDevice`, and `GEDevDesc.displayList` stays `R_NilValue`; a pairlist is built only for `recordPlot` and `dev.copy`. Cost: a C device that tests `displayList != R_NilValue` before replaying on resize never replays (none does today).
  - `R_GE_checkVersionOrDie` accepts engine versions 14 to 17 rather than GNU R's exact match, so device binaries built for R 4.1 to 4.6 load (`DevDesc` only grew into its reserved space). `GEDevDesc` gained `lock` before `gesd` in 4.4, so each system descriptor sits in two adjacent slots with `ask` mirrored. `R_GE_getVersion` and a recorded plot's `engineVersion` follow the presented release (16 through 4.5, 17 from 4.6).
  - `GEregisterSystem` hands back the index before calling the system on open devices, because grid's `InitState` reads it then. `patternFill` defaults to `R_NilValue`, which ragg reads.
  - `fromDeviceHeight` in inches has no sign, as in GNU R; otherwise y-down devices get negative string heights.
  - Base text, rasters and X-splines go to `GEText`, `GERaster` and the engine's `xspline`, so a device package draws them itself. `GEText` gets both adjustments, so an unspecified vertical adjustment centres the label on its glyphs' extent from the device's metric callback. The X-spline is from Blanc and Schlick's paper; its sampling (one point between two corners, else a step of `2 / sqrt(length in 1/1200 inch)`, at most 0.2) reproduces GNU R's open splines exactly. `plot.new` marks the device dirty, because grid starts its own page unless another system drew.
- **Built-in devices record a drawing and render at close.** Callbacks append `graphics::render::Item`s in inches; PDF, SVG, PostScript, PNG, JPEG, BMP and TIFF are writers over one `Drawing` (tiny-skia, ab_glyph). Rendering at close keeps devices free of file handles and gives bitmap devices one file per page; vector devices create their file at open so a bad path fails there.
  - Patterns, clips, masks and groups are `Definition`s in an append-only arena; R receives the index, so pages rendered at close find them after R released the reference. Nesting is recorded by running the definition's function with the target swapped; rendering bounds it at 32 levels.
  - Device versions follow GNU R: pdf, svg and bitmap are 16; PostScript is 15, refuses definitions, reports capabilities `NA`, and drops semi-transparent colours with GNU R's per-page warning.
  - Deliberate improvements over cairo: bitmap devices render luminance masks; `svg()` composites like `pdf()` (blend modes only; other operators warn and draw as `over`) instead of rasterizing; `svg()` marks non-interpolated images `image-rendering:pixelated`.
  - A raster is one `Mark::Image`. PostScript resamples with GNU R's sixteenth-step bilinear filter, so its hex data is byte-identical. tiny-skia has no `saturate`, so `draw_items` composites `dst + src * min(1, (1 - Da) / Sa)`, cairo's exact formula. A padded tiling pattern in svg adds edge strips under the tile so renderers show no seams. Glyph callbacks draw nothing for an unreadable font, as GNU R's pdf device. Known difference: bitmap devices' edge pixels in a raster differ from cairo's anti-aliased coverage by a few levels.
- **Geometry is GNU R's**, checked against its pdf output and ragg pixels; positions are computed in inches, so a coordinate's last bit can differ. A line of `lwd` 1 is 1/96 inch, a margin line is `mex * csi`, margin text sits on its baseline offset by `ylbias`, and symbols are sized from half the character height.
  - Point size and `cex` reach the device separately (`text_context`), because rounding to whole points is the device's business.
  - User coordinates map through the region `usr` was set on (GNU R's `win2fig`), so changing `mar` after `plot.window` moves nothing until the next `plot.window`.
  - `mtext` clips to the device; `clip()` keeps its region only while `xpd` is unchanged, as `GClip` does. A missing `adj` or `at` in `mtext` defaults by `las` and side (`ComputeAdjValue`, `ComputeAtValue`); `tck` below 0.5 is a fraction of the plot region's shorter side, above it of its extent across the axis.
  - Contour labels port GNU R's placement, quirks included (cumulative gradient variance, `180 / 3.14`), because any other placement lands elsewhere.
  - Every text path goes through `push_label` with a `Label` (plotmath via `plotmath.rs`); `pch` 0 to 25 go through `graphics::engine::symbol` only, because a second copy drew shapes differently.
- **The editor's plot panel reads the display list.** A console with a subscribed editor makes its default device a `pdf(NULL)` with the display list on, replacing the platform default (X11 would open a window or fail); a default the user set is kept. `publish_plot` in `console_server.rs` compares `graphics::engine::display_list_stamp` (one global counter, so a reused slot never repeats a stamp), replays changes onto svg with `dev.copy` and sends a `ryPlot` event; warnings are muffled and every device the replay opened is closed, so a failed replay leaks neither. A separate httpgd-style device would duplicate the engine. File devices keep the display list off, as in GNU R, so `png()` output is never sent.
- **Plot gallery.** `crates/oracle/gallery/*.R` (about 150 figures: base graphics with the PerformanceAnalytics charts, grid, lattice, ggplot2) renders on both engines with `oracle gallery`, auto-printing a figure's visible value because lattice, ggplot2 and xts draw only when printed; `agg` is the sharp check (0.2% tolerance), `png` and pdf get 5% with a one-pixel neighbourhood because cairo and tiny-skia antialias differently (a lattice parallel plot otherwise differs in 18% of its pixels while looking identical). `svg` is not compared (cairo writes glyphs as paths). `test_gallery.rs` runs a seeded sample; a bug class it finds is pinned by a `graphics__*` case that states a value, not a pixel.
- **Device table mirrors GNU R's**: slot 0 is the null device, at most 64, `.Devices` (entries carry `filepath` for a file device) and `.Device` rebound after every change, `dev.set(1)` starts the default device but reports 1, and a routine needing a device opens `getOption("device")`, which is how a script with no device gets `pdf("Rplots.pdf")`.
- **One `par`.** ry reads inline parameters from the call instead of keeping GNU R's default and current copies. Regions remember the unit they were set in (`Margins`, `OuterMargins`, `PlotRegion`, `FigureRegion`), so `par(mai = ...)` then `par(cex = 2)` keeps the inches; storing all units would drift.
- **Text metrics are Helvetica's AFM widths and ASCII kerning** (generated from GNU R's `afm/Helvetica*.afm`; oblique faces share them) at the nearest whole point size, with the cap height for `strheight` (Symbol AFM for `font` 5), matching GNU R's pdf device exactly; bitmap devices in GNU R use cairo fonts. Glyphs arrive as Adobe Symbol codes but strings as plotmath's Unicode, so only the string path maps back (`symbol_metrics`, `adobe_symbol_code`); mapping both confuses code 174 with U+00AE.
- `cairoProps` reports cairo, so `capabilities()` lists png, jpeg and tiff and bitmap devices need no display. The palette is thread-local in `crates/graphics/src/routines.rs`, packed with red in the low byte, because only the colour routines read it.
- **`scan` lives in `utils.rs`**, because `scan`, `readtablehead` and `countfields` share one tokenizer; connections expose unread input through `connections::with_input`, and `pushBack` splices into it.
- **Hash tables keep entries in R vectors** (type, keys, values, hashes, count) behind the external pointer, and a lookup compares hashes before calling `identical()`, so the collector sees every key and value without a Rust table to trace.
- **`contourLines`** reproduces GNU R's order and direction by observed rules (segment edge order, the saddle rule, the triangle for one missing corner, the nudge of values equal to the level, closing a loop) in `contour_level` (`crates/graphics/src/routines.rs`); a saddle within rounding of the level can still pick the other pairing.

## parallel's fork routines

**Status:** built.

- `crates/interp/src/parallel.rs` and `fork.rs` implement all of parallel's `.Call` routines (the L'Ecuyer stream jumps and the `mc_*` routines behind `mcfork`, `mclapply`, `mcparallel`) with GNU R's pipe protocol (a native-endian `R_xlen_t` length, then bytes; zero means exiting), because parallel's R code drives it unchanged.
- **Fork safety.** The runtime starts no helper threads (no GC, JIT or I/O threads), so `fork()` copies a consistent interpreter and no lock can be held by a thread absent in the child. `mc_fork` flushes stdout, stderr and file connection buffers first (`connections::flush_pending_writes`). Children close siblings' pipes so a sibling's standard input still reaches its end, and `mc_exit` uses `_exit` so exit handlers do not run twice.
- **Reaping without SIGCHLD.** GNU R reaps from a SIGCHLD handler and its children wait for SIGUSR1; ry does neither. A child exits at once, and the master calls `waitpid(WNOHANG)` on released children at the start of each routine. A child is released only once its pipe ends or it is removed, detached or estranged, so its pid cannot be reused while tended. `mc_children` lists tended children only, which `mccollect`'s loop needs to end.
- **Cleanup scopes.** `mc_cleanup` acts on children forked since the innermost `mc_prepare_cleanup` mark (each child records it at fork; all children when there is none) and pops it only when it signals or detaches, because `mccollect`'s `cleanup(FALSE, FALSE)` runs inside `mclapply`'s scope.

## One Rmath, one codec stack, and the numerical routines

**Status:** built.

- **One Rmath**, `crates/numeric/src/rmath.rs`, shared by the interpreter and libR, because two copies let a precision fix land in only one. The interpreter vectorizes it; libR only converts C flags, raises the collected warnings and draws variates; `gamma`, `lgamma`, `beta` and `lbeta` call it instead of libm's `tgamma`, which is not exact for whole arguments.
- **One compression stack.** libR calls `interp::connections::decompress` (file magic) and `interp::serialize::decompress_record` (lazy-load records), so one set of codecs (`bzip2`, `lzma-rust2`) reads every file.
- **Time zones come from jiff** (`system.rs`, `Zone`). An unknown name acts as UTC under glibc's abbreviation (its leading letters when three or more). Copied from glibc: an `isdst` contradicting the rule shifts by an hour, even in a zone without daylight saving time, except for `"UTC"` and `"GMT"`, which GNU R converts itself; years outside jiff's range move by 400-year cycles. A repeated fall-back wall time takes the offset in force at that time read as UTC, as `mktime` with `isdst = -1`; `strptime` keeps a spring-forward gap's fields.
- **The locale comes from the C library.** The session calls `setlocale` as GNU R does at startup (numbers stay C), `Sys.setlocale`/`Sys.getlocale` go through it, and `sort()` reads `LC_COLLATE` (`sort::refresh_collation`) instead of a fixed C.UTF-8 answer, which withr's `local_locale` tests and C-collation sorts observe.
- **`nlm`, `nlminb`, `polyroot`** follow UNCMIN (translating GNU R's `uncmin.c`, see "licensing"), PORT (see "`nlminb` runs PORT's own drivers") and Jenkins-Traub, which also fixes GNU R's root order.
- **One UNCMIN, one QUADPACK, one interval search**: `stats::nlm`, `stats::optimize::{qags, qagi}` (writing into caller-owned `Subintervals`) and `interp::arith::find_interval`; libR only converts C callbacks and arguments, as `lbfgsb` does, and passes `work`/`iwork` straight through. GNU R decided where the old copies disagreed: the cubic backtrack groups its coefficient as `3 * t3 * (...)`, and a non-finite value (nlm makes it the largest double) shrinks the step by ten. nlm's call protocol is GNU R's: an uncached first probe that alone decides whether `gradient` and `hessian` attributes count, a ring of five evaluations, and "non-finite value supplied by 'nlm'". An attribute of wrong length or mode warns and is ignored; where GNU R reads past a too-short later attribute, ry errors or uses zeros. Bit-exact methods 2 (double dogleg) and 3 (More-Hebdon hook) needed departures from the textbook, found by tracing every evaluation in `%a`: the trust-region retry with a doubled radius only for a Newton step predicted within a tenth; central differences with an analytic gradient build the Hessian from gradient calls; the hook uses `phip0`; `phip0` and `phip` square `sqrt(dot)`; the secant update sums its two corrections before adding. `stats__uncmin_quadpack.R` pins iterates; libR's `optif9_trust_region` (`crates/libr/tests/test_numerics.rs`) compares at tolerance zero, so it assumes reference-BLAS rounding in the GNU R that recorded it (GNU R's `ddot_` and `dnrm2_` come from the system BLAS).
- **`parse_Rd`** is a hand-written parser (`crates/interp/src/rd.rs`) tracking the three lexical modes (LaTeX-like, R-like, verbatim) per macro, keeping srcrefs, with GNU R's warnings and errors for unterminated strings (`tools__parse_rd`). `deparseRd` reads the same tree.
- **`iconv` goes through the C library**, because GNU R's results (accepted names, `sub` substitution, transliteration) are glibc's. UTF-8 to UTF-8 (both names spell UTF-8, any case, hyphen optional) copies the strictly valid prefix (`platform::Iconv::convert`, used by `Riconv` and `iconv()`): glibc costs about 30 instructions a byte, `str::from_utf8` plus a copy 1.2 on ASCII and 5.7 on dense non-ASCII, and processx converts every child-output chunk, which made it the largest single entry in vctrs', rlang's and purrr's test runs; glibc converts the rest, because it accepts more than strict UTF-8 and reports a cut-off sequence as `EINVAL`; UTF-8 is stateless, so the split equals one call. A full output stops at the last whole character with `E2BIG`, as glibc does. `Riconv_open` resolves `""` to the `LC_CTYPE` codeset (`platform::native_codeset`) first, as GNU R passes `""` to `iconv_open` (ASCII under `LC_CTYPE=C`) (`platform::tests::utf8_identity_matches_glibc`, `strings__riconv_utf8_identity`, `strings__riconv_native_encoding`).

## POSIX regular expressions run on an automaton when they need the longest match

**Status:** built.

- `Matcher::Automaton` keeps two regex-automata `meta::Regex` beside fancy-regex: a leftmost-first search gives the start, and an anchored `MatchKind::All` search the longest end, POSIX leftmost-longest in linear time (`leftmost_longest` on fancy-regex backtracked forever on lgr's `(.*z.*){10}`). Groups come from fancy-regex only for callers that report them (not `regexpr`/`gregexpr` without `perl`, nor `sub`/`gsub` without backreferences); patterns regex-automata cannot compile, such as backreferences, stay on fancy-regex.

## `perl = TRUE` runs on PCRE2, linked statically

**Status:** built.

- Translating PCRE into fancy-regex would chase constructs one at a time and never match its backtracking or messages, so the `pcre2` crate compiles as `R_pcre2_prepare` does (UTF, `CASELESS` for `ignore.case`, JIT) in `strings::compile_perl`, with GNU R's warning-then-error on compile failure (`PCRE pattern compilation error`, PCRE2's message and the rest of the pattern). `.cargo/config.toml` sets `PCRE2_SYS_STATIC=1`, so a release binary needs no system PCRE2.
- The crate sets `PCRE2_MATCH_INVALID_UTF` only with `PCRE2_UCP`, which GNU R does not use, so its `Regex` validates the whole subject on every match and global `gsub` goes quadratic. `crates/interp/src/pcre.rs` calls the library directly with `PCRE2_NO_UTF_CHECK`, sound because subjects are Rust `str`.
- The TRE dialect stays on fancy-regex behind an Extended-only translator; a real TRE build is open in `backlog.md`.

## TRE approximate regular expressions

**Status:** built.

- `strings::parse_bound` ports `tre_parse_bound`, so counts, settings and errors agree with GNU R, including `{,n}` allowing `n + 1` copies (`{,1}` exactly one) and an approximate bound needing copies (`{2+}`, `{1,2#}`) being "Invalid contents of {}".
- A pattern with settings and no backreference compiles to `Matcher::Approximate` (`approximate::ApproximateRegex`), a port of `tre_tnfa_run_approx` over a position automaton; scopes are named groups (`SCOPE_GROUP`) that become parameter changes on transitions. With a backreference TRE's backtracker ignores the settings, and so does ry.
- Observed details: nesting depth is counted in `{` order, and more than three scopes trip TRE's `value <= 3` assertion only when a match reaches the fourth; an unset cost is free inside its scope yet counts 1 overall; ties go to the earlier start; minimal repetition is ignored; later `gsub`/`gregexpr` searches use `REG_NOTBOL`. `strings__tre_bounds` pins it.

## TRE minimal repetitions over alternatives

**Status:** built.

- Without submatches (`regexpr`, `gregexpr`, `grepl`), TRE minimizes lazy repetitions over all top-level alternatives: `regexpr("a.*?Z|a.*?Y", "aXbYcXdZ")` has length 4. Such patterns compile to `Matcher::Automaton` with `shortest`, taking the earliest end among leftmost matches.
- Submatch queries (`sub`, `regexec`) keep leftmost-first, so `sub("(a).*?Z|(a)(.*?)Y", ...)` takes the first alternative, as TRE does on the corpus's shapes; TRE's submatch results for these are irregular in general (`regexec` can skip the leftmost match). `connections__message_sink_and_flush` pins both.

## The message sink and connection flush points

**Status:** built.

- `sink(type = "message")` sets `message_slot` (GNU R's `R_ErrorCon`); messages, warnings and `stderr()` writes go through `connections::write_message`, which flushes every write as `REvprintf` does. Closing it resets the slot to 2.
- GNU R flushes a file connection after `cat`, each message-sink write and sink removal, but not after `writeLines`; ry matches each, so a second reader sees what GNU R's would (`connections__message_sink_and_flush`).
- `Rprintf` and `REprintf` go through the same table (`libr::boundary::write_console`), so sinks divert C output.

## utils' sockets, internal downloads and allocation profiling

**Status:** built.

- `make.socket` keeps its `TcpStream`s and `TcpListener`s in one locked map in `crates/interp/src/utils.rs` keyed by the OS handle, because that is the `socket` number R code passes back.
- `download.file(method = "internal")` and `url(method = "internal")` read only `file://` and otherwise give GNU R 4.2+'s "defunct" or "not supported" errors.
- `Rprofmem` logs only vectors with more than 128 data bytes, sized as GNU R counts (data rounded to 8 plus a 48-byte header), because GNU R takes smaller vectors from small-cell pages; ry has none, so it writes no `new page:` lines. The heap calls a plain `fn(usize) -> bool` reporter (`Heap::report_allocations`, one compare per vector while no profile runs) that must not reach the heap, since the heap is mutably borrowed; returning false (a failed write) ends the profile. The compiler hides its own vectors with `Heap::swap_report_threshold`.
- `Rprof` raises intervals below 10 ms with GNU R's warning, since GNU R's timer cannot sample faster. `system(intern = FALSE)` and `system2` return invisibly.

## One session temporary directory, removed at exit

**Status:** built.

- `interp::system::session_temp_dir` is the only one: `mkdtemp` `RtmpXXXXXX` under the first writable `R_TMPDIR`, `TMPDIR`, `TMP` or `TEMP`, passed to native code as `R_TempDir`. `session::finish` removes it only in the creating process, so a forked `mcparallel` child never deletes its parent's directory.
- Exit finalizers run first (`run_exit_finalizers`, also on `quit()`), because a finalizer may write there; `R_CleanUp` and `Rf_endEmbeddedR` remove it through `R_CleanTempDir` after theirs.
- `tempdir(check = TRUE)` recreates the same path, unlike GNU R, because native code already copied it; it is created private, and an existing directory there must belong to the user.

## Base R kernels: radix sorting, gather subsetting, x87 accumulation and shortest-digit formatting

**Status:** built, except the radix keys computed per pass (`SortKey::get`), which "Base R kernels: position tables, a most significant digit radix order, and a per-call string memo" supersedes.

- `sort.rs` sorts integers, doubles and strings with radix and counting sorts (strings by their interned order), and `subset.rs` gathers plain vectors in one typed loop; both, `rowSums`, `cumsum` and `as.character(double)` run faster than GNU R.
- `long_double.rs` is the one home for GNU R's long double accumulation, on x87 where available (`add_all`, `add_differences`, `add_products`, block row sums, `running_sums`). cov and cor round each column mean to double before the products, as GNU R does.
- `format.rs` uses Rust's shortest round-trip digits only for normal values needing at most 15 significant digits; past that, or when zero padding would pass 15 integer digits, GNU R prints exact digits the shortest form lacks.
- **Strings stored at once skip the root handle.** `values::mkchar` pushes a handle that lives until the builtin returns; in per-element loops (one handle per element held 8 MB at 1e6 rows) use `values::set_mkchar` and `set_mkchar_bytes`, which store into a vector the caller keeps rooted. `Heap::mk_char` scans bytes once, a word at a time, for NUL, ASCII and the hash (`strings::scan`), compares an 8 to 16 byte candidate with two word loads instead of `memcmp`, and keeps allocation in a cold function. A re-intern hit costs about 126 instructions; its time (about 30 ns at 200,000 strings) is the two cache misses on the table and the candidate.
- **`format` picks digits with GNU R's arithmetic.** `scientific` mirrors `format.c`'s `scientific()`: scale in long double, `nearbyint`, drop trailing zeros, so `roundingwidens` (a value just under a power of ten that rounds up to it) agrees bit for bit; shortest round-trip digits disagree near 15 digits. GNU R's `tbl` holds double literals, so `1e23` to `1e27` are the nearest doubles, and scales past 10^27 use glibc's `powl`, not correctly rounded for 65 exponents, so `GLIBC_POWERS_OF_TEN` stores glibc's results. `scientific = TRUE`/`FALSE` set `scipen` to -99/310 as `do_format` does (`fuzz_format_numbers_matches_gnu_r` in `crates/oracle/tests/test_differential.rs` checks random vectors against live GNU R).
- Pinned by `stats__long_double_moments`, `vectors__radix_sort_and_gather`, `strings__double_to_text`, `arith__cumulative`.

## Base R kernels: position tables, a most significant digit radix order, and a per-call string memo

**Status:** built.

- `sort.rs`'s `PositionTable` (open addressing over 1-based `u32` positions, keys left in their vector, slot from the hash's high bits) serves `match` and `duplicated`; an integer range of at most about four slots per element uses `DenseRange`.
- `radix_order` sorts by the first key, then each run of ties by the rest, so later keys sort in cache. One key: a fused min/max/sortedness pass, counting sort under about a million buckets (past that its passes miss cache on every row), pair sort under 1024 rows, else MSD radix with 11-bit digits ping-ponging between two buffers; at a 1e7 permutation the radix sort's sequential scatters beat counting (0.34 s against 0.43 s). Keys that fit 32 bits (integers, factor codes, string ranks) sort as `u32` in 8-byte pairs; only doubles need `u64`.
- `values::StringMemo` fronts the heap's string table for one vectorized call (`substr`, `formatC`) and switches off after 65,536 lookups with under one hit in eight. It is per call because the session table misses cache on every probe at 1e7 strings while one call's distinct pieces fit; a faster session table would make it unnecessary. `substr` at 1e7 runs 1.0 s (GNU R 1.8 s).
- `formatC(format = "f")` uses `fixed_fast` below 2^52 scaled magnitude: an `fma` gives the exact error of `value * 10^digits`, so glibc's half-to-even is decided exactly; larger values take Rust's arbitrary-precision formatter (about 1,100 instructions a value). At 1e7 rows the kernel runs 2.7 s (GNU R 5.6 s); a unit test cross-checks it against the exact formatter.
- `vectors__radix_paths` pins the paths, including integer `NA` at either end.

## The methods package's core runs natively behind hash-guarded prologues

**Status:** built, except the native class table with dense class ids, which the entry names as the next step.

- **Shape.** The core is Rust (`crates/interp/src/methods_core.rs`); the package's R code and metadata objects (classRepresentations, `.__C__` and `.__T__` tables, generics, method tables) stay the single source of truth, read and written directly, so saved RDS objects, `methods:::` callers, Reference Classes and the S4 cache keep working.
- **Mechanism.** `R_initMethodDispatch` calls `install_fast_paths`, which compares each function in `methods_core.R` with `FAST_PATHS` by a stable hash and rewrites the body to `{ prologue; original body }`; the prologue's `.Internal` either does the whole job and returns or returns without observable effect. Patching in place reaches every copy of the closure, including the per-class `initialize` copies in `.AllMTable`, so every table entry is hashed. `FAST_PATHS` lists one hash per checked `methods` version (bundled GNU R 4.6.2 is the primary target). A miss on the bundled version is a start-up error, because the base changed under the core; on another version the R code stays. R text the native definitions fill in (coerce and replace methods) lives in `METHODS_TEMPLATES`, parsed once at install.
- **Exactness.** A fast path reads promises only when forcing runs no code (`quiet_value`), bails before any effect wherever R code could observe the work (validity functions, `as()` caching, user `initialize` methods, `.S3Class` slots, a data part not set through the standard replacement cached in `coerce<-`'s table, list entries in the class table), and evaluates calls that may signal in the R function's frame, so condition calls and `sys.calls()` match GNU R. A signature argument that fails to evaluate is reported as `h(simpleError(msg, call))`. Known difference: frame-local temporaries are not bound when a fast path completes, visible only to code inspecting that frame from outside (a debugger, `sys.frames()`).
- Generics are looked up in `.genericTable`, because the namespace binding may be an unforced promise. `R_set_slot` modifies in place, `.allowPrimitiveMethods(FALSE)` turns primitive dispatch off (selection recurses otherwise), and an argument is `"missing"` only when its own binding is missing, not when a caller passed a missing argument on.
- **Definitions.** `setGeneric`, `setMethod` and `setClass` are native for the usual shapes (local supers only, no union member classes passed as a classRepresentation, a `validity` that is `NULL` or a function of `object`) and bail before any effect otherwise; results are byte-identical to the R path (compared by `serialize()` on generated S4 packages, Matrix and the methods tests). Adding a direct subclass rebuilds the whole subclass list as `completeSubclasses()` does, regenerating every indirect extension (whose `by` and `to` carry the package attribute differently the second time) and repeating a class reached through two direct subclasses; appending would differ. Exception to bailing before effects: `setClass` runs `tryNew()` for slot prototypes before its last checks, which fills the same `initialize` cache the R code fills.
- **Switches.** `RY_METHODS_NATIVE=0` (definition fast paths off; the differential uses it), `RY_TRACE_METHODS_BAILS=1`, `RY_PRINT_FAST_PATH_HASHES=1` (for adding a version).
- **The S4 cache is deleted** ("Caching is a sign of a slow design"); per-generic units plus native definitions bring a cold first `new()` on `target/s4heavy` to 80 to 87 ms, against 0.36 to 0.40 s with a cache miss before.
- **A promise stays a root while forced** (`force_promise` in `eval.rs`), as GNU R's `R_PendingPromises`, because a loader S4 placeholder removes its own binding while it runs (a collection mid-force freed the promise and its environment). It costs one handle push per force.
- **`setMethod` on a base S3 generic** builds the implicit generic natively (`implicit_generic`), writing the same objects as `setGeneric(f, where)` (`makeGeneric`, a `derivedDefaultMethod`, `.MTable`/`.AllMTable` holding `ANY`, `.genericTable` and `methods:::.implicitTable` entries, `.__T__f:base`) without R's message for a non-S3 function, and bails when `.BasicFunsList`, `.__IG__table` or `.__IGM__table` would supply it, when a table already holds the name, or outside a namespace.
- **Next: a native class table, not more ported functions.** A cold run of the 2,892 generated definitions takes about 145 ms with about 24 calls still bailing, yet about 670M instructions against the roughly 250M a sub-100 ms cold `new()` allows. The cost is flat (environment lookups of `.__C__`/`.__T__`, slot reads, `substitute`-built extensions, allocation), and every ported function still reads and writes the R metadata. The target is dense class ids, a bitset extends relation and id-keyed method tables, materializing `classRepresentation` and `.MTable` views only when R code reads them. Per-generic units came first because not running unused definitions removed more for less. What remains is unit 0 (about 416M instructions on `target/s4heavy`): `setClass` 29% (`try_new`, class lookups, `combine_extensions`, `direct_extension`), lazy-load unserialization of `methods` objects 12%, the collector 10%, symbol interning 8%.
- **Unions and `cacheMetaData` replicate GNU R's quirks**, because state must `serialize()` identically: `.recacheSubclasses` matches the subclass's own name (always `NA`), so every union-member subclass's extension is overwritten, re-sorted and recached; `cacheMetaData` drops duplicate generic names but not their packages, so packages misalign after the first duplicate; classes are visited in frame order and generics sorted; `completeExtends` takes `.resolveSuperclasses`' first consistent candidate (`resolved_superclasses`). `.S3Extends` is not ported, so such members bail.
- **The first union fills `initialize`'s dispatch cache itself** (`union_initialize`), as the R code's `new("ClassUnionRepresentation", ...)` would, unless first-unit definitions are pending (they may add a preferred `initialize`). Only the default `initialize` is accepted (`is_default_initialize`) for the union and for `classRepresentation`, `SClassExtension` and `classPrototypeDef` (`definition_caches`), since GNU R's `new()` of a definition calls a package's method; a cached package method sends `setClass` and `setClassUnion` to the R code.
- **`setClass` does `setIs`'s bookkeeping by GNU R's quirks**: only direct superclasses go through `setIs`; ancestors record the class only when `possibleExtends` is false (so a later subclass of a union member is not added to the union); with a union ancestor, ancestors are recorded first (other unions recache their subclasses' `contains`, dropping `conflicts`), then direct superclasses, the first on the earlier-read definition and later ones on a fresh read (`record_subclasses`, `recache_subclasses`, `recachable`). Recaching bails when a union member is not cached or has a non-numeric distance. Cache and namespace binding may differ after `setClassUnion`, and `getClassDef` reads the cache, so `local_class` takes the cached definition and only requires a binding to exist. `prototype()` objects reduce to the list `do.call("prototype", list)` would wrap (`prototype_def_list`). A slot default whose class has a methods-package `initialize` runs `new()`, which cannot fail, unlike a package method, where `tryNew` falls back to the prototype.
- **`setMethod` builds `.local` natively** (`conform_definition`) with `rematchDefinition`'s result: generic formals, `.local(args)` with args after `...` and from the first `missing` signature position passed by name, and method defaults kept unless a symbol or missing. A method omitting only `...` gets the generic's formals in place. An omitted argument bails only when the signature names it, and a renamed argument becomes a `.local` wrapper; a different order, or added formals without `...` in the generic, bail.
- `setGeneric` accepts a braced `standardGeneric` body as a `nonstandardGenericFunction`, as `.NonstandardGenericTest` does; any other body bails.
- **Every fallback says why**: `bail!(skip, "reason")` and `report_fallback` under `RY_LOAD_VERBOSE` (`reference/package-loading.md`).
- **`cacheMetaData`** skips classes whose bound definition is the cached one, merges a package's own standard generics natively, and runs GNU R's loop body per remaining item (`Template::CacheClassItem`, `CacheGenericItem`), so effect order matches and a partial port is safe. On `target/s4plain` that took `cacheMetaData` from 104 to 16 ms.
- **A foreign generic with no methods in the namespace is reset natively** (`cache_foreign_generic`), because `setOldClass()` with a prototype makes nearly every package cache `Ops`. It walks the group tree as `.updateMethodsInTable` does, resets each `.AllMTable` to its direct methods and re-sets the primitives' dispatch tables (rlang's `cacheMetaData` fell from 19% to 2% of a warm load), and bails before effects on a group slot, a global binding, a namespace method table, or a non-primitive default. Primitive group members take their generic from the generic table, as `getGeneric()` does; lazy-loaded promises are forced by `forced_value` (`s4__cache_metadata_shapes.R`).
- Object creation and class queries were ported first as the run-time hot path (`new()` 13.7 µs, `validObject` 3 µs, `is()` 2.3 µs against GNU R's 130, 73 and 11.8 µs). `as()`, `setDataPart()` and inherited dispatch remain (`backlog.md`, "Open: native methods core"). `s4__native_core_queries.R` and `s4__native_definitions.R` pin the covered functions, including error messages and calls.

## Hot base R closures get hash-guarded native prologues

**Status:** built.

- **Why.** Validation code calls these closures at every boundary, and their bodies spend the time in nested closure calls (`match.arg` in `sys.function`, `formals` and `eval`; `format.default` in `match.arg` and `prettyNum`).
- **Mechanism.** `crates/interp/src/base_fast_paths.rs` puts `.Internal(ryX())` in front of a base closure's body when base loads, as the methods core does: a stable hash of formals and body guards the install (a miss is an error on the bundled R version and a silent skip on any other), the closure is patched in place, and the start-up image carries the patched closures. A prologue either returns from the closure's frame or returns NULL and lets the body run.
- **Patched closures and their reach.** `match.arg` (a single ASCII string), `setdiff` (plain atomic vectors; R 4.6.2's body spends 17 of its 24 µs in two `tryCatch` calls), `format.default` (no marks or `justify`), `structure` (plain attributes, a non-factor character class), `stopifnot` (all-TRUE logicals), `readRDS`, `Reduce` (`accumulate = FALSE` over a plain vector), `deparse`/`.deparseOpts`, `formatC` (plain integer or double, `mode` NULL, formats d f e E g G fg), `pmax` (plain atomics, first without attributes, no fractional recycling), `tryCatch` (one handler), `withRestarts` (`function` literals or strings), and `invokeRestart`/`tryInvokeRestart` (a name only). Small closures with call arguments (`ifelse`, `isTRUE`, `isFALSE`, `unname`, `%in%`, `unlist`) have their own entry, "Small base closures with call arguments run their bodies natively behind prologues".
- **Invariants.** A prologue forces only what the body forces, in the body's order, so a declined call sees the same promises. It covers the common case only and declines everything else, so errors, warnings and messages always come from the R body. A defaulted argument is checked by the cell holding the bound default (`gp::BINDING_MISSING`), not `missing()`: a wrapper passing on its own missing formal makes `missing()` TRUE, but forcing it in the body errors.
- **Nested closures** (`NESTED_FAST_PATHS`). `assignNativeRoutines` is defined inside `loadNamespace`'s body, so the prologue goes into that `function` expression, found by its `name <- function` assignment; `ryAssignNativeRoutines` binds all routines at once instead of growing vectors with `c()` (12% to 2.5% of rlang's warm load); it declines on the warning cases and on `symbolNames` (`namespaces__native_routines.R`). Hashes of nested functions are taken with nested prologues stripped (`without_nested_prologues`), because the image saves patched bodies.
- **`readRDS(path)`** reads the file whole, inflates gzip in one pass and unserializes the slice; the R body's `gzfile()` connection costs three times as much (rlang's `nsInfo.rds` 82 to 48 µs, its 15 KB `.rdx` 220 to 190 µs). Inflation is about half of what remains of an `.rdx` read. It declines for `~` paths, unreadable files, xz, bzip2, streams without an `X`, `B` or `A` header (the slice reader also takes `save()` files) and any unserialize error, so the R body reports those (`io__read_rds_formats.R`). An uncompressed form would need a second file per database or a non-GNU `saveRDS`, so it is not done; `zlib-rs` inflated no faster than `miniz_oxide`.
- **`match.arg` with `choices` missing** evaluates the caller's default only when it is a character constant or `c()` of them, and binds `choices` as the body does, so a declined call does not evaluate it twice.
- **`Reduce`** (`ryReduce`) covers a closure or builtin `f`, both directions, `init` given or not; `right` and `accumulate` are forced in the body's order, which depends on whether `init` is missing. It binds `mis`, `len`, `f`, `init` and `i` in its frame and calls `f` through `eval::call_with_values` with forced promises of the body's own expressions, so `sys.call()` and `substitute()` inside `f` match. `x` is a plain vector with at most names: a list that is not ALTREP, or an atomic vector in any representation, compact sequences included, whose elements are read as `x[[i]]` reads them (`Reduce(`+`, 1:10)` takes 2.2 µs against GNU R's 5.7, and 6.4 through the R body). A function named by a string (`Reduce("+", x)`) runs the R body, whose `match.fun` looks the name up from the caller. Each step compares the frame's `x` with the vector the fold started on and evaluates `x[[i]]` in the frame when `f` rebound or removed it. With `accumulate`, `simplify` is forced only when every accumulated value has length one, as the body's `&&` does, and a value that is not `TRUE` or `FALSE` evaluates the body's own last two expressions.
- **`deparse` and `.deparseOpts`.** testthat deparses a call for every expectation label, and the R calls spent most of their time on defaults (`backtick` runs `mode()` and `%in%`; `.deparseOpts` runs `pmatch`, `unique` and `sum`). The prologue forces `expr`, `width.cutoff`, `backtick`, `control` and `nlines` in the body's order, folds `control` into option bits natively and calls the internal in deparse's frame, so a width warning carries the R body's call; options must be spelled in full, and abbreviations, duplicates, `NA`, non-strings, `"all"` with `"exact"` or `"hexNumeric"` with `"digits17"` decline (`deparse__fast_path.R`).
- **`formatC` and `pmax`.** `formatC` was 77% of the report workload and 67% of strings (inclusive), almost all in argument handling and `prettyNum()`'s regex surgery. The prologue (flags `0+- #'I`) declines attributes, `mode`, `format = "s"`, digits the body would reduce with a warning, a value `format = "d"` would turn into NA, `preserve.width = "common"` and other marks. It does the body's NA/NaN/Inf substitution and default-digits arithmetic and calls `format::format_c_vector`, the same body as the `formatC` internal, with Rust values. An ASCII `big.mark` with default marks is inserted natively, matching `prettyNum()`'s reversed `([0-9]{k})\B` substitution. While `decimal.mark` holds its unforced default, it reads `OutDec` through `envir::option_value`: base's closure fixes the promise's code, `getOption()` has no side effect, and the prologue returns before the body could force it. The `'` and `I` flags are not pinned because GNU R's output depends on the C locale (`base__format_c_fast_path.R`, `base__format_c_out_dec.R`).
- **`as.Date.character`, `pmin` and `pmax`** (`ryAsDateCharacter`, `ryPmin`, `ryPmax`). `as.Date.character`'s body builds a POSIXlt three times (`strptime` per tried format and for the result, `is.na.POSIXlt` through `as.POSIXct`, `as.Date.POSIXlt`); the prologue gets each date from the parsed text (`system::date_from_text`), because `POSIXlt2Date` reads only the wall-clock fields. It declines on a `%z` offset read in the session's zone, on "Inf", on any `strptime` warning or error, on attributes other than names, and when no format matches, so `optional` and the error are the body's. `pmin` and `pmax` copy the first argument's attributes as `mostattributes<-` does and decline on `tsp`, `row.names`, and `names` beside `dim`. `just bench-ci`: `k2` 0.53 to 0.09 s (GNU R 1.07 s), `k8` 1.26 to 0.16 s (GNU R 1.55 s).
- **An argument the body forces inside an inner closure must not run code.** `as.Date.character` forces `x` inside `charToDate` and `format` inside `strptime`, so code run by forcing them sees those frames in `sys.calls()`. Its prologue reads such an argument only when it is a value, a forced promise or a promise `eval::settled_without_code` settles (`given_without_code`). Under S3 dispatch `x` is already forced, so the common call keeps the fast path (`datetime__as_date_character_fast_path.R`).
- **`tryCatch`, `withRestarts`, restarts.** The prologues keep every frame the R bodies make (`tryCatchList`, `tryCatchOne`, `doTryCatch`, `withOneRestart`, `doWithOneRestart`); only the bookkeeping between them is native, because a frame GNU R shows cannot be skipped (`sys.calls()`, `conditionCall()`, handler frame variables). Inner closures are made through `bytecode::inner_closure`, which reuses the compiled body stored in the outer function's constants; otherwise each new closure recompiled. `tryCatchList` covers one handler. The native bookkeeping forces the handler dots, builds `handlers`, `classes` and `parentenv`, and builds restart objects without `makeRestart`'s `do.call`. Two or more handlers decline; `withRestarts` declines other specs, and `invokeRestart` declines a restart object, `"abort"` or a missing name. `.signalSimpleWarning` and `.handleSimpleError` are called from the base environment, as `errors.c` does, so `sys.parents()` gives their frame its own number (`conditions__try_catch_fast_path.R` pins frames, `conditionCall`, handler order, `finally` and `on.exit` on every exit kind, and the muffle restarts).
- **Known difference.** The prologue is visible: `body(match.arg)[[2]]` is `.Internal(ryMatchArg())`, so printing, `deparse()` or digesting a patched function differs from GNU R.
- **Known gap.** The `format` internal checks its arguments (`trim`, `digits` 1 to 22, `nsmall` 0 to 20, `width`, `justify`, `na.encode`, `scientific`, `decimal.mark`) in `do_format`'s order against the calling closure, but does not yet warn "NAs introduced by coercion" for a string `digits` or `width`.
- **Measured.** `validation` went from 0.58 to 0.65 times GNU R to 1.87x with the JIT on and 1.77x off (callgrind 1.32G instructions against GNU R's 3.16G); `format(2.5, nsmall = 3)` 4.7 µs (GNU R 13.9); `pmax(3L, 2L)` 0.6 µs (GNU R 4.6); `formatC(42L, width = 6L, flag = "0")` 13.2 to 1.4 µs (GNU R 14), with `big.mark` 76 to 2 µs (GNU R 106); `deparse` 9.1 to 1.4 µs (GNU R 12.8); `tryCatch(1, error = h)` 3.7 µs (GNU R 4.1; 19 µs without `inner_closure`), `tryCatch(stop('x'), error = h)` 12.3 (12.3), `withRestarts(1, r = h)` 8.8 (7.5), `suppressWarnings(warning('w'))` 11.6 (26.1), two handlers on the R body 8.2 (6.3). `match`, `%in%`, `intersect`, `ls` and `pmatch` were each under 1% of the testthat profile and left alone.
- Next candidates: `utils::modifyList` (needs an install hook when utils loads) and `tryCatchList` with several handlers.
- **Bugs the `formatC` oracle case found in shared kernels** (the R bodies call them too): an `fg` zero printed with its flag and width, zero padding before a sign, logical and complex `x` formatted instead of rejected, and `pmax` keeping the first NA instead of the last NA or NaN, typing an empty result by its first argument, failing on `NULL`, accepting an NA `na.rm` and never warning on fractional recycling. `attributes<-` and `attr<-` reject a non-character class and a `"factor"` class on a non-integer object (GNU R's `classgets`).

## Builtin fast paths take names as CHARSXPs and evaluate nothing twice

**Status:** built, except the `c()` flattener's `LeafName`, which "Builtins with positional direct entries, one implementation per semantic" supersedes.

- Names stay CHARSXPs end to end (`do_attributes` collects pairs on the stack); `c()` widens integer and logical runs with a direct loop (`int_to_real`, NA to NA), and every gain is work not done (no interning, no pairlist, no second evaluation), so nothing needs invalidating; no per-builtin cache.
- `forceAndCall` reuses the call's cells after `n` and `FUN` when unchanged (`call_tail`), and passes variables eagerly to an effect-free closure when no argument is a call (`no_calls`), the same conditions as a compiled call site.
- The apply family's known element reaches a builtin `FUN` directly, and a special through `dispatch_evaluated_subject`, so `[[` methods still dispatch.
- `cached_item` (`records.rs`) reads a classless, non-ALTREP list by position or exact name; out of range falls back to `[[` for its error. A one-string constant is a side-effect-free subscript at the top level of an element assignment, and the in-place assignment rejects `""` and `NA`, which match no name.
- Fixed names come from `symbols()` (`type_names` for `typeof`, the generic for internal dispatch on `$`, `@`, `$<-`, `@<-` and `seq`, `X`/`FUN`/`i` for `lapply`/`vapply`), and a replacement call shares one tail pairlist between its getter and setter calls. `options(c("a", "b"))` reads only `a`, and `options(character())` is an "invalid argument" error, as in GNU R (`strings__interned_names.R`).
- **`lapply` and `vapply` share `ElementCalls`** (`envir.rs`), which writes `i` in place and reads `X[[i]]` directly, but rebinds a fresh `i` whenever its reference count moved (`bound_refcount`), because a promise or closure `FUN` made may read `i` later and must see its own value. `interp::testing::check_element_access_agreement` fuzzes the direct entries against the AST evaluator.
- Open: the closure call inside `vapply`/`lapply` allocates `i` and a promise per element; `$<-` and `[[<-` with a new name take `complex_assign`; `[<-` with a scalar costs 813 instructions against GNU R's 497, almost all tier-0 guards and frame lookups.

## One-argument builtins and small base closures skip dispatch when their arguments are values

**Status:** built.

- `BuiltinDef::unary` (`builtins.rs`, for `!`, `length`, `is.null`, `is.na`, `is.character`, `is.logical`, `is.function`) is called by `op_call_builtin` with the operand register for one positional, non-missing argument, skipping `call_builtin`'s dispatch and `run_builtin`'s scope. It returns `None` for anything not plain (object, ALTREP, attributes, a ry native value), so dispatch and error messages stay on the general path. Results are the shared immutable `TRUE`, `FALSE` and `NA` from `values::scalar_logical`, so modifying one copies it, as in GNU R.
- Native entries (`NATIVE_ENTRIES` in `base_fast_paths.rs`, for `identical`, `isTRUE`, `nrow`, `match`, `%in%`, `%||%` and others) are asked by `apply_closure` before it builds a frame. They are keyed by closure identity in `Interp::native_entries` and filtered by `gp::NATIVE_ENTRY`; both are rebuilt on an image start because the registry is not in the image. An entry declines when the closure is traced, debugged or stepped, an argument is named, or an argument is an unforced promise of a call; a promise of a variable or constant is settled with the value it would have produced, so later `substitute` or `missing` agree.
- `match` and `%in%` scan in place for one element of the table's type (strings by pointer when the element is ASCII or `NA`) and otherwise call the `match` kernel directly.
- **Why a field and not new tier-0 ops.** The JIT matches exhaustively on tier-0 ops, so a new op would change `crates/jit`; a field keeps compiled code unchanged and gives the baseline tier one function to call.
- `crates/oracle/cases/builtins__native_entries.R` pins the edges. `missing` is a special and costs about twice GNU R.

## Builtins with positional direct entries, one implementation per semantic

**Status:** built, except the fused element op and `element_access::read_element` under "What is left", which "Tier-0 element reads and stores as fast handlers, not new ops" supersedes.

- **`BuiltinDef::direct`** (`DirectFn = unsafe fn(call: Sexp, &[Sexp]) -> R<Option<Sexp>>`) takes the call (for errors and native context) and the values in formal order. `op_call_builtin` tries it when no argument is tagged or empty, and `replace_variable` when the only tag is the trailing `value`. It declines everything the full call treats differently (an object that would dispatch, ALTREP, a ry native value, an argument whose error message the full call words). `unary` remains the one-operand form that reads its register without a slice. The caller sets visibility, records feedback and releases the entry's handles, and skips the entry while a profile or activity trace runs so samples name the builtin.
- **One implementation per semantic.** The full builtin calls the same function after matching arguments. No cache: every gain is work not done, so nothing can go stale. `attribute_access.rs` holds attribute reads and writes by `CHARSXP` (a full match is a pointer compare against the interned `which`, only a miss scans prefixes, in GNU R's `do_attr` order, including its special case for `names` and expanded compact row names on a partial match), the implicit and explicit class as a fixed-size list of `CHARSXP`s, and `inherits` over it. `combine.rs` holds `c()` and `unlist()` as GNU R's two passes (size: type, length, whether names exist; then write), so no per-leaf vector or `String` is built; `direct_c` copies attribute-free atomic arguments without the naming walk, because no name can arise from them. `element_access.rs` holds `[[` on plain vectors and lists (`[[<-` keeps compiled code's `assign_element_in_place`).
- `same_text`: interned ASCII strings are equal exactly when they are the same object, so bytes are compared only when either side is not ASCII.
- **`x[i] <- v` in place** (`assign_subset_in_place`, from `op_sub_assign`) writes an unshared, attribute-free atomic vector with an integer, real or logical index and GNU R's recycling and declines NA or zero positions, growth, widening and partial recycles, so the full `[<-` keeps one implementation of those rules. Plain lists accept a `list(...)` value, each element counted as stored through `set_element`; an atomic value for a list target declines, since it would need boxing.
- **`.Call` by address** (`crates/libr/src/dot_call.rs`): an untagged, non-null `address` is a native entry point, because builtin-library routines carry a marker tag and base routines a null address. `call_registered` reads the `address` and `numParameters` slots by position (names checked by pointer), passes arguments from a `SmallVec<[Sexp; 8]>`, and `retire_escaped` returns at once when no data pointer was handed out. `PACKAGE` or an arity mismatch declines to the general path that owns the errors.
- **`apply_results::VapplyResults`** owns GNU R's `vapply` checks and error text, writes each result into the preallocated answer with inline widening and sets names, dims and dimnames once; every loop that calls `FUN` hands results to it, and the loop owns calling `FUN`. It fixed complex widening, list strictness, `USE.NAMES = NA` and array `FUN.VALUE` (`builtins__vapply_results.R`).
- **Element assignments stay in slot frames.** `ForStep`'s variable gets a slot even if never read; without one, the first `ForStep` gave the frame an environment and every `x[[i]] <- v` after it ran through `frame_cell`. The `SLOTS` constant's fourth element maps constant index to slot (`slot_at`), so `ForStep` and `SubAssign` find their slot in one load instead of comparing every slot name; `index_slots` derives it from code, names and constants in the compiler and the image reader, so images store only names and the map cannot go stale. It covers only the variables `ForStep` and `SubAssign` name, because a map over every constant raised peak RSS by 2 MB. Parentheses over a side-effect-free subscript stay side-effect free.
- **No per-call allocations.** `subset::resolve` returns a `SmallVec` with eight inline slots; negative subscripts build a `SmallVec<[u64; 4]>` bitset (inline up to 256 elements), so `x[-1L]` on a short vector makes no Rust allocation; `match_builtin_args` uses a bitset and borrowed names; the primitive formals `check_argument_names` reads are a `Vec` indexed by `builtin_index` (`subset__negative_index_bitset.R`).
- **What is left.** At tier 0, `x[[i]]` and `x[[i]] <- v` cost about twice GNU R, all of it dispatch around the builtin: for a read, `GetFun`, the primitive and object branches, `CallBuiltin` and the `Jump` cost about 300 instructions around a 130-instruction read; for an assignment, two `Guard`s cost about 100. Under the JIT both run far below GNU R. Oracle cases `builtins__attribute_access.R`, `builtins__combine.R`, `builtins__element_access.R`, `builtins__assign_subset_vector.R` and `builtins__dot_call_native.R` pin the edges.

## Builtin call machinery and subassignment toward 10x

**Status:** built.

- `DirectFn` takes the call so builtins whose errors name it (`[`, `.Call`, `round`) can have a direct entry. `direct_subset` reads an in-range numeric scalar position of an attribute-free atomic vector and otherwise calls the same `subset()` as the full builtin. `.Call`'s direct entry calls `call_native` inside `foreign_context` with no argument list.
- `-x` on an attribute-free integer or double scalar goes through `BuiltinDef::unary`, so `x[-1L]` pays no general call per iteration (the compiler does not fold `-1L`). `c()` reuses the tag's `CHARSXP` as the element name when an argument contributes one unnamed element.
- **Appending a name** (`append` in `subset.rs`) grows the vector in place when it is unshared, not held by a register and not bound through a promise, and copies with room to grow otherwise, so growth is amortized like GNU R's growable vectors.
- `scatter_slab` copies contiguous runs with `copy_from_slice` when the first dimension is taken whole and walks the other dimensions with a counter. `round` on doubles runs `fround_slice` and copies attributes only when present.
- `Reduce(accumulate = TRUE)` runs natively; `out[[i]] <- init` writes the slot directly while `out` is unshared and `init` is not NULL (NULL deletes the slot, so it evaluates the assignment then). The final `unlist` reads lengths directly unless an element is an object, when the R tail is evaluated.
- **Why no new tier-0 ops.** The `direct` and `unary` fields reach the same code from tier 0 and the JIT fallbacks without changing the op set.
- **Measuring RSS.** A cold binary inflates peak RSS through page-cache fault-around on its text, so compare builds only after reading both files once.
- Left: `structure()`, `format.default` and `Reduce`'s callee calls are dominated by closure frame setup and argument matching. `vapply` and `lapply` over three elements beat GNU R (2677 against 2920, 2625 against 2718 instructions); what remains is calling `FUN`. Oracle cases `builtins__round_vector_fast_path.R`, `assignment__append_name_in_place.R`, `subsetting__matrix_slab_assign.R`, `builtins__dot_call_direct.R`, `subsetting__direct_single_bracket.R` and `apply__reduce_accumulate.R`.
- **Open:** `.Call`'s remaining gap to GNU R is the compiled loop and the JIT's call sequence (`rlang:::ffi_length` 2,916 instructions per call against GNU R's 830).

## One kernel layer for R's vector builtins: slice kernels, a reuse rule, and a fused superinstruction

**Status:** built, except the helper `first_nan`: the kernels pick the NaN payload inline.

- **Slice kernels** (`crates/interp/src/kernels.rs`) are the interface compiled code calls. They take `Reals` (doubles, integers read as doubles, or a scalar) or `Integers` (slice or scalar) and write into `&mut [T]`. They touch no R object, allocate nothing and raise nothing; integer overflow is a returned flag. `kernels::binary` serves plain operands only (double, integer or logical, no attributes, not ALTREP, not an Array) and returns `None` otherwise, so dispatch and messages stay on the builtin. Scalar operands are answered without the element loop, because most package calls are on scalars.
- **No AVX2 build.** A second AVX2 build of every kernel cost 0.6 MB of resident code for no gain on memory-bound loops. A narrow AVX2 `real_operation` and unary minus were faster on L1-resident chunks in isolation, but 15 to 25% slower end to end on 10,000 doubles, and their 85 KB sat on every double arithmetic call, so every workload faulted in its 64 KB text windows. Only `vector_math`'s exp and log run AVX2, where the gain is 4x.
- **NaN payloads.** SSE returns the first operand's NaN payload and LLVM may commute `+` and `*`. GNU R's loops: for two doubles, `x + y` and `x * y` take `y`'s payload when a scalar `x` meets a longer `y` and when both recycle, `x`'s otherwise; with an integer operand always `x`'s; `-`, `/`, `%/%` take `x`'s. `kernels::payload_from_right` encodes this by swapping operands. Beside a non-NaN scalar, `+` and `*` use the plain operator (only the vector element can be NaN). Probed against GNU R 4.3.3 in `crates/oracle/cases/kernels__elementwise.R`.
- **Reuse rule.** A result goes into an operand's buffer only when the compiler marked its register as a temporary only this instruction reads (operand 6 of `Op::Arithmetic`) and at run time the count is zero, it is mutable, not ALTREP, and has the result's type and length. A builtin called from the AST evaluator never reuses this way. The count alone is not enough: registers and the JIT's unwritten slots hold uncounted references. This is GNU R's `R_allocOrReuseVector` restricted to what the compiler proves.
- **Aliased destinations.** `kernels::binary`/`unary` take an optional destination that may be an operand (`x <- x * y`); the slice kernels take operands as `Option`, where `None` means the output buffer, so no `unsafe` aliasing. `kernels::fits` requires length above one, because the shared scalar constants can be held by a single binding with a count of one. `Call.reusable` offers `x` for `x <- f(x, ...)` when the binding holds the only reference and `f` is marked `reusing_first_argument` (the arithmetic, comparison and logic operators, `!`, and the one-argument math functions); an `Ops` member dispatches first so a method sees untouched operands.
- **AST temporaries** (`eval::temporary_argument`): a `reusing_first_argument` builtin called from AST code reuses an argument that is a two-argument call to a base operator builtin with count 0, so `x * 2 + 1` in AST code peaks at one result as in GNU R (153 MB over the inputs at 2e7 doubles, against 305 without). The operator must be the base builtin (a closure bound to `*` may return a held value), and unary `+` is excluded because it returns its operand. Reference-counted registers were rejected: a count update on every register write, unneeded while every reuse source is a known fresh temporary.
- **Reductions.** `sum` on integers (`sum_integers`, an `i64` total, NA on the first NA unless `na.rm`), `any`/`all`, `min`/`max`/`range` are SIMD kernels, `range` in one pass; `real_extremes` lets the first zero decide a zero bound's sign, because GNU R keeps the first of equal values. `prod` and double `sum` accumulate in x87 long double (`long_double.rs`), which no SIMD lane reproduces.
- **Fusion.** `Op::Fused dst program target` precedes the ordinary code of an element-wise tree (layout in `bytecode::fusion`). The compiler emits the ordinary code unchanged and matches the plan against it, emitting `Op::Unfused` when they differ. At run time it reads leaves in the ordinary code's order, checks operator guards, and declines (falls through) on scalars only, vectors shorter than `kernels::SHORTEST_FUSED` (64: below it fusion saves too little allocation to pay for reading the program), active or missing bindings, attributes, objects, ALTREP, non-scalar recycling, integer overflow, or a produced NaN; after 16 declines in a row it rewrites itself to `Op::Unfused` and drops its program, so a site that never fuses costs one dispatch and holds no heap. A frame argument's promise is forced as `GetVar` would. Otherwise it runs 512-element chunks in per-thread scratch and records the replaced instructions' type feedback.
- **Why a declining superinstruction.** Nothing observable happens before it decides, so fused and unfused evaluation are indistinguishable, and the JIT keeps compiling the ordinary code (baseline lowers `Op::Fused` to `runtime::jit_fused`, which reads the program's registers through `bytecode::fused_operand_registers` and returns `FUSED` or `FUSED_INVALIDATED`; feedback comes from `bytecode::fused_result_site`).
- **Call leaves.** A call such as `mean(x)` in `sum(x - mean(x) > 0)` is evaluated ahead by `Compiler::fused_call`: guards for every operator head before the last call leaf come first, because the guards' cold fallback evaluates the whole AST and would run the call twice; R looks operators up before evaluating arguments anyway. Pre-checked heads get no guard in the ordinary code (`Compiler::preguarded`). Variables read before a call are hoisted with it (`Compiler::hoisted`, consumed occurrence by occurrence) so a call that rebinds them leaves earlier reads with the old value. A call that `may_modify_in_place` is never a leaf, because registers do not count as references.
- **Fused assignment** (`fusion::ASSIGNED`, reading `y`'s symbol and slot from the `SetVar` at the jump target, because two stored words per program grew the start image by two 64 KB pages) writes `y <- tree` into `y`'s old buffer when `bytecode::reusable_target` allows (not active or locked, count one, `eval::reuse_permitted`); `kernels::fused` takes it only as a double vector of the result's length; when `y` is also a leaf, `kernels::chunks` copies each chunk's root over only after every node read it. Integer passes never reuse, because an overflow declines halfway. Do not verify reuse with `.Internal(inspect(y))`: the call references `y` and defeats it (`kernels__vector_math.R`).
- **Rejected: lazy fused vectors as ALTREP** (Riposte, pqR): every reader, C code through `DATAPTR` included, would materialize them, and when a deferred warning surfaces would become observable.
- **SIMD `exp` and `log`** (`crates/numeric/src/vector_math.rs`) are four-lane ports of glibc's `__exp_fma` and `__log_fma`, which GNU R calls through ifunc on AVX2+FMA, so the bits match; any other SIMD polynomial would not. The first call probes against the host glibc and disables the kernels on a mismatch. Kernels are off without AVX2+FMA. Lookups use 128-bit loads, not `vgatherqpd`, which is microcoded slowly under the Gather Data Sampling mitigation (1.02 against 0.84 ns per element for exp). glibc's scalar exp costs 3.9 ns per element and log 2.9; the kernels 0.84 and 1.1. `kernels::vector_lanes` adds R's NA handling and the produced-NaN warning.
- **`R_POW`'s bits.** GNU R computes `x^2` as `x * x` and `R_pow` returns `x + y` for NaN, so both quiet a signalling NaN (`NA^2` is `7ff8...07a2`). Division by a normal power of two multiplies by the exact reciprocal (`kernels::exact_reciprocal`), bit-identical and avoiding `vdivpd` (0.6 ns per element).
- **Complex arithmetic.** `complex_binary` serves complex beside plain double (or, from R 4.4.0, logical or integer); `arith::complex_arithmetic` calls the same `kernels::complex_arithmetic`. `z^2` computes `R_cpow_n`'s `1 * (z * z)`. GNU R's `^` is `R_cpow_n` for an integer exponent up to 65536, else glibc's `cpow`.
- **Complex bits.** GNU R uses GCC's libgcc `__muldc3`/`__divdc3` and glibc `cpow`; Rust links compiler-rt's, whose recovery differs, so `arith::complex_multiply`, `infinite_product` and `complex_divide` port libgcc's, and `cpow` is called through FFI. Which NaN wins decides `NA` against `NaN`, so steps use first-operand-wins `arith::add`/`subtract`/`multiply` in GCC's operand order (read from `libgcc_s.so.1` disassembly). A NaN ratio inside `__divdc3` fails its subnormal test, so NaN operands take the alternate formula. A 625-case probe over NA, NaN, 0, 1 and 2 in each part matches GNU R exactly. The ordered formula runs only in out-of-line `nan_product`, after deciding the recovery, because vectorized mandelbrot hits the recovery on about 40% of products, and running the ordered formula first made `mandelbrot_noout` slower than a plain-formula loop.
- **Complex coercion.** An integer or logical NA becomes `NA + NAi` before R 4.4.0 and `NA + 0i` from it (`r_at_least(4, 4)`). `abs`/`Mod` keep `dim` and names; other `Math` functions and `clog` map NA in either part to `NA_complex_` and warn `NaNs produced in function "<name>"` as `cmath1` does; `log(z, base)` is `clog(z) / clog(base)` through the `__divdc3` port; `atan` reproduces `z_atan`'s full complex product.

## Package code that dominates a workload runs natively: rlang's trace_back

**Status:** built.

- **Decision.** Package functions get hash-guarded prologues like base's (`package_fast_paths.rs`). `registerS3methods()` runs for every namespace load (`library()`, `requireNamespace()`, `pkg::`, `ry load`, image or lazy-load) after the code is in place and before anything can call it, so its first statement `.Internal(ryPackageFastPaths(package, env))` installs them without changing `loadNamespace()`. A hash miss silently keeps the R body.
- **Policy for package-specific native code.**
  - *Generic first.* Measure the R body on ry against GNU R in the same sitting and fix every slower primitive; native code covers only what remains.
  - *Eligibility.* The package is in the AGENTS.md benchmark set, or a real workload profile puts the function above about 2%.
  - *An exact guard per release.* `FAST_PATHS` names the release and hash; `crates/ry/tests/scenarios/native-package-functions.scenario` fails when the installed release differs, so an update is not a silent slowdown.
  - *Fallback.* `decline()` whenever the R body could observe something the port does not model.
  - *Evidence.* A seeded differential harness against the R body (`fuzz_native_trace_back_matches_its_r_body` in `crates/oracle/tests/test_differential.rs`), oracle cases against GNU R, and a news-page line.
- **Why trace_back.** It is about 80% of `expect_error()` on GNU R too; no primitive under it was slower than GNU R, so the gain had to be native. `ryTraceBack` is a pure function of `interp().frames` and reproduces rlang 1.3.0's columns (`call_zap_inline`, `call_trace_context`, trimming, attribute order). It declines on `rlang:::visible_bottom`, `rlang:::error_frame`, `knitr.in.progress` without `top`, an unforced promise in call position, an object as function, or a malformed `function` call. `conditions__rlang_trace_back.R` (hand-written stacks) and `conditions__rlang_trace_back_generated.R` (50 seeded random stacks) compare with GNU R and with the R body on the same frame; `native-package-functions.scenario` pins the script and `ry load` paths.
- **Interned strings carry a validity fact.** `flag_bits::VALID_UTF8` is set in `Heap::intern_new`, and `char_str` borrows such a string unchecked unless it is marked Latin-1 or bytes. The header flag byte is unreachable from `SETLEVELS` and interned bytes never change, so unlike the gp `ASCII` bit it is a fact.
- **Names stay symbols.** `::`, `getNamespaceValue`, `options()` and the fast paths take symbols and `CHARSXP`s; fixed names come from `Symbols`, generated by one macro so a name is listed once (`envir__namespace_lookup.R`).
- *Review rule.* A reviewer accepts a new entry only with the same-sitting generic measurement, the profile share, the hash test entry, the differential harness and the news line.
- **Measured.** Stubbing `testthat:::can_entrace` to `FALSE` removed 23% of the testthat workload's instructions (every `expect_error()`, `expect_warning()` and `cnd_entrace()` traces the whole stack); the native trace took it from 6,787M to 4,690M (-30.9%). Under the R body at depth 50 ry's primitives ran at 0.5 to 1.2 times GNU R's cost (`call_trace_context`, about 1.5 ms of the trace, 0.7 times). The R body takes 1.19, 3.20 and 8.96 ms at depths 10, 50 and 200 (GNU R 0.89, 2.31, 7.74); the native trace 0.015, 0.045 and 0.16 ms. `Heap::install` re-interning names had been 1.6% of the workload.

## withr's environment and option helpers run natively; defer() stays in R

**Status:** built.

- **Decision.** withr 3.0.3's `as_envvars`, `get_envvar`, `set_envvar`, `get_options`, `set_options`, `reset_options`, `list_combine` and `reset_gettext_cache` get prologues under the package policy above. `defer()` and the `local_*()`/`with_*()` functions keep their R bodies, so restores register through the ordinary exit-handler path.
- **Generic first.** The bodies' primitives got base fast paths first (`ryIntersect`, the `names` branch of `ryStructure`, `rySysGetenv`, `rySysSetenv`, the `Sys.unsetenv` native entry), which help every caller.
- **Exactness.** Helpers decline whenever the body could raise a condition: `set_envvar` with `action` other than `"replace"` or a non-string, non-NA value; `as_envvars` on missing, empty or `NA` names or extra attributes; `set_options`/`reset_options` unless every option sets quietly (`envir::option_sets_quietly`), because an option error's call is the R body's `do.call()`-built call.
- **reset_gettext_cache.** ry's `bindtextdomain()` keeps no cache, so the native helper calls the `tempfile()` and `bindtextdomain()` kernels (keeping the `tempfile()` sequence) but skips creating and removing the directory. That is unobservable: names mix the clock with a counter and the directory never outlives the call. It declines when the session temp dir is missing.
- **GNU R behavior.** `Sys.setenv`/`Sys.unsetenv` return `FALSE` for an empty name or one containing `=`, and write `NA` as `"NA"`. `Heap::install_char(NA_STRING)` installs the symbol `NA`, as `installTrChar` does. A list with an `NA` name prints `$<NA>`.
- **Evidence.** `fuzz_native_helpers_match_their_r_bodies` (`test_differential.rs`, comparing value, visibility, condition, environment and option state), oracle cases `packages__withr_env_and_options.R`, `base__intersect_native.R`, `base__structure_names_native.R`, `system__sys_env_native.R`, and `crates/ry/tests/scenarios/native-withr-helpers.scenario`.
- **Measured.** withr's helpers and `reset_gettext_cache()` (a temp-directory create and delete per test, through `local_reproducible_output()`) were the next package-level cost after `trace_back`. The workload fell from 4,705M to 3,313M instructions (-29.6%): the generic base fast paths took 6.2% and the native helpers 23.3%. Warm wall time fell more (0.51 to 0.24 s), because the directory system calls are kernel time callgrind does not count. No helper retains memory (80,000 calls keep RSS flat).
- **JIT and RSS.** With these helpers, `isTRUE`'s body becomes the one function the JIT compiles in the testthat workload, and the code generator's first use costs about 4 MB (peak RSS 86.7 to 87.9 MB with the JIT on, 86.5 to 83.8 MB off); making that cheap is JIT work, not a reason to keep the helpers in R.

## Environment variable calls read `environ` once

**Status:** built.

- `scan_environment` (`crates/interp/src/system.rs`) walks `environ` once for all names of a call; `std::env` took a lock, allocated a C string and scanned all of `environ` per name. Names are keyed by their first two bytes as glibc does (a one-byte name uses `=` as the second). A one-name call compares each entry's first then second byte, exactly glibc's loop (building a two-byte key per entry cost twice glibc). Several names use a 256-bit first-byte set, keys in a plain slice zeroed when found, and stop once all are found; a `SmallVec` deref or shrinking list in the loop costs more than glibc's whole lookup.
- `Sys.setenv` skips a name whose value is unchanged (unless repeated earlier in the call), and `Sys.unsetenv` skips an absent name, because withr restores every variable on exit, and in a 172-variable environment with 64 names starting `CL` glibc's two-byte check cost a `strncmp` per entry. The three calls fell from 126M to 82M instructions on the testthat workload, and a one-name `Sys.getenv` from about 3,900 to 2,100 instructions, below libc. Writes go through libc, so C code sees every change.
- **Rejected.** A private copy or index of the environment would miss C code calling `setenv()`, and it would be a cache.
- **Evidence.** `fuzz_environment_variables_agree_with_the_c_library` (`crates/interp/tests/test_fuzz.rs`, sets and unsets from both R and Rust) and `system__sys_env_round_trips.R`, covering empty names, NUL bytes, `NA`, values with `=`, empty against unset, repeats and non-UTF-8 values (marked native).
- **Measuring RSS.** Stage both builds' files at the same time and warm them: a freshly written code image sits whole in the page cache, so fault-around maps more of it and shows a false gap of several MB.

## Conditions: message(), warning(), signalCondition() and getOption() run natively when nothing could observe the difference

**Status:** built.

- **message()** (`ryMessage`) writes directly when no handler for `simpleMessage`, `message` or `condition` is established (`conditions::handled`, which allocates nothing), `domain` is default, every `...` argument is a plain atomic vector, and no `conditionMessage` method exists; the R body would then signal to nobody and write `conditionMessage()` to `stderr()`. Latin-1 or bytes text declines.
- **signalCondition()** (`rySignalCondition`) binds `msg` and `call` in its frame first, because handlers read them through `sys.frames()`. It reads `message` and `call` as `$` does (an exact name wins, an absent field is `NULL`, as testthat's expectations have no `call`); a name only a longer field starts with declines, because `$` would partially match. It declines when a `conditionMessage`, `conditionCall` or `$` method exists for a class before `"condition"`. Handler lookup re-reads the class per handler, because a calling handler may change it.
- **warning()** (`ryWarning`) builds the message for `NULL`, logical, integer, double and character arguments without attributes (where `.makeMessage()` runs nothing observable and ry's `gettext()` is the identity) and signals through `conditions::signal_warning` from warning's own frame, so the call and `sys.calls()` match and calling handlers, `tryCatch()` and every `warn` level see the same condition. Condition objects, classed arguments, a non-default `domain`, a non-logical `call.` or `immediate.`, and Latin-1 or bytes text decline. `noBreaks.` is ignored, as ry's `.Internal(warning())` ignores it.
- **getOption()** is a native entry that compares the name's CHARSXP by pointer while walking `.Options` (`envir::option_value`), by bytes only for a non-ASCII name. A symbol-keyed table would be a second copy of `.Options`, which R and C code (`GetOption`) read and write directly; the fix is a redesign of `.Options` (`backlog.md`, "Options as a symbol-indexed array").
- **Switch.** `RY_FAST_PATHS=0` disables these paths and the warning-call shortcut, so a case can be diffed against ry's own R bodies (`development/corpus-and-oracle.md`).
- **Measured** (per call, `RY_FAST_PATHS=0` against the default): unhandled `message()` 31.7 to 0.95 µs, unhandled `warning()` 22.2 to 6.0 µs, `signalCondition()` with no handler 5.15 to 2.70 µs, `getOption()` 0.75 to 0.20 µs. A `warning()` muffled by a calling handler only drops from 201.3k to 171.5k instructions, because signalling and the restart dominate.
- **Evidence.** `conditions__message_and_restart_frames.R`, `conditions__signal_condition_dispatch.R`, `conditions__warning_native.R`.

## Builtin and assignment hotspots of the public suites

**Status:** built.

- **Measured.** Profiling the public suites (`tools/bench/public/{awfy,rcp,shootout}`) against GNU R put the slow programs' time in assignment forms and small kernels, not one builtin.
- **`<<-` to a symbol is `Op::SuperAssign`** (a lookup and a store, not a builtin call): it assigns in the first enclosing environment that binds the name, creating it in the global environment, erroring on a locked binding.
- **Defensive copy narrowed.** The copy in complex assignment guards an index expression that rebinds the target (`x[{x <- 0; 1}] <- v`), so it is taken only when an index syntactically assigns to the target or a part of it (`eval::assigns_to`); an index that assigns another variable still compiles to `Replace`, because the AST fallback rescans the target's attributes on every call.
- **Array slabs in place.** `x[i, j, ] <- v` on an unshared numeric or logical array writes through an odometer (`subset.rs`). `c()`, `length<-` and the binds copy the existing prefix with one slice copy, and scalars come from `alloc_scalar`. `[<-` is a special, so `replace_variable` accepts a special with a direct entry for a non-object target and allows empty subscripts only for it, falling back when the entry declines.
- **Matrix `[[i, j]]`** (`direct_subset2`, `scalar_position`) reads two scalar in-range subscripts and declines the rest (NA, zero, negative, non-scalar). A negative matrix `[[` subscript is an error in GNU R 4.3.3 ("attempt to select less than one element in integerOneIndex", "invalid negative subscript in get1index <real>"), while 4.6.2 applies the extent-two rule per extent (PR#19116, `m[[-1, 1]]` of a two-row matrix reads row 2); `get1index` follows the emulated release (`r_at_least_release(4, 6, 2)`).
- **`dim<-` and `array()`** validate as 4.6.2's `dim2total`: empty `dim` ("'dim' cannot be of length 0"), `NA`, negative extents, then a double product beyond the longest vector ("too many elements specified"), and `dim<-` prints the mismatch with both lengths (`dims_total`). Older emulated releases keep their own messages ("length-0 dimension vector is invalid", the product only when it fits an `int`), and their `array()` no checks.
- **`matprod` lives in interpreter state**, as GNU R's `R_Matprod`: `Interp::product_options` (`linalg::ProductOptions`) is written only by `set_option` and reset by `clear_options`. `%*%` reads it instead of looking up `matprod` and `ry.blas` per call. The option list stays the source of truth; the state is its parsed form, written where the option changes. A one-row `%*%` is computed as dot products (200k 5x5 products 0.070 to 0.042 s, GNU R 0.040 s).
- `attr<-` installs the name once (`install_charsxp`) and compares by identity. Complex arithmetic: see "Complex results match GNU R bit for bit, NaN payloads included".
- **Left for other owners.** Closure call overhead (`rev.default`, `rep_int`, `as.vector`, `get` are closures), `:` and `rep`, and unboxed scalar JIT loops dominate the remaining slow programs (fannkuchredux, nbody, spectralnorm_alt_3).
- **Evidence** (JIT on and off). `assignment__superassign_compiled.R`, `assignment__array_subassign_compiled.R`, `builtins__grow_copies.R`, `builtins__matrix_element.R`, `assignment__assigning_index_compiled.R`, `arith__complex_vectors.R`, `attributes__many_attributes.R`.

## One-pass attribute lookup and the blocked matrix product

**Status:** built.

- `attribute_access::attribute` finds a full and a partial match in one walk; only a tag strictly longer than the wanted name can partially match, so vectors used as maps (shootout's knucleotide stores thousands of attributes) cost one pointer compare per tag instead of a second walk with a `memcmp` per tag (knucleotide_brute_2 0.69 to 0.48 s, GNU R about 0.95 s).
- `%*%` computes `dgemm("N", "N")` itself in the reference BLAS order, adding `x[, inner] * y[inner, col]` into each column in ascending `inner`, with four result columns sharing each pass over `x`, so a large `x` streams from memory a quarter as often (spectralnorm_math's 1000 by 1000 product 0.29 to 0.17 s; the rest there is reference LAPACK's `eigen`, which GNU R uses too). Do not reorder the sum (blocking over `inner`, pairwise or FMA kernels): results would differ from GNU R in the last bits.
- **Evidence.** `attributes__partial_lookup.R`, `numerics__matrix_product_blocks.R` (every remainder of four columns, non-finite entries).

## Distribution functions and the RNG run as vector kernels and batched samplers

**Status:** built.

- **Kernels.** `distributions!` (`crates/interp/src/distributions.rs`) generates one `Kernel` type per row, so `math::<K>` monomorphizes with the scalar body inlined; recycling uses one wrapping counter per operand. NaN operands go to a cold path that keeps GNU R's NA-over-NaN rule. A kernel may override `fill_first` for when only the first operand varies: `qnorm` runs Wichura's AS 241 central region across AVX lanes and the tails in a batch (`qnorm_central_fill`, `qnorm_tails_fill` in `rmath.rs`).
- **Samplers.** `random { ... }` rows generate a `Sampler` with `prepare` and `draw`: scalar parameters prepare once per call, recycled ones again only when a parameter's bits change. `Poisson` and `Binomial` hold GNU R's static caches (the table for `mu < 10`, the BTPE constants) as fields, so the sequence is the one GNU R's caches give.
- **Batched uniforms.** `with_deviates!` splits the RNG into `Draws<Twister>` or `Draws<&mut State>` once per call, so state stays in locals and the kind is matched once. The twister regenerates eight words per AVX2 instruction and tempers four at a time (`twist_words_avx2`, `temper_block_avx2` in `random.rs`), and inversion normals combine uniforms four at a time (`inversion_fill_avx2`).
- **Bit-exactness.** Every SIMD lane performs the scalar operations in the same order, and Rust never contracts `a * b + c` into an FMA, so AVX multiversioning cannot change a result. Unsigned-to-double goes through `(word ^ 2^31) as i32 as f64 + 2^31`, which is exact. `log` and `exp` vectorize only through `vector_math.rs` (`pnorm_standard_fill`, `qnorm_tails_fill`), with scalar libm loops where those kernels are off. The inversion combine runs on lanes only for generators whose uniforms lie in (0, 1), because vector truncation and Rust's saturating cast disagree on overflow, which a user-supplied generator can reach.
- **`sample` without replacement** (`do_sample2`) keeps a bitset over the population when `population / 128 <= size` (then at most twice the hash set's memory, with no hashing; below it the bitset would dominate the call) and an `FxHashSet` otherwise; draw order and redraws are unchanged (`random__integer_index_draws.R`).
- **`.Random.seed` in place.** `put_rng_state` overwrites the vector only when it is unshared, plain, of the right length, in an unlocked, unwatched, ordinary binding, so a copy the user saved keeps its values (`random__batched_streams.R`).
- **Measured** (callgrind, `rnorm(1e6)` three times): 164 instructions per normal on the per-deviate shape, 67 batched. Per element at length 1e6 against GNU R: `rnorm` 3.2x, `runif` 5.7x, `qnorm` 3.0x, `pnorm` 1.7x faster, `rpois` and `sample` about 1.1x.
- **Evidence.** Seeded tests in `random.rs` (`batched_draws_match_single_draws`, `simd_kernels_match_their_portable_versions`) and `distributions.rs` (`qnorm_lanes_match_the_scalar_function`, `pnorm_batches_match_the_scalar_function`, `recycling_matches_modular_indexing`, `prepared_samplers_match_fresh_draws`); oracle cases `distributions__vector_paths.R`, `random__batched_streams.R`, `random__prepared_samplers.R`.

## unlink() follows GNU R's R_unlink, with directory descriptors

**Status:** built.

- `crates/interp/src/file_removal.rs` is GNU R's `R_unlink` on directory descriptors (`openat`, `readdir` with `d_type`, `unlinkat`), so only `force` or an unknown entry type costs a `stat`, each subdirectory is removed as soon as it is empty, and the path length is tracked as a number so nothing is allocated per entry. The change is for correctness (`force`, `expand`, `NA`, link handling, `recursive` for empty directories), not speed: a testthat-shaped tree takes 0.29 to 0.39 ms against GNU R's 0.31 to 0.42.
- **GNU R's quirks kept.** `lstat`, so a link to a directory is removed as a link; `force` uses `chmod`, which follows links; the directory test is `st_mode & S_IFDIR`, so sockets and block devices are walked and fail; `NA` counts as a failure, `"~"` is skipped, `expand` globs with `GLOB_NOCHECK`; a path of 4096 bytes or more is "path too long".
- **Rejected: `rmdir` on a background thread.** ext4's `rmdir` waits for the journal (about 0.1 ms idle, 2 to 4 ms under writes), and a helper thread cut a testthat-shaped tree from 2.0 to 3.7 ms to 0.27 to 0.46 ms under write load. But most corpus `unlink()` calls remove single files (`cli`'s snapshot tests remove testthat's `verify_exec_*` files), so the corpus did not move (1.013x, 95% interval 0.973 to 1.048), and the thread cost 0.28 MiB of peak RSS plus a join before every fork and at exit.
- **Coverage.** `interp` `test_file_removal` compares generated trees against a port of `R_unlink`; oracle cases `io__unlink`, `io__unlink_fork`.

## Parse data as dense columns

**Status:** built.

- `parse(keep.source = TRUE)` builds parse data by replaying bison's reductions over ry's syntax tree (`crates/interp/src/parse_data.rs`); testthat's `source_file` parses every test file this way. An item records only `reduced_by`, children are a `SmallVec` dropped in `reduce`, and one backwards pass derives each row's parent and the id handed down through invisible items. Ids are dense, so placing rows at their id (`row_of_id`) orders them without a sort. ## Stats distribution closures enter their routine directly

**Status:** built.

- **Recognition by shape, not hash.** `recognize_routine_closure` (`base_fast_paths.rs`) accepts a stats-namespace closure whose body is `.Call(C_<routine>, ...)` with formals in order or `1/<formal>` (the exponential family's `rate`), optionally inside `{}` or `if (missing(f)) <call> else ...`, which applies only while `f` is not supplied (t, chisq, beta and F with `ncp`). Defaults used must be constants, and the routine and arity must be a row of `distributions::DIRECT_ROUTINES`. Stats bindings are lazy-load promises, so recognition runs in `do_lazy_load_fetch`, and an image start re-recognizes forced closures (`register_routine_entries`). A user's own `dnorm` is never in the stats namespace. Not recognized: the gamma family (`rate`/`scale` check), `dsignrank` (`on.exit`), nbinom (`mu`).
- **Why.** Below length 10 the call, not the kernel, was the cost: about 0.9 µs per call through the closure frame, promises and `.Call` machinery.
- **Decline instead of signal.** The entry matches arguments itself (exact tags, then positions) and runs the kernel in `Conditions::Decline` mode: any warning (NaN produced, NAs produced, Rmath's own) or error, a non-numeric or ALTREP argument (coercion warns, ALTREP may run code), or a supplied `missing()` formal returns `None` and the closure runs, so conditions report GNU R's call. A draw first takes `random::checkpoint` (`.Random.seed` a plain integer binding equal to the live state, no user generator), and a declined draw calls `random::rollback`, so the R body redraws the same deviates.
- **Wrappers.** A promise of a variable bound to another unforced promise is read through, up to eight deep, when every promise settles without running R code; a self-referential chain (`function(n = n)`) declines so the R body reports GNU R's error. This holds for every native entry (`function(n) dnorm(n)` 799 to 435 ns per call).
- `Interp::native_entries` is a `Vec<(Sexp, Entry)>` sorted by address and binary-searched; `Entry::Routine` carries an inline `RoutinePlan` (at most six sources).
- **Measured** (ns per call inside a closure; before, after, GNU R): `dnorm(x)` 932, 462, 1044; `qnorm(0.3)` 889, 582, 914; `rnorm(1)` 1286, 677, 2820; `rpois(10, 3)` 1857, 963, 2271.
- **Evidence.** `stats__direct_routine_calls.R` (named and positional arguments, `sys.call()` in handlers, declined draws with NA parameters, masking, `1/rate` with integer and invalid rates, `ncp`, `.Random.seed` after every draw).

## Base `.Internal` wrappers inlined; string fast paths not kept

**Status:** built, except the rule that a replaced base binding always takes effect in compiled code, which "Compiled code binds GNU R's inlined base functions at compile time" supersedes.

- **Shape.** Tier 0 inlines the safe base internals (the first twenty of `INLINED_BASE_INTERNALS` in `crates/interp/src/bytecode.rs`, GNU R's `cmp.R` list) as `Op::Guard` plus `Op::Internal` when the head is base's closure by identity, its defaults are constants, and its body is exactly `.Internal(f(...))` over formals and literals. No wrapper closure runs, so `eval::call_inlined_internal` blames an error that names no call on the original call (`nchar(x, ...)` as in GNU R). The `Op::Guard` is the existing guarded-inline one, through the site's lookup-cache slot, so nothing new is cached. Gain: about 1.9k instructions per `match` or `identical` call (testthat_full -4.7%). The JIT treats `Op::Internal` as opaque, because `match` can run R code through `mtfrm`.
- **Past GNU R's list.** A census of base closures whose body is only `.Internal(f(...))` found the missed calls were mostly string builders in the string-heavy applications (report: 60k each of `paste`, `paste0`, `sprintf`) and frame readers in testthat. The `vector` family (which passes a literal mode), `paste`, `paste0`, `sprintf`, `startsWith`, `endsWith`, `make.unique`, `.row_names_info` and `isNamespace` are inlined too. A wrapper with `...` takes R's matching (exact tags, positions before `...`, rest into `...`); a tag partially matching a formal before `...`, or `...` at the call site, refuses the inline, and `sprintf` refuses tagged arguments because `Op::Internal` passes no tags; `list(...)` bodies get tags through base's `list`. Per call: `paste` 8.6k to 5.4k instructions, `sprintf` 10.4k to 5.0k, `character` 4.8k to 2.5k (report -28.5%, validation -8.4%).
- **Base namespace and the wrapper's call.** `Op::Internal` runs the internal in `base_namespace`, so `paste` dispatches `as.character` from there and a caller's local method is not found, as in GNU R. `call_inlined_internal` sets `assignment_call` to the original call, so a warning reports `sprintf(...)`, not the enclosing call.
- **Left out on purpose.** Frame readers (`parent.frame`, `sys.call`, `sys.function`, `sys.parent`, `sys.nframe`, `sys.frame`, `environment(NULL)`, `eval`, `new.env`, `get`, `get0`, `exists`) read the wrapper's own context and would need a per-internal frame offset; together they are about 1.1% of testthat_full at 1.5k instructions per call. `options(...)` passes tags. `lengths` and `as.vector` dispatch internally. `lockEnvironment` returns invisibly, which `Op::Internal` does not keep. `file.path` has a non-constant default.
- **Not kept: string compare, `nchar` and JIT string ops.** A pointer-compare `==` on `CHARSXP`s with equal encoding marks, a stored-length `nchar` and JIT `Str`/`StrVec` types cut a compare from about 2,400 instructions to 935 in tier 0 and 235 in the JIT, and `nchar` from 5,200 to 1,210 and 229, but no program moved (at most strings' 0.5%): a loop's string work is mostly the element read, already fast through the const `STRING` paths in `element_access.rs`. Revisit only when a profile shows string compares or `nchar` on top.
- **Evidence.** `calls__inlined_base_internals`, `calls__inlined_base_internals_c_api`.

## The serialize reader checks what a stream claims before it stores it

**Status:** built.

- **Why.** The heap takes an object's kind from the position that holds it, so a stream with another kind there left objects the collector misread, and the damage outlived the read. One stream corrupted a collection during a later read. Made-up lengths (gigabyte allocations), out-of-range reference indexes and deep nesting (stack overflow) were found by the libFuzzer target `interp_unserialize` in its first minutes.
- **Shape** (`crates/interp/src/serialize.rs`). The reader refuses a stream at the first claim it cannot back: a length must fit the rest of the input (`Reader::expect_elements`, for a read from memory), a reference must name a slot (`reference_slot`), nesting runs through `on_large_stack`, and an item read for a kind-implying position is checked (`Reader::character` for a symbol's name or string element, `environment`, `attributes` as `NULL` or a symbol-tagged pairlist ending in `NULL`, `tag` as `NULL` or a symbol because calls and argument lists are read by tag unchecked, `named_cells` for formals, `fill_frame` for bindings). Each check is a comparison per item, which a lazy-load fetch also pays. `named_symbol` guards symbol-name reads, because the unbound marker is a symbol without one.
- **Runtime state stays out.** A promise keeps only the two bits GNU R writes (ry's other bits name a live frame slot), a promise without a value needs an environment, and a `wrap_*` ALTREP must wrap a vector of its type, since the stream's attributes are set on the result and `NULL` or an environment is shared by the session. A byte-code reference slot is filled after its cell is read, unlike GNU R, so a cell cannot contain itself and every list a stream builds ends. A closure without an environment gets the base environment, as in GNU R.
- **Divergence.** A cell whose tag is not a symbol (only C code writes one) is refused here, where GNU R accepts it.
- **Evidence.** `crates/interp/tests/test_fuzz.rs` (`unserialize_refuses_an_object_of_the_wrong_kind` also reads every GNU R stream of libR's conformance cases under collection stress; `unserialize_keeps_a_stream_out_of_the_runtime_state`). `crates/rdb` and `crates/libr` have their own readers, which this does not cover.

## sprintf formats numbers with the native kernels

**Status:** built.

- `%f`, `%e`, `%g` and integer conversions write through `format.rs`'s `push_fixed`, `push_scientific` and `push_general`, so ry has one native number formatter. A scalar call costs about 2,180 instructions, 607 of them `mk_char`, where per-conversion `format!` cost about 4,340 and `sprintf` was 15.8% of the report workload. Formats parse once into a flat `SmallVec` of pieces; `n$` and `*` are `Amount::Argument` indexes, and the `%d` check on a double (whole and in range, or NA) runs once per argument.

## Hash tables for `unique()` and `match()` start at 512 KB and grow by extrapolation

**Status:** built.

- `PositionTable` (`crates/interp/src/sort.rs`) starts at two slots per element, capped at 65,536 slots (512 KB), so a long vector with few distinct values zeroes 512 KB once (presizing a million strings zeroed 16 MB). Starting small and always doubling was rejected: rehashing made `match()` on 5,000 distinct strings cost about 100 more instructions per element and slowed `merge()` by about 10% through `cbind()`'s `make.unique` check.
- A slot is 64 bits: the 1-based position below the hash's high 32 bits. A probe reads the stored key only when the hash bits agree, so a miss in a table larger than the cache costs one random read instead of one per occupied slot, and growing moves slots without rehashing keys.
- Past the cap the table grows to the distinct keys that the share of distinct keys so far predicts for the remaining lookups, at least twofold and at most eightfold per step. A vector of distinct values grows a few times instead of once per doubling; the eightfold cap exists because `anyDuplicated` often stops early, and without it `anyDuplicated` of 1e6 doubles zeroed a 16 MB table and ran at half GNU R's speed.
- Strings hash by interned object, which is exact only for ASCII (equal text in latin1 and UTF-8 is two objects), so `TableKey::exact` is checked per distinct key and miss, and the first inexact one goes to the general path.
- Duplicate flags are a bitset built a register word at a time; `anyDuplicated()` stops at the first word with a duplicate. `split()` counts per level, allocates each piece once and scatters typed slices through per-level cursors on the stack (1e6 doubles 121M to 69M instructions; `match()` of 1e6 strings 51M to 37M; the sales workload -20.8% warm). The table is a call local, so peak RSS does not rise.
- `gather_kind` keeps the filtered position walk: mask walks and branchless compaction cost more where the selection branch predicts well.
- **Pinned by** `subset__logical_index_gather`, `base__split_factor_kinds`, `base__unique_match_kinds` (NA keys, latin1 against UTF-8, `incomparables=`, `fromLast=`, unused levels, multi-word early stops).

## Positional builtin calls read their arguments from the registers

**Status:** built, except the values-plus-parallel-tags closure call shape.

- **Shape.** Whether a site is positional (every argument cell untagged, none empty, as many cells as registers) is a fact of the call expression, not of the builtin bound at run time, so the compiler writes `POSITIONAL_CALL_BUILTIN` into the opcode word, and `op_of` reports it as `CallBuiltin`, so the JIT, step table and images see no new opcode; the verifier accepts it only where `positional_call` holds. The handler writes up to eight `Arg`s into a stack array (`eval::with_positional_args`, shared with `jit::runtime::jit_call`), tries dispatch only for objects or S4 values (or matrix products, whose arity error dispatch raises), and calls `eval::call_builtin_positional`. The generic handler forwards positional words, because the optimizing tier routes every `CallBuiltin` to it.
- **Why compile time, not run-time quickening.** The image's code is mapped privately, so writing quickened opcodes at run time copies each touched page into anonymous memory in every process (+130 to +230 kB RssAnon on the benchmark workloads). Compile time writes no code page and costs nothing per call, which a side array of quickened state would not; a rule that needs the bound builtin would have to quicken at image build. Warm instructions fell 1.25% on testthat_full and 5.2% on bond_book_full.
- `heap::activity::HOOKS` holds the activity-summary and profile-tick bits, so the common call tests one byte instead of separate flags.
- **GC liveness.** The stack array copies registers that stay rooted and unchanged until the result is written, so it needs no root set.
- **Planned.** Builtins and closures agree on positional values plus parallel tags as the call-boundary shape; the closure protocol adopts it first. Pinned by `builtins__positional_and_tagged_calls`.

## A warning reaches `suppressWarnings` and `tryCatch` without running R

**Status:** built.

- **Why.** The R route (`.signalSimpleWarning`, `withRestarts`, three restart frames, the condition object, `inherits`, `tryInvokeRestart`) cost about 72,000 instructions per muffled warning, about 12% of a workload calling `suppressWarnings(as.integer(x))` over 14,000 strings; the fast path saves about 68,600.
- **Muffled.** `muffled_by_suppress_warnings` reads the topmost handler for `simpleWarning`, `warning` or `condition`, and the warning returns at once when it is a calling handler with formals `w` and body exactly `if (inherits(w, classes)) tryInvokeRestart("muffleWarning")`, whose environment is a frame directly inside the base namespace binding none of `if`, `inherits`, `tryInvokeRestart`, and whose `classes` names one of the three classes. Those conditions make it behave exactly as the stock handler whoever built it; one in the global environment or a frame that rebinds `inherits` takes the R route. Identity with the literal in `base::suppressWarnings` does not work: the image does not keep a body and its compiled code as one object.
- **Why unobservable.** The handler's only effect is the unwind, and the muffled path runs no handler that could see frames or the condition. A `classes` promise is read without forcing only when its code is a string literal; otherwise (`classes = f()`) the R route forces it once, as in GNU R. Lower handlers never see the warning in either route, `last.warning` is untouched, and `options(warn = 2)` converts only at top level. Follows `RY_FAST_PATHS`.
- **Exiting handlers.** For a topmost `tryCatch(warning =)` or `condition =`, `warning_call` builds `simpleWarning` natively and jumps, because the handler runs after the unwind anyway. With no handler the default runs natively unless `warn = 2`, whose converted error's handlers see R frames. Other calling handlers take the R route. The `withCallingHandlers` setup on every `suppressWarnings` call remains and is the larger share of its cost.
- **Limit.** A rebound `base::inherits`, `base::tryInvokeRestart` or `base::simpleWarning` is not detected; the R route would call the rebound function.
- Pinned by `conditions__suppress_warnings_muffle.R` and `conditions__warning_signal_routes.R`.

## `%%` and `%/%` on doubles port GNU R's kernels, with a 64-bit path for whole numbers

**Status:** built.

- Both kernels (`real_modulo`, `real_integer_divide` in `crates/interp/src/arith.rs`) port GNU R as it runs with an x87 `long double`. **Status:** built.

## The radix string order ranks bytes with integer keys, and plain POSIX patterns capture on the automata

## Strings collate with ICU4X's CLDR collator, as GNU R's ICU does

**Status:** built.

- **Before.** `sort.rs` approximated a UTF-8 locale's order with hand-made primary weights (`ASCII_PRIMARY_WEIGHTS`, `base_letter` and a few non-ASCII ranges) and `capabilities("ICU")` was `FALSE`. It got ß, ignorables (U+FEFF, U+00AD, ASCII controls), most scripts and canonical equivalence wrong, and `icuSetCollate` was a stub.
- **Shape.** `refresh_collation` follows GNU R's `Scollate` and `resetICUcollator` and builds one `icu_collator` 2.x collator (compiled data) per locale change: `LC_ALL`/`LC_COLLATE` equal to `C`, or a C locale, gives code-point order (or `strcoll`); anything else maps the POSIX name to a BCP 47 tag (`@collation=` to `-u-co-`) and falls back to root when the tag has no data. `R_ICU_LOCALE` overrides the name. An invalid UTF-8 byte compares as U+FFFD, as in GNU R.
- **ASCII fast path.** Printable ASCII under root or an untailored language (en, de, fr, it, nl, pt) compares by a 95-entry rank table, then the first case difference; controls take the collator because ICU ignores them. A unit test checks the table against ICU4X, and 24,500 random strings gave GNU R's `order` and `rank`.
- **Sort keys.** A sort or rank builds one byte key per distinct string (`CollationKeys`): the rank-table key for all-printable-ASCII input, otherwise ICU4X's sort key (`icu_collator` 2.4 or later), whose byte order is the collator's and which holds no zero byte. `byte_ranks` then ranks the keys with an MSD radix sort, so no pair is collated. Comparing pairs cost about 143 ns each in ICU4X, which scans both strings for invalid-byte stand-ins on every call.
- **Ties.** Strings the collator calls equal tie: `order` keeps input order and `rank` averages, and `sort` reorders tied runs with GNU R's Shell sort (`ssort2`'s gaps), so its placement of ties matches.
- **`icuSetCollate`** applies `case_first`, `alternate_handling`, `case_level` and `strength` (GNU R spells the strength values with a trailing space, so `"primary"` is ignored there too), accepts `hiragana_quaternary` and `normalization` as no-ops, and reports `french_collation`, which ICU4X lacks.
- **Gaps.** ICU4X always normalizes, and GNU R's ICU runs with normalization off, so a string with combining marks out of canonical order can order differently. ICU4X carries CLDR 47 and GNU R 4.6.2's ICU 74 carries CLDR 44.
- **Measured** (5 sorts, release, seconds; ry, GNU R): `sprintf("key%07d", sample(2e5))` 0.34, 4.27; a 2e5 mixed-case ASCII vector 0.26, 3.11, and `order` of it 0.32, 3.98. ## Base and stats kernels: exact shortcuts, GNU R's quirks kept, and one prepared state per call

**Status:** built.

Each kernel below matched or trailed GNU R in the builtins sweep (`tools/bench/builtins`) and keeps GNU R's result bit for bit.

- **`strtod` scales short decimals exactly.** A hardware division gives the double when its exact remainder (Dekker's product) shows it is not near a rounding tie; otherwise integer arithmetic rounds once to 64 bits and then to double, as the long-double reader does. A fuzz test checks both paths against `LongDouble`.
- **`floor`, `ceiling` and `trunc` round whole vectors with `roundpd`** (`numeric::vector_math::round_all`), compiled for AVX or SSE4.1 and chosen at run time, because glibc's own `floor` is an ifunc that uses SSE4.1's `roundsd` one element at a time. Without SSE4.1 the loop rounds with the 2^52 trick on SSE2 lanes. An NA or NaN input comes back with its own bits, as GNU R's `math1` keeps them.
- **`cospi`, `sinpi` and `tanpi` reduce with `x - p * trunc(x / p)`** (`arith::periodic_remainder`) for a power-of-two period, which is exact and equals `fmod` without its bit-by-bit loop.
- **`.bincode`** is one loop per side of the interval (`bin_codes::<LEFT>`): with up to 64 breaks it counts the breaks below each point, a branch-free sum the compiler vectorizes, and beyond that it runs a fixed-length binary search whose steps add a comparison times the half width. Breaks holding NaN keep GNU R's bisection, whose answer on them is not a partition point. The errors keep GNU R's order.
- **Grouping comes from the radix sort's tie runs.** `radixsort(retgrp = TRUE)` reports the last key's runs as well, so the group ends need no second pass over the keys. With `sortstr = FALSE`, GNU R numbers strings by first appearance within each run of rows tied on the earlier keys, and reverses a run whose strings are strictly in descending byte order; ry ports both. Under `na.last = NA`, a run that holds an NA is never reversed, and the first key of such strings drops no NA unless every entry is NA, when it drops every row; a later key drops its NA rows like any other (GNU R's `csorted`).
- **`duplicated` and `anyDuplicated` of a non-decreasing double vector compare neighbours** without a hash table. A NaN fails every comparison, so such a vector holds none, and the test fails at the first descent of unsorted input.
- **`runmed` slides one sorted window** of order-preserving integer keys, finding the outgoing and incoming values by binary search. The NA stand-ins follow `Srunmed`: the stand-in is its `BIG_dbl`, and only a missing row whose median is a stand-in gets its NA or NaN back.
- **Kendall's covariance counts sign products as integers.** Each is -1, 0 or 1, so the long-double sum over ordered pairs is an exact integer: ry counts unordered pairs once and doubles.
- **`model.matrix`** resolves each term's parts, allocates the matrix once and writes each column in place. Automatic row names are `as.character(seq_len(n))` deferred, as in GNU R.
- **`approx`, `spline` and `splinefun` look points up in a knot grid** (`KnotGrid`, `crates/stats/src/routines.rs`): equal buckets over the knots, sized by the points that fall inside, each holding the last knot not above its left edge. A lookup reads one bucket and walks at most eight knots, then falls back to bisection. On sorted knots without NaN, bisection's answer is the partition point the walk also finds, so the two agree exactly.
- **`smooth.spline` prepares each point's cubic B-spline state once** (`CubicPoint`, `crates/stats/src/spline.rs`): the knot interval and de Boor's differences are shared by every criterion evaluation in the search for the smoothing parameter, and the basis values come from `bsplvd` once per fit.
- **`rhyper` prepares its sampler once per call** (`Hypergeometric`), holding the setup GNU R keeps in static variables between calls with the same parameters, and draws the same uniforms in the same order. A single `rpois` draw from a mean of at least 10, as `rgeom` makes per element, builds only the normal method's constants, not a sampler with the inversion table.
- **Long batches read the twister ahead** (`random::Lookahead`). Drawing one deviate at a time is a serial chain (twister word, inversion, `qnorm`, then a branch on the value that mispredicts), so a sampler waits on latency, not on instructions: `rpois` with mean 500 took 66 ns per draw against GNU R's 47 with similar instruction counts. A batch of at least 64 draws with scalar parameters tempers the block 64 words at a time and computes the inversion normal at every position of a chunk with `qnorm_standard_fill`; a normal that straddles the block end takes the scalar path. A block is generated only when a draw needs it, and the cursor is stored as the twister's position, so the stream and `.Random.seed` are GNU R's, also after a batch that draws nothing. Recycled parameters skip the lookahead, because their normals are sparse and one at every position costs more than it saves; `rnorm` and `runif` have vectorized fills of their own.
- **`rsignrank` sums whole ranks in a `u64` over a filled chunk of uniforms**, testing `u + 0.5 >= 1` for `floor(u + 0.5)`; `rwilcox` keeps its pool of ranks across draws (`Wilcoxon`).
- **`forceint` adds and removes 2^52** instead of calling `round_ties_even`, which is a libm `rint` call on baseline x86-64; the two agree bit for bit on 10^8 sampled doubles.
- **Not explained: `rpois` with a vector mean** (about 0.85 times GNU R's speed) and `rgeom` (about 0.9 times at 10^6 draws). Cachegrind's branch simulator counts five times GNU R's mispredicts in the scalar `qnorm` on the same inputs, which no branch in its code accounts for; both stay in `slower.txt`.
- **Oracle cases:** `coerce__string_to_number_last_bits`, `kernels__pi_trigonometry_periods`, `kernels__bincode_breaks`, `kernels__sorted_duplicates`, `kernels__interpolation_grid`, `stats__smooth_spline_prepared_points`, `random__hypergeometric_and_poisson_streams`, `random__lookahead_streams`.
