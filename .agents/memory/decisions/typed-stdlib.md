# Decisions: Typed ry and the standard library

Typed ry's values, records, tuples and tags, and `std`.

## Beta semantics: Signature matching is name-aware

**Status:** built.

An R call site matches arguments by name, so matching an annotation against a definition by flat position routes a value to a wrongly typed formal and accepts code that crashes at run time. Contract and implementation match by name where names exist.

## Records, tuples and tags are ry values, not R lists

**Status:** built, except the lowercase `record{...}` and `tuple{...}` spellings, which "The DataFrame API is Polars', and ry's own types are UpperCamelCase" supersedes.

- **Shape.** One heap object kind of ry's own (a type code GNU R leaves unused) holding a 32-bit interned layout id and eight-byte slots. The layout is keyed on the tag (an interned small integer) and the canonically sorted field names only; which slots hold raw scalars is a per-object mask, so same-typed values share a layout id. Values are immutable with value semantics. Plain R is untouched, because every new form is a syntax error in R. Draft: `docs/src/content/docs/development/design/records-and-tags.md`.
- **Why not R lists.** A plain or classed list would make R's list semantics (attributes, partial `$` matching, `c()` coercion, `names<-`) the semantics of ry's types and give the JIT no fixed layout.
- **Types.** Tags are structural; a tag union is an ordinary union, `..` makes it open, and there are no row variables, which keeps the checker Hindley-Milner.
- **R boundary is explicit.** `as.list()` converts out, `as.record()`/`as.tuple()`/`as.tag()` in. Implicit classes `ry_record`, `ry_tuple`, `ry_tag` serve `class`, `inherits` and S3 dispatch. Printing, `identical`, `all.equal`, field access, type predicates and builtins that only store a value accept native values; every other builtin raises one error naming the conversion. C sees an opaque object (`TYPEOF` 27): list element moves work and every other accessor raises the same error, because a deep scan at `.Call` would cost time proportional to the data. `serialize` refuses them.
- **The refusal is a builtin flag, not a scan.** `BuiltinDef::accepts_native` is set from `syntax::native_values::ACCEPTS_NATIVE`, and `install_all` asserts every listed name exists, so a renamed builtin cannot silently drop off. Only top-level arguments are tested. The checker reads the same list (it lives in `syntax` because `semantics` and `interp` both depend on it) and reports a native value passed to an unlisted R function as `type-mismatch`, only when every member of the argument's type is the same native kind and never for a project-defined or shadowed function.
- **Raw slots under NaN prefixes.** A raw integer or logical sits under its own quiet-NaN prefix, so a one-bit mask suffices and a slot read needs no layout lookup. The slot count lives in header padding, so the collector never reads the layout table.
- **Compiled sites.** `x$name` compiles to `bytecode::Op::Field` with a per-site `[layout id, slot]` cache (`records::cached_field`, `records::NO_LAYOUT` until seen); any other object takes `$`'s own path. The JIT turns a filled cache into `Intrinsic::Field` (guard kind, no object flag, layout id; load unboxed when the mask bit and NaN-box prefix match feedback). `$` had to join `base_primitive`'s list, or every site compiled as a general call. `x[[k]]` with constant `k` is `Op::Item` with the same cache (`records::cached_item`); a list or vector subject falls through to `[[`'s path. Constructor calls with distinct names intern their layout at compile time (`Op::Construct`, an opaque pure step to the JIT), and a payload-free tag is one shared constant. A guard-free `match` compiles to `MatchShape`, `MatchTag`, `MatchLiteral` and `Slot` tests, binding only after the whole pattern matched, as the special does, and ends in `MatchFail` with the special's error; a `match` with a guard stays with the special. The JIT branches on kind, layout and tag natively.
- **Measured** (profiling build, 5,000,000 iterations): `s <- s + p$x * p$y + p$z` 0.074 s on a record against 1.83 s on a list; `t[[2L]]` 0.026 s against list `l[[2L]]` 0.83 s. 2,000,000 three-arm tag `match`es 0.57 s against `switch` on a list's `$kind` 1.10 s; 2,000,000 `:Ok(i)` constructions 0.13-0.23 s against `list(kind =, v =)` 0.35 s.
- **`$<-` on a record keeps its type**: writing a field checks the value, and writing a missing field is an error, because the runtime layout is fixed by the field names.
- **Pattern encoding reuses the value constructors** (`.ry_tag`, `.ry_tuple`, `.ry_record`), so a quoted pattern deparses like a quoted value; `_`/`..` stay bare symbols.

## Inline annotations at run time

**Status:** built, except GNU R through `ry run` and `ry repl`, which "ry run and ry R: the command chooses the runtime" supersedes.

ry's runtime checks a function's inline parameter and return types at its boundary and erases binding annotations. The contract is the typing reference, "Annotations at run time".

- **Why check.** The checker trusts an annotation at every call site in other files, so an unchecked wrong annotation can stay false forever; a boundary check turns it into an error at the call that broke it. It also gives the JIT a guarantee inside the body: after entry a `double` parameter is known to be stored as logical, integer or double, so a guard on it is redundant.
- **Parameters are checked when forced**, because checking on entry would force every annotated argument and change R semantics (laziness, `missing()`, `substitute()`). The promise carries `gp::CHECKED_PROMISE` and `force_promise` checks before storing: a failed check leaves the promise unforced and still checked, so caught errors cannot expose an unchecked value. A promise forwarded through `...`, or a variable passed to an effect-free closure (the caller's own promise, `eval::eager_args_into`), is pending in several typed frames, and forcing it checks every one, outermost first as R would force them; the bit clears only once no frame holds it. A check that may convert (`I64`, or `NA` to `character`) of a shared promise (a reference count above one; a promise made for the call is held by its binding alone) binds a new promise wrapping the caller's (`annotations::check_argument`), as GNU R binds one per call, and `missing()` and empty subscripts walk such chains (`eval::root_promise`, GNU R's `findRootPromise`), so the conversion never reaches the caller's variable or an outer frame's check of the same promise (scenario `typed-argument-conversion-stays-local`). An already computed value is checked on entry, and a converted forced promise is rebound, never written in place.
- **Storage masks.** A check is one bit test of the `SEXPTYPE` against a `u32` mask (`crates/interp/src/annotations.rs`). Each mask is at least as loose as the static type (vector shape ignored, numeric promotion admitted, alias, class, type variable, `Any` or frame unchecked), so a value the checker accepts never fails at run time. Element types and attributes would need a walk, too costly per call.
- **Where the signature lives.** Lowering a `function` registers masks keyed by the formals pairlist (or the body, without parameters), which closures share by pointer, so `environment<-` copies keep checks and `formals()`, `body()`, `deparse()` see no change. A closure matches only when its body is the definition's body object, because `rlang::new_function(formals(f), body)` would otherwise inherit `f`'s checks. The key carries `gp::TYPED_DEFINITION`, so an untyped call pays one header bit test. Entries are weak references whose key identity guards against address reuse; dead entries are swept when the map doubles. A parameterless function whose body is a constant or symbol has no unique key and is not checked.
- **Bindings are not checked**: `x: T <- v` would need a check per assignment and a reassignment policy, and the checker already reports a wrong value statically. For `amounts: double[] <- frame$col` on a frame without `col`, strict mode reports that value as undetermined (`StrictOriginKind::UncheckedAnnotation`), which names the hole before the code runs, so the decision stands.
- **The JIT** may skip a check at a call site whose argument types the checker proved, because the mask test is pure and its failure path is an ordinary R error. The pending-check stack (`annotations::State::pending`, popped by frame depth) is the only state a compiled frame honors.
- **Opt-out.** `[check] inline-annotations = false` erases annotations and registers no checks (`RuntimeFlags::annotation_checks`), so the setting means the same in analysis and at run time. `ry run`/`ry repl` preflight the code as a one-file project (`crates/ry/src/preflight.rs`): they print `inline-annotation` and `annotation-mismatch` warnings and refuse in strict mode; other findings stay `ry check`'s, and a script with no inline annotation and no strict mode skips analysis.
- **The console sees whole commands.** The filter holds an unfinished command and releases it whole; "unfinished" is `syntax::input_is_unfinished` (every syntax error marked `incomplete` by the parser, which a range check cannot know because an error at a trailing newline is reported on the last code character). Otherwise strict mode could refuse the last line of a definition R had partly read.
- **The console preflight checks each command against the session's interface** (`semantics::session`). Each accepted command is its own `SourceFile` with `command: Some(index)`; a singleton salsa input log (`ConsoleSession`, grown by `commit`, shrunk from the end by `truncate`) records what each command binds, declares and defines, its `# typing:` directive and whether it used ry syntax. Lookups for earlier commands fall back to the log, untracked on purpose: they read only smaller indices, and the log changes only past the reader or by dropping later commands. Re-analysing one growing session file was O(n²) per paste (1,000 typed lines took 3.6 s); per-command files make a 5,000-line typed paste take 1.4 s, linear. Findings name the command they are in, with lines counted from its start.
- **Function bodies see the latest binder**, as R's global environment does, through a `SessionBinder` input per name created on first such read. `commit` returns earlier commands that read the name, transitively through function bodies (a caller's type follows its callee's); strict mode rechecks those that passed when they joined, a strict error refuses the new command, and `truncate` undoes the commit. Tracking immediate reads too would make each rebinding invalidate a chain and bring the quadratic cost back. Command files are not in `ProjectFiles`, because a fold over them costs O(session) per command.
- **Rollback.** An error never cuts a paste short (R gets one line per chunk), so only Ctrl-C drops input. The console counts the dropped lines in `pending` and calls `InputFilter::discard`; `ConsoleFilter` maps dropped lines back to the command's bytes (identity for ry's runtime; `syntax::erased_lines_end` for GNU R's erased program), and `Preflight::retract` replaces the last command with the prefix that ran, unchecked. A `# typing:` directive governs only later commands.

## Ry's standard library (`List`, `Str`, `Num`, `Result`, `Dict`, `Set`)

**Status:** built, except the `ry` namespace as the library's home at session startup, which "The standard library is the `std` namespace, with an optional prelude" supersedes.

- **Names.** Plain qualified names such as `List.map` are ordinary R symbols with a dot. There is no static dispatch, so a call is a symbol lookup and the checker reads one stub per name. User code shadows a library name like any R binding, and `test_standard_library.rs` asserts no shipped package's `.exports` holds a library name, so plain R cannot change meaning. Module names are Roc's; a Roc name that means something else in R is renamed (`Result.try` is `Result.and_then`).
- **One source of truth per side.** Types live in `types/std.Rtypes`; runtime functions in `crates/interp/src/standard_library.rs`, registered with `BuiltinDef::accepting_native`. A test asserts the name sets are equal and every declared parameter name is accepted at run time.
- **`Dict` and `Set` are native kinds** (`Fields::Dict`, `Fields::Set` in `crates/heap/src/records.rs`) with value semantics, insertion order and an open-addressing index, because a named list matches partially and allows duplicates and an environment has reference semantics. `identical()` ignores order, as Roc's equality does.
- **Errors are tags, not conditions.** A fallible function returns `:Ok(x) | :Err(:Tag)`; a wrong argument type raises an R error naming the parameter, so misuse is loud and a domain failure is a value.
- **Analysis cost.** The checker, hover, completion and goto-definition read the stub file like any other, so incremental analysis gains nothing new to invalidate.
- **Docs.** Contract `reference/standard-library.mdx`; open questions `development/design/standard-library.md`.

## Standard library updates reuse a uniquely held value

**Status:** built.

- **Shape.** Perceus-style reuse, as in Roc and Koka. `eval::rebind_call` recognizes `x <- f(x, ...)` for a builtin flagged `reusing_first_argument` and passes the first argument as `Call::reusable` when the frame binding holds its only reference and no other argument is the same value; `standard_library::owned` also accepts a refcount-zero temporary. Dicts and sets are counted records with resizable key and value vectors that double when full, and `build_index` takes spare room so `reserve` can presize the index. Without this a loop growing a collection is quadratic: 40,000 `Dict.insert`s took 17.4 s, and take 0.04 s with reuse.
- **Why not a special form or last-use analysis.** A special form would make every library update syntax, and last-use analysis needs the compiler; the reference count is exact at the call boundary for AST frames. It is not exact for a frame a compiled closure owns, because bytecode registers hold uncounted references; see "In-place updates through nested targets".
- Value semantics are unchanged: any second holder copies. Remaining copies (a parameter's first update, `state$seen <- Dict.insert(state$seen, ...)`) are in `backlog.md`.

## Standard library breadth against Roc's builtins

**Status:** built, except the skipped wrapping arithmetic and the R-sized limits and conversions (`Num.max_integer`, `Num.to_integer_checked`), which "Typed ry has its own numbers, `Bool`, `Str` and `List`" supersedes.

- Each module was compared with Roc's builtins (pre-`Try` API) and everything typed, `NA`-free and reporting failure as a tag was taken; the list and renames are in `development/design/standard-library.md`.
- **Skipped:** `Box`, `Encode`, `Decode`, `Hash`, `Inspect` and the `Eq` implementations (they serve Roc's layout or abilities; `Bool.is_eq` compares by `identical()`); effectful `!` variants (R tracks no effects; `List.for_each` covers them); `Str` capacity functions (R strings are immutable and interned); Roc's `nan_f64` (nothing takes or returns `NaN` on purpose).
- **Capacity functions are taken** (`Dict.capacity`, `release_excess_capacity`, `with_capacity`), because the heap never shrinks a resizable vector, so room after `reserve` stays until the value dies. An empty collection has no key vector until its first key fixes the key type, so its index carries the requested room (`standard_library::empty_room`) and the first insert allocates with it; `Dict.with_capacity`, `Set.with_capacity` and `Dict.reserve` on an empty dictionary all work this way.
- **`NaN` is never a result.** An unchecked function that would produce `NaN` or overflow (`Num.sin(Inf)`, `Num.pow(-1, 0.5)`) raises an R error naming the `_checked` variant, which returns `:Err(:Undefined)`. Unchecked operations are kept so a step can be passed by name (`List.walk(xs, 0, Num.add)`). `Num.is_nan` is the one function that accepts `NaN`.
- **`Bool` is taken** so boolean steps can be passed by name. `Bool.true`, `Num.pi` and the other constants are values in `standard_library::CONSTANTS`; under GNU R, `crates/ry/src/load.rs` binds each non-function `std.Rtypes` declaration as an active binding that stops with the "only ry's runtime" error.
- **UTF-16 and UTF-32** follow Roc's newer `Str` builtins (`:BadUtf16`, `:BadUtf32`); NUL is bad because an R string cannot hold it.
- **Hover docs** come from `#'` lines above a declaration in a `.Rtypes` file (`StubLibrary::documentation`); a later source's first declaration of a name replaces or clears them, like the type.

## The standard library runs only on ry's runtime

**Status:** built, except the check-time diagnostic for library calls in a project that targets GNU R.

- A pure-R build for GNU R was declined: many functions return result tags and `Dict`/`Set` values GNU R cannot represent, and a partial `Str`/`Num` build would split the library into two dialects.
- Instead, a diagnostic should flag library calls once a project can declare that it targets GNU R (`backlog.md`).

## Nominal and structural types cover both product and sum types

**Status:** built.

- **Shape.** Every record, tuple or tag union is structural (`alias` only names it), and `type Name = ...` (or `#: @type`) wraps it in a nominal type: one mechanism gives the 2x2 grid. Contract: the reference section "Nominal records, tuples and tags".
- **Construction.** `@Name(...)` is the only constructor and its parentheses are the value's own (`@Point(x = 1, y = 2)`, one-field `@UserId(id = 1L,)`). `@Point((x = 1, y = 2))` also works, because the inner parentheses are only R grouping, but the docs never write it. A bare value of the right shape is refused, keeping construction in one checked place like Roc's opaque `@Name`. `Point(x = 1)` was rejected because it collides with R calls.
- **Projection.** Exhaustiveness, pattern checks, field writes, `$` completion and the native-to-R check project the nominal value to its representation through the visible type definitions (`exhaustiveness::structural`, `Checker::structural`, `ide::representation`), so the definition is the single source of truth for the shape. Binding patterns keep the nominal type. Exhaustiveness splits on constructors only while a row has a constructor head, which lets a recursive `type Tree<T>` terminate.
- **No new stored state.** The projection reads per-name definitions each item already depends on, so incremental analysis is unchanged. The user guide teaches the grid in `guide.mdx`.
- **Tests:** the `nominal_grid` typing group, `crates/ide/tests/ide/records-and-tags.R.test`, `crates/interp/tests/test_records.rs`.

## An Array is a flagged R vector, written `[...]`

**Status:** built, except the type name `Array<T>` and its R item types, which "Typed ry has its own numbers, `Bool`, `Str` and `List`" supersedes.

- **Shape.** `[a, b, c]` is a strict vector: one exact item type, no `NA`, no attributes, no recycling, no implicit conversion. `c()` cannot be that type, because R coerces its result (`c(1, "a")` is character), recycles and lets it hold `NA`. Contract: `reference/type-system.mdx`.
- **Runtime representation.** An ordinary R vector carrying `flag_bits::ARRAY` (`crates/heap/src/object.rs`): atomic storage for scalar items, a VECSXP for ry-value items. A separate object type was rejected because every C API accessor, `sum()` and the JIT already read unboxed storage, so converting to R is dropping the flag. Setting any attribute clears the flag, keeping "no attributes" true without checks at every attribute write. `values::duplicate` and `shallow_duplicate` drop the flag on the copy (nested Arrays keep theirs), because a copier is about to write and may write an `NA`; only `arrays::writable` re-flags a copy after checking the write.
- **One place enforces the rules**: `crates/interp/src/arrays.rs` (operators via `strict` wrappers in `arith.rs`). Bytecode fast paths and the JIT's type guard refuse a flagged operand, so they can never skip a check; a dedicated Array feedback kind is backlog work.
- **R code keeps working on Arrays.** Reads follow R's positions wherever R gives no `NA`; anything producing `NA` is an error. A replacement or operand that is not an item of the item type yields the plain R vector R would build (`arrays::check_operands`), because base functions such as `ifelse()` assign into an argument and `str()` computes `ob - signif(ob, digits)` on a plain vector. Typed code cannot reach that path because the checker rejects the value, and the rules the checker cannot see (bounds, no recycling) are runtime errors, so a typed Array never holds a plain vector.
- **`List` results** are Arrays only when the collection argument (`list`, `first`, `lists`) is one, never because an item argument is. A callback's result type is bound by the `item` constraint in `types/std.Rtypes`, so the checker rejects mapping to a non-item.
- **The flag is the single source of truth for strictness.** An Array passes to R code, but an R vector needs `as.Array()`; a DataFrame stores an Array column as its plain vector. Tests: `crates/semantics/tests/typing/arrays.R.test`, `crates/interp/tests/test_arrays.rs` (including a generated round trip), Array seeds in both fuzzers.

## Array storage stays row-major; record Arrays go columnar only with JIT field fusion

**Status:** built.

- **Scalar Arrays already have the data-oriented layout**: one contiguous NA-free buffer.
- **An Array of records stays a list of record objects**, one 48-byte object per item whose length-one numbers are unboxed into slots. A columnar shape would save per-item headers and collector work, but every `xs[[i]]` would allocate a record to hand out and `.Call` code reading `VECTOR_ELT` would need a materialized copy. It pays only once the JIT fuses `xs[[i]]$field` into a column load, and DataFrame already serves columnar records.
- **Trigger to revisit.** When the JIT compiles `xs[[i]]$field` on Arrays, measure a million-item record Array row-major against columnar (`backlog.md`, "Columnar record Arrays") and switch only if it pays.

## In-place updates through nested targets

**Status:** built.

- **Nested targets.** `rebind` accepts a target that is a chain of `$` or `[[` with a constant name, string or number (`same_expression`), so `state$seen <- Dict.insert(state$seen, k, v)` updates in place. `solely_held` requires one reference at each plain list on the chain, and no other argument may be the value or a list on the chain, because argument values are not counted (`holds_on_chain`).
- **Bytecode.** `CallRebinding` carries the target so compiled code takes the same path. It is appended last because `OPS` is indexed by discriminant. The JIT treats it as a generic call and inlines it only when the target's slot type is plain.
- **Register rule.** Registers hold uncounted references, so an update from outside the body (`eval.parent()`, a forced promise) could change a value a register is about to use: `r <- list(x, h())` with `h` running `eval.parent(quote(x[[1]] <- 99))` gave `r[[1]][[1]] == 99`. `gp::COMPILED_FRAME` marks an environment while a compiled body runs on it, and `reuse_permitted(env, value)` allows an update when the flag is clear, when the innermost frame is that environment's own compiled closure (whose updates the compiler orders with `may_modify_in_place`), or when no live register holds the value. A stale register only costs a copy. This applies to `complex_assign` too, so it fixes plain R as well.
- **Record fields.** `r <- (..r, field = f(r$field, ...))` lowers to `.ry_update(r, ...)`, which `rebind_update` evaluates with `r$field` as a nested target. That needs records to count holders: interpreter-made plain records are counted (`records::allocate`, `set_record_slot`), tuples and tags stay saturated. Fields after the updating one must be constants, because their code could otherwise see the field half-updated. A record still solely held afterwards takes the new values into its slots; otherwise the update builds a new record (`records::with_slots`). In a slot frame the compiler leaves such an update to `CallRebinding` (`eval::updates_own_field`), and the call makes the frame's environment. 2e6 updates of `List.append(r$values, x)` inside a function take about 0.7 s.
- **Moving a value into a helper's parameter** is built with escape checks and an undo journal; see "Moving a collection into a helper's parameter".
- **Collection storage stays as it is**: a dictionary or set is already struct-of-arrays in the collector's heap, which a `SEXP`-holding value must be. Hashing and probing were at most about 15% of a call; the rest was call overhead, which "Library leaves resolve at compile time" removes.
- Value semantics are pinned in `crates/frames/tests/test_standard_library.rs`, including the cases that broke an earlier move attempt; nested accumulator loops are linear.

## Library leaves resolve at compile time

**Status:** built.

- **Tier 0.** The bytecode compiler resolves a qualified library name (`library_function` in `bytecode.rs`) to its builtin when it is native-accepting and every argument is positional with no `...`, emitting a guard on the symbol's binding and a direct `CallBuiltin`. A failed guard (someone rebound `Dict.len`) falls back to the general call.
- **Leaves.** `standard_library::is_leaf` names functions that never call back into R: every `Result`, `List`, `Dict`, `Set` function without a callback that does not update its first argument in place, and every `Num`, `Bool`, `Str` function except the `Str` walks. The JIT treats a leaf as `Effect::PureUnlessObserved`: it flushes nothing unless an argument's object or ALTREP flag is set, because reading an ALTREP vector runs its class's methods, which a package may write in R. In-place updates are excluded because compiled code may hold the argument in an uncounted register. `leaves_are_the_functions_without_callbacks` derives the rule from the stub signatures.
- **Intrinsics.** `Dict.len`, `Set.len`, their `is_empty`, `contains` and `Dict.get` call small runtime helpers (`jit_collection_count`, `jit_collection_position`, `jit_dict_get`) that take the key unboxed; anything unhandled (wrong type, `NA`, mismatched key kind, an index-less one-entry collection) hands the instruction to tier 0, which raises the same error. `Dict.get` still allocates its `:Ok(value)` record; `:Err(:KeyNotFound)` is one shared value (`standard_library::Tags`).
- **Hash.** `key_hash` applies MurmurHash3's 64-bit finalizer after FxHash, because FxHash's low bits are constant for whole-number doubles and the index picks slots by low bits, so integer-valued keys clustered. The index is not serialized, so the hash can change freely.
- **Measured** (`ry run`, profiling build, 1,000,000 calls on a 1,000-entry dictionary, us per call, general call against compiled leaf): `Dict.len` 0.271 to 0.009, `Dict.get` 0.450 to 0.053, `Dict.contains` 0.320 to 0.018, a missing key 0.800 to 0.025, so library calls in loops cost about what `length()` does. Errors are pinned in `test_standard_library.rs`, including compiled-loop error cases.

## Library traversals compile to loops

**Status:** built.

- **Interpreter.** `standard_library::Callback` checks a closure callback once per library call: with no `...` and exactly the arguments the library passes, items bind positionally (`bind_arguments`, `run_closure`), skipping argument matching; any other callback goes through `eval::apply`. The frame's call still quotes the values, `(f)(5)`, as `eval::apply` does; a call naming the formals, like GNU R's `FUN(X[[i]], ...)`, would be wrong, because `sys.call()`/`match.call()` users evaluate it in the caller's frame, where formal names find the caller's variables.
- **JIT.** `call_builtin` turns the looping library functions into `Action::Traverse` when the callback inlines (a closure literal, a function constant, or a name whose lookup finds a closure now). The element type is the join of the callback's own read feedback (or a declared scalar annotation), and the body lowers through `lower_expression`, so it must be scalar arithmetic, comparisons and intrinsics. A general callback call costs about 5,000 instructions per element under callgrind, against about 1,000 for the body `a + x`.
- **One loop, described by a struct.** `analysis::Traversal` is a fold (`Walk { until }`, `Map`, `Filter`, `Any`, `All`, `CountIf`, `Find { index }`), a source (`List`, `Dict`, `Set`) and flags (`backwards`, `indexed`, `from`); `Traversal::of` decodes every looped name, so a new variant is a combination, not a code path. A `Dict` or `Set` gets its keys and values from `jit_collection_parts` (count `-1` hands off), `indexed` passes the 1-based position as an integer, `from` takes an integer or whole double of at least 1, and a find builds its `Result` through `jit_found` after the loop. `walk_until` bodies lower through `lower_step` into a (break, value) pair (`:Break(s)`/`:Continue(s)` give a constant flag, `if` merges arms with `Action::Select`); other body shapes refuse, so the call stays generic.
- **Guards.** The loop hands the whole call back to tier 0, which reruns it from the start, when the list is not a plain `VECSXP`, an element is not the expected unboxed scalar, a predicate returns `NA`, or arithmetic overflows. A hand-off before anything visible is written is invisible; `map` and `keep_if` build their result in the destination register, which tier 0 overwrites. A named callback adds an identity check plus a speculation on its binding that keeps the closure alive (so a recycled address cannot pass) and recompiles when the binding changes.
- **`if` in inlined bodies** lowers to `Action::Select`, evaluating both arms, which is sound because an inlined body has no effects; an `NA` condition hands off. A formal whose value cannot be unboxed binds to `UNUSED`, so a body reading it refuses rather than resolving to a caller variable.
- **Measured** (`ry run`, profiling build, a hot caller traversing a 100-item double list 10,000 times): 0.008-0.036 s per traversal function against 0.34-0.46 s with the JIT off and 0.57-0.94 s for the `Reduce`/`lapply`/`Filter`/`vapply` equivalents on GNU R. A cold caller gets only positional binding, about 1.2x to 1.6x.
- **Tests.** `traversals_agree_across_tiers` and `fuzz_stdlib_traversals_agree_with_model` (random traversals in every tier against a Rust model) in `crates/jit/tests/test_tiers.rs`. What still runs each callback through `standard_library::invoke` is in `backlog.md`.

## The standard library is measured against GNU R, function by function

**Status:** built.

- **Benchmark.** `just bench-stdlib` (`tools/bench/internal/stdlib`) times every `List`, `Str`, `Dict`, `Result` function at 1e6 against the fastest of base R, purrr, stringr and stringi, with checksums; `tools/bench/internal/stdlib/results.md` holds the last full run. A row slower than R is fixed or listed in `backlog.md` ("Open: standard library rows slower than GNU R") with its reason. Where the input is a vector, ry's side also runs on an Array, because R's vectorized functions work on unboxed storage too.
- **Accessors read in place** (`list_count`, `list_item`, `list_slice`) over a list or an Array, so accessors, `take_*`/`drop_*`, `sublist`, `split_at`, `starts_with`/`ends_with` cost what they return. Copying the list into a `Vec` per call made them quietly quadratic (8.6 s for 100,000 `List.is_empty` calls). `List.contains` compares a number by value, which is what `identical` decides for a non-`NaN` number; a length-one Array is never such a plain scalar, because `identical([1], 1)` is `FALSE`.
- **Leaf callbacks skip the call.** A leaf builtin callback (`Str.trim` passed to `List.map`) is called through its `BuiltinFn` (`Callback::leaf`, `call_leaf`). A leaf reports errors against its own function object, so `call_leaf` swaps in the call `eval::apply` would have built only when an error escapes, so the condition is unchanged.
- **Updates in place.** `Dict.update` and `List.update` reuse their first argument and re-check ownership after the callback returns, because the callback may have stored the collection. `List.update` holds a reference while the callback runs, so a `<<-` into the list copies it, and a callback returning the list itself takes the copying path so the list never holds itself. Removal through `Dict.update`/`Dict.remove` rebuilds, because a `Dict` keeps insertion order and an ordered removal shifts every later entry. Other updates are amortized O(1).
- **Tests.** The docs tests run every library example, and `fuzz_stdlib_traversals_agree_with_model` feeds Arrays as well as lists.

## Moving a collection into a helper's parameter

**Status:** built.

- **Shape** (`crates/interp/src/moves.rs`). `rebind_call` offers `d <- helper(d, k)` to `moves::call_moving`. A static check (`movable`) requires positional arguments without `...`, and that the other arguments, the callee's defaults and its body call only closures and inert builtins (`inert_builtin`, plus native-accepting library builtins), never naming the caller's variable unless it is the callee's own local. The caller's binding is then `NULL` for the call. At run time anything the check did not cover ends the move first and restores the binding: entering another closure, forcing an unseen promise, a non-closure library callback, the default error handler. Clearing the binding without restore was rejected: a second argument naming `d`, a nested closure, `get(..., parent.frame())` and an unwinding error all read the cleared variable.
- **Undo journal.** An in-place dict/set update either appends or replaces (`insert_in_place` reports replacements to `moves::replacing`), so the original is the first `entries` entries with replaced values restored (`collection_prefix`). A plain list moves the same way (`moves::extent`; `List.set`/`List.swap` report replacements); growth past capacity copies.
- **Dead frame release.** When the callee returns without the move ending and creates no escaping closure, `release_parameter` clears the parameter's binding; otherwise the dead frame keeps the result shared and the next call copies. The heap does not count an environment's enclosure as a reference, so the environment's refcount cannot decide this as GNU R's `R_CleanupEnvir` does.
- **Holes the static check cannot see.** An environment-valued variable can reach any frame, so `$`, `[[` and their assignments on an environment end every move (`moves::reaching_environment`). A local assignment of the caller's variable name does not shadow it (a read before it, or on a path skipping it, finds the caller's variable), so such a body is not movable; only a parameter shadows. Closures created in the body are recorded (`moves::created_closure`, also for `values` duplicates), and release and tail update require each to be referenced only from the move's private frames (`closures_dead`). `movable` accepts a `function` literal whose defaults and body pass the same check (`check_literal`); entering such a checked closure does not end the move, and its frame joins the tracked frames, so forcing a promise made there is covered. At return, `closures_dead` releases the parameter only when no created closure is the result and each one's refcount is covered by the tracked frames' own cells.
- **Base replacements end the move.** `xs[[i]] <- v` and kin modify in place without the journal, so `subset::modifiable` and complex assignment call `moves::modifying` first, before the sharing check, because ending the move makes the object shared and forces the copy.
- **A shared start does not stick.** A value something else holds (`.Last.value` after a top-level `d <- Dict.empty()`) cannot move, but the call runs tracked (`Move::shared`) so the dead frame is released and the next call moves.
- **Tail update.** `f(p, ...)` in tail position, `f` a reusing library builtin and `p` the first parameter, compiles to `Op::CallTailUpdate` (`bytecode::tail_updates`). Tail position is the body, the last statement of a `{` or a branch of an `if` in tail position, or the argument of a `return` outside any function literal or `local`. It updates in place only when a move into this frame still lasts after argument evaluation and every closure created meanwhile is dead with the frame and absent from the call's other arguments (`moves::frame_private`). The AST evaluator never does this, so the calls before tier 0 compiles the body copy. The dynamic closure rule (instead of refusing closure-creating bodies statically) took 20,000 calls of `h <- function(d, k) { inc <- function(x) x + 1L; Dict.insert(d, k, inc(k)) }` from 30.6 s to 0.85 s (debug build).
- **Slot frames.** A move names its binding as `moves::Binding` (a cell, or a slot) and the caller's names as `moves::Heads`; `op_call_rebinding` hands the call to `moves::call_moving_from` with the other arguments as the frame's lazy promises; `moves::resolve_function` reads a slot frame's bindings without making its environment, and the move is refused while a register of the calling expression holds the value, since registers are not counted.
- **Measured** (profiling build, 40,000 calls of `d <- add(d, i)`): copying took about 16-17 s; moving takes 0.10 s for `{ d <- Dict.insert(d, k, k); d }`, 0.066 s at top level, 0.053 s for the tail form, 0.046 s for a list helper, 0.14 s for a closure-creating helper (linear at 20,000 to 80,000 calls). 2e6 calls of `xs <- helper(xs, i)` inside a function take about 2 s for a list, dictionary or set.
- **Why static types do not prove it.** A type says what a value is, not which frames a function reads or whether it captures its environment; effect annotations would be the typed route, and ry has none.
- **Limits.** The tail update covers only the last statement and is off in a body that may capture its frame (`backlog.md`).

## A key of the wrong type is an error, not a missing key

**Status:** built.

A dictionary or set holds keys of one kind. A lookup with another kind stops with an error through the same `joined_key_kind` check insertion uses, because returning `:Err(:KeyNotFound)` hid a bug the checker reports statically. Integer and double keys join as numbers, and an empty collection has no kind yet, so any key misses.

## Records, tuples and tags compile natively

**Status:** built.

- **Construct.** `Action::Construct` writes `(kind, bits)` pairs into a stack buffer (`runtime::representation`'s encoding) and calls `runtime::jit_construct`. Unboxed scalars go into unboxed slots, allocated through `Heap::alloc_record_slots`; a double whose upper word collides with an integer or logical prefix stays a handle, and slots past `UNBOXED_SLOTS` are boxed in codegen.
- **Guarded match.** The guard compiles in place with bound names read from registers, and `Op::MatchCondition` applies the special's condition rules (a record gets the boundary error); the JIT turns it on a logical into a move, so a guard of plain arithmetic and comparisons runs natively. Anything that would reach the frame by name evaluates in a scratch child frame holding the bindings (`Op::BoundEval`): a call the compiler cannot inline (a closure's promises would read the frame), `[[`-style subject dispatch, and every runtime fallback. A guard that assigns, creates a closure, nests a `match`, leaves a loop or calls a bound name (`guard_compiles_in_place`) runs whole through `Op::BoundEval`, so an assignment in a guard never reaches the function's frame.
- **`MatchFail` always signals**, so the JIT treats it as `PureUnlessObserved` and leaves every register `Bottom` after it; as an opaque step its stale register types widened the join after each `match` and pushed loops to tier 0.
- **List element reads** speculate on site feedback like tuple items and record fields; a check on the loaded element hands off to tier 0 on a mismatch.
- **`List.range` and `List.repeat` stop past 2,147,483,647 elements** (R's longest integer-indexable vector), so a typo cannot request an unbounded allocation.
- **Benchmarks.** `tools/bench` `#@ typed` / `#@ untyped` variant blocks let the finance `ledger`, data-science `readings` and biostatistics `followup` templates use records, tags and tuples when typed and `list(kind=)` when untyped, drawing the same instances. The typed folds run in 0.05 to 0.10 s, against 0.65 to 0.91 s untyped and 0.40 to 0.70 s in GNU R.

## The standard library is the `std` namespace, with an optional prelude

**Status:** built.

- **Shape.** The library is its own namespace, `std` (`types/std.Rtypes`, `types/std.exports`); `ry` keeps the DataFrame API. `std::Name` always resolves. `[check] prelude` (default `true`) also puts bare names in scope; `false` makes a bare name unbound (with a fix to `std::Name`) unless the project defines it. Types (`Result`, `Dict`, `Set`) stay in scope, because they are type syntax, not namespace members. This is Rust's `std::prelude` shape, which fits because R already reads `pkg::name` as namespace access; Roc has no opt-out and Gleam no prelude.
- **Incremental.** The checker gates bare lookups through `stubs::outside_prelude`, which reads the setting only for library names, so flipping it rechecks only items using the library (`test_incremental.rs`).
- **Runtime.** It binds both namespaces and attaches `package:std` only with the prelude on; the host passes the negative flag `RUN_FLAG_NO_PRELUDE`, so `R CMD` and older hosts keep the prelude.
- **Docs are generated.** `crates/semantics/tests/test_std_docs.rs` renders `reference/std/` from `types/std.Rtypes` and fails when committed pages are stale (`just docs-std` rewrites them), so the declarations are the single source for checker, hover and docs; a hand-written copy drifted.
- **Gap.** Compiled code fast-paths only bare library calls, so `std::List.map` is neither fast-pathed nor JIT-looped (`backlog.md`).

## Typed ry has its own numbers, `Bool`, `Str` and `List`

**Status:** built, except the closing note that typed `I64` code runs in the interpreter, which "Typed `I64` runs in registers, and list arithmetic fuses into one loop" supersedes.

- **Shape.** Two number types, `I64` and `F64`, plus `Bool`, `Str` and `List<T>`, all `NA`-free, so a typed program needs no R data type. Design `development/design/native-types.md`; contract the reference section "Numbers, `Bool` and `Str`".
- **Only `I64` and `F64`.** All thirteen Roc number types were tried: each width multiplied checker constraint cases, interpreter arithmetic and JIT register types, and no typed program used another. A width returns only when a benchmark program needs it. Any other literal suffix is a syntax error. `Constraint::Int`/`Constraint::Frac` default to `I64`/`F64` and have no spelling; `number` is the only written constraint. An R `integer` or `raw` becomes `I64` at the boundary.
- **Representation.** `F64`, `Bool`, `Str` reuse R's `double`, `logical`, `character` storage and cross into R for free. `I64` is its own vector type, `SexpType::I64` (code 28, `I64SXP`) with `REALSXP`'s layout (16-byte header, length and capacity, then 8 bytes per item at `VECTOR_DATA_OFFSET`); a scalar is a length-1 vector and `List<I64>` the same object at length n with the Array flag (`numbers::alloc`, `numbers::list`). No attributes, never ALTREP. A boxed record per number with an R list of boxes for `List<I64>` was rejected: two representations for one type, one traced object per item, and an item-by-item arithmetic path. A dense vector gives one representation for scalars and lists, a zero-copy handoff to `crates/typed`, no per-item tracing, vectorized list arithmetic (`numbers::arithmetic`, no recycling, overflow an error) and bit64 `integer64`-compatible storage. **A new type code beats a gp bit on `REALSXP`**: R and C code testing `TYPEOF` refuse it instead of reading the bits as doubles, and `is_atomic` is false, so every R builtin raises the `Num.to_r()` boundary error (`records::boundary_message`).
- **Literals.** A suffix names the type (`5i64`), and a `-` written directly before a literal is part of it. An unsuffixed literal keeps R's type unless an expected type, the other operand or a later use decides it. A literal branch adapts to the sibling branch's ry type (`adapt_literal_branch`), and a `match` or `if` arm in a function's tail adapts to the declared result.
- **The checker decides a literal's run-time type.** A runtime with its own syntactic literal rules returned a `double` from a `match` arm adapted to a declared `I64` result, which broke soundness, and so did an unannotated `[1, 2]`. Each `ItemCheck` records the unsuffixed literals it typed `I64` (`i64_literals`), `semantics::file_elaborations` maps them to ranges, and the preflight spells each as `5i64` (`preflight::elaborate`), the mirror of erasure for GNU R. Empty lists likewise: a library call whose result items come from no list argument (`check::builds_fresh_items`; `List.map` qualifies, `List.keep_if` does not) and `[]` are wrapped as `.ry_items(expr, "I64")`, a no-op on every other value, so a shadowing project function is safe; the typed core lowers it as its argument. An empty list is stored by its items, so without the wrapper `[]` is `logical(0)` and `List.sum` of it R's `integer` 0. `List.keep_if` and the other slices need no wrapper because `standard_library::subset` gives an empty result its input's storage, and `numbers::operands` treats an empty list of any storage as an empty `I64` operand. Accepted costs: the spelling shows where code reads itself as data (`match.call`, `body`, `substitute`), and columns after an elaborated literal shift in run-time error messages.
- **Elaboration plumbing.** `ry run` hands the elaborated text to the runtime through `ry_set_script_source` and the console filter releases it as the command; it rewrites the file's own bytes (invalid bytes read as `?` so offsets stay byte offsets, then escaped as reading the file does), so a Latin-1 script keeps its bytes. A whole literal spelled with a fraction or exponent converts digit by digit, because an `f64` rounds past 2^53. `lower::with_annotated_literals` remains for `ry load` and `source()`, which run unelaborated text; it is redundant on elaborated text and goes once those paths elaborate. A file with no ry syntax and no strict mode skips analysis (`preflight::has_ry_syntax`, which also counts `#:` comments and `Module.function` calls). A `List<I64>` given to `DataFrame()` becomes an `integer` column when every item fits, else `double`, as `Num.to_r` converts.
- **String and logical literal variables.** `greeting <- "hi"` binds a literal variable (`Constraint::StrLiteral`, `BoolLiteral`) that an annotated binding or typed parameter in the same item decides as `Str`/`Bool`, and any other read defaults to R's type, so plain R types as before. Meeting a `List` item variable binds the ry type directly in `unify`'s var-var arm (`infer.rs`), because no constraint spells "only `Str`". Call arguments and annotated-binding values that are plain reads join `literal_reads`, so the call or annotation, not the read, decides them.
- **Top-level literals in typed files are ry values.** In a strict file or one with ry syntax (`semantics::file_holds_ry_values`), a literal bound outside any function (`Checker::binds_ry_value`) defaults to `I64`/`F64`/`Str`/`Bool` (`5L` included, an `I64`). The flag is one tracked bool per file, so the firewall is untouched. Letting later top-level items decide it was rejected because it breaks the per-item firewall (an edit to any reader would re-type the binding); keeping R types forced suffixes on every constant. A value of literals alone (`literal_value_scalar`: arithmetic, logic, comparisons, an `if` of such branches, a one-statement `{}`) adapts wherever a lone literal does: top-level bindings, expected types, `List` items, `number`-bounded parameters, and beside a `Bool` operand of `&&`/`||`. A number with `.` or an exponent and no `L`, or a whole number past `I64`'s range, defaults to `F64` (`NumberLiteral::default_native`), as Roc's `2.0` is a `Frac`. Plain R files keep R types. A host with no settings counts as strict for strict origins but not here, because this changes types.
- **The boundary is explicit.** An `I64`, or a `List` whose items share no R representation, passed to an R function is `NativeValueToR` naming `Num.to_r()`/`List.to_r()`, the static twin of the runtime error; `F64`/`Bool`/`Str` and lists of them pass unconverted.
- **Smaller rules.** `/` decides `F64` and is a `type-mismatch` on `I64`, as in Roc. Lengths, counts and positions are `I64` (`standard_library::whole_number`). List operators work item by item and never recycle (over the buffers for `List<I64>`, `arith::item_by_item` for nested lists). `try f(x)` is the `Ok` value or an early return of the `Err`; `try (expr)` keeps R's `try()`. No row variables: an open tag union cannot pass unlisted tags through with their types (user direction).
- **Typed programs are written in ry types only**: `tools/bench/kernels/*.typed.R`, `tools/bench/applications/*.typed.R`.

## Typed boxes have shapes, and a tag type is a union of them

**Status:** built, except the deep conversion of a box result, which "A typed record or tag that R holds stays a box until R reads into it" supersedes.

- **Boxes.** A record, tuple or tag is a counted allocation (`values::Boxed`): a header with the count, the shape id and two bitmasks (words holding counted pointers, first words of strings), then one word per field and two per string. Freeing reads only the header, never the shape table. A field-less shape (`:B`) is one static, uncounted box per shape (`shapes::constant`), so code bakes its pointer in.
- **Shapes** (`crates/typed/src/shapes.rs`): a heap layout (the interpreter's `heap::records::Layout`) plus each field's item type, so code knowing a box's shape reads fields at fixed offsets. `Type::Record(shape)` names one shape, `Type::Tag(union)` an interned union. A tag-typed *field* is normalized to any tag (`shapes::ANY`), which keeps recursive types finite.
- **Matching any tag.** A tag from R has type `Tag(ANY)`, because the runtime does not check tag-union annotations. A `match` over it switches on the shape id (`Op::ShapeOf`) over the *confirmed* shapes a pattern names and gives up on any other. A shape is confirmed when the boundary converts it or when code constructing it compiles (`Lowered::constructed`, confirmed only once the whole function lowers, so a refused lowering confirms nothing). Confirming can grow the set a `match` in the same function relied on, so `compile` lowers again until its epoch is current, and `typed::compiled_for` recompiles when the set grows. Correctness rests on the switch being exhaustive over what compiled code can see, which the epoch guarantees.
- **Stray shapes from ill-typed R.** When an arm does not lower for one confirmed shape, `Lowering::rewind` drops it and that shape alone gives up, so one stray value from R does not refuse the whole function. An arm can also lower and give another type (`:One(x) => x` once `:One(2.5)` confirmed `One(F64)` beside `One(I64)`), and then the arms do not join. A `match` whose value is the function's result (`lower::tail_matches`) lowers each arm against the declared result type (`typed::declared_result`, `lower::Expected::Declared`): a number converts to a declared `I64` inside the arm as the exit would, and an arm for an only-confirmed shape whose value still cannot have the type is rewound; a `match` elsewhere, with no declared type, is lowered again against a target when a stray shape explains why its arms disagree: two confirmed shapes of one tag (`stray_target`), the arms of the other tags joining to the target, and each tag keeping an arm that gives it. The stray shape's arm is then rewound like a tail `match`'s, but against that target only the exact type passes: a stray `:One(2)` is not converted to `I64`, so its call runs in the interpreter as R gives it. A `match` whose value the program drops (a statement, `RUse::Unused`) may have arms of different declared types (`:One(I64) | :Two(F64)`); once a stray `One(F64)` is also confirmed, the type most arms give would be `F64` and the legitimate `One(I64)` arm would leave for the interpreter, so a dropped `match` is lowered again only when a name its arms set would otherwise not join and code outside the `match` mentions it (`lower::mentions_outside`; a pattern variable is a frame name too). Arms that disagree make a value unusable, not the function refused. `switch_shapes` takes the four cases as `lower::Expected`.
- **Ry lists in a tag from R** (`typed::list_of_array`) convert deeply into owned native lists, taking the item type from the value. The declared type need not be threaded in, because compiled code that meets a field type it cannot use gives up and the interpreter makes the call. An empty logical `Array` (a bare `[]`) cannot say its type, so it refuses rather than confirm a `List<Bool>` shape; a `[]` the checker typed is `.ry_items([], "I64")`, which has `I64` storage. Every boundary refusal carries its reason into the `RY_TYPED_LOG` line.
- **Boundary.** A record or tag argument from R converts deeply into boxes (`typed::to_box`). Plain record and tuple *parameters* are not taken from R (`type_of` gives `None`; the typed-record-parameter design is parked); records pass natively only between typed closures (`CallTyped`).
- **Alias-only annotations.** `annotations::register_definition` skips only a closure with no annotation text, because one annotated only with aliases or tag unions has empty storage masks yet is typed.
- **Typed calls are never read ahead.** `native::pure_value` does not evaluate a typed call inside an unforced argument promise: the call may not finish, and R never runs an argument its callee does not force (`ignore(1, spin())` must return). So `evaluate(build(14, 8))` runs `evaluate` in the interpreter, and `expr_tree.typed.R` binds the tree first.
- **Test.** `typed_core_keeps_tier_zero_semantics_for_records_tags_and_text` in `crates/jit/tests/test_tiers.rs`, including the ill-typed payload case; `orders`, `expr_tree`, `report` and `team_scores` run natively with checksums equal to tier 0's.

## R lists do not convert to records at a typed boundary

**Status:** built, except the "Gap" bullet, which "A ry list is one item word" supersedes.

- **Decision.** R values enter typed code only through the per-parameter boundary, as plain vectors and scalars checked at entry; records, tuples and tags are built inside typed code. A plain R list where a record is expected is a `type-mismatch` (`reference/type-system.mdx`, "Records from R"); a record from `as.record()` passes the check but runs in the interpreter, which `RY_TYPED_LOG` names. The typed log-rank benchmark (`tools/bench/kernels/log_rank.typed.R`) takes its columns as `List` parameters.
- **Rejected (by the owner): record parameters filled from R**, with fields spread into separate compiled parameters. An R list is untyped and mutable, so the boundary would be implicit (field types, lengths and `NA`s checked deep inside a call instead of where the caller converted), it adds a second conversion route beside `List.from_r()` and `Num.from_r()`, and spreading fields gives the typed core a second kind of binding with its own refusals.

## A uniquely owned Array grows in place

**Status:** built.

- **Decision.** The ownership rule for R lists (`owned`: refcount 0, or the reusable binding with refcount 1) applies to a non-empty Array, so `List.append`, `List.set`, `List.concat` and `List.swap` update in place with amortized constant time, as the standard-library page promises. An update checks the new item against the storage without allocating (`arrays::holds_item`), then stores (`arrays::store_item`) or appends into spare capacity, doubling when full (`append_owned`). A misfit item takes the copying path, which reports the error and never sees a half-updated Array. An empty Array is `logical(0)` until its first item decides storage, so it takes the copying path once. The moves journal (`crates/interp/src/moves.rs`) records replaced items so a failing helper restores the original.
- **Rejected: a separate List representation.** An Array is already the one storage of a ry list in the interpreter and typed code; the problem was ownership.
- **Measured.** Copying on every update made 40,000 appends take about 25 s; two million interpreted appends to `[]` take about 0.2 s. The rcp `list-for` and `list-while` typed ports (`tools/bench/public/rcp/*.typed.R`) run in about 0.015 s against about 0.35 s untyped.
- **Reserved room.** `List.with_capacity`/`List.reserve` of an empty Array give an empty resizable `logical` Array whose capacity is the room; the first append keeps it, and `.ry_items` keeps it when retyping. Typed code lowers `.ry_items(List.with_capacity(n), "I64")` (written by the preflight, since only the checker knows the item type) to `Op::EmptyList`.
- **Pinned by** the Array growth and `move_undo` cases in `crates/frames/tests/test_standard_library.rs`.

## Typed `List.sort_with` is a merge sort with its comparator inlined, and strings order by the interpreter's collation

**Status:** built.

- **Sorting.** `sort_with` in `lower.rs` builds a bottom-up merge sort in the IR with two buffers that trade places per pass, and inlines the comparator once into the merge step. A right item goes first only on `:GT` (`Op::ShapeOf`), which keeps the sort stable as the standard-library page promises. Rejected: a native sort that calls back, which needs a compiled comparator with a native entry, which inlined lambdas lack.
- **Tuple index.** `[[` on a tuple with a constant position is `Op::Field`; a computed position, or any index of a named record, refuses, because the field's type depends on the position.
- **String order.** `values::str_order` calls `interp::sort::collate`, the function behind R's `<`, for `ry_str_compare` and list comparisons. The interpreter reruns failed native calls, so the tiers must agree in every locale; one function is the only way, and `collate` reads the locale per call, so `Sys.setlocale` is honored.
- **Measured.** Typed knucleotide runs natively in about 0.04 s against about 0.5 s untyped, same checksum.
- **Pinned by** `typed-sort-with.scenario`, `test_tiers` sort and string cases, and `comparisons_and_logic_follow_r` in `crates/typed/tests/test_typed/values.rs`.

## The typed suite scores typed ry against Rust

**Status:** built.

- **Shape.** `tools/bench/typed/` is a suite like the others: `suite.toml` names each program's `typed_source` (owned by the kernels or applications suite) and `rust_source`, and every twin includes `harness.rs`, which prints the typed harness's line (`name checksum median min cold`, repeat count from `RY_BENCH_REPEAT`); program sizes are those of the kernels and applications suites. `bench.py` runs it with Rust as baseline, needs `rustc` and no GNU R, and fails a program whose checksums differ. `just climb` (`tools/climb/run.py`) loads `bench.py` and times through the same runner, so one copy of the twins and one statistic exist; separate twins with their own statistic had drifted from the programs' sizes.
- **A results file names its baseline and ratio direction**: `baseline` (`gnu_r`/`rust`) and `ratio_kind` (`speedup`/`slowdown`); missing keys read as `gnu_r`/`speedup`. A typed-over-Rust ratio is a time where lower is faster, so renderers keep it out of every speed-up table, chart and sentence.
- **`rustc -O` on one file**: level 3 like cargo release, no target-CPU flag, no cargo project per program; flags and version go to `meta.rust`.
- **Too-short floor per suite**: 0.1 ms on Rust (`RUST_SHORT`), stored as `meta.too_short_seconds`, because both harnesses time warm runs in-process.
- **The typed harness** (`tools/bench/harness.typed.R`) **reads `Sys.time()`** with six decimals, because `proc.time()`, which `harness.R` reads, is a millisecond clock.
- **No peak memory**: `wait4` reports a child's peak no lower than the runner's own at fork, which exceeds a Rust twin.
- **`--any-build`** lifts the release-build refusal for a local look; `--write` still requires `--release`.
- The bar for the suite's geometric mean is 2x Rust's time or better (user direction); `just bench typed --ry PATH --any-build` scores a local build against it.

## `Dict.update` probes once and builds no `Result`

**Status:** built.

- The lowerer emits `Op::DictFind` (position or -1), branches, and lowers an inline `f` once per branch: found reads with `Op::DictAt`, applies `f` to `:Ok(value)` and stores with `Op::DictPut` at the known position; absent applies `f` to `:Err(:Missing)` and stores with `Op::DictInsert`. Each branch's `Result` is built and read in one function, so `typed::unbox` removes it. A called (not inlined) closure keeps one joined lookup and one call (`lower::dict_update`, `store_update`).
- **Why two copies of the callback**: one copy at a join sees a `Result` assigned on two paths, which unboxing keeps as a box. The cost is bounded by `MAX_INLINE_CALLS`.
- `ry_dict_put` falls back to an insert when the dict is shared, static or the position is -1, so `Op::DictPut` is correct wherever `Op::DictInsert` is.
- **Pinned by** `typed_core_keeps_tier_zero_semantics_for_records_tags_and_text` in `crates/jit/tests/test_tiers.rs` (inline and called callbacks that insert, replace and remove) and `test_values`.

## `Str.split_on` with a one-byte separator scans a word at a time

**Status:** built.

## `List.count_if` with a comparison predicate counts over the whole list

**Status:** built.

- **Shape.** In `Lowerer::walk`, a `count_if` over a `List<F64>` whose inline one-parameter predicate only compares the item with numbers (`Lowerer::compares_item`: comparisons against a double literal or `F64` local, joined by `&`, `|`, `!`, parentheses) lowers the body once with the parameter bound to the list, giving `Op::CountTrue` over the mask, which `typed::fusion` fuses. Other predicates keep the per-item loop.
- **Why only `List<F64>` comparisons.** Binding the list to the item name is sound only where every operation means the same elementwise; checked `I64` arithmetic may fail per item, and calls or `match` have no list form. `I64` over `List<I64>` is left out because its declared-`I64` lowering differs from a list comparison; add it when a program needs it.
- **Kernel.** A one-step program tallies answers as it compares (`tally_compared`); the general path tallies a chunk's lanes in a byte (a chunk is 128 items, a true lane is 2), so it adds whole vectors of lanes.
- **Pinned by** `test_tiers::typed_core_keeps_tier_zero_semantics_for_i64_and_list_arithmetic` (literal and local operands in both orders, connectives, a named local predicate, a shadowed name, the empty list, and a computing predicate on the loop path) and `test_values::fused_counts_follow_three_valued_logic`.

## `List.sum` adds doubles in order in double precision

**Status:** built.

- **Decision.** `List.sum` over `F64` is the left-to-right double sum from zero. The interpreter folds with `+`, compiled code calls `values::ry_list_sum_dbl` (`Reduce::ListSum`), and a fused elementwise total adds each chunk in order (`values::add_in_order`), so all give the same bits. R's `sum()` (`Reduce::Sum`, `values::ry_sum_dbl`) keeps the long-double fold, because GNU R defines it.
- **Rejected: matching `sum()`'s long double**, which tied a ry function to an R kernel and kept the sum on the x87 stack where it cannot vectorize, at several cycles of latency per item; the typed `array_map` benchmark paid for precision its Rust twin lacks, and falls under the bar of twice its twin with in-order sums. The interpreter's `standard_library::list_sum` implements the rule. **Rejected: a vectorized order**, because the interpreter, the chunked kernel and a user's loop would each need the same lane layout to agree; in-order is what every path gives without trying, as Rust's `iter().sum()` and Roc's `List.sum`.
- `List.sum([1, 1e-16, 1e-16])` is `1` where `sum()` gives the next double, as the reference states. `test_standard_library` pins the difference and `test_tiers` that the tiers agree bit for bit.

## Counts that share a list share one kernel pass

**Status:** built, except the "Not done" bullet on range facts, which "Whole-number ranges decide which checks typed code needs" supersedes.

- **Shape.** `Op::CountTrue { program, inputs, counts }` pairs several counted operands with their `I64` result locals and has no `dest`. `Inst::assigned` is the one place that says which locals an instruction writes, and every pass asks it. At most `values::COUNTED_LISTS` (8) counts share a pass; a counted operand may be a step or a logical list input.
- **Why.** The log-rank statistic asks five counts per event time over the same three lists (`time >= t`, `time >= t & treated`, `time == t & event`, that with `& treated`, and `event`), which read the lists five times and compared `time >= t` twice; its Rust twin makes one pass with five counters. Typed `log_rank` now makes one pass per event time, at one more linear walk of compile time for functions with a count.
- **Merge rule (`fusion::merge_counts`).** After each count has absorbed its own comparisons, it merges into the nearest earlier count of its straight-line run (its block and the single-predecessor blocks jumping into it) when no `CallR` or `CallTyped` lies between them, nothing from the earlier count on assigns the later count's inputs or results, nothing between reads the later count's results, they read at least one common list, and the merged program fits the kernel limits. Identical steps are reused, so a shared comparison runs once.
- **Why a shared list.** A pass fails unless all its list inputs have one length; merging counts over unrelated lists would give up (and rerun) calls that each count alone would pass. A shared list ties the lengths, so the merged pass fails only where one count would.
- **Why a call keeps them apart.** A count fails on `NA` and gives up the call; moving it before an R call would run that call twice. Calls are the only effect a rerun repeats.
- **Why the later count moves up**: the earlier count's results may be read in between (`n1 <- count(a); x <- n1 + 1; n2 <- count(b)`), and moving up needs only the later count's inputs unchanged over the gap.
- **Not done: range facts for `I64` subtraction.** Dropping the overflow check from `fib`'s `n - 1` and `n - 2` changed its time by less than the noise.
- **Pinned by** `crates/typed/tests/test_typed/fusion.rs` (which counts share a pass, and each rule that keeps two apart), `fused_counts_follow_three_valued_logic` in `crates/typed/tests/test_typed/values.rs`, and the log-rank cases of `typed_core_keeps_tier_zero_semantics_for_i64_and_list_arithmetic` in `crates/jit/tests/test_tiers.rs`.

## An R vector with `NA` converts through `List.from_r_or` or `List.from_r_missing`

**Status:** built.

- **Surface.** `List.from_r` refuses `NA`, because no ry value holds it, and its error names the two siblings. `List.from_r_or(vector, default)` puts `default` in place of every `NA` (and `NaN`), with one overload per atomic type (`Bool`, `I64`, `F64`, `Str`). `List.from_r_missing(vector)` gives `List<Result<T, :Missing>>`. Both refuse what `List.from_r` refuses (a class, attributes, an R list or a ry list of ry values, another vector type). The default is a single value that is not `NA` or `NaN`, checked even where nothing is missing. A number wider than the items widens them as R coerces: a whole number fills a logical vector as `I64`, and a fractional one fills a logical or integer vector as `F64`. The checker picks the overload the same way, because a literal that does not fit a candidate's parameter rules that candidate out (`Checker::check_argument`), so `List.from_r_or(x, 0.5)` with an integer `x` is a `List<F64>`. Rejected: an `Option`-like type (ry has `Result` already), a lenient `List.from_r` (a silent `NA` in typed code is what the boundary exists to stop), and one function with a mode argument (the result type would depend on a value).
- **One runtime function for both tiers.** `numbers::list_from_r::<MISSING>` (`crates/interp/src/numbers.rs`), instantiated once per treatment of `NA`, is the builtin behind all three conversions and serves the interpreter and compiled code. The checker types the vector argument as a conversion and the default as ordinary ry code (`native.rs`), and the preflight's `.ry_items` carries the checked item type for both; `arrays::checked_missing` widens the `Ok` payloads as `checked_conversion` widens items.
- **Compiled code passes the default as a value.** `RUse::Converted` carries the default's local, `Op::CallR` passes its words after the arguments', and `typed::call_r` converts it to R and hands it to the same builtin as its second argument, so the fill happens in one place. A default whose lowering calls R is refused with a message to compute it first, because R evaluates the default after the vector and compiled code would reverse that order.
- **`List.from_r_missing` compiles to a list of the union `:Ok(item) | :Err(:Missing)`.** The builtin builds R tag records, and `typed::results_list` boxes each one and checks its shape against the union's members; a guessed payload of another type fails the guess as any other conversion does. **Follow-up (not done):** build the boxes directly instead of through R records, if a measured program converts large vectors this way.
- **The typed code file format recorded a conversion's default type from version 4** (version 5 is current: "An R call's argument passes R literals and outside variables as code").
- **Pinned by** the `conversions__missing_values_convert_with_a_default_or_as_results` typing fixture, the `List.from_r_or`/`List.from_r_missing` cases of `crates/interp/tests/test_arrays.rs` and `crates/frames/tests/test_standard_library.rs`, and the `gaps.R` section of `crates/ry/tests/scenarios/typed-code-calls-r.scenario` (native at the first call, `--aot`, and `RY_JIT=off`).

## `Num.sqrt(NaN)` is an error, as every library function's `NaN` is
