# Decisions: Heap and collector

The object model, allocation, the garbage collector, and start-up and code images.

## The runtime's object model, collector and native boundary

**Status:** built, except one-step promotion and the 16 MB large-vector budget, which "Two old generations, separate vector and node limits, and a pool as large as the vector limit" supersedes, and the small `Rf_eval` subset, which "The interpreter and base R" supersedes.

Code: `crates/heap` and `crates/libr` (C half in `src/native.c`, headers in `include/`). Spec: `development/design/r-runtime.md`, section 4.

**Two crates, split by who may see the layout.** `heap` owns layout, allocation, the collector, interning and frames, and knows no C; `libr` owns runtime state, the native boundary and every export. Its cdylib has the `libR.so` soname, because a GNU-R-built package needs that library and it must hold the whole runtime.

**One header, three payload shapes.** A 16-byte header: type code, collector bits, object and ALTREP flags, GNU R's 16 gp bits at GNU R's positions (packages test `LEVELS(x) & 8`), a 16-bit saturating reference count, the attribute pairlist. Vectors store length and capacity, so `INTEGER()` is an interior pointer at offset 32; everything cons-shaped is a triple. Rust-side atomic vectors start zeroed (uninitialized reads are undefined behavior in Rust); `Rf_allocVector` skips it.

**Binding cells are heap objects** (`SexpType::Binding`, code 26, unused by GNU R and never handed to native code). A cell's address is stable while referenced, so compiled code can watch one and hold it after `rm()`. Base keeps its cells on the symbols, as GNU R's `SYMVALUE`, so a base lookup is one load. Each frame keeps a 64-bit symbol filter (a removed binding leaves its bit set, which only costs a scan), and `INLINE_BINDINGS` (8) slots keep a frame in the 192-byte class (`crates/heap/src/env.rs`). Frames up to `INDEX_THRESHOLD` (32) bindings scan; larger ones keep a hash index.

**A promise keeps its expression and carries its bytecode in the attribute slot**, which GNU R never uses for a promise. GNU R's `PRCODE` holding code would send every expression reader (`substitute`, `match.call`, deparse, C's `PRCODE`) through an accessor. The C API hides the slot (`ATTRIB`, `ANY_ATTRIB`, `DUPLICATE_ATTRIB` see none; `SET_PRCODE`/`SET_PRENV` drop the code; serialization writes none). Arguments worth compiling (`compiles_as_promise`: no `function`, loop, `break`, `next` or `return`; a bare symbol stays an ordinary promise) are compiled at the site's first closure call (`compile_promise_arguments`), not with the body: a builtin callee never pays, and eager compilation was exponential in nesting depth. Promise code has no closure to compile against, so a closure call inside it makes ordinary promises. `bytecode::run_promise` skips the entry profile, loop states and optimizing tier, and restores the srcref current when forcing began. A loop passing arithmetic arguments to a closure ran about 1.6x faster, JIT off.

**`switch` compiles to one table lookup and a chain of identity tests** (`SwitchArm`, then `BranchUnlessSame` per arm), because every op in the JIT's control-flow graph has at most one jump target, which rules out one jump-table opcode. Testing arm numbers with `MatchLiteral` instead (reading both scalars by kind) cost 9% of expr_tree's warm instructions. Names match by identity first and by text only for another encoding or `NA` (`eval::switch_name_matches`). Rare shapes (a tagged, dots or missing selector, `...` among the alternatives, two defaults) stay AST calls (`switch_compiles`), both paths read the selector through `eval::switch_selector`, and errors match GNU R's AST `switch` ("duplicate 'switch' defaults"; an empty default that runs is "argument is missing"), not its byte compiler, since GNU R runs a closure's first call through the AST.

**A closure call runs one collection check for its frame**: `frame_environment` reserves the environment, cells and default promises (`Heap::reserve`) and `bind_arguments` uses the `_uncollected` allocators. Safe because the caller keeps argument values alive, defaults are reachable from the closure, and `match_args`' result is computed before the reservation.

**Compiled `x[[i]] <- v` updates in place** (`assign_element_in_place`, `bytecode.rs`) only when the result certainly equals what `[[<-`/`[<-` returns (a local, unlocked, unshared, classless, non-Array vector, a scalar position inside it, and a non-`NULL` value under `[[` on a list or an attribute-free scalar of the vector's own atomic type), with `complex_assign`'s sharing checks (`moves::modifying`, `maybe_shared`, `reuse_permitted`), clearing the binding's missing bits; otherwise it falls back to `complex_assign`. Pinned by `assignment__element_in_place`.

**The Linux release build is profile-guided.** `just package` on x86_64 Linux runs `tools/layout/optimize.sh`: an instrumented build of every crate linked into libR and `ry` runs `tools/layout/train.py`, the release build uses the merged profile, and BOLT lays out libR from a second training run. Held-out programs gain as much as trained ones, so the profile generalizes.

- **Profile flags go through `RUSTC_WRAPPER`** (`tools/layout/rustc-wrapper.sh`, `RY_LAYOUT_RUSTFLAGS`), not `RUSTFLAGS`, which changes every crate's `-C metadata` hash and so every v0-mangled symbol: the profile silently matched about 1% of functions (LLVM warns on hash mismatch, never on a missing record). Both builds keep `strip` off and use their own target directory, since cargo does not rebuild when only the wrapper's flags change; `-p libr -p rcmd` and `-p ry-lang` build separately, as feature unification differs.
- **Measured** (testthat_full, plain / PGO / PGO + BOLT): test phase 0.252 / 0.228 / 0.219 s, process wall 1.68 / 1.51 / 1.44 s, callgrind 2.60G / 2.22G / 2.21G; public suites (GNU R over ry, geometric mean) awfy 1.96 / 2.45 / 2.48, shootout held out 2.16 / 2.55 / 2.58. PGO is nearly all the gain; BOLT cuts I-cache misses another 9% and grows libR from 107 to 136 MB (the original text stays in the file) without raising peak RSS. An earlier attempt that profiled only `interp`, `heap`, `libr` and trained on oracle cases alone ran 1.4 to 1.9x slower, for an unconfirmed reason.
- **The build fails on a stale profile** (`-pgo-warn-missing-function` over 1% of records, since LTO drops a few never-called functions, or any hash mismatch). `EMBEDDED_RUNTIME`/`EMBEDDED_BASE` are read through `black_box`, because a `const None` folded an arm away in the profiled build only.
- **BOLT needs LLVM 20+**: BOLT 18 produced a libR that segfaulted in blake3's AVX-512 assembly, and one that the dynamic loader rejected when it optimized only a few functions. Only functions the PGO profile saw run are instrumented (`tools/layout/hot_functions.py`), because all of libR's text needs over 14 GB; `objcopy --remove-relocations` drops the `--emit-relocs` sections that keep the symbol table alive through `strip`.
- **Benchmarks keep the plain build** (`target/release`; the layout build writes `target/x86_64-unknown-linux-gnu/release`), so a change is never measured with a profile collected before it. BOLT lays out libR only: `ry` runs 0.05% of testthat's instructions and its text causes under 5% of start-up faults, below the 10% that would justify a second training run.

**The dispatch loop reads only `code` and `registers` into locals**, and the constants and the cache through `decoded` where an op needs them, because each destructured field of `Decoded` was reloaded or spilled per instruction. It fetches the opcode with an unchecked index, sound only because code words are built in process and never deserialized. Returning a `Flow` enum from `step` was tried and cost about 860 instructions per fill, because the loop state left registers. Codegen here is fragile: measure every change to `step` with callgrind.

**S3 dispatch**: `decisions/interp.md`, "S3 methods are found through one row per method symbol".

**S4 dispatch keeps a polymorphic inline cache per generic** (`methods::S4Cache`), valid while the generic's `.SigArgs`, `.SigLength` and `.AllMTable` bindings hold the values seen; up to four entries keyed by the signature arguments' first classes, each holding the table's binding cell and method, so `setMethod`/`removeMethod` make it miss. Inherited methods are cached only once `.InheritForDispatch` stored them. The cache is a GC root, cleared when full rather than evicted (`s4__method_cache_invalidation`). `standardGeneric` costs 8,688 instructions per dispatch, JIT off (GNU R 4.3.3: 11,681; uncached 14,263). NextMethod passes `.Class` from the class whose method it found and always defines `.Group` (`""` without a group), as GNU R does (`dispatch__next_method_class_and_group`).

**NextMethod runs from a method in slots**, finding the frame by position (`Call::frame_index`) and reading dispatch variables through `eval::pending_name`, so no environment is reified. The next method's arguments are promises over the frame's pending environment, which reify keeps as the same object, so a method that assigns to a formal is seen and a promise kept past both returns reads the method's value. A pending `.GenericCallEnv` resolves as UseMethod's caller does (`pending_enclosure`). A closure next method's `parent.frame()` is the method's caller (named by position through `slot_owner` while in slots) and a builtin one runs in the method's frame (`apply_next_primitive`), as in GNU R. `MadePromises` holds one counted reference per promise NextMethod makes, so an unforced promise held only there is known dead; otherwise a released dead promise looks forced. A preserved promise, one a global handler holds, and the returned value count as held (`dispatch__next_method_from_slots`). Per call it is at or below GNU R 4.6.2 (one level 17,160 against 17,736 instructions).

**The collector: non-moving mark-sweep with sticky mark bits.** A survivor keeps its mark, so outside a collection "marked" means "old"; a minor collection marks from roots, the remembered set and the escaped set, and sweeps only pages allocated into since the last one; a major clears the marks and sweeps every page. A vector whose element pointer native code took joins the escaped set, which every collection rescans. Moving was rejected: a moving nursery cannot coexist with raw pointers native code holds. Weak references follow ephemeron rules; the `CHARSXP` intern table is weak.

**Small objects live in bitmap pages** (`crates/heap/src/space.rs`): objects up to 2 KiB in one reserved range (64 GiB, halved on failure down to 1 GiB for capped address spaces such as valgrind's), 64 KiB pages of 17 size classes, with mark, allocated and finalizable bits in side bitmaps. Sweeping is word operations (`dead = allocated & !marks`) that never read a dead object except a dead environment, to drop its Rust-side frame. Allocation claims a run of free slots from the allocated bitmap and bumps through it, with no free list. Empty pages return to a pool any class can take, so one size class cannot strand memory. Large objects are allocated individually and keep a header mark bit. Against free-list pages: 4% fewer instructions and 46% fewer L1 data misses on a call microbenchmark; a full collection of the loaded dsbench heap takes about 35 ms against GNU R's 130 ms.

**libR keeps freed memory until `gc()`.** mimalloc's purge delay is `PURGE_DELAY_MS` (1e9 ms, `crates/libr/src/libr.rs`), because returning pages after 10 ms made the kernel re-zero them on reuse (15% of the benchmark tests' profile). Not -1, because mimalloc schedules purges only for a non-negative delay and `gc()`'s `mi_collect(true)` (`frame::release_worker_memory`) carries out scheduled ones, so `gc()` returns free pages as GNU R's does; with -1 resident memory stayed at its peak all session. The price, which GNU R pays too, is a refault on the first kernel after a `gc()`.

**Roots** are the `PROTECT` stack, the precious set, the handle stack, registered globals, interned symbols, the weak-reference list and every `RootSource`. A function that allocates while holding an unrooted handle must root it first; collection stress exposes a miss. The four root stacks are `RootStack`s with a scan watermark, so a minor collection marks only entries pushed since; permanent objects go through `Heap::add_global_root`, and interned symbols are heap roots already, so a `RootSource` traces only state that changes (frames, handlers). Under stress, every eighth collection is major while the heap is small, then one per sixteenth of the live objects, which keeps total stress time linear; `RY_GC_STRESS=startup` on an empty script takes about 7 s in a debug build, which relies on the `heap` crate's `opt-level = 2` in the dev profile.

**Peak memory comes from what the heap keeps alive, not from the allocator** (glibc `malloc` gave the same peaks). At 1e6 rows the base kernels' peak RSS was 1.1 to 1.6 times GNU R's.

- `Heap::mark` sets a leaf's bit (a `CHARSXP` or attribute-free, non-ALTREP atomic vector) without pushing it, or a million-element character vector grows the mark stack to 8 MB, which keeps its capacity; a non-leaf's attribute slot is always traced, which compiled promises depend on.
- Builtins write into the result vector rather than copying from Rust vectors.
- **A large vector beyond memory plus swap is refused up front** (`memory_ceiling`, `CannotAllocate`) on Linux unless `vm.overcommit_memory` is 1, because mimalloc reserves without committing, so `numeric(1e10)` would fail only when touched, where GNU R reports "cannot allocate vector of size". macOS and Windows have no bound, matching GNU R there.
- **Rejected:** `mmap`ing large vector bodies and unmapping them when unused lowered no peak (rowSums rose from 168 to 173 MB), and `MIMALLOC_PURGE_DELAY=0` lowered the setup peak by only 4 MB.
- **Not heap:** ry started about 13 MB above GNU R in clean file-backed pages, with anonymous memory at parity ("Start-up memory: release relocation tables and preflight code pages").

**Removing a binding is O(1) amortized**: the slot keeps a sentinel symbol and the frame compacts once half its slots are removed. Shifting made `rm()` over a large frame quadratic.

**The handle scope roots what the API hands out, not every allocation, and only recently.** During a native call, a handle an API function returns goes to the handouts stack (`Heap::hand_out`), truncated on return. Rooting every allocation would keep all of `Rf_eval`'s garbage when native code loops over it.

- A call keeps only its latest `HANDOUT_WINDOW` (1,024) to twice that, dropping the older half in one `drain`. Invariant: ry allocates for native code only where GNU R does, so code correct under GNU R never needs an older handout. Results that would break it stay out of the window: a view of something GNU R stores in the argument (`FRAME`'s pairlist) is `Pinned` to the call's handle stack, and a field read (`CAR`, `TAG`, `PRINTNAME`, ...) is `Reachable` and takes no slot.
- Only the outermost API function hands out (`Runtime::api_depth`); a nested one returns to ry's code, which the outer scope covers, and would displace native code's recent handouts. A C context saves `api_depth` and the window base with the `PROTECT` depth, so a jump cannot strand handouts. Handouts have their own stack because the window drops entries from the middle of a call's region.

**Accessors are inline in `Rinternals.h` and mirrored in libR.** The header reads the kind byte (offset 0), ALTREP flag (offset 2, bit 1), length (16), elements (32) and cell fields (16, 24, 32) at fixed offsets that `heap/src/object.rs` pins with const assertions, and the exported functions take the same fast paths before `enter`, so binaries built against GNU R's headers skip the boundary too. Source compatibility alone (an opaque `SEXP`) saves nothing, because the opaque `SEXP` already forces every accessor to be a real function. Element pointers into lists and character vectors go through libR ("Read-only element pointers escape too").

**Each native call owns a `PROTECT` region.** `UNPROTECT` below its base is an error (GNU R allows it silently); an imbalance on return warns and cuts the region back, so a leak never accumulates.

**The boundary rule.** Inside Rust every non-local exit is an `Err(Unwind)`. Native code runs in a C trampoline with a jump target (`ry_call_native` and per-signature trampolines). An API function runs under `enter`, which catches the `Err` and any panic, drops everything, then calls `ry_jump`, so the skipped frames hold nothing with a destructor, the condition under which `longjmp` over Rust is defined. API callbacks (`R_UnwindProtect`, `R_ToplevelExec`, `R_tryCatch`, ...) run from C, so a jump out of them never skips a Rust frame, and a C++ exception from an `R_UnwindProtect` cleanup unwinds only C frames compiled with `-fexceptions`. A jump restores its context's `PROTECT` depth and `R_alloc` watermark, as GNU R does. Wrapping every API function in C instead was rejected: every signature in two languages for no safety gain.

**Exporting C symbols from a Rust cdylib.** rustc's version script exports only Rust symbols, so `build.rs` writes a second one from `RY_EXPORT` markers in `native.c`, which lld merges (GNU ld rejects a second script, which matters on a platform without lld). Variadic functions (`Rf_error`, `Rprintf`) must be C.

**Finalizers run at safe points, never inside a collection**: ready ones run when a native call returns, on `R_gc` and on `R_RunPendingFinalizers`, as if at top level.

**ry presents the version of the base R it runs** (revision at least 89194, which keeps data.table on its modern branches) with UTF-8 as native encoding (`decisions/libr-rcmd.md`, "The presented R version comes from the base package the runtime runs").

## An escape lasts until the outermost native call returns

**Status:** built.

- `Heap::retire_escaped` runs when the outermost native call returns (`crates/libr/src/boundary.rs`): native code may store through an element pointer only during that call, so each old escaped vector that may hold a younger child is then remembered, rescanned once and becomes ordinary. GNU R's collector never sees those stores, so this is strictly safer than GNU R. A permanent escape made every minor collection reread data.table's huge string columns after one `STRING_PTR` (`shift(x$v1)` went from 0.024 s to 0.14 s).
- During the call an old escaped character vector is not rescanned; a minor collection marks every young `CHARSXP` instead, sound because a `CHARSXP` points at nothing. The cost: a garbage young `CHARSXP` lives until the next major collection.
- **Minor budget**: the larger of `GcPolicy::young_limit` (8 MB) and half the old small objects, as GNU R's cons-cell trigger grows with its heap; old large vectors do not count ("Collections run on GNU R's schedule").
- `crates/heap/tests/test_gc.rs` pins that stores through an escaped pointer survive minor collections, before and after the escape is retired.

## Read-only element pointers escape too

**Status:** built.

- **Why.** data.table's `setcolorder`/`setorder` permute columns with `memcpy` through `DATAPTR_RO`. A large list is remembered per 128-element card, so moving a young column from a dirty card to a clean one hid it from the next minor collection, which freed it ("Column N is NULL; malformed data.table"). GNU R remembers whole objects, so the fix cannot rely on the read-only contract.
- **Shape.** Every pointer into a handle vector's elements, including `DATAPTR_OR_NULL`, `STRING_PTR_RO`, `VECTOR_PTR_RO` and an ALTREP class's `Dataptr_or_null`, reaches libR (inline `DATAPTR`/`DATAPTR_RO` only for atomic vectors) and escapes through `Heap::escape(vector, writable)`. A writable escape of an old vector remembers it at once. At retire an old vector is dirtied and remembered only if it may hold a younger child: it is remembered, or a collection ran during the escape (`Heap::escaped_collected`), which can age its children without remembering it, because all of an escaped vector's children are marked. Any other old vector held only old children, and a permutation cannot change that. Dirtying every escaped vector was rejected: data.table takes read-only pointers to every column it reads.
- **Reference counts.** Each counting escaped list gets an `EscapedList` entry that `retire_escaped` settles:
  - A writable escape snapshots the elements; retire counts what the list holds and releases what the snapshot names. A counted store in between (`SET_VECTOR_ELT`, `copy_elements`) counts the new value, adds it to the snapshot and releases nothing (`Heap::count_escaped_store`), so each value is released exactly once; releasing as usual could free a value another list holds. Collections mark snapshot entries until retire, because an entry may have left the list. Attribute stores count as usual.
  - A read-only escape records an order-independent digest: a permutation keeps it, any other store changes it, and then every element is counted once more (counts err high, never free early). The first counted change under a digest (an element store or `resize_within_capacity`) takes the snapshot (`Heap::escaped_snapshot`), since the slot may hold an uncounted value; following the digest through the store freed such a value while another list held it. A resize of a list with a snapshot releases no dropped slot.
  - `move_elements` copies from an escaped list, and a list that dies with an entry pending releases what the entry counted, not what it holds (`release_swept_lists`).
  - Rejected: deferring counts to retire (copy-on-modify would see stored values as unshared), patching the snapshot by index (wrong after a raw permutation), snapshotting read-only escapes (vctrs and purrr take `DATAPTR_RO` per call). Lookup is a linear scan because all header GC bits are taken.
- **Not covered:** a pointer kept past the outermost call (across two `.Call`s, or taken by an embedding host outside any call) that later moves elements, and ALTREP storage outside `data1`/`data2`. Packages built against older headers are refused (`decisions/libr-rcmd.md`, "A package ry compiled records its headers' binary interface").
- `RY_GC_VERIFY=1` checks the invariant before each non-major collection. Pinned by `element_pointers_keep_permuted_young_elements_alive` (`crates/libr/tests/test_native.rs`), `element_pointer_permutations_keep_the_write_barrier` (`test_gc.rs`), `datatable__setcolorder_young_columns`, `datatable__setorder_young_strings`, `native_cases_keep_the_write_barrier_under_seeded_gc_torture` (under `RY_GC_STRESS=seed:N`).

## data.table's C runs at or below GNU R's time: barrier, pacing and string kernels

**Status:** built.

- Native code fills vectors one store at a time and allocates many large columns before filling them, so (all in `crates/heap/src/heap.rs`): the write barrier reads the parent's header OLD bit; `Heap::copy_elements` decides the barrier once per range (`Rf_duplicate` uses it); large vectors have their own young budget (`GcPolicy::young_large_limit`, 16 MB or half the old generation), so `fread` does not collect per column, at the cost of up to the budget in dead large vectors; the major limit shrinks by at most a fifth per collection, so an explicit `gc()` does not buy a full collection mid-operation (it cost 31 ms of `rbindlist`'s 90 ms at 1e6 rows).
- At 1e7 rows every helper in `tools/bench/internal/table/ops.R` runs at or below GNU R's time (table in `development/design/r-runtime.md`, section 7): `tstrsplit` 3.71 s against 5.73 s, `fread` 2.36 s against 3.16 s, `rbindlist` 0.71 s against 0.90 s.
- `duplicated`/`unique` hash an all-ASCII character vector by `CHARSXP` pointer, since interning makes equal ASCII text one object (`crates/interp/src/sort.rs`). `strsplit` with `fixed = TRUE` builds one `memchr::memmem` finder per pattern and collects byte ranges, not `String`s (`crates/interp/src/strings.rs`). `vectors__duplicated_fast_paths` pins both against GNU R.
- **The ASCII flag is a hint only** (`char_str` uses it for a strict word-at-a-time check): native code can set any gp bit through `SETLEVELS`, so only `flag_bits::VALID_UTF8`, set at interning and out of C's reach, licenses `from_utf8_unchecked`.

## What keeps a dropped object alive: registers, handles, caches and dying finalizers

**Status:** built.

GNU R finalizes an object at the first full `gc()` after its last reference goes, and R6, lgr's buffered appenders and processx depend on that. Each place below held a reference GNU R does not have.

- **Registers and handles.** `Op::EndStatement dst start end` clears a statement's temporaries (registers are allocated in stack order), and `bytecode::execute_code` releases the activation's handles after every instruction, safe because live values sit in registers between instructions; `do_begin` roots only the block's own value for the same reason. The JIT lowers it to inline `NULL` stores (`Action::Clear`) and kills those registers in its liveness. Cost: one instruction per block statement and a handle-stack truncation per instruction.
- **A JIT helper that stores into the register window releases the handles it made** (`scoped`, `crates/jit/src/runtime.rs`): interpreter constructors root their results, and only tier 0 releases those at a backward jump, which a compiled loop lacks.
- **Inline caches** hold a start environment and cell, so their list carries `WEAK_PAIRS` (`Heap::mark_weak_pairs`, `clear_dead_weak_pairs` nils a dead pair, a cache miss), because a body shared between closures (R6's `clone()` rebinds methods with `environment<-`) kept the original object alive. Minors need no special case: an old list that gained a young key is remembered and traced. Emptying every cache per collection was rejected: every site would pay a full lookup after each one.
- **Tier-1 code** embeds its enclosure and outlives any one closure, so the TIER1 external pointer protects a weak reference keyed on the enclosure whose value lists what the machine code embeds. Once the enclosure dies, `compiled_for` frees the code and clears TIER1, safe because a running activation keeps its own enclosure reachable.
- **Removed binding cells** get the unbound marker (`remove_binding`), so a stale cached cell reaches nothing.
- **Dying finalizers.** `process_weak_refs` takes every dying reference off the list before marking any, as GNU R's `CheckFinalizers`; marking one at a time could revive another's key after the ephemeron fixpoint and sweep its value while it stayed registered.
- **Visibility.** Reading a variable can force a promise that decides visibility, so compiled code sets the flag before the load and treats it as unknown after a load that may force.
- `eval::eval_all` (how testthat runs a file) releases each expression's handles before the next, so a `gc()` in one top-level statement finalizes what an earlier one dropped (lgr's `AppenderBuffer` flushes this way).
- A pending compiled unwind is traced (`Interp::held_unwinds`), because a deoptimization exit allocates before tier 0 raises it. `run` in `crates/jit/src/jit.rs` pushes the address of the activation's field around the compiled entry, so `park` and the take stay plain moves.
- Pinned by the `evaluation__*finalizer*` oracle cases (same output under `gctorture(TRUE)`) and `conditions__exiting_handler_from_compiled_code` under the `ry-jit-gctorture` engine.

## libR commits mimalloc arenas lazily, and handle vectors are not zeroed before their fill

**Status:** built.

- libR's own mimalloc sets `mi_option_arena_eager_commit` to 0 from an `.init_array` constructor (`crates/libr/src/libr.rs`): an eagerly committed arena is backed by transparent huge pages, so re-touching purged parts made the kernel zero and compact whole huge pages.
- `Rf_allocVector` allocates numeric vectors uninitialized (`Heap::alloc_vector_uninit`), as GNU R does, and `Heap::alloc_vector` zeroes only the header of a vector it fills with handles. Purging stays on (`MIMALLOC_PURGE_DELAY=-1` shaves a little more), or resident memory would only grow.
- At 1e7 rows `rbindlist`'s first calls take about 1.3 s (GNU R 0.9 to 2.1 s; 2 to 6 s with eager commit). Parallel package-load planning gains too, since every planning thread's arena paid the zeroing.

## The young generation allocates by bumping a cursor

**Status:** built.

- **Shape** (`crates/heap/src/space.rs`, `heap.rs`). Each size class has a cursor over a run of free slots claimed by `claim_run`, marked allocated up front so an unhanded slot sweeps like a dead one; a collection first frees each run's unhanded tail (`release_cursors`). `refill` takes the next run in the current page, then an available, empty or new page. `Heap::allocate` is `#[inline(always)]` (trigger check, bump, prefix zeroing, header store); the collection check and `keep` slice live on the cold `allocate_small_slow`, and `refill` is cold.
- `small_trigger` (`young_limit.max(old_bytes / 2)`, or 0 under gc stress) is derived state refreshed only in `Heap::new`, after collections and in `update_policy` (which replaced `policy_mut`, so the policy cannot change without a refresh), to keep its computation off the hottest path.
- **The barrier reads `gc_bits::OLD`**, set at an object's first mark and never cleared: in a non-moving heap "marked once" is exactly "old", so the fast path `parent & (OLD | REMEMBERED) != OLD` is one load from a header the store touches anyway. `verify_barrier` cross-checks OLD against the mark bit.
- `Heap::reserve(bytes, keep)` runs one collection check for a batch the `_uncollected` allocators (`cons_uncollected`, `alloc_environment_uncollected`, ...) then fill, sized by `TRIPLE_BYTES` and `ENVIRONMENT_BYTES`. The reservation is a budget, not memory: overrunning it only moves the next collection earlier.
- **Size classes are the per-type pools**: triples share the 40-byte class, environments alone fill 192 bytes, and scalar vectors fill 32 and 48. Splitting the triple class by `SEXPTYPE` was rejected, because a call allocates promises, cells and conses interleaved and one cursor keeps them adjacent.
- **Measured:** a `cons` costs about 54 instructions, a scalar `alloc_vector` 46 plus 12 of zeroing; `sd` on 20 doubles costs 110.3k instructions per call against GNU R's 70.6k, and the rest of that gap is the interpreter's call path (`frame_cell`, `Frame::insert`, argument matching). `crates/heap/tests/test_gc.rs` pins that bump runs refill the holes a minor leaves and that a reserved batch survives later collections.

## The string intern table is a packed open-addressed array

**Status:** built.

- **Shape** (`crates/heap/src/strings.rs`). One `Vec<u64>` with linear probing; a slot packs the address divided by 8 (44 bits, enough for 47-bit user addresses) with 20 hash bits, so a probe touches the object only on a tag match (about once per million wrong candidates). A table of pointers cost a cache miss per candidate, so `formatC` at 1e7 rows went from 5.9 s to 7.8 s with 1e7 live strings while GNU R stayed level; it now spends about 0.8 s either way. Deletion leaves tombstones; growth at 7/8 load counting them and rebuilds to between 5/16 and 5/8 load keep probes short and memory near GNU R's (whose table resizes at 0.85).
- **Dead young strings** are found through an `interned` bitmap beside the mark bits (`Space::set_interned`): a minor collection removes `interned & !marks` on touched pages, so no list of new strings is kept. Strings above the largest size class use the short `young_large` list, which the intern fuzz test in `test_gc.rs` exercises by mixing in large strings.
- **One probe per new string.** `find_or_vacancy` returns the string or a `Vacancy` that `insert_at` fills. The `CHARSXP` allocation between them may collect, so the vacancy carries the table's `generation`, bumped by every fill, rebuild (`place`, which growth, `remove_dead` and `canonicalize` go through) and `load_image`; a stale vacancy, or one whose fill would need growth, falls back to `insert`. The fuzz test's `GcStress::EveryAllocation` mode collects at exactly that allocation. A collection that only makes tombstones keeps the generation, since a tombstone or empty slot on the path is still a correct place for an absent string.
- **A `CHARSXP` is aligned to 8, not 16**, so its header plus up to 7 bytes fits the 40-byte class instead of 48, which most short strings (`paste0("id", i)`, formatted numbers) are.
- `values::StringMemo` stays in `substr` and `formatC`, whose results repeat: a small per-call table stays in cache where one probe into the session-wide array misses. It is not needed for time to stay level.

## Collections run on GNU R's schedule, and dead large vectors go back to the kernel

**Status:** built, except `heap_limit` bounding all bytes and the single old generation, which "Two old generations, separate vector and node limits, and a pool as large as the vector limit" supersedes.

- **Escalation.** A minor collection that leaves less than a fifth of `min_heap_limit` (64 MB, `R_VSIZE`) free runs a major one (`R_MinFreeFrac`). After a major, `HeapGrowth::next_limit` applies `AdjustHeapSize`'s fractions, never closer than that fifth to the need, or every later minor collection would escalate. `HeapGrowth::from_environment` reads GNU R's `R_GC_*` variables with its presets and ranges (`reference/cli.md`, "Memory").
- **The small-object trigger is half the old small bytes**, as GNU R's cons-cell trigger ignores vector memory; counting large vectors let small garbage pile up (vapply over a 1e6 list peaked at 230 MB; now 112 MB, GNU R 58 MB).
- **Vectors of at least `large::MAPPED_BYTES` (1 MB) get their own mapping**, unmapped when they die (`crates/heap/src/large.rs`). `MappedPool` keeps freed mappings up to the vector limit (a sixteenth of it cost a subset loop 4.2 s of system time against 2.2 s) and resizes them with `mremap`; with none long enough it grows the longest and unmaps the rest, so it never holds idle memory while pages are added. It is a pool of address space, not a cache: nothing in it can go stale. `MADV_HUGEPAGE` was rejected for it (9.9 s of system time, from huge-page zeroing and compaction); huge pages are used only by table operations (`decisions/frames-table.md`, "Table operations map their large blocks on huge pages").

Growing such a block is an `mremap`, not a copy.
- `rep`, `rep.int`, `rep_len` (`RepPlan`, `crates/interp/src/arith.rs`, `subset::select_positions`) and a plain vector's negative subscripts (`gather_kept`, `crates/interp/src/subset.rs`) stream positions instead of building an 8-byte position per element.
- Peaks against GNU R 4.3.3: rep 242/239 MB, a subset loop over `runif(5e7)` 1386/1386 MB, data.table's `dt[v > 0.5]` loop 329/330 MB. Pinned by `runtime_peak_memory_stays_near_gnu_r` (`crates/ry/tests/test_perf.rs`).

## Two old generations, separate vector and node limits, and a pool as large as the vector limit

**Status:** built, except `jit_expand_sequence`: the JIT's `for` walks a compact `1:n` without expanding it (`jit_loop_sequence` in `crates/jit/src/runtime.rs`).

- **Why.** With one old generation a temporary live at one minor collection died only in a full one (`R_GC_MEM_GROW=0` ran 66 majors on finbench, 4.8 s collecting); GNU R's second old generation frees promoted temporaries without a full mark.
- **Generations** (`crates/heap/src/heap.rs`, `space.rs`, `large.rs`): a minor collection makes a young survivor `OLD`, a deeper one makes an old one `TENURED`. An intermediate collection frees untenured old objects, treating tenured ones as roots through the remembered set; a deeper collection empties the remembered set first and tracing re-adds each tenured object that still points at a younger one (`mark_child::<true>`). A full heap escalates minor, intermediate, major (`escalate_if_full`), as GNU R's `num_old_gens_to_collect`.
- **Limits.** `heap_limit` counts large vectors (`R_VSize`) and `node_limit` small objects (`R_NSize`, at least 32 MiB), each grown after a major. The need includes a fifth of the smallest limit (`R_MinVFree`), so a live set just under the grow fraction cannot pin the limit where every collection escalates. A major that escalation forced before a limit's worth of vectors was allocated counts as thrashing and grows the limit as if the survivors filled it, because each one tenures the in-flight working set, which only the next major frees (`sales`: 21 majors in 20 calls without it, 9 with it).
- **`MappedPool::limit` equals the vector limit**: a quarter of the heap limit made `vector_arith` (8 MB temporaries) and `loop_sum` page-fault fresh mappings every call (0.6x and 3.8x of GNU R against 1.2x and 5.0x), and kept mappings never lift the peak, since the pool maps nothing while it holds a mapping.
- **Repeated strings.** Tracing a character vector skips already-marked elements through a 64-entry address table (`trace_children`): columns of a few repeated strings are common, and a skipped `CHARSXP` has no references. On `sales` a 764,705-element column cost each intermediate collection 3.5 ms of mark-bitmap lookups, 0.5 ms with the table; the sweep was never the cost (about 0.2 ms).
- **Measured** (ratio to GNU R 4.3.3, peak MiB): `vector_arith` 1.2x, 132 (GNU R 165); `loop_sum` 4.2x, 82 (130); `sales` 1.2 to 1.7x, 128 (149). `sales` runs about 8 ms per call slower than a limit of twice the survivors would (2 majors where GNU R's schedule runs 3 majors and 5 intermediates): the price of the lower peak. Suites: finbench 360 MiB, 0.72 s collecting of 18.4 s; dsbench 382 MiB, 0.88 s; biobench 362 MiB, 0.95 s.
- **Gap:** `R_GC_MEM_GROW=0` on finbench runs 48 majors and 3.8 s collecting against GNU R's 1.6 s, because the tight limit escalates past the intermediate collection.
- `runtime_speed_stays_ahead_of_gnu_r` (`crates/ry/tests/test_perf.rs`) holds each program above a floor; open work: `backlog.md`, "Open: collector throughput on the benchmark suites".

## Large temporaries: freed from their reference counts, tracing stays for cycles

**Status:** built.

- **Why.** With tracing alone, a temporary a minor collection saw live was promoted, so a loop's dead large vectors stayed resident until a major collection.
- **Shape** (`crates/heap/src/heap.rs`: `note_zero`, `reconcile`, `shallow_roots`, `free_released`). The copy-on-modify count (`Sexp::refcount`) frees memory: a counted store releases the old value (`release_reference`); an object whose count falls to zero enters `Heap::zero_count` (a flat `Vec`, `ZERO_LISTED` header bit against duplicates) only if it is a non-ALTREP list or large atomic vector. Strings and small vectors stay with tracing, since their pages are not returned one at a time.
- **Reconcile only at an allocation** (inside `maybe_collect`), because C code may hold an unprotected `SEXP` until its next allocation, as GNU R allows. It runs past `RECONCILE_BYTES` (4 MiB) or 65,536 entries, sets `HELD` on everything the shallow roots reach one level deep (root stacks, root sources, weak references, fields of untracked objects (`untrack_references`, R's `DISABLE_REFCNT`), elements of escaped lists), and releases every candidate still at zero and not held: a list gives up its elements, a large vector's pages are freed at once.
- **Invariant: counts only overcount.** Environments, closures, promises and external pointers stay with tracing, which handles cycles (the shape of CPython's cycle collector and Nim's ORC), and a missed decrement only defers a free to tracing. A sweep decrements children only for swept zero-listed lists (`release_swept_lists`, so a dead data frame's columns become candidates again) and pending frames, which it clears first; elsewhere a leftover count is harmless.
- A freed vector's bytes stay counted until the next collection recounts them; uncounting them delayed collections, and dead temporaries only a collection finds (forced promise values) piled up (`rep` peaked about a quarter higher).
- `RY_GC_VERIFY=1` makes a reconcile free nothing and run a full collection, panicking if anything it would free is reachable; `fuzz_reconciles_free_only_unreachable_vectors` and `fuzz_temporaries_are_freed_and_live_vectors_kept` (`test_gc.rs`) run it, and the oracle cases pass under `RY_GC_STRESS=1 RY_GC_VERIFY=1` with the default run's results.
- **Measured** peak RSS (MiB, `wait4`) against GNU R 4.3.3 for the `reference/cli.md` ("Memory") scripts: subset loop 1097 against 1386, data.table loop 277 against 340, `rep` 239 against 239 (its live data). Suite CPU matches tracing alone.

## Frames released at return

**Status:** built.

- **Why.** Every binding of a dead frame lived until a collection found the frame dead, so dead `[.data.frame` frames held subset columns across majors.
- **Shape** (`Heap::release_frame`, `release_returned`, `clear_frame` in `crates/heap/src/heap.rs`, called from `run_closure` and `apply_internal_method` in `crates/interp`), following GNU R's `R_CleanupEnvir` and `unpromiseArgs`. Enclosures are counted stores, so a frame's count is exactly its heap references. At return, a frame that is not the result, precious or a symbol frame, and whose count equals its self-cycles (refcount-1 promises bound in it whose environment is the frame), is cleared at once: refcount-1 promises give up value and environment, bindings become nil and the enclosure is dropped.
- Otherwise it waits on `Heap::returned` with the closures it made (`Interp::frame_closures`, at most `FRAME_CLOSURES`) and is cleared at the next reconcile once no non-handle shallow root reaches it and its count equals its cycles plus its dead closures; only a root scan proves a closure dead, and one scan per reconcile is cheap where one per return is not. The caller's scope handle roots every frame it made, so frames are tested against the roots before the handles are marked. A collection clears an unmarked pending frame before the sweep, so its children's counts do not stay overcounted.
- **Native state that keeps an R closure preserves it** (`R_PreserveObject`, the precious set), because both release paths test it: a closure held only by an uncounted root looks like it dies with its frame. The loader's deferred-S4 `force` closure in `DeferredDefinitions` once relied on a root-source trace alone, and a compiled `.ry_defer_s4` (`outliving_cause` in `eval.rs`) then discarded its slot frame under the live callback ("could not find function `.ry_force_s4`" after a reload). As a second guard, closures never count as self-cycles at return.
- **Arguments are not released after the call**: they travel in an uncounted slice, and an untracked cell may bind a promise without counting, so a zero count does not prove it unreachable. A promise bound in a counted frame is released with that frame.
- `RY_GC_VERIFY=1` checks each reconcile against a full collection, and the oracle cases give identical output with frame release on and off. `sales` runs one major per call instead of three (0.044 to 0.046 s, GNU R 4.3.3 about 0.084 s).

## The start-up image is the heap's pages at a fixed address, mapped in place

**Status:** built.

- **Why.** A per-object image decoded, per start, a result that already had a memory layout and was the same in every process.
- **Shape.** The first heap in a process reserves its small-object space at `IMAGE_BASE` (`0x2000_0000_0000`, 64 GiB) and the writer moves large objects to `IMAGE_LARGE_BASE`, so handles in the pages are valid as is. The writer collects, tenures everything (`OLD | TENURED`) and writes pages, per-page metadata and the large section; the loader maps them `MAP_PRIVATE | MAP_FIXED` (`crates/interp/src/image.rs`; Windows reads them through `fill_from`). Soundness (`crates/heap/src/image.rs`, module doc):
  - **Same starting state.** `Heap::image_precondition` digests allocation state, table counts and fixed objects' addresses; equal digests mean the pages replace every object the loader holds. A mismatch, or a heap not at `IMAGE_BASE`, starts the slow way.
  - **No process-local addresses in the pages**: spilled frames, builtin-routine pointers (as tokens) and native payloads of fixed objects (ALTREP class tables) are cleared and restored from metadata.
- Relocated path strings are new strings that the listed referring fields point at; the pages are not patched otherwise.
- The header is checksummed, the pages are not, since reading them would fault every page in and undo sharing. The file is replaced by rename, because truncating a mapped file raises SIGBUS.
- **Mapping, not reading**: a private mapping faults lazily and shares unwritten pages across parallel test workers. Image objects are tenured, so marking writes no small-object header and collections leave those pages clean; large objects still take a mark bit per major.
- **Mapping beat reading** on an empty run: 29.2 against 33.3 ms median, and 87 against 131 MB Pss over 4 concurrent workers, at 4,337 faults against 3,217, because reading into huge-page memory (about 4.5 ms for 14 MB) zeroes then copies each page and makes every page private. An empty `ry run` executes 47.9M instructions, 7.2M in the load; testthat's remaining start-up cost is package loading.

## Code images: compiled code beside the lazy-load database

**Status:** built, except the file name `R/<pkg>.ryc`, which "Start-up and code images are keyed by build inside a base R tree" supersedes.

- **Shape.** `R CMD INSTALL` writes a code image beside `R/<pkg>.rdb` (`crates/interp/src/code_image.rs`, driver `crates/rcmd/src/code-image.R`). A fresh session records every fetch from the package's databases (`ryCodeImageRecord`), loads the namespace, forces every binding, optionally trains (`--ry-train=tests|examples|<script>`, `ry install --train`), and compiles and writes each recorded closure (`ryCodeImageWrite`). A failure warns and leaves the package without an image. `RY_CODE_IMAGE=0` ignores images at load; `--ry-no-code-image` skips writing.
- **Identity without a second key.** A closure is named by its record's database offset plus the order the stream reader creates closures (`serialize::unserialize_with_closures`), which depends on the record bytes alone; the image is stamped with the database's length and modification time ("Lazy-load records are read in place from the code image") and with `RY_RUNTIME_ID` plus a layout magic, so another build reads it as absent, quietly.
- **No second copy of the source.** Every language object a code object points at is encoded as its preorder number in the closure's body (`serialize::walk_source`). Nested function bodies are compiled at install (`bytecode::compile_nested_functions`).
- **Decoded where compiling would happen, not at the fetch.** A fetch notes where each closure's code lies (`code_image::State::pending`, keyed by body, the body preserved so its address cannot be reused), and `bytecode::run_body` decodes it at the call that would compile. A namespace fetches many closures it never calls (every registered S3 method), and decoding costs about what compiling does, so untrained tier-0 code is not a speedup: the image's value is the trained profile. Decoding at every fetch cost 2% more instructions on `library()` of twelve CRAN packages, and decoding (about 65k instructions per closure) still cost more than it saved at the first call; with deferred decoding, images are neutral (1,201.9M against 1,200.7M instructions).
- **Pending code is checked against formals.** Compiler output depends on formals (`local_symbols`, `effects::summarize`, `tail_updates`, the missing-subscript path), and `formals<-`/`as.function` share the body, so `take_pending` hands code only to a closure with the fetched closure's formals. Keying by closure would miss `environment<-` copies, which are safe to share.
- **A damaged image only costs its speedup.** An unreadable file, hash mismatch, mismatched record or rejected code warns once (`code_image::give_up`), marks the database as having no image and drops its pending code; raising an error made the package unloadable and retried at every fetch.
- **Decoded code is verified, not trusted**, because tier 0 indexes operands, registers and jump targets unchecked and the hash only detects accidents: `bytecode::verify` checks opcodes, operand bounds, jump targets against an instruction-start bitset, side tables and switch tables linearly. The encoder refuses Record ops (process-local layout ids), writes shape caches empty and masks constant gp bits to the S4 bit. `fuzz_code_image_load` runs mutated, rehashed payloads, and crashes within 20 seeds without the verifier. Residual trust: register dataflow and the JIT.
- Images are written to `.partial`, fsynced and renamed, because a mapped file that shrinks raises SIGBUS; `lazyLoadDBflush` (called by `unloadNamespace`) drops an image and its pending entries.
- **Training** keeps PROFILE counters, inline-cache hints and FEEDBACK words, so a hot body tiers up at the call that takes its code from the image (the first when the body has a loop, otherwise the second); TIER1 decodes as nil. A trained loop-heavy function saves its warm-up (12M of the 76M instructions a 200-call workload adds), a constant that does not grow with the run. Compilation and cold-refusal counts are written as 0 (they describe the trainer's code); a final refusal is kept. Machine code and inline caches are process-local and not saved (`decisions/jit-ssa.md`, "No baseline tier, and code images hold bytecode only").

## Card marking, frame watermarks and moved list growth

**Status:** built.

- **Cards for large handle vectors.** A list, expression or character vector too large for the small-object pages keeps one card byte per `CARD_ELEMENTS` (128) elements of its capacity after its data (`Sexp::cards`, `object.rs`), so a remembered large vector is not rescanned whole at every minor collection. `Heap::element_barrier` stays one load and compare for a young or remembered small parent; a large old parent takes the slow path on every store while remembered, so each store's card is dirtied. A minor collection marks only `CARD_YOUNG` cards and downgrades them to `CARD_UNTENURED` for a tenured vector, which only an intermediate collection reads (`scan_cards`). `RY_GC_VERIFY` checks every younger child sits in a dirty card.
- **Frame watermarks.** A spilled frame keeps `Spilled::scanned`, the bindings a minor collection already marked. Frames only append or compact (`retain` resets it), so a minor collection marks only appended cells (`Frame::unscanned_cells`, `mark_scanned`). The verifier checks every cell below the watermark is marked.
- **Moved growth.** `[[<-` that grows an unshared, non-ALTREP list as its final step moves the element pointers (`Heap::move_elements`) and empties the old list, so no counting pass runs; cards cannot help here, since each regrowth makes a young copy. Growth by `[<-`, or growth followed by work that can fail, still copies, because the original must stay intact on error. `release_swept_lists` releases a dead list's elements in one pass.
- **Peeked connection reads.** Unserialize serves small reads from the bytes a gzip file, raw, loaded or `gzcon` connection has buffered (`connections::peek`, `consume`; a longer read goes through the connection) and consumes them before a `refhook` call, an ASCII byte read and at the end, so the connection stays exactly after the object (`Reader::settle`).
- Pinned by `test_gc.rs` (`a_frame_filled_across_minor_collections_keeps_every_young_binding`, `moved_elements_keep_their_counts_and_survive_in_the_new_vector`, the card test, the fuzzers) and oracle cases `builtins__list_growth_moves.R`, `serialize__connection_reads.R`.

**Status:** built, except the out-of-line `Space::age`, which "Marking a traced object costs a few table loads" supersedes.

- `Space::mark` is `#[inline(always)]` and only tests and sets the mark bit, with unchecked bitmap indexing (`locate` has bounds-checked the page, and a slot of the smallest class still has its bit in the last word). Large objects go to `Space::mark_large`. `Heap::mark_child::<TENURED>` replaces a runtime flag: `trace` picks the instantiation once per object, so a minor collection's loops carry no younger-child test. A character vector of up to 16 elements skips the dedup table, which costs more to clear than its repeats save.
- **Why.** A package load's objects almost all survive, so each minor collection traces about 360k young objects and meets mostly old, already-marked children; the check per child was an out-of-line call through two bounds-checked lookups that stored the bit even when set (about 44 instructions).
- **Left open:** `locate` (page, class, multiplier, word and bit) is about 13 instructions of what remains.
- **Left open:** collecting less often while a namespace loads, since its survivors are retraced only to be promoted (`backlog.md`, "Open: collector throughput on the benchmark suites").

## Minor collections touch only what changed

**Status:** built.

- **Finalizable frames only when they own memory.** `Frame::owns_memory` (spilled bindings, an index or a hash table) sets the finalizable bit at allocation, at image restore, and when `define`, `define_formals` or `set_frame_hashed` makes a frame own memory; nothing else gives a frame heap memory (the JIT only reads frames). Most closure frames fit their inline slots, so the sweep no longer reads every dead call frame.
- **Method caches log writes.** `MethodCache::written` logs the key of each entry stored into either method cache since the last collection (`dispatch::Written`). A minor collection marks the entries those keys still name (`Marker::is_minor`); any other walks every entry. The log is cleared only when `Marker::is_collecting`, because a reconcile also traces sources. It holds keys, not objects: logging objects marked entries replaced before the collection, and with only minor collections whatever they mark is promoted and never freed (5 MB of peak RSS on testthat). Past 65,536 keys the log is dropped and the next collection walks everything.
- Freed-by-type counting is its own pass (`Space::count_dead_by_kind`) under `Activity::Profiler`, run only while profiling, so `--profile-summary` shows it as "profile summary bookkeeping" in the overhead column, not as collection.
- **Left open** (`backlog.md`, "collector throughput"): minor collections during `library(testthat)` trace each load survivor once (about 10 ms), dead returned frames are cleared one cell at a time (about 7 ms), and the sweep visits every touched page. Before the write log, the S3/S4 method-cache walk grew from 12 µs to 1.2 ms per minor collection over the testthat run.

## Pretenuring lazy-load fetches

**Status:** built.

- **Shape.** `do_lazy_load_fetch` reads inside `Heap::begin_pretenuring`/`end_pretenuring` (`pretenured`, `crates/interp/src/serialize.rs`). `Space` swaps in a second set of cursors whose refills file pages in `pretenured_pages` instead of `touched`; the inline allocation paths are unchanged. No collection runs while pretenuring, and pretenured bytes stay out of the nursery budget, since the win is the collection they no longer trigger. The next collection (or `promote_young`) flushes them before marking anything: it ages each to `OLD`, remembers each with a younger child (`has_younger_child`), then marks them and files their pages. A large object is promoted when pretenuring ends, with the same check (dirty cards for a carded one). R code the reader calls (the `PERSISTSXP` hook, `findPackageEnv`, `..getNamespace`) runs under `outside_pretenuring` and allocates young.
- **Why the flush checks children instead of a barrier.** The reader stores into objects it just built without a barrier, and a pretenured object looks young until the flush, so the flush checks every child, keeping the old-to-young invariant exact. If nil is still young at the flush, it is marked first: tracing skips leaves, so an old leaf pointing at a young nil would later read as a tenured object holding an untenured one (fuzz seed 24).
- **What it bought:** `library(testthat)` runs no collection (one before). The testthat load fetches only about 28k objects, so counting pretenured bytes toward the nursery budget would keep that collection at its old cost: the flush costs about what tracing those objects did.
- **Measuring RSS:** a freshly written binary has more of its file pages resident, which reads as several MB of RSS, so compare RSS only between copies made the same way.
- Pinned by `environments__pretenured_fetch` (writes its own lazy-load database and stores young values into a fetched environment) under `RY_GC_VERIFY=1` and stress, and `pretenured_objects_are_old_and_keep_the_young_objects_they_hold` (`test_gc.rs`).

## Lazy-load records are read in place from the code image

**Status:** built.

- **Shape.** The code image holds each recorded fetch's uncompressed serialize stream after the code payloads (streams last, so payload offsets stay 32-bit). The file is mapped read-only (`ImageFile`), so workers share its pages, and `code_image::read_image_record` unserializes straight from the map: no per-fetch inflate (about 18M instructions of a testthat run, 475 fetches) and no private copy of the `.rdb` per worker. The whole fetch path outside `read_image_record` (database number, search, first-read hash) is 1.6M of `do_lazy_load_fetch`'s 54.2M instructions on testthat_full.
- **The database file is the record's identity.** The image is stamped with the database's length and modification time (`DatabaseStamp`); any mismatch ignores the whole image, so a copy that drops modification times loses the image but never reads a wrong one, and without a modification time none is written. A per-record hash was a second identity and is gone. Each stream carries an FxHash checked on first read (`Image::streams_verified`), which catches damage or truncation and falls back to the database.
- **Base-priority packages get stream-only images** (`crates/rcmd/src/base.rs`, `BASE_CODE_IMAGES`, `ryCodeImageWrite(code = FALSE)`): a session from the start image fetches every record of every base `.rdx` by key, because start-up forces some bindings before recording starts and forcing bindings missed 14 records that testthat_full then inflated. They carry the build stamp, so they are rewritten with every start image (14.5 MB on disk). Full untrained base images (compiled and machine code) were rejected: on testthat_full `jit::ahead::load` went from 0.8M to 7.5M instructions and decoding cost 7.7M while compiling saved 3.8M, 3M net worse than no base images, plus 25 MB on disk.
- **Databases are numbered.** `code_image::Databases` keeps one column per fact indexed by database number, found by a pointer scan over the interned paths; a record is then a binary search over offset-sorted entries, since the key stays `c(offset, length)` (makeLazy's promise shape is visible to R). The `.rdb` is mapped; an install replaces it by rename, and `lazyLoadDBinsertValue` appends then unmaps it (`serialize::forget_database`), as `lazyLoadDBflush` does.
- **Measuring memory:** with a hot page cache a freshly written image sits in large folios, so touching one byte maps 2048 kB (64 kB after `drop_caches`) and peak RSS reads several MB high; drop the page cache before comparing. Over 4 workers the mapped streams trade anonymous memory (189.1 to 179.1 MB) for file-backed (43.6 to 57.9 MB), since streams are larger than compressed records.
- **Rejected: mapping heap objects per package**: it needs a fixed address per package or relocation, plus fix-ups for per-process symbols and refhook environments. Unserializing from a mapped stream keeps one layout and one allocation path.

## Escalation prediction and the dense precious set

**Status:** built.

- **Why.** A program that builds and keeps a large structure made every intermediate collection free under 1%: what it could free (objects promoted since the last deeper collection) was exactly the structure being built, and the major after it traced them again. On `tools/bench/real`'s `records`, `escalate_if_full` was 10.2% of the instructions; the prediction cut the run 9.4%, intermediate collections from 5 to 2 and peak RSS from 111 to 97 MB.
- **Prediction instead of a fixed ladder.** `Swept.untenured_bytes` counts dead objects a deeper collection freed outside the tenured generation, and `Space::younger_old_bytes` the live younger-old bytes (marks without the tenured bit, by popcount). After each escalation `younger_dead_share` is the share found dead, updated only when the younger-old bytes exceed a twentieth of the minimum node limit, since a share of a few objects predicts nothing. When old small bytes minus that share of the younger-old bytes would still leave the node limit full, escalation skips the intermediate collection. Vector pressure always tries the intermediate first, because large vectors die independently of small-object structure.
- **Only an intermediate collection teaches the prediction (settled).** Learning from majors made the policy alternate (a major found 83% dead, the intermediate it then trusted freed 10 to 14 KB of 31 MB), because of nepotism: a dead tenured object keeps its younger children alive through the remembered set until a major, so what a major frees outside the tenured generation overstates what an intermediate can. After `RETRY_INTERMEDIATE_AFTER` (4) predicted majors in a row, one intermediate runs anyway to measure again; without that retry a workload that returns to short-lived objects never runs an intermediate again (0 intermediates and 20 majors in the test's second phase). Pinned by `an_escalation_learns_only_from_intermediate_collections` (`test_gc.rs`).
- **The carded path skips repeated strings too (settled)** through `Heap::mark_strings`: the repeat table keeps each element's younger-than-the-vector flag in the low address bit, and a repeat ORs it into its card. A cheaper mark test cannot replace the table: per element of a tenured 1M-element vector, a mark test on a marked string costs 25 instructions, a table repeat 6, and a strings-only bitmap would still need a range check, a shift and two reads (about 15); a header bit costs a cache miss per element. Moving interned strings to an untraced space was rejected, because it would delay their death to a rare full collection (an RSS risk). A table miss costs 11 instructions more than a plain mark, so the table is dropped after the first card without a repeat: distinct identifiers cost 118.8 instructions per element as without it, repeats 13.4 instead of 33.3 (`sales` ran 9.96% fewer instructions). Pinned by `a_string_repeated_across_cards_keeps_each_card_dirty`, `a_vector_of_distinct_strings_keeps_a_later_card_dirty`.
- **Rejected: a nursery sized by survival** (doubling up to 64 MB while a minor promotes over a fifth): 0.6% fewer instructions on `records` over the prediction, but peak RSS rose from 111 to 141 MB, and the rule is no peak RSS regression per worker, which four parallel workers pay four times. Bounding growth by the live set buys nothing, since the small-object trigger is already `max(young_limit, old_small_bytes / 2)`.
- **Dense precious set.** `Precious { objects, counts }` plus `flag_bits::PRECIOUS`, so "is this frame preserved?" at every frame release is a flag test (every gc bit is taken, so the index cannot live in the header). `R_ReleaseObject` scans from the newest entry, as GNU R's list does; Rcpp and cpp11 preserve only their own list heads.
- **No precise remembered or escaped set.** A probe split testthat_full's minor collections (2.2% of the run) by marking source against a 2% bar for a structural change: the whole remembered set is about 0.3% of the run, roots about 0.45% (`InterpRoots::trace` 0.2%), the escaped set is empty at minor collections, and the largest piece, the work after marking (weak references, returned frames, sweep), is about 1.45%, which caps each of its sub-steps below the bar (`backlog.md`, "Open: collector throughput on the benchmark suites").

## The start image keeps base R's closures compiled

**Status:** built, except the image layout, which "The start image is compacted in touch order at write time" supersedes.

- **Why.** Recompiling every base closure at its second call cost 12.2M of an empty run's 50.4M instructions; keeping the code cut that run 18.8% and testthat_full 1.1%, at a start image of 19.2 MB against 17.2 MB.
- **Shape.** `bytecode::compile_namespaces_for_image` compiles every closure bound in a loaded namespace afresh, never runs it, and installs it as the body; the image keeps exactly that set and stores any other code object as its source. Code that ran during start-up carries the writer's inline caches, feedback, counters and slot hints, so it cannot be imaged as is. Inline caches are weak-pair lists, written empty anyway; `PROFILE[RECORDING]` follows whether the writer had a tier, and a process without one clears it at first entry. Unforced lazy-load bindings stay promises (`backlog.md`, "Unforced base bindings still compile at run time").
- **Why the heap image and not base `.ryc` code.** Decoding costs about what compiling does ("Code images: compiled code beside the lazy-load database"); heap pages are mapped as they are, and pages of never-called code stay in the page cache.
- **Rejected layouts:** own pages plus `MADV_RANDOM` (each touched page becomes its own read: a cold empty start ran 1.20x, testthat_full 1.14x); own pages without advice (no RSS gain, 1.3 MB of holes); ordering only the fresh code (start-up also reads about 160 KB of objects allocated while compiling cold closures).
- Allocating the fresh code after start-up, where it filled start-up's free slots, cost the empty run 1.6 MB of peak RSS.

## The start image is compacted in touch order at write time

**Status:** built.

- **Shape.** `Heap::write_image` numbers every live object with a stable id (a depth-first walk from address-independent seeds, `number_for_image`), ranks objects by recorded first-touch order then id, and moves every movable small object into dense pages in that rank (`Space::compact_for_image`); large objects follow the same rank. Every handle field, frame cell, the intern table, the symbol map and the roots are forwarded (`forward_for_image`). This removes the holes start-up's collections leave (about 37% of the small pages) and keeps never-run code off pages a cold start faults in through fault-around and readahead. The format is unchanged.
- **What stays put.** Objects allocated before start-up (`Space::pin_allocated`, right after `image_precondition`, whose digest covers them), fixed objects, environments, ALTREP objects and symbols. Symbols stay because frame filters, slot indexes, hash tables and record layout tags hash their addresses.
- **The profile is beside the image, not in it.** `ids`, the touch files and `order` (`development/architecture.md`, "The touch profile") are build inputs only the layout build reads; in the image they would add 3.7 MB of ids no session reads. Each names what it belongs to (`ids` and touch files carry the image's header checksum; `ids` and `order` the numbering digest), so `tools/layout/image_order.py` refuses a touch file for another image and the second write refuses an order for another numbering: a stale profile fails the build. Without an order the image is compacted in id order, the tested fallback (`crates/heap/tests/test_image.rs`, even seeds).
- **The order is regenerated, never committed.** Any change to what start-up allocates renumbers objects. `tools/layout/optimize.sh` records a profile against the binary it builds and writes the second image from it; a failing training run fails the build, as for PGO and BOLT. Rejected: an order keyed on an identity that survives renumbering, since most objects (promises, constants, pairlists) have no name and a content hash is costly and ambiguous for identical objects.
- **Merge rule.** An object's place is the lowest phase in which any run touched it (start-up, namespace load, other), then its earliest position as a fraction of that run's touches, so a long run does not push a short run's objects back.
- **Dense tables, not hash tables.** `Space::slot_index` numbers slots from a page-class snapshot taken before anything moves; seen and fixed sets are bitsets (`SlotSet`) and forwarding is a `Vec<Option<Sexp>>`. The loader has no slot numbering (building one walks every page per start), so its relocation table is a sorted `Vec<(Sexp, Sexp)>` the writer emits in address order.
- **An older-format image is stale, not damaged**: it starts the slow way silently and home assembly (`rcmd::refresh_start_image`) rewrites it (`crates/libr/tests/test_start_image.rs`).
- **The image bytes are a function of the session**, as reproducible builds and stable touch checksums need: the writer zeroes every byte live contents do not determine and rebuilds the intern table in address order (`StringTable::canonicalize`). Path strings make numbering depend on the install path's length, so training and the final write use the same base tree path.
- **A stale order is safe**: every live object is placed ranked or not, so it only costs compactness (an order forced onto another numbering passed the oracle under `ry` and `ry-gctorture`). No `MADV_RANDOM` advice ("The start image keeps base R's closures compiled").
- **Measured** (paired rounds against the uncompacted image): image 16.4 MB against 17.5 MB; empty run 0.85x hot and 0.95x cold, peak RSS 34.7 to 31.3 MB; testthat_full 0.94x cold. Programs held out of training gain as well (package loads 0.93 to 0.95x).
- **Measuring images:** each build needs its own base R copy, start image, assembled home, cache and package library, because a build loads only images it wrote itself and a shared one compares a fast start against a slow one. Confirm each start used its image (an `RY_IMAGE_TOUCH` file, or `strace` showing the map at the heap's fixed address).

## Young collection stress keeps survivors untenured

**Status:** built.

- **Gap.** `RY_GC_STRESS=1` runs a minor collection at every allocation, which ages each survivor into the old generation, so an object then held only by a Rust local is safe under stress but freed by the next minor collection outside it (`eval::detach_reference` was such a bug).
- **Shape.** `GcStress::Young` (`RY_GC_STRESS=young` or `startup-young`) runs an intermediate collection at every allocation with `promote_bits` limited to `OLD` (`keep_untenured`), tenuring only every 64th time, so a survivor stays collectable. A minor collection without promotion is impossible: mark bits are sticky and mean "old". Majors keep the plain mode's spacing. `Heap::trace` keys remembered-parent bookkeeping off `deeper` (any non-minor collection), not the promote bits, because an untenured intermediate still has to re-remember tenured parents.
- About five times slower than plain stress, so the default suite runs a sample (`cases_survive_young_gc_torture`, and `fuzz_programs_survive_gc_torture` runs both engines); `just gc-torture young` and `tools/fuzz-deep.py` run the deep passes.
- **Weak pairs.** `trace_children` checks a tenured weak-pairs vector's elements for younger children, since tracing never visits weak pairs and the vector otherwise left the remembered set with a young value (`deeper_collection_keeps_a_tenured_weak_pair_list_remembered`).
- **Quarantine.** A sweep restarts cursors at page start, so a freed slot is reused at once and a stale read finds a valid object (stress alone missed `datetime__year_overflow`). Under `RY_GC_STRESS` or `RY_GC_VERIFY` (`Heap::refresh_quarantine`), freed objects are poisoned (`0xDB`) and held back: small slots in a per-page `quarantined` bitmap `claim_run` treats as taken (FIFO past 16 MiB), large objects to 64 MiB; they are not in `allocated`, so marking, tenuring, images and dead counts never see them, and a page holding any stays with its class. Debug builds panic in `Sexp::kind` on a poisoned kind; release builds poison it as `Free` (`POISONED_KIND`), because the check cost about 10% of instructions. Tests use `Sexp::is_poisoned`.
- **Quarantine costs nothing while off**: `refill_from::<false>` and `sweep_page_words::<false>` contain no quarantine code, and `refill`/`sweep_page` dispatch once; inline bitmap reads or poisoning through `self` in the word loop (LLVM reloads bitmaps every word) cost 0.1 to 0.2% of release instructions with quarantine off.

## Evaluated arguments are rooted, and `gc()` runs queued finalizers first

**Status:** built.

- **Every evaluated builtin argument is rooted** in the current handle scope as soon as it is evaluated, as `...` values are. Evaluating a variable returns its value held only by the binding, so in `c(x, { x <- 5; 3 })` the first argument's old value was held only by the Rust argument list (`collect_evaluated_args`); plain stress hid it because the value was already promoted; young stress freed it (`jit__write_back_in_place` and `kernels__elementwise` segfaulted).
- **`do_gc` runs pending finalizers before it collects**, so `gc()` finalizes every object dead when it was called. A queued finalizer is a root until it runs, and its closure can reach a dead frame binding another dead object, so collecting first finalized one environment instead of two (`bytecode__finalizer_under_wide_window`).
- Pinned by `evaluator_survives_young_gc_stress` (`crates/interp/tests/test_rust_allocations.rs`) and `gc_runs_queued_finalizers_before_it_collects` (`crates/libr/tests/test_finalizers.rs`, under young stress); both fail without their fix.

## Start-up and code images are keyed by build inside a base R tree

**Status:** built.

- **Why.** One file name per tree held one build's images at a time, so builds sharing `target/base-r` displaced each other and silently started the slow way; a per-build tree copy would duplicate the identical sources.
- **Shape.** `crates/rcmd/src/images.rs` names every image by build: `library/base/R/ry-start.<build>.image`, `R/<package>.<build>.ryc`, `sysdata.<build>.ryc`. A build with no current image of its own (at `just base-r`, `just start-image`, home assembly, or reuse of a pruned home) writes its start-up image, the base packages' code images and an untrained code image for every other package in the tree (`run_image_writer`, `crates/rcmd/src/base.rs`; about 2.6 s and a 190 MiB peak), and leaves other builds' files alone. Writes go to `.partial` and rename under the tree's `.start-image.lock` with a re-check, so concurrent starts write once. `crates/repl/build.rs` embeds only the building build's images, and `tools/smoke-test.sh` fails when an installed archive's first start writes or skips an image.
- **Prune rule.** Under the lock, the writer records itself newest in the ledger (`library/base/R/ry-builds`, oldest first, replaced by rename) and keeps the images of `KEPT_BUILDS` = 4 builds. Builds missing from the ledger count as oldest, by name; order never comes from file times, which `cp`, `tar` and extraction reset. Every process holds a shared `flock` on its start-up image until exit (`images::hold_start_image`, taken before the check), and the pruner removes a build only under an exclusive lock on it, so a running build's images survive; a start that loses the race rewrites them. Unkeyed names belong to older runtimes and are never pruned. Pinned by `fuzz_prune_keeps_the_most_recent_and_running_builds_whole`.
- **A package installed by another build is named, not rebuilt**: one note per library and session says to reinstall it (`note_foreign`, `crates/interp/src/code_image.rs`; scenario `install-foreign-code-image`), and `RY_IMAGE_LOG=1` reports each as an unused image. Rebuilding at load was rejected: it writes into possibly read-only or shared libraries, makes a first load compile the whole package, and leaves unpruned images.
- **Benchmarks.** `bench.py`'s `refuse_foreign_images` starts each build once before timing and refuses packages with only another build's image; timed processes run with `RY_IMAGE_LOG=1`, and `spawn` fails one printing `ry: image unused: <reason>` (missing, another build, format or database version, damaged) or `ry: image written: ...`, since only the loader's verdict catches damage or a prune between preflight and run.
- Pinned by `two_builds_alternate_starts_without_displacing_each_others_images` (`crates/ry/tests/test_perf.rs`). Disk grows by about 54 MiB per kept build (a 16 MiB start-up image, 38 MiB of code images), bounded at four plus running builds.

## Marking a traced object costs a few table loads

**Status:** built, except the "Measuring" advice to give each build its own R home, which "Start-up and code images are keyed by build inside a base R tree" supersedes.

- **Shape.** Every decision a marked object needs is a table load instead of a recomputation from its kind (on `records` the collector was 757M of 5.55G instructions, about 1,600 per kept record; this cut it 26%):
  - `KIND_TRAITS` (element width plus a `LEAF` bit) and `SHAPES` (`crates/heap/src/object.rs`) make `element_size`, `holds_no_references` and `shape` one load each; `SLOT_INDEX_MULTIPLIERS` (`space.rs`, 256 entries, zero for bytes that are no size class) makes `locate` a load, multiply and shift with no bounds branch.
  - `Space::age` is inlined into `mark` and `mark_beside_tenured` and returns whether the object is tenured; `mark_child` returns whether the child is younger instead of storing a heap field. `trace_children` skips `NULL` before the bitmap (`mark_roots` marks it first, so it is tenured from the first collection); roots go through `Heap::mark`, which never skips.
  - A small vector counts the vector cells of its size class (`SLOT_VECTOR_CELLS`), as GNU R counts small `Vcells`; a large one its exact length. The count only feeds `gc()`, `gcinfo` and `max_vector_cells`.
- **The floor for this design.** About 50 instructions per traced object remain, spread over `locate`, the mark test, `age` and the stack push and pop. Prefetching (adds instructions) and a bitmap layout without `locate` were rejected without a prototype against a bar of another 2% of `records`: the drain is 306M of its 4,987M instructions and `locate` about 60M, so removing it saves at most 1.2%. Reopen only with a wall-clock target, where prefetching can pay.

## Peak RSS is judged as anonymous, image and code size, not as one number

**Status:** built.

- **Rule.** `tools/bench/bench.py` reports anonymous RSS, start-image RSS and `libR.so` file RSS separately, plus the size of `libR.so`'s `.text` (`size -A`; `sample_memory`, `text_size`). Anonymous and image RSS must not grow. Resident text is not judged per change; `.text` size is, and growth matching the added code is accepted. Resident text is checked on the shipped layout (`tools/layout/optimize.sh`) when a release is cut, and a regression becomes a backlog item.
- **Why.** Release builds are fat LTO without function ordering, so resident `libR.so` text depends on where the linker puts hot functions; one number mixed a real signal with layout noise of the same size, and blocked changes on noise alone.
- `sample_memory` samples `/proc/<pid>/smaps` every 20 ms, because smaps cannot be read after exit.
- **`RssFile` depends on the page cache**: a just-written file sits in large folios and a fault maps a whole folio, so a build shows megabytes more right after writing its images. A file read back after eviction is cached 16 pages at a time. A comparison first runs `tools/bench/evict.py` (which evicts `base-r` and ry's cache directory) for both builds; `/proc/PID/pagemap` shows which pages of each mapping are resident.

## A handler stack set aside is traced

**Status:** built.

- **Rule.** A handler stack replaced while a calling handler, `R_ToplevelExec`, `R_tryEval` or `on.exit` code runs must stay traced: a handler closure `.addCondHands` received is referenced by its entry alone, and a Rust local or thread-local is never traced.
- **Shape.** `conditions::set_aside(handlers, restarts)` pushes the stacks onto `Interp::suspended_handlers`, which the root scan traces, and returns a guard that truncates the list to its earlier length on drop. Every site that hides a stack uses it: the three signalling loops, `run_on_exit`, the help server, libr's `try_eval`, and `ry_handlers_enter`, whose context entry owns the guard until `ry_handlers_leave`. Truncation rather than pop keeps the list consistent when an error drops a guard or a C context is left out of order.
- Cost: one `Vec` push and truncate per signal, no allocation once the list has grown. Pinned by `caught_twice` in `YOUNG_STRESSED`, `crates/interp/tests/test_rust_allocations.rs` (young stress reproduces the bug every time).

## The verifier checks every root and every traced reference

**Status:** built.

- **Rule.** Under `RY_GC_VERIFY=1` the collector checks each root before it marks (`Heap::verify_roots`) and each child of every object it traces (`Heap::verify_children`): a reference that is neither nil, nor the start of an allocated small slot, nor a live large object panics with `heap corrupted`.
- **The report** names the holder (a root stack and position, a root source's id, or an object's kind, length, address and child position), what the reference points at (`describe_stray`: an object that collection N freed, a free slot, the inside of a live object, or no heap address, printed as the integer or double it reads as), the address of the word that holds it, and the collection that found it. Small objects sit at fixed addresses, so a seeded replay reports the same address and collection number for them; a large object's address changes between runs.
- **Why.** A write past an object's storage (a tier-0 store into GNU R's storage-less ALTREP wrapper of a long vector) overwrote its neighbor's header and pointers, and crashed only when that neighbor was next used, far from the write. A value kept without a root crashed the same way, in the marker. The checks move both failures to the next collection and say which reference is wrong; `RY_GC_STRESS=1 RY_GC_VERIFY=1` names the damaged object on the first call that writes.
- **Shape.** `verify_children` (`#[cold]`) runs in `drain` beside the barrier check and shares `children_of` with it; `Space::is_allocated_object` answers the check, and `Space::slot_at` gives the slot start, size and allocated bit a report describes a stray address with. Poisoning stamps the freeing collection's number into the freed object's second word (`space::FREED_BY_OFFSET`), which is what "collection N freed" reads. `HeapObject::slice_mut` also asserts in debug builds that it never hands out an ALTREP's storage.
- **Not built: the allocation site of the freed object.** Recording a serial or a site per allocation puts a store on `init_small`, the hottest path of the runtime, in every build. The holder, the word's address and the freeing collection narrow the search instead.
- **AddressSanitizer.** A sanitizer build (`cfg(sanitize = "address")`, `space::sanitizer`) poisons every freed object for the sanitizer except its first word and lifts the poison where the allocator claims a run of slots, so a read or write through a stale reference stops at the faulting instruction. `libr` keeps the system allocator in such a build, because the sanitizer tracks only that one.
- **Between collections**, a build with debug assertions checks under verification that the holder and the value of every counted store (`Heap::verify_store`) and every value pushed on the handle stack (`Heap::root`) are allocated objects. A builtin that fills an unrooted result otherwise read the freed vector's poisoned header as an ALTREP header and crashed in the ALTREP dispatch. A release build has no such check: it would add a branch to every store and root.
- Cost: verification only, one bitmap lookup per root and per traced reference.

## Interpreter code holds values through handles the borrow checker checks

**Status:** built for `heap::handle`, `interp::handles`, tier 0's element stores, the attribute builtins and most of `strings.rs`; the rest migrates under the ratchet (backlog, "Open: the handle migration"). Design: `development/design/memory-safety.md`.

- **Rule.** Migrated interpreter code never holds a `Sexp`. It takes `&mut Cx<'s>`, the permission to allocate, collect and call R, and holds a value as `Gc<'a, T>` (unrooted, borrows the context), `Local<'s, T>` (rooted for the scope `'s`), `Fresh<'s, T>` (a new vector nothing else sees) or `Owned` (a vector proven the caller's alone, the only way to a `Write`). A function that can collect takes the context mutably, so a `Gc` held across it does not compile. `unsafe` in a file outside `heap`, `libr`, `jit`, `typed` and `ssa` may only fall: `tools/unsafe.py check` in `just gate` compares each file with `tools/unsafe-baseline.txt`, `baseline` only lowers a count, and a hand-raised line needs a backlog line naming the functions, because a count raised to turn the check green defeats the check.
- **Why.** The source of truth for "this pointer is safe to use here" was the author's reading of every callee: whether it can allocate, whether the object has storage, whether anything else can see it. Two crashes show the two halves. A matrix element store in tier 0 copied its argument with the shallow copy, which for 64 elements or more returns an ALTREP wrapper with no storage, and wrote through `slice_mut`. Names were compared by `CHARSXP` pointer across encoding marks, so equal text compared unequal. Earlier ones (a pointer from `DATAPTR_RO` the barrier missed, replacement index promises) were values held across a collection. Each fast path that keeps a pointer across a call (slot frames, in-place replacement, call-site plans) added one more place to get this wrong, and only review checked it.
- **How each bug class is ruled out.**
  - *Held across a collection.* `Gc<'a, T>` borrows `&'a Cx`; allocation, evaluation and every helper that can reach them take `&mut Cx`. `cx.root(value)` returns a `Local<'s, T>` that is `Copy` and does not borrow.
  - *A write into an object without storage.* A kind names a representation. `Local<Value>` has no slice accessor, `standard::<Real>()` answers `None` for an ALTREP object of that type, and `handles::dense` materializes one. `shallow_duplicate` and `duplicate` return `Fresh<T>` only for a `Local<T>` already known dense, and only `Fresh` and `Write` have `as_mut_slice`.
  - *A write into a shared object.* `Fresh` is not `Copy` and becomes a `Local` by `finish`, after which it has no mutable access. An existing vector is written only through an `Owned` (next entry).
  - *Names compared by address.* `is` needs `Identity`, which `Chars` does not implement, so comparing two strings by pointer does not compile. `handles::same_text` compares text, and a `Symbol` comes only from `handles::install`.
  - *A rooted value that outlives its scope.* `'s` is invariant and a `Local<'s, T>` cannot leave `cx.scope`, whose result is rerooted in the outer scope.
- **Rejected.** Indirect handles as in V8 (a slot and a load per value, needed only by a moving collector, and scopes are unchecked). Collection only at an empty stack as in `gc-arena` (R evaluation is recursive Rust that re-enters from C). `CAMLparam` macros (the `PROTECT` discipline again, unchecked). Reference counts as liveness (cycles, and uncounted holders in native code and registers). Conservative stack scanning (finalizer timing would depend on code generation, and it covers one rule). A brand alone is not enough: it proves a rooted value stays inside its scope and says nothing about the unrooted value, which is why unrooted values borrow the context.
- **Shape.** `crates/heap/src/handle.rs` holds the types, with a compile-fail doctest for each rule and `tests/test_handles.rs` on a heap that collects before every allocation. `crates/interp/src/handles.rs` is the interpreter's side: a safe builtin is `fn(&mut Cx<'s>, &Args<'_, 's>) -> R<Local<'s>>`, `safe!` makes the raw entry the builtin table holds, and each raw helper a safe builtin calls has a wrapper there with the reason the handle types make it sound. That file is where migrated code meets unmigrated code, so it is the one file whose count may rise, and by less than the other files lose in the same change.
- **Cost.** Measured on `nchar` against its raw form in one release build (callgrind): 233 instructions per scalar call in the builtin against 249, and 278.8 per element of a 100,000-string vector against 284.8. The pointer types are one word each and rooting is the same push as `heap.root`. A wrapper in `interp::handles` whose common case is a test keeps the test `#[inline]` and its slow path `#[inline(never)]`: with the wrappers out of line the safe form ran 42 instructions per call longer. The context parameter on the call path and in the bytecode loop is not measured.
- **What the types do not check**, and the harness that does: a `Trace` impl that misses a field, an ownership check that is wrong before `Owned::assume`, native code, generated code (`memory-safety.md`, "What the types do not check"). The guarantee also covers only a function that names neither `Sexp` nor `interp::heap()`: while the raw API is public, `raw()` and a `Sexp` comparison compile in safe code, and review is the check until the raw accessors move behind the boundary (`memory-safety.md`, "Migration"). Seeded stress with the heap checked, each oracle case run twice in one process, covers them.
- **Impact.** Correctness: the two classes above are compile errors in migrated code. Simplicity: a migrated builtin has no `unsafe`, no manual root and release, and no per-element ALTREP test. Performance: equal by construction for the pointer types, measured as above for the wrappers. Unmigrated code is unchanged.

## Whether a vector may be written in place is a value, `Owned`

**Status:** built; tier 0's element and matrix stores use it. Design: `development/design/memory-safety.md`, "Writes".

- **Rule.** A store into an existing vector goes through `heap::handle::Owned<'s, T>`. It has two sources: `fresh.owned()`, and `unsafe Owned::assume(local)` in the code that holds the variable and has tested that nothing else refers to its value. `owned.write(cx)` is the only constructor of a `Write`. A store takes its caller's claim as `Option<Owned>` and calls `handles::writable`, which returns the owned vector or a `handles::shallow_duplicate` copy of it.
- **Previous source of truth.** Each store read the counts itself (`maybe_shared`, `reuse_permitted`, `slot_owns`) and then chose a copy function by name. The three copy functions look alike and differ in whether the result has storage, and a store that picked `shallow_duplicate_attr` wrote past an ALTREP wrapper of 64 or more elements. The ownership test and the write were also separate statements with arbitrary code allowed between them.
- **Target shape.** The holder's test is the one `unsafe` line per caller (`assign_element`, `assign_matrix_element_in_place`, `assign_slot_matrix_element`). The stores (`store_element`, `store_matrix_element` in `bytecode.rs`) are safe and generic over the kind through the `Stored` trait, so doubles, integers, logicals, strings and lists share one body. A kind test replaces the type and ALTREP tests, names are matched as text (`handles::same_text`), and an environment's `$<-` goes through `handles::bind`.
- **Handles in a loop.** Tier 0 releases handles only at a statement's end, so raw code that roots operands per call would grow the handle stack in a loop body without braces. `handles::with` enters a context, runs the safe body and releases what it rooted; the caller roots the result only when it is a new object.
- **Impact.** Correctness: a write into a shared vector or into one without storage has no spelling in the stores. Simplicity: five per-type copies of the element store and three of the matrix store are one generic function each. Performance: `mechanisms.py` on the assignment rows before and after is in the change that introduced it.

## A builtin's fast-path entry runs in its caller's handle scope and answers unrooted

**Status:** built for the attribute readers and setters, `inherits`, `unclass`, `length<-` and the string builtins. Design: `development/design/memory-safety.md`, "Scopes, registers and unwinds" and "Cost".

- **Rule.** A `BuiltinDef::unary` or `direct` entry written against the handle types is `fn f<'a, 's>(context: &'a mut Cx<'s>, ...) -> R<Option<Gc<'a>>>`, wrapped by `safe_unary!` or `safe_direct!`. The wrapper adopts the operands with `handles::held` (no push), enters the context with `handles::in_caller_scope` (no mark, no release), and the answer borrows the context, so the signature proves nothing collects between the read and the return.
- **Why it is sound.** Every caller of an entry releases the handle stack once it returns: tier 0's `op_call_builtin` and `positional_call_builtin`, compiled code's `jit_call_builtin` (inside `scoped`), `quiet_step`, and `eval::call_direct` through `run_direct`. The operands sit in registers or the argument array, which are traced. A new caller of an entry must release as well; that is the safety contract of `in_caller_scope`.
- **Previous shape.** The first safe entries went through `handles::with`, which marks, roots each operand and the result, and releases. Against the raw forms (`just bench-mechanisms`, instructions per operation) `attr` ran 52% longer, `names` 30%, `dim` 24%, `attr<-` 21%, `class` 19%, `levels<-` 17%.
- **Shapes the same measurement fixed.** A wrapper called from a very large function is `#[inline(always)]`, because LLVM declines `#[inline]` there. An attribute list is walked through the `attribute_cells` iterator, never collected first. A rooted allocation has one out-of-line body with the allocator inlined into it (`Heap::alloc_vector_rooted`, `values::alloc`). Text kept for the length of a call goes to a stack buffer, since `Cow::into_owned` is a `malloc` and a `free`.
- **Rejected: a string's bytes for the whole scope** (`Local<Chars>` to `Gc<'s, Chars>`). Rooting keeps the string alive, but native code writes into a string in place (a package trims one by storing a NUL), so a slice that outlives the context borrow can change under its reader. `sub` and `gsub` copy the replacement text instead.
- **Impact.** Performance: the table in `memory-safety.md`, "Cost"; the migrated rows are equal to or faster than the raw forms except a few that pay about ten instructions in their entry. Correctness: an entry cannot return a value read before a collection. Simplicity: an entry has no mark, root or release to balance by hand.

## A raw entry into handle code picks its scope by who releases

**Status:** built for `subset.rs` (`[`, `[[`, `$`, `@` and their replacement forms). Design: `development/design/memory-safety.md`, "Migration" and "Writes".

- **Rule.** A function unmigrated code calls with `Sexp` arguments enters the handle types through one of three helpers in `interp::handles`, chosen by what its caller does with the handle stack.

  | Helper | Scope | For |
  | --- | --- | --- |
  | `with` | marks and releases; the result leaves unrooted | an entry whose caller roots the result or drops it |
  | `with_result` | marks and releases; the result is rooted again in the caller's scope | an entry that allocates its result and whose caller keeps raw operands across the next allocation (the replacement entries) |
  | `in_caller_scope` with `held` operands | no mark, no release, no operand root | an entry called once per instruction or loop iteration, whose caller already roots the operands and releases (`subset::vector_element`, tier 0's `$` entries) |

- **Why three.** One helper cannot serve all callers at the measured costs (callgrind, one release build): a root is about 7 instructions, a mark and release with the result rooted again about 15, and a call that returns `R<Local>` out of line 20 to 30. An element read is about 40 instructions in all, so `vector_element` through `with_result` and an out-of-line `element` ran twice as long as the raw form, which showed as 1.3% to 1.7% on the apply rows. `$` on an environment lost about 54 instructions to a root in `materialize` and two in `frame_value`.
- **Shapes the same measurement fixed.** A test that answers "nothing to do" for almost every value runs before the root (`handles::is_altrep` at the top of `materialize`). A function with one caller per loop body has an `#[inline(always)]` twin (`element_inline`) and an out-of-line name for everything else. `Cx::alloc_unfilled` for a list or string vector calls the heap's inline allocation path, one call deep, as for a number vector.
- **A new vector is filled once.** `cx.alloc_unfilled::<T>(n)` returns an `Unfilled`, whose `fill` (plain elements) or `fill_elements` (references, counted once at the end) is the only way to the vector. It replaces `set_elt` per element, which pays a count and a barrier each, and the raw `slice_mut` plus `count_written_elements` pair, where forgetting the count leaves the references uncounted.
- **Contract of `held`.** The caller's root or register keeps the value alive for the whole call. It is `unsafe` to reach from raw code for that reason, and each use states which root holds the value.
- **Impact.** Correctness: the subscript resolvers, the element reads and stores and the four operators with their replacement forms hold no raw pointer across an allocation. Performance: the per-operation table in the change that built it; the residue is one root per name lookup (`handles::names_of`, about 17 instructions against `values::names`). Simplicity: `subset.rs` holds 49 `unsafe fn` where it held 101: the specials' entries, the entries unmigrated callers reach, the attribute setters `set_dimnames`, `set_row_names` and `set_attribute_checked`, and the raw builtins `lengths`, `matrix`, `array`, `t`, `asplit`, `aperm`, `cbind`, `rbind` and `max.col`.

## An allocation failure reports the size of the vector's data

**Status:** built.

- **What GNU R prints.** "cannot allocate vector of size 7.5 Gb" names the vector's data in whole 8-byte words: no header, and the unit changes above 1024 of the smaller one (`>`, so exactly 1024 Kb prints as Kb).
- **What ry counts.** `Heap::alloc_vector_general` asks for the object's size, which has the header and, for a list or character vector above the small size, one card byte per 128 elements (`CARD_ELEMENTS`). Reported as is, a list of 1e12 elements printed 78.3 Gb where GNU R prints 78.2 Gb. The error is therefore rewritten at that one place to `length * element_size` rounded up to a word.
- **Not matched.** The size at which an allocation fails is the machine's, so a request GNU R can satisfy and ry cannot (or the reverse) differs by design.
- `complex(length.out = n)` reads `n` as GNU R's `asInteger` does (a warning and "invalid length" for a value outside the integer range) before it allocates.
- Pinned by the oracle case `vectors__allocation_failure_size`. Found by the metamorphic fuzz kind.

## A list of inert elements skips its children when it dies

**Status:** built.

- **Rule.** A list carries `INERT_ELEMENTS` (flag bit 6, shared with the string-only `VALID_UTF8`) while every element is inert: nil, a symbol, a `CHARSXP`, a character vector, or a small or ALTREP atomic vector (`object::is_inert`). Giving up such references can free nothing and release no frame, so `reconcile` and `release_swept_lists` skip a dead list with the bit, as GNU R's sweep skips every dead object's children.
- **Maintenance.** Allocation sets the bit; `set_element`, `copy_elements`, `move_elements` and `count_written_elements` clear it when a non-inert element arrives; `escape` clears it, since native code may store anything through the pointer. `count_written_elements` derives it in the same pass that counts the elements (`increment_refcount_inert`, one header read per element, branch-free).
- **Safety.** A set bit leaves the elements' counts overcounted, which is safe because counts only overcount; a clear bit only costs a walk. A large atomic element is not inert, because its release returns pages early.
- Measured on a shallow copy of a shared 1,000-element list of doubles, freed each iteration: 3.2 µs per copy without the bit, 2.7 µs with it.

## A cached ASCII string is the only string with its text

**Status:** built; cross-checked behind `syntax::testing::enable_invariants()` in debug builds.

- **Rule.** `values::same_string` answers `false` for two different objects as soon as either is cached ASCII, without reading the other's header or bytes. Name scans are dominated by this comparison (62% of instructions on a k-nucleotide hash workload when both texts were read).
- **Why it holds.** Every `CHARSXP` comes from `Heap::mk_char`, which interns ASCII text once and unmarked. `new_char` is private to the heap and makes only `NA_STRING` and image strings that were uncached when written (relocation keeps their marks). The C API refuses `allocVector(CHARSXP, n)`. GNU R's `Seql` needs both sides cached because its C API can make uncached strings.
- **Check.** `handles::assert_distinct_text` panics when the identity rule answers `false` for two strings with the same text, which names a new creation path that bypasses the cache.
- A lookup that misses a coerced name is usually not this rule: deferred string conversions are ALTREP (next entry).

## A vector kind has no `downcast`: the caller chooses `standard` or `dense`

**Status:** built (`heap::handle`, `Exact`); oracle cases `altrep__subset_inputs`, `altrep__attribute_values`, `altrep__bytecode_stores`.

- **Rule.** `downcast::<U>()` exists only for an `Exact` kind (`Value`, `Alt`, `Chars`, `Symbol`, `Pairlist`, `Language`, `Closure`, `Environment`, `Promise`), whose test cannot depend on ALTREP. For a vector kind the caller names its choice: `standard::<U>()` (and `Owned::standard`) returns `None` for an ALTREP vector, for a fast path that falls back to one that expands it; `handles::dense` expands it, for a reader whose `None` would mean "absent". A compile-fail doctest in `handle.rs` pins the refusal.
- **Previous shape.** One `downcast::<U: Kind>()` answered `None` for both "another type" and "an ALTREP vector of this type". Fast paths rightly read that as "decline", but readers of names, dims and dimnames read it as "absent", so deferred names (`names(x) <- 1:2`) made `x[["2"]]` NULL and `$<-` append a duplicate, and an ALTREP `dim` (which `dim<-` keeps) made `m[[1, ]]` report "subscript out of bounds".
- **Why a type split, not an audit alone.** Each such bug came from one call site choosing silently, and audits fix the sites that exist. With two spellings every new site chooses in writing, and the reviewer sees `standard` where the code reads `None` as absent.
- **Rejected.** A downcast that materializes (it needs `&mut Cx` and allocates, so it would turn every non-allocating fast path into a safepoint), and a three-way result type (each fast path would match an arm it only declines).
- **Audit.** The 71 vector downcasts in `interp` became `standard` except where `None` meant absent: dimnames in matrix subsetting and `[[<-`, the first dimnames of a one-dimensional array, `srcref` lists, the `dim` count in `[[`'s missing-subscript check, and the class named in the S4 `names<-` error. `stored_names` asks for the slow path for an ALTREP dimnames list.

## glibc's malloc keeps freed package buffers

**Status:** settled.

- **Previous shape.** libR left glibc's `malloc` at its defaults. Package C code allocates through it, but ry's own values come from mimalloc, so glibc's heap held little else and its top was free most of the time. A `free` that left more than the trim threshold (128 KB by default) there returned the memory to the kernel, and the next call faulted the pages in again. In GNU R its own vectors fill the same heap, so this rarely happens.
- **Measured (a test user's report, data.table on a 20-row table).** `merge(all.x = TRUE)` cost 560-640 µs per call alone and 650-710 µs after 3,000 joins, while GNU R did not change. Callgrind and cachegrind counted the same instructions and cache misses per merge either way. The difference was system time: 38 µs per merge alone, 73-96 µs after the joins, against GNU R's 2-8 µs. Over 6,000 merges that came from 1,900 or 5,786 `brk` calls and 94k or 261k minor page faults, against GNU R's 600 and 30k, all from `malloc` in data.table's C code.
- **Shape.** libR's load-time constructor (`crates/libr/src/libr.rs`) pins glibc's mmap threshold at 32 MB and its trim threshold at 64 MB, the values glibc's dynamic tuning converges to after freeing large blocks. `MALLOC_MMAP_THRESHOLD_`, `MALLOC_TRIM_THRESHOLD_` or `GLIBC_TUNABLES` in the environment leave glibc's own settings in place. Freed memory above the heap's live data stays resident up to 64 MB, and blocks of 32 MB and more still get mappings that go back to the kernel when freed.
- **Effect.** Over 6,000 merges, 287 `brk` calls and 30k page faults; system time 5-17 µs per merge whatever ran before; `merge()` after joins 828 to 550 µs per call (GNU R 1,270). `freed_native_buffers_stay_resident` in `crates/libr/tests/test_native.rs` pins it.


## Profiles run over the start-up image

**Status:** built.

- **Rule.** A session that sources a site or user profile loads the start-up image, then runs GNU R's start-up order over it (`session::start_from_image`): it cuts the search path to `.GlobalEnv`, `package:methods`, `Autoloads`, `package:ry` and base (the slow start's order, which a test worker needs to load its package from the profile), sources the site profile, then the user profile, calls a `.First` closure from the global environment, and then does `.First.sys()`'s work. For each name in `options("defaultPackages")` that is not attached, the image's own package environment is relinked in front of what the profile attached, unless an attach hook is set for it, in which case GNU R's `require()` runs. ry's own entries (`tools:ry`, `package:std`, `package:ry`) then move to the top, so a profile that lists `std` in `defaultPackages` cannot link one twice. A held entry the profile dropped stays loaded and unattached. Scenario `run-with-a-profile-over-the-start-image`, `test_start_image.rs` (its last round), and libr's `ry_repl` reads `RUN_FLAG_SITE_PROFILE` and `RUN_FLAG_USER_PROFILE` like a script session.
- **Why.** callr gives every child its own `R_PROFILE_USER`, so a slow start with a profile would cost every callr child, `ry test --jobs` worker and `ry run` in a project with a `.Rprofile`. Measured: `ry run` with a profile costs about 0.01 s of CPU from the image against 0.06 s slowly, a `callr::r()` child about 0.05 s against 0.09 s. A test worker's larger fixed cost is loading testthat and the package (backlog, "the package loader").
- **Relink, not attach.** `attach()` copies an environment, so a package environment relinked by `set_enclosure` keeps its identity: `as.environment("package:stats")` is the namespace's own package environment, as after a slow start.
- **Accepted differences from GNU R**, all because the image holds the default packages loaded: during a profile `loadedNamespaces()` lists them and their `.onLoad` options are set, and a default package a profile drops stays loaded as a namespace. Rejected: images per default-package set, which multiplies image size for a rare case; unloading a dropped namespace, which can run its `.onUnload` and leave a DLL registered.
- **Startup warnings** print under GNU R's `During startup - ` (`conditions::DURING_STARTUP`), so the warning for a missing default package matches; a warning a profile raises prints after its expression without the heading, as GNU R's `R_ReplFile` does (`session::source_file`).

## Native routines enter through the same safe entry as builtins

**Status:** built for the stats routines of `arima0` (`arma0.rs`) and `ppr` (`ppr.rs`). Design: `development/design/memory-safety.md`, "Migration".

- **Shape.** `handles::Args` is generic over an `Invocation` (a builtin's `Call` by default, or a `NativeCall`), so `NativeArgs` shares `value`, `tag` and `error` while the builtin-only methods (`matched`, `environment`, `warning`) exist only for `Call`. `safe!(native f)` makes the routine-table entry; both arms expand one internal arm, so the entry's `unsafe` text appears once. A native error names the calling closure, as GNU R's does.
- **State behind a handle.** `arima0`'s model lives in a thread-local slab of `Option<Starma>`, and R holds the slot index as an integer where GNU R holds an external pointer. An external pointer with a finalizer needs the raw heap; GNU R's R code (`arima0`, `predict.arima0`, `ar.mle` through `arima0`) only passes the handle back and frees it in `on.exit`, so the slab loses nothing R code observes. A handle that names no live slot is "bad Starma struct".
- **Impact.** Correctness: the routines cannot hold a value across a collection. Simplicity: a stats port needs no `unsafe`, so a new file's zero baseline holds.

## A replacement form updates a variable in place only when its binding holds the value

**Status:** built for tier 0's replacement forms (`op_sub_assign`, `op_super_sub_assign`, `op_sub_assign_matrix`, `op_replace` in `bytecode.rs`). Design: `development/design/memory-safety.md`, "Migration".

- **Rule.** `x[i] <- v`, `x[[i]] <- v`, `x$name <- v` and `x[i, j] <- v` write into the variable's vector only when `handles::claim_binding` (an environment binding) or `RunningFrame::claim` (a frame slot) returns an `Owned`: the binding or slot holds the value itself, the value is not shared, and no suspended compiled body holds it uncounted; the callers decline an active or locked binding before they claim. A variable whose binding is a promise (an argument read before it was assigned) is copied once, then the assignment rebinds it and later writes go in place.
- **Previous shape.** The raw paths looked through a forced promise to its value and wrote into it when its count allowed. That value may also be reached through the promise by the caller's frame, so the write leaned on the count being exact for promise results.
- **Why.** The claim is a value (`Owned`) built from facts the handle types can state: the binding's content is the value read, and the value is unshared. Through a promise, the second fact would need the count to cover every promise that holds the value, which nothing checks. The cost is one copy of an argument whose value nothing else holds (`f(c(1, 2))` with `x[1] <- 0` in `f`), on the first write only; GNU R writes that value in place.
- **Slots.** `RunningFrame` and `Slot` give tier 0's handlers a frame's registers without a raw pointer in safe code: a read is a `Gc` borrowing the context, so a slot value kept across an allocation must be rooted, and every write of a slot after code ran goes through `RunningFrame::bind`, which binds in the frame's environment when forcing, a lookup, a dispatch or a calling handler gave the frame one, because the variable then lives in a cell and a slot write would be lost.

## The evaluator's specials take handles; call machinery and assignment move with the bytecode loop

**Status:** built for the control-flow and language specials. Design: `development/design/memory-safety.md`, "Migration".

- **Rule.** A tree-walking special (`{`, `if`, the loops, `break`, `next`, `return`, `function`, `&&`, `||`, `switch`, `missing`, `on.exit`, `nargs`, `substitute`, `~`, `delayedAssign`, `makeLazy` and the rest the doc lists) is a safe builtin. The loop and function contexts, the srcref and the closure maker stay raw, because the bytecode loop and the JIT call them, and the specials reach them through `handles.rs` wrappers.
- **Why not the rest of `eval.rs` with them.** `eval`, `apply_closure`, argument matching, promises and assignment keep values in frames, `Arg` slices and unwinds that the bytecode loop also writes. Migrating them alone would wrap every frame access in a raw entry; with the register accessor and `Held<T>` they take handles in one step.
- **Impact.** `eval.rs` loses 35 `unsafe`, `methods.rs` 1, and `handles.rs` gains 23 for the wrappers (13 fewer in all). Tier 0 runs compiled code, so the per-operation table moves only where the tree walker runs (`just bench-mechanisms`, in the change that built it).
